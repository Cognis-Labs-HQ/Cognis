# ツーリング

## 概要

`src/tooling/` ディレクトリには、Cognisコードベースのすべての開発者ツールが含まれています: リントスクリプト、TypeScript ソース検査、コンテナヘルスチェックスクリプト、`cognisctl` 運用CLIです。

## 責務

- `lint-readable.mjs` を通じて読みやすさのルールを強制する（タブなし、末尾の空白なし）。
- `lint-placeholder.mjs` を通じてプレースホルダー標準を強制する。
- `npm run typecheck` ですべての TypeScript ソースとテストを検査する。
- `cognisctl` を通じて運用管理コマンドを提供する。

## アーキテクチャ

### TypeScript ソース検査

コミット前に `npm run typecheck` を実行してください。`npm run ci:test` はテストの前に型を検査し、両方の CI パイプラインが同じ検査を使用します。`npm run build` は esbuild を使い、Node 24 向けの本番資産を別途生成します。

ルートの `tsconfig.json` が、ファイルを出力しない厳密な検査の基準です。`src` 以下のすべての `.ts`、`.tsx`、`.mts`、`.cts` を対象とし、宣言、テスト、任意のコンポーネント、入れ子のコンポーネントも含めます。除外するのは生成済みの `dist` と依存関係だけです。新しいコンポーネントのために参照一覧を更新する必要はありません。

NodeNext の解決と ES2024・DOM ライブラリでサーバーとブラウザーの契約を扱います。`@cognis/core` はこのチェックアウトのソースを参照します。インポートされた自前の JavaScript は `allowJs` による型推論を提供しますが、`checkJs` は無効のため、JavaScript 全体の検証ではありません。コンポーネント設定はルートの検査範囲を制限しません。

範囲テストはコンパイラーの一覧と空でないソース一覧を比較し、静的なテスト素材に対して実際の npm コマンドを実行します。本番とテストの型エラーを独立して検出し、正常な検査を繰り返してもファイルを生成しないことを確認します。

### `cognisctl` CLI

`cognisctl` はプライマリ運用コントロールサーフェスです。コマンドモジュールは以下から自動検出されます:

- `src/tooling/cli/commands/` — コア組み込みコマンド
- インストール済みモジュールからエクスポートされた `cli/index.js`

| namespace     | サンプルコマンド                                                                                                                                |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `user:*`      | `user:create`、`user:role`、`user:set-password`、`user:disable`、`user:enable`、`user:delete`                                                   |
| `system:*`    | `system:health`、`system:info`                                                                                                                  |
| `component:*` | `component:list`、`component:enable`、`component:disable`、`component:import`、`component:config:get`、`component:config:set`、`component:test` |
| `api:*`       | `api:token`（curl 用の一時的な 1 時間管理者緊急トークンを発行）                                                                                 |

組み込みの `cognisctl` コマンドは、端末が対応していれば見出し、整列した項目、ANSI カラーを使ったレスポンス対応の端末出力を描画できます。カスタムレンダラーを持たないコマンドは整形済み JSON にフォールバックします。

## 設定

| 変数                           | デフォルト         | 説明                                                             |
| ------------------------------ | ------------------ | ---------------------------------------------------------------- |
| `COGNIS_CLI_TOKEN_PATH`        | —                  | 認証済み `cognisctl` コマンド用APIトークンを含むファイルへのパス |
| `COGNIS_EXTERNAL_MODULES_ROOT` | `external-modules` | モジュール提供のサブコマンドを検出するために使用                 |
| `COGNIS_GATEWAY_CLI_PATHS`     | —                  | ゲートウェイ提供サブコマンド用の任意のパス一覧                   |
| `COGNIS_ADAPTER_CLI_PATHS`     | —                  | アダプター提供サブコマンド用の任意のパス一覧                     |

## テスト認証情報の分離

`npm test` と `npm run ci:test` は実行ごとに一時トークン保存ディレクトリを作成し、各テストワーカーに別々の書き込み可能なファイルを割り当てます。静的な事前読み込み処理がテストモジュールの読み込み前にパスを設定し、継承した本番トークン保存先は使用しません。再起動や障害のテストでは、その後に各テストが自分のパスを明示的に変更できます。子プロセスの成功または失敗後に一時ディレクトリを削除し、通常の終了シグナルを転送します。強制終了やホスト障害では一時ファイルが残り、OSによる削除が必要になる場合があります。本番のトークン保存は変更せず、保存失敗時に成功として扱いません。
