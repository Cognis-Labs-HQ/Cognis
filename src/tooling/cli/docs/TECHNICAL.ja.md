# 技術リファレンス

コマンドラインツール の公開インターフェースと運用規則を説明します。

## インターフェース

CLI の登録で名前、使い方、説明、引数、execute を定義します。コアと提供元が自身のグループを登録し、HTTP ヘルパーがサーバーへ認証付きで送ります。

## 設定

| 変数                           | デフォルト         | 説明                                                             |
| ------------------------------ | ------------------ | ---------------------------------------------------------------- |
| `COGNIS_CLI_TOKEN_PATH`        | —                  | 認証済み `cognisctl` コマンド用APIトークンを含むファイルへのパス |
| `COGNIS_EXTERNAL_MODULES_ROOT` | `external-modules` | モジュール提供のサブコマンドを検出するために使用                 |
| `COGNIS_GATEWAY_CLI_PATHS`     | —                  | ゲートウェイ提供サブコマンド用の任意のパス一覧                   |
| `COGNIS_ADAPTER_CLI_PATHS`     | —                  | アダプター提供サブコマンド用の任意のパス一覧                     |

## 動作

### 概要

`src/tooling/` ディレクトリには、Cognisコードベースのすべての開発者ツールが含まれています: リントスクリプト、TypeScript ソース検査、コンテナヘルスチェックスクリプト、`cognisctl` 運用CLIです。

### 責務

- `lint-readable.mjs` を通じて読みやすさのルールを強制する（タブなし、末尾の空白なし）。
- `lint-placeholder.mjs` を通じてプレースホルダー標準を強制する。
- `npm run typecheck` ですべての TypeScript ソースとテストを検査する。
- `cognisctl` を通じて運用管理コマンドを提供する。

### TypeScript ソース検査

コミット前に `npm run typecheck` を実行してください。`npm run ci:test` はテストの前に型を検査し、両方の CI パイプラインが同じ検査を使用します。`npm run build` は esbuild を使い、Node 24 向けの本番資産を別途生成します。

ルートの `tsconfig.json` が、ファイルを出力しない厳密な検査の基準です。`src` 以下のすべての `.ts`、`.tsx`、`.mts`、`.cts` を対象とし、宣言、テスト、任意のコンポーネント、入れ子のコンポーネントも含めます。除外するのは生成済みの `dist` と依存関係だけです。新しいコンポーネントのために参照一覧を更新する必要はありません。

NodeNext の解決と ES2024・DOM ライブラリでサーバーとブラウザーの契約を扱います。`@cognis/core` はこのチェックアウトのソースを参照します。インポートされた自前の JavaScript は `allowJs` による型推論を提供しますが、`checkJs` は無効のため、JavaScript 全体の検証ではありません。コンポーネント設定はルートの検査範囲を制限しません。

範囲テストはコンパイラーの一覧と空でないソース一覧を比較し、静的なテスト素材に対して実際の npm コマンドを実行します。本番とテストの型エラーを独立して検出し、正常な検査を繰り返してもファイルを生成しないことを確認します。

### `cognisctl` CLI

`cognisctl` はプライマリ運用コントロールサーフェスです。コマンドモジュールは以下から自動検出されます:

- `src/tooling/cli/commands/` — コア組み込みコマンド
- インストール済みモジュールからエクスポートされた `cli/index.js`

| namespace     | サンプルコマンド                                                                                                                                |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `user:*`      | `user:create`、`user:role`、`user:set-password`、`user:disable`、`user:enable`、`user:delete`                                                   |
| `system:*`    | `system:health`、`system:info`                                                                                                                  |
| `component:*` | `component:list`、`component:enable`、`component:disable`、`component:import`、`component:config:get`、`component:config:set`、`component:test` |
| `api:*`       | `api:token`（curl 用の一時的な 1 時間管理者緊急トークンを発行）                                                                                 |

組み込みの `cognisctl` コマンドは、端末が対応していれば見出し、整列した項目、ANSI カラーを使ったレスポンス対応の端末出力を描画できます。カスタムレンダラーを持たないコマンドは整形済み JSON にフォールバックします。

### テスト認証情報の分離

`npm test` と `npm run ci:test` は実行ごとに一時トークン保存ディレクトリを作成し、各テストワーカーに別々の書き込み可能なファイルを割り当てます。静的な事前読み込み処理がテストモジュールの読み込み前にパスを設定し、継承した本番トークン保存先は使用しません。再起動や障害のテストでは、その後に各テストが自分のパスを明示的に変更できます。子プロセスの成功または失敗後に一時ディレクトリを削除し、通常の終了シグナルを転送します。強制終了やホスト障害では一時ファイルが残り、OSによる削除が必要になる場合があります。本番のトークン保存は変更せず、保存失敗時に成功として扱いません。

### CLI の対話入力

対話コマンドには stdin と stderr の端末が必要です。stdout をリダイレクトすると最終結果だけを保存できます。入力案内と進捗は stderr に表示されます。入力待ちの間は進捗表示を停止し、送信後に再開します。各項目は入力が表示されるか非表示かを示します。コマンドの所有者が安全だと明示したユーザー名やロールは表示されます。パスワード、トークン、未宣言の項目は非表示です。各値は Enter キーで送信し、Ctrl-C でキャンセルします。送信前に入力が終了すると、コマンドを実行せずに失敗します。スクリプトやリダイレクトした stdin では、文書に記載された引数を指定してください。使用方法は `--help` で確認できます。端末メッセージは `LC_ALL`、`LC_MESSAGES`、`LANG` に基づいて英語、ドイツ語、インドネシア語、日本語を選び、該当する翻訳がない場合は英語を使用します。

### コマンド入力の契約

HTTP コマンドはヘルプのグループ名とは独立して入力スキーマを所有します。ヘルプはパス引数と JSON 本文・クエリの項目および必須指定を表示します。引数なしの実行では宣言された入力をまとめて収集します。引数の一部を明示する場合は必須の JSON 項目も必要です。不完全な入力はコマンドのリクエスト前に拒否されます。たとえば `cognisctl tfa:preferences:set <username> '{"methodIds":["<configured-method-id>"]}'` は既存ユーザーの優先メソッド順を設定します。表示名ではなく、そのユーザーについて報告されたメソッド ID を使用してください。対話入力ではユーザー名とカンマ区切りのメソッド順を尋ねます。新しい TFA メソッドを設定したり、認可要件を変更したりする操作ではありません。

コマンドの所有者は組み込み引数の収集に `wizardFields` を指定し、HTTP 本文・クエリを含む各 `WizardField` に `sensitive` を指定できます。未指定の入力は非表示で、`sensitive: false` の明示だけが表示を許可します。パスワード、トークン、任意の JSON は非表示にし、通常の項目は内容が既知の場合だけ表示してください。項目名やプロバイダー ID で機密性を推測しません。不正な JSON のエラーは入力値を繰り返しません。

必須項目は値の存在を要求し、コレクションの要素数は制限しません。宣言された型で許可される場合、`[]` と `{}` は有効です。配列の入力ではカンマ区切りまたは JSON 文字列配列を使用でき、`[]` で優先順を空にできます。数値は有限値、真偽値は明示的な真・偽の選択だけを受け付けます。宣言された型はコマンドのリクエスト前に検証します。パスワードを含む文字列の先頭と末尾の空白は保持します。ID や業務上の規則は引き続き担当 API が検証します。

本文全体の JSON は対話入力・明示入力ともにオブジェクトである必要があります。明示した `{}` はそのまま送信し、省略した任意入力は送信しません。必須のクエリ項目も収集して検証します。GET/DELETE は `[query-json]`、クエリ項目を宣言した POST/PUT はパス引数の後に `[body-json] [query-json]` を使用します。パス・本文・クエリ全体で項目名を一意にしてください。曖昧なスキーマは入力案内や送信の前に登録時点で拒否します。

定義済みのクエリ値は常にエンコードし、明示した空文字列も `key=` として保持します。省略された値だけを除外します。

`user:delete` コマンドは確認済みの削除、拒否、不明な結果を区別します。送信済みの削除を自動で再試行することはありません。

削除には正確な確認応答に加えて HTTP 200 が必要です。201、202、207 などその他の成功ステータスは不明のままとし、非ゼロの終了コードを返します。公開 `apiRequest` の `expectedStatus` オプションは、指定した呼び出し側だけで受け入れる成功ステータスを制限します。省略時は従来の複数の 2xx ステータスと進捗処理を維持し、HTTP エラー処理を無効にしません。

### 応答の根拠

API の正確な通常応答 `{data:{deleted:true}}` だけを成功として受け入れます。HTTP 500 の `user_deletion_cleanup_incomplete` が `data.deleted: true`、`data.outcome: committed`、`data.cleanup: incomplete` と整合する場合は、通常の成功ではなく削除済みで後処理が未完了と報告します。

所有者による整合した拒否は既存の 400、403、404 のコードとステータスの組み合わせを保持し、`data.deleted: false` と `data.outcome: rejected` を追加します。証明の欠落、失効、利用不能、破損または矛盾した応答、確認フィールドの欠落、読めない JSON、通信障害は不明と扱います。ステータスや単独の `deleted` フィールドだけでは結果を確定しません。事前照会の失敗は削除未送信なので、通常の診断を維持します。

有効な完了結果で証明が利用不能の場合は HTTP 503 `account_policy_unavailable` を保持し、`data.deleted: null`、`data.outcome: unknown` を追加します。フロー例外による不確実性や不正な完了結果には HTTP 500 `user_deletion_outcome_unknown` を使います。どちらも CLI では不明と扱い、非ゼロで終了し、自動再試行しません。503 の応答はアカウントが残っている証明にはなりません。

結果が不明な場合は、再試行するか決める前にアカウント状態とサーバー記録を確認する必要があります。送達前のリクエスト消失と削除後の応答消失は CLI から区別できません。後の照会で見つからないだけでは、どの操作が削除したかは証明できません。コマンドの再実行は新しい手動操作であり、自動復旧手順ではありません。

### 翻訳と診断

結果文には CLI のドイツ語、英語、インドネシア語、日本語の XML カタログと通常の言語選択を使います。優先言語の文がなければ英語にフォールバックし、英語もなければ明示的に失敗します。内部の例外や通信詳細を結果説明として出力しません。詳細出力でも同じ規則が適用され、部分的または不明な結果が成功扱いになることはありません。

## セキュリティ

CLI は COGNIS_CLI_TOKEN_PATH を読み、サーバーがロールと対象権限を検証します。トークンファイルを保護し、詳細出力や共有記録に秘密情報を含めないでください。
