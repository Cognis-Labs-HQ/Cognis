# 技術リファレンス

カレンダー の公開インターフェースと運用規則を説明します。

## インターフェース

カレンダー は担当のゲートウェイを通じて統合されます。マニフェストに識別情報と必要な依存先が記載されています。

## 設定

設定は担当のゲートウェイが提供します。カレンダー のマニフェストには追加の設定は宣言されていません。

## 動作

### 共有の配信

Calendar は `ctx` のフローフックとケイパビリティを通じて Share ゲートウェイに機能を提供します。ユーザー受信者への配信では、受信者所有の共有カレンダーを作成し、汎用ナビゲーション URL と一度だけ表示するローカライズ済み成功フィードバックを返します。パスワードは Share が所有し、正規の共有識別子でキーリングから取得します。

### カレンダーの操作境界

サインイン後のカレンダーページは、永続的なページルートから表示、期間、タイムスロット操作を委譲するため、Composer の再描画で操作が外れません。予定作成では最初に標準の書き込み可能判定ですべてのカレンダーを絞り込み、追加先がなければフォームを開かず、書き込み可能なカレンダーがないことをローカライズ済みトーストで示します。公開の書き込み可能共有では、限定ゲストトークンで予定変更を認証します。

### Share シェル統合

Calendar は実績のあるミーティング共有のライフサイクルに従います。Share が読み込み用 Composer を消去し、ページルート、解決済みコンテキスト、翻訳、終了シグナルを Calendar に渡します。その後 Calendar は、標準ヘッダー、テーマ操作、フッターを備え、アカウントナビゲーションを持たない完全な `createPageComposer` ページを所有します。単一カレンダー要素はフォーム、ポップアップ、時刻、表示の依存関係を直接 import し、予定変更は渡された限定ゲストトークンで認証します。

### 空き状況

カレンダー予定の開始時、または現在の時間帯に予定を作成した時点で、ユーザーの空き状況が更新されます。その後に手動で選んだ状態は、別の予定が開始するまで優先されます。カレンダーによる状態更新は、ユーザー設定 → 一般から無効にできます。

### 古いカレンダー読み込みを中止

カレンダーから移動すると、古い初期化処理はページやURLを変更する前に停止します。ルートのシグナルをページ構成処理に渡し、カレンダー、予定、招待の遅延応答によって移動先が古い画面に置き換わることを防ぎます。中止した初期化処理は遅れてエラー通知を表示したり、空き状況のタイマーを再開したりしません。

### カレンダーの起動を高速化

カレンダー一覧と並行して招待を取得し、一覧が準備でき次第、予定を読み込みます。ページの構成は必要な取得処理の完了を待ちます。招待の取得に失敗した場合は従来どおり招待を空として扱い、移動のたびに最新のデータを取得します。中止の確認により、遅延結果が古いページを構成することを防ぎます。

### リマインダーの選択

標準のチェックボックスで複数のリマインダーを選択し、まとめて保存できます。すべての選択を解除すると、カレンダーに既定値があってもリマインダーは無効になります。既存の独自の通知間隔も編集時に保持されます。

作成時に `reminderOffsetsMinutes` を省略するとカレンダーの既定値を使用し、空の配列を明示すると通知を無効にします。更新時に省略すると既存の選択を保持します。

### 保存済みキューの結果

キュー内の新規予定と後続の編集を、キャッシュ済み一覧と詳細ポップアップに反映します。同時送信は一つのリクエストを共有します。任意の活動記録、在席状況、表示更新の失敗で、保存済み予定を作成失敗にしません。再送には同じ予定UUIDを使用し、現在のサーバー権限を確認します。

### オフラインのステータス表示

Calendar プロバイダーは、オフラインで初めて利用する前にイベントステータス用の遅延スタイルを準備します。共通のポップアップ、トースト、機密情報の表示切り替え用スタイルはホストが準備するため、オンラインで事前に詳細を開かなくてもキャッシュ済みイベントを開けます。

### 実行時リクエストの修正

通常のHTTPリクエスト中にCalendarが通知登録を試みることによる、言語切り替えと同意状態の更新の失敗を修正しました。Calendarは通知プロバイダーの起動後、ブートストラップ完了時にカテゴリを一度だけ登録します。Shareは登録済みのカテゴリを使用し、Authは早期の重複登録を行わず完了フックを使用します。SMTPの登録は引き続きブートストラップ中に限定し、実行時のハンドラーは既存の配送機能を取得して使用します。Calendarは**1.5.5**です。

アダプター契約の登録は[共通ゲートウェイブートストラップ契約](/docs/gateways)に従います。

### 所有されたブラウザー操作

ゲスト Calendar の読み込みと変更は、ライフサイクルに従う `calendar:sharedClient` と名前付きフロー `calendar:shared:*` を使用します。要求は明示的なゲスト権限を維持し、ページとプロバイダーのキャンセルを組み合わせ、アカウントの送信待ちキューには保存しません。利用側は共有エンドポイントを組み立てません。

Calendar は有効なブラウザープロバイダーから `meetings:createMeeting` を取得します。作成要求と遷移先はプロバイダーが所有し、Calendar はモジュール ID やルートを知らずに、イベント用の有効な HTTP(S) URL を解決します。プロバイダーがない場合は処理を拒否し、オフラインでは会議オプションを無効にします。

### 画面に合わせた作業領域

狭いカレンダーパネルは、すべての予定と選択中の日を含む一覧、コンパクトな表示切り替え、日付選択を表示します。広いパネルはカレンダーグリッドを表示します。日付欄から予定のない日へ移動でき、月全体のスクロールは不要です。共有カレンダーも同じ表示方法を使用し、読み取り専用の権限を守ります。

日付の移動とネイティブな表示選択は、アカウント用と共有用のページでCalendar所有の共通処理を使います。無効な入力では現在の表示を変えず、ページの終了時にリスナーを解除します。

### 読みやすいモバイル表示

カレンダーは低い画面でも予定一覧や時間グリッドの領域を確保し、予定は内部でスクロールします。各日付の予定追加アイコンは44pxのタッチ領域と読み上げラベルを備えています。

サイドバーのカレンダー行はメニュー項目として表示し、新規カレンダーの操作部は44pxのタッチ領域とテーマに合ったホバー表示を維持します。

共有カレンダーの期間見出しは、画面幅による再描画後も現在の日付と表示形式に従います。

表示切り替えボタンは、各日付表示で見た目の選択状態と押下状態を同時に更新します。表示切り替えボタンは、見た目の選択と押下状態を同期します。

## セキュリティ

### 公開共有レンダラー

Calendar はカレンダーリンク用の `mountScriptUrl` として `/static/gateways/calendar/ui/share-renderer.js` を提供します。Share は解決済みカレンダーペイロード、許可されたケイパビリティ、限定ゲストトークン、翻訳、終了シグナルを `mount(root, options)` に渡します。アダプターレンダラーは、日・週・月・年の表示切替と標準タイムスロット表を備えた単一のカレンダーカードをマウントし、受信者のほかのカレンダーやダッシュボード操作は読み込みません。カレンダーは使いやすい最低高さを保ちながら画面に合わせ、サインイン後のカレンダーページと同じ動作をします。読み取り共有は予定を表示します。`calendar:write` 共有では、限定ゲストトークンを使って `/api/v1/calendar/shared/:calendarId/events` から予定を作成、編集、削除できます。

## リファレンス

### 技術仕様

| ページ・画面 | ガイド             | アクセス           |
| ------------ | ------------------ | ------------------ |
| `/calendar`  | カレンダーの使い方 | ログイン済み利用者 |

公開機能 `ui:tutorials` を通じて、コンポーネント所有の定義、カタログ、対象、ライフサイクルのシグナルを登録します。ページ、表示中の領域、アクセス権により利用可否が決まります。コンポーネントを解除するとガイドも解除します。共通の表示と完了動作は[ホストのチュートリアル契約](/docs/tutorials)を参照してください。

予定がなくても日付操作を強調します。予定作成ではカレンダー全体を繰り返さず、実際の作成対象を一つ強調します。

日付と予定作成のステップは、現在のカレンダー表示にある操作部を対象にします。予定一覧とグリッドの動作は[カレンダー](/docs/gateways/calendar)を参照してください。
