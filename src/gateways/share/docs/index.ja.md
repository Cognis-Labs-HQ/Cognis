# Share ブラウザークライアント

アダプターは自身のナビゲーションプロバイダーを宣言し、有効状態に連動させます。送信者の取得には具体的な通知ゲートウェイではなく `notify:listSenders` を使います。Share の定期保守はゲートウェイの停止と再開に従います。

Share ブラウザークライアントは、Share ゲートウェイの公開ブラウザー契約を通じて、現在認証されている共有ゲストプロフィールをモジュールが取得できるようにします。

## 使用例

`uiCtx` をインポートして `share:uiClient` を要求し、`getGuestProfile()` を呼び出します。返された `Response` を確認してから `{ data }` JSON ペイロードを読み取ります。

## 技術仕様

クライアントは `/api/v1/share/guest-profile` を所有し、元の `Response` を返し、認証と接続処理をホスト API クライアントへ委ねます。プロバイダーは Share ゲートウェイが有効な場合だけ動作するため、マウント時に必要とするルートは `share:uiClient` を宣言する必要があります。

共有アクションを描画するブラウザーコンポーネントは `share:uiGateway` を要求し、`mountTrigger(container, options)` を呼び出します。ローカライズ済みのアイコンとラベル、操作結果に応じたスタイル、ゲストセッションでの非表示、破棄ハンドルはゲートウェイが所有し、利用側はコンテナと起動コールバックだけを渡します。

## 共有とテストの信頼性

Calendar と Flashcards の共有フックは、ほかのリソースプロバイダーが結果を返さない場合にも対応し、すべてのプロバイダーが有効な状態でリンク共有とアカウント共有を作成・解決できます。読み込み画面、アカウント共有の状態画面、ゲスト用カレンダーは、8 列を必須とせずレスポンシブな最小サイズを使用し、狭い画面でも表示できます。共有メンテナンスは順番に実行し、重複した呼び出しをまとめ、失敗した処理回を終了して次の 15 分間隔で再試行します。無効化は後続処理を停止し、再有効化はスケジュールを再開します。

ゲストの Flashcard 練習では一時的なモード選択を使用し、アカウント拡張機能とレイアウト設定の保存を無効にします。アカウントの練習設定は読み書きしません。

## レビューとライフサイクルの強化

Share アダプターは `defineContracts(ctx)` をエクスポートできます。Share はメソッドを構築する前に、共通の契約レジストリとアダプター所有のブートストラップスコープでこの関数を呼び出します。無効なメソッドは定義をロールバックし、安全な失敗メタデータを記録します。定義はゲートウェイの無効化と再有効化に従います。

ゲストページの起動処理は、翻訳、Composer 初期化、セッションとプロバイダーの読み込み、スタイルとレンダラーのインポート後にキャンセルを確認します。Composer、Calendar ポップアップ、リソース要求はページのシグナルを使用します。キャンセル済みページが次のページを上書きしたり、古い結果を表示したりすることを防ぎます。メンテナンス処理も各ジョブに中止シグナルを渡し、Share の無効化後は実行中の走査から後続の期限切れ通知を送信しません。

## 所有されたブラウザー操作

共有リソースは `page.mountScriptUrl` とエクスポートした `mount(root, options)` を提供します。未使用のレンダラースクリプトレジストリと別の描画経路を削除しました。テストはレンダラー内の HTTP コードを要求する代わりに、実行されるフローへの参加と権限・キャンセルの境界を検証します。
