# 通知ゲートウェイ

ゲートウェイは任意の送信アダプターを介して通知を配信し、メール転送方式を必須としません。アダプターは `createNotificationSender()` を公開し、設定、接続、キュー、テスト配送を所有します。メール配信がなくてもアプリ内通知を利用できます。

## 使用例

コンポーネントは実装への参照ではなく ctx 機能を使います。

- `notify:dispatch` は受信者がカテゴリごとに選んだ送信者と常時有効な送信者を使います。
- `notify:dispatchToRole` はアカウント ID を解決して役割ごとに配信します。
- `notify:listSenders` は公開メタデータを返します。`requiresVerifiedEmail` は送信者 ID に依存せずメール要件を示します。
- `notify:registerCategory(id, label)` はブートストラップ中に限られます。送信者はチャネルと専用の配送関数を作成します。共有チャネルは最後の所有者が解除されるまで維持されます。

公開契約は `@cognis/core` が提供します。アダプターのブートストラップには ctx 機能と制限されたホスト登録関数を渡し、具体的なゲートウェイ実装は渡しません。テストは `testSender(senderId, recipient, config)` に委譲します。

管理画面の通知でメッセージを準備し「通知を送信」を選ぶか、一斉通知でお知らせを準備し「一斉通知を作成」を選びます。これらの明示的な操作で下書きを送信または公開します。一般設定の「保存」ではどちらも行いません。

## 技術仕様

### メールアクション

任意のメールプロバイダーは `notify:registerEmailPurpose(id, action)`、`notify:sendEmail`、`notify:emailAvailable`、`notify:emailDeliveryPolicy` を提供します。呼び出し側が内容を用意し、自身のブートストラップ中に所有者付きの用途を登録します。配送にはその用途、宛先、変数が必要で、配送時にキューを作ることはありません。プロバイダーがなくても保存済みアドレスは閲覧できます。

メール確認はローカルと SSO の両アカウントに適用します。コードとトークンは完全なアカウント ID とアドレスに結び付きます。メール確認は、コード発行のたびに提供元が所有する契約 `notify:emailDeliveryPolicy` バージョン1から `codeLength` を取得します。SMTPでは、通知アダプターのコード長設定がメールコードTFAにも適用されます。変更はその後のコードに適用され、既存のコードは使用・置き換え・有効期限切れまで発行時の長さを保持します。ポリシーの提供元が存在しない場合、無効な場合、または未設定の場合、コード発行は明示的に失敗します。配送障害でも確認義務は解除されません。セキュリティ設定には `userValidationMode: "email"` または `"none"` を使います。

### ライフサイクル

無効化や解除は所有する登録と保留中の配送を取り消します。再有効化は中止済みメッセージを再送せず新しいチャネルを復元します。共有カテゴリの別の所有者は引き続き動作します。非同期アクションは登録の解除や置換後に配送を追加できません。

### ブラウザー機能

ライフサイクル付き `notify:emailClient` は自分のメール操作、信頼済みドメイン、管理者用 `listUserEmails`、オンライン専用 `resendUserEmail`、`emailAvailable` を提供します。設定、ユーザー管理、管理画面は ctx で解決します。所有プロバイダーがメール変更を保存してキューに入れ、確認はオンラインに限定します。認証必須の `GET /api/v1/notify/email-delivery` は可用性だけを返し、設定は公開しません。

オフラインモードと Broadcast はヘッダー上のバナースタックを共有します。オフライン表示は最優先で閉じられず、接続確認と復旧後の更新を提供します。Broadcast の確認、対象、スケジュールは独立して適用されます。背景と折りたたみ可否は共通バナー機能で設定します。

### 提供元が所有するコントラクト

Notifyは `contracts/` に配送方式に依存しない送信者と配送結果の型を持ちます。提供元固有の実行時宣言と任意のアクション型は、提供するアダプターが所有します。提供元は設定スキーマ、翻訳、条件付きフィールド、保存済みシークレットの情報、テスト用フィールドを渡し、ゲートウェイは配送方式を仮定せず中継します。NotifyはAuthへメール確認ポリシーを提供します。メール配送とテンプレート機能は、アダプターが提供した場合にのみ利用できます。

設定フィールドには、任意の翻訳キー `infoKey` を指定できます。共通エディターはその説明をラベル横の情報ツールチップに表示します。空の数値フィールドはゼロに変換せず、設定更新の内容から除外します。

提供元は、実行時の状態を変更せずに設定を正規化する任意の純粋なフック `normalizeConfig(patch)` を実装できます。Notifyは正規化した更新内容と保存済みの設定を結合し、省略されたフィールドを維持して、送信アダプターに適用する前に結果を保存します。実行時の適用に失敗すると、Notifyは提供元を無効化し、以前の保存済み設定を `enabled: false` の状態で復元して、明示的なエラーを返します。通常の配信を再開するには、管理者が設定を修正して提供元を復旧する必要があります。

設定の保存と更新、有効状態の変更、保存済み設定の再読み込みは、保存失敗時の復元を含めて送信者ごとに順番に実行します。異なる送信者は独立して処理します。設定処理中の登録済み送信者を置き換える操作は明示的に失敗し、処理完了後に置き換え可能になります。設定リスナーはトランザクション解放後に実行するため、後続の更新を待機できます。`notify:onSenderConfigChange` のデータからは、提供元のスキーマで `password` と宣言したフィールドと `getConfiguredSecretFields()` が列挙したフィールドを、新しく送信された値も含めて除外します。公開可能な正規化済みフィールドと有効状態は引き続き含まれますが、リスナーは未加工の認証情報に依存できません。

アダプター契約の登録は[共通ゲートウェイブートストラップ契約](/docs/gateways)に従います。

### 共有とテストの信頼性

管理者は送信機能を有効にする前に設定をテストできます。テストで通常の配信は有効にならず、各プロバイダーが診断用通信と終了処理を管理します。

### 型付き配信契約

送信側のキュー参照は任意であり、Notify契約で型を定義します。起動処理はゲートウェイ所有のストアを直接読み込み、不完全なコンストラクターの型アサーションを使わずにメールと設定の操作を公開します。一斉通知の検証は、保存前に有効なロールと日時を返します。

### 登録時のメール確認

Notifyは起動中にnotify:email:addとnotify:email:verifyをauth:onboardingへ登録します。入力は{email}と{email, code}のみで、アカウント識別は検証済みのコンテキストから取得します。通常のメール追加・確認と同じ重複アドレス、配信可用性、コード有効期限、送信間隔の規則を使用します。一覧取得、削除、主アドレス変更、他人のアカウント、通知管理は許可しません。

非同期読み取り後の変更前に権限を再確認します。Notifyの無効化や削除で操作も削除されます。メールがポリシー上必須でない場合だけ、存在しない任意操作を省略できます。登録済みの配信失敗はエラーのままです。コードとメールリンクは独自の有効期限を持ち、ログインセッションを生成しません。ログイン済みメール設定のチュートリアルは変更されません。

配信や失効に失敗してもアドレスが保存済みの場合があります。有効なコードが消費された後に、権限確認やデータベース処理が失敗する場合もあります。再試行前に現在の状態を確認してください。

### 管理画面の下書き

通知と一斉通知の下書きは、同じ管理ページ内の再描画中はメモリに保持されます。未保存の変更について移動時に確認されたら、「このページに留まる」で下書きを保持し、「破棄して移動」で破棄します。「元に戻す」はフォームの初期値を復元します。ブラウザーの再読み込みやタブを閉じた後には下書きは保存されず、アカウントを切り替えると消去されます。

送信と作成は、検証を含めて一度に1件のリクエストだけを受け付け、処理中は該当する操作を利用できません。拒否された送信の下書きは保持されます。成功時は、下書きが送信した値とまだ一致する場合に限り初期値に戻ります。待機中に行った新しい編集は変更されず、未保存の状態で残ります。一般設定の「保存」で通知を送信したり一斉通知を公開したりすることはありません。

一斉通知の状態変更も同時に1件だけ実行できます。作成や状態変更が成功した後に一覧の更新が失敗しても、成功した操作は取り消されません。更新エラーは別途通知され、読み込み済みの行は表示されたままになります。同じ操作を繰り返す前に現在の状態を確認してください。自動的な再試行は行いません。確認詳細を閉じる、別の詳細を開く、ページを離れる、またはアカウントを切り替えると、古い詳細応答が現在の表示を変更することはありません。

「一斉通知を作成」の隣にある「更新」で、読み取り専用のリクエストにより一覧だけを読み込み直せます。読み込みエラー後にも利用できます。下書きは保持され、作成や状態変更は繰り返されません。他の一斉通知操作の処理中は「更新」を利用できません。
