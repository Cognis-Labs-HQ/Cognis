# 登録契約

登録ゲートウェイは公開登録と招待の引き換えを管理し、ゲートウェイの機能とルートを通じてプロバイダーの操作を提供します。

## 使用例

公開登録の呼び出し側は、登録済みの機能を取得します。戻り値にはusername、enabled、プロバイダーのロールが含まれます。

```js
const register = ctx.capabilities.require("registration:public:register");
const account = await register({ username, password, email, displayName });
```

## 技術仕様

招待の引き換えはPOST /api/v1/registration/redeemを使用し、token、username、passwordと任意のemail、displayNameを含むJSONオブジェクトを送信します。ゲートウェイは入力全体を招待プロバイダーに渡します。トークン検証、アカウント作成、引き換え状態の永続化はプロバイダーが担当し、失敗はルートのエラー処理に伝播します。公開登録ではregistration:public:isEnabledで利用可能性を確認し、registration:public:registerで実行します。無効なゲートウェイはgateway_disabledで実行を拒否し、公開プロバイダーが利用できない場合はpublic_disabledで拒否します。利用可能性は実行時に確認されます。ブートストラップはこれらの機能を登録し、ctxを通じて既存のgateAccountCreationとconstructRegistrationUiフローを拡張します。呼び出し側は具体的なアダプターをインポートせず、これらのインターフェースを利用します。

## 制限された完了処理

verifyTokenはオンボーディング権限だけを持ち、onboardingOperationsは登録済みIDを示します。ブラウザーは登録処理内で資格情報を保持し、ログイン画面へ戻る前に失効させます。重複送信は同じ進行中の試行を共有します。ページ終了後の応答は拡張機能や画面遷移を実行せず後処理します。失効処理の失敗を成功として表示しません。アカウント作成後に資格情報の発行が失敗した場合、accountCreatedによりログインでの復旧を案内できます。招待の引き換えと保存は不可分ではありません。

拡張機能はonboardingOperationsを宣言し、completeRegistration({values, i18n, descriptor, executeOnboarding})を実装します。executeOnboarding(operation, input)は解析済みの結果を返し、未宣言の操作を拒否します。各操作にはauth:onboardingで登録された現在のサーバーハンドラーも必要です。任意の認証済みapiFetchは提供されません。ユーザーの実際の選択、入力検証、文書バージョン確認を維持し、登録自体を同意と見なしてはいけません。

これは互換性のない契約変更です。Terms of Service 1.6.13は制限された同意操作とconstructRegistrationUiを使用します。対応するCognisとモジュールを同時に配備し、旧版と新版の混在中は登録を停止してください。他の完了処理提供元も移行が必要です。広い権限のトークンへの代替経路はありません。

登録ページはログイン済みユーザー向けチュートリアルの対象外です。招待とポリシーのガイドは既存の操作と対象を維持します。メール確認と同意は通常のログインより前に行われ、登録によってTFA設定が完了することはありません。

すべての操作宣言は、拡張機能のインポートやコールバックの実行前にコピーされ、変更できない状態になります。オンボーディング操作を宣言するプロバイダーは、アカウント作成が許可される前に呼び出し可能な完了ハンドラーを読み込む必要があります。フィールド生成処理や他の拡張機能が、取得済みの権限を拡大することはできません。

登録設定の構成に失敗した場合、空の連携一覧ではなく registration_configuration_unavailable が返されます。操作宣言のない未移行の完了処理も登録をブロックします。任意のフィールド専用プラグインは、引き続き独立して読み込まれます。
