# ファイルストレージゲートウェイ

## 概要

ファイルストレージゲートウェイは、ファイルの保存と取得のための統一された**名前空間ベース**のインターフェースをプラットフォームに提供します。すべてのファイル操作は名前空間にスコープされます — 通常は1つのコンポーネント（`profile`、`chats`、`classes`）が所有する独立したコンテンツ領域と、コアが所有する2つの組み込み名前空間（`default`、`user`）です。名前空間はACL上限とオプションのストレージクォータを持ち、ゲートウェイは個人ドキュメント、チャットルームの添付ファイル、プロフィールのアバター/バナー、クラス教材など、あらゆる種類のアップロードを1つの実施ポイントからサポートできます。各コンポーネントがアクセス制御とクォータチェックを再発明する必要はありません。

このゲートウェイは常時有効で（マニフェストで `required: true`）、実行時のアダプター切り替えはサポートしていません。ローカルファイルアダプターが現在唯一の具体的なストレージバックエンドですが、`FileStorageGateway` インターフェースは `src/core/contracts/files-gateway.ts` で定義されているため、ゲートウェイのブートストラップやコンシューマーを変更することなく、代替バックエンドを追加できます。

## 責務

- `MEDIA_LOCATION` から導出されたストレージルートで `LocalFileGateway` をインスタンス化する。
- `NamespaceRegistry` を所有し、`files:registerNamespace` 機能を介してあらゆるコンポーネントから名前空間登録を受け入れる。
- すべての書き込みで各名前空間のACL上限を、すべての読み取り/削除でオブジェクトACLを実施する。
- すべての書き込みの前に、名前空間ごとおよびグローバルなストレージクォータ（クォータアダプター経由）を実施する。
- 名前空間ベースの `files:*` 機能と名前空間ベースのHTTPルートを提供する。
- 構造化ログ書き込み（ユーザーコンテンツではない）にのみログゲートウェイが使用する、レガシーな非名前空間の `file:write`/`file:read`/`file:append` を保持する。

責任範囲外: ファイルの物理的な保存場所の決定（アダプターの責務）、または `groupIds` エントリの意味の解釈（所有コンポーネントが選択する不透明なコラボレーターセットID — チャットルームID、クラスIDなど）。

## アーキテクチャ

### 名前空間

名前空間は、所有コンポーネントによって `files:registerNamespace` 機能を介して一度だけ登録されます:

```ts
ctx.capabilities.get("files:registerNamespace")?.({
    id: "profile",
    ownerComponent: "social-profile",
    acl: { visibility: "component-managed" },
    allowComponents: ["some-other-component"], // オプション、"core" は常に許可される
});
```

登録は一度限りです。重複したIDはエラーをスローします。組み込み名前空間（このゲートウェイ自体がブートストラップ時に登録）:

| 名前空間  | 所有者 | 可視性            | 目的                                                                      |
| --------- | ------ | ----------------- | ------------------------------------------------------------------------- |
| `default` | core   | component-managed | アプリケーション/システム所有のコンテンツ（ロゴ、生成されたドキュメント） |
| `user`    | core   | private-owner     | 厳密にプライベートなユーザーごとの個人リポジトリ                          |

コンポーネントによって登録される名前空間:

| 名前空間  | 所有者          | 可視性            | 目的                               |
| --------- | --------------- | ----------------- | ---------------------------------- |
| `profile` | social-profile  | component-managed | アバター/バナー — 広く読み取り可能 |
| `chats`   | social-messages | private-group     | チャットルームの添付/アバター      |
| `classes` | study-classes   | private-group     | クラス教材                         |

### ACLモデル

各名前空間は、そこに書き込まれるすべてのオブジェクトを制限する `visibility` 上限を宣言します:

- **`private-owner`** — オブジェクトはその所有者にのみ表示されます。`groupIds`/`publicRead` は書き込み時に完全に拒否されます。
- **`private-group`** — 所有者、またはオブジェクトの `groupIds` にリストされている任意のアクターがアクセスできます。`publicRead` は拒否されます。
- **`component-managed`** — 所有者、グループメンバー、または（`publicRead: true` の場合）誰でもアクセスできます。最も制限の少ないレベルです。

すべての書き込みには、呼び出し元コンポーネントによって設定されるオブジェクトごとのACL（`ownerId`、オプションの `groupIds`、オプションの `publicRead`）も含まれます。ゲートウェイは、名前空間の上限が許可するよりも広いアクセスを主張するオブジェクトACLを拒否します（`AclCeilingViolationError`、HTTP 400）— オブジェクトはその名前空間が許可する以上にオープンになることはありません。

### クォータ

個別のクォータアダプター（`src/adapters/file/quota/`）が以下を追跡します:

- 管理者が調整可能な名前空間ごとのデフォルトクォータ、およびすべての名前空間にわたる単一のグローバルデフォルト。
- アカウント作成時（`files:quota:provisionUser`）に現在のデフォルトから取得されるユーザーごとのクォータスナップショット。これにより、ユーザーのクォータは登録時に適用されていたものを反映します。管理者はその後ユーザーのクォータを編集できます。

使用量は、すべての書き込みで再スキャンされるのではなく、ファイルオブジェクトのメタデータテーブル（`file_objects`）で段階的に追跡されます。名前空間またはグローバルの使用量がクォータを超える書き込みは、`QuotaExceededError`（HTTP 413）で拒否されます。

### 提供される機能

| 機能                                   | 説明                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------- |
| `files:registerNamespace`              | 名前空間の一度限りの登録（重複IDでエラー）                                      |
| `files:namespace`                      | コンポーネント向けの名前空間バインド済みクライアントを作成する                  |
| `files:put`                            | 明示的な名前空間相対キーへの書き込み                                            |
| `files:store`                          | `{actorId}/` の下に生成されたUUIDベースのキーで書き込み                         |
| `files:get`                            | 読み取り（ACLに従う）                                                           |
| `files:delete`                         | 削除（ACLに従う）                                                               |
| `files:list`                           | 呼び出し元のアクセス権でフィルタリングされた名前空間内のオブジェクトの一覧表示  |
| `files:quota:provisionUser`            | （新規）ユーザーの現在の名前空間/グローバルクォータデフォルトのスナップショット |
| `file:write`/`file:read`/`file:append` | レガシー、非名前空間 — ログゲートウェイのみ                                     |

コンポーネントは、`ctx` 経由の日常的なファイル操作では `files:namespace` を優先してください。ブートストラップ時に `namespaceId` と `callerComponent` を一度だけバインドし、その後は返されたクライアントへ操作ごとのアクター、キー、コンテンツ、ACLオプションを渡します。呼び出し元が本当に動的に名前空間を選ぶ必要がある場合に備えて、低レベルの `files:put`/`files:store`/`files:get`/`files:delete`/`files:list` 機能も引き続き利用できます。すべての名前空間ベースの機能は `FileAccessContext`（`actorId`、`callerComponent`、オプションの `role`）を取るため、ゲートウェイはオブジェクトごとのACLに加えて名前空間のコンポーネント横断許可リスト（`"core"` は常に許可）をチェックできます。

### HTTPルート

- `PUT/GET/DELETE /api/v1/files/:namespace/*key` — 汎用的な名前空間ベースのファイル操作。認証が必要で、アクターIDはセッションから取得されます。
- `GET /api/v1/files/:namespace` — 一覧表示。
- `GET/PUT /api/v1/files/admin/namespace-defaults[/:namespaceId]`、`PUT /api/v1/files/admin/global-default`、`GET /api/v1/files/admin/users/:username/quotas`、`PUT /api/v1/files/admin/users/:username/quotas/:namespaceId` — 管理者専用のクォータ管理（`namespaceId: "global"` はユーザーのグローバルクォータを対象とします）。

### ブートストラップ順序の制約

`GatewayService.bootstrap()` は常にファイルゲートウェイをデータベースゲートウェイより先にブートストラップします。そのため、ファイルゲートウェイは自身のブートストラップ時に `db:executor` が利用可能であることを前提にできません — データベースに依存するスキーマ作成（ファイルオブジェクトのメタデータ、クォータテーブル）は、即座に実行されるのではなく、最初の実際の呼び出しまで延期されます。

## 設定

| 変数             | デフォルト   | 説明                                                                                                            |
| ---------------- | ------------ | --------------------------------------------------------------------------------------------------------------- |
| `MEDIA_LOCATION` | `/app/media` | メディアストレージのルートディレクトリ。アップロードは `$MEDIA_LOCATION/uploads/<namespace>/...` に保存されます |

### ブラウザークライアント機能

`files:uiClient` は Files UI プロバイダーが提供し、ブラウザーモジュール向けに名前空間付きファイル URL の解決を公開します。
