# ガイド付きチュートリアル

ガイドはページまたは表示中の画面に結び付けます。対象となる初回訪問では未完了のガイドを一つ自動開始します。ページタイトル横の ? SVG から利用可能なガイドを再実行できます。表示とライフサイクルはホストが、文章・対象・進行は各機能が所有します。

## ガイドの登録

ブラウザープロバイダーはスコープ付き ctx から `ui:tutorials` を使用します。契約のバージョンは `1` です。所有者の登録には、寿命を制限する `AbortSignal` が必要です。

```js
export async function mountProvider(ctx) {
    const tutorials = ctx.capabilities.get("ui:tutorials");
    if (tutorials?.version !== 1)
        throw new Error("tutorial_contract_unavailable");
    const owner = tutorials.owner("module.example", {
        signal: ctx.signal,
        stringsBaseUrls: ["/static/modules/example/languages"],
    });
    try {
        const target = await owner.target("primary", {
            root: () => document.querySelector(".example-panel"),
            resolve: () =>
                document.querySelector(".example-panel [data-example-primary]"),
        });
        const play = await owner.register({
            version: 1,
            page: "/example",
            id: "introduction",
            titleKey: "module.example.tutorial.title",
            steps: [
                {
                    id: "primary",
                    highlightNext: false,
                    target: target.id,
                    titleKey: "module.example.tutorial.primary.title",
                    bodyKey: "module.example.tutorial.primary.body",
                    effects: { callout: true, arrow: true, spotlight: true },
                    interaction: "target",
                    advance: { event: "click" },
                },
            ],
        });
        ctx.capabilities.contribute("example:tutorial", play);
        return owner.dispose;
    } catch (error) {
        owner.dispose();
        throw error;
    }
}
```

登録はインポート時ではなく `mountProvider` で行います。`owner.dispose` を返し、失敗時には途中の登録を解除します。Workspace と Study は組み込みガイドを提供します。`src/ui/reuse/tutorials/tests/fixtures/` の外部モジュール用フィクスチャは、公開契約を使う独立した利用例です。

## ページの紐付けと初回訪問

すべてのガイドに `page` が必要です。`/dashboard` などの正確なパス、または複数の URL やページ固有条件を判定する信頼された同期関数 `({ pathname }) => boolean` を指定します。ステップ内の移動とは別の設定です。対象外での開始は拒否します。登録、ページ表示、アカウント変更、ポップアップの終了時に再判定し、解除されたプロバイダーのヘルプ操作も削除します。必須ダイアログの表示中は自動開始を待ちます。

Study は概要に結び付く言語紹介向けに `study:tutorialTargets.matchesPage({ pathname, language })` を公開します。活動ガイドは現在のホスト画面に属し、仮名から漢字へ切り替えても言語紹介や概要への移動を開始しません。コンポーザーは表示完了を `page:mounted` の `publish` ステージで公開します。

## 対象と翻訳

対象名は `owner:name` になります。明示的に `public: true` を指定しない限り非公開で、他のコンポーネントは私有セレクターではなく公開された意味的 ID を使います。所有者、ガイド、対象の重複 ID は拒否します。リゾルバーは現在の文書の要素一つか `null` を返し、ページのノードを永続保持しません。`root` は解決範囲を制限し、追加の `signal` は寿命を短縮できます。非表示、inert、無効な対象は利用できません。使用中の対象を撤回すると、そのセッションを終了します。

要素の置換後や表示中も対象を再解決します。指定範囲にホストが含まれる場合、開いた Shadow DOM の対象を利用できます。閉じたルートとフレーム内部は対象外です。埋め込み要素を含む対象では入力制御を保証できないため、ブロックモードを使用できません。ポータルには同じ文書内で明示的に公開されたルートが必要です。

`stringsBaseUrls` はホストの翻訳カタログと英語へのフォールバックを使用します。カタログと再実行はページを更新せず現在の表示言語を解決します。代わりに、リゾルバーまたは非同期リゾルバー生成関数を `i18n` で渡せます。必要な翻訳が欠けている場合、登録または操作を失敗させます。文章を HTML として解釈することはありません。

## ステップの設定

- `effects` の `callout`、`arrow`、`spotlight` は独立して指定できます。既定では文章だけを表示します。視覚的に隠した説明も支援技術では利用でき、操作と進捗は常に残ります。
- `placement` は `auto`、`top`、`bottom`、`left`、`right`、`padding` は 0～40 ピクセルです。入れ子のスクロール、サイズ・レイアウト変更、視覚ビューポートに追従します。開始時に画面外の対象を表示しますが、その後の意図的なスクロールは妨げません。
- `interaction`: 説明用の既定値 `none`、`free`、`target` を指定します。`none` は強調領域を覆い、ページ操作や JavaScript のホバー処理を防ぎます。チュートリアルの操作は使えます。`target` は対象内とガイドのポインター・タッチ・キーボード操作を許可します。`advance` があるステップの既定値は `target` です。`none` では操作イベントを要求できません。
- `suppressHover`: 操作ステップに指定できる任意の真偽値です。`interaction: "target"` と true を指定すると、対象のクリックとキーボード操作を許可しつつ JavaScript のホバー処理を防ぎます。通知とアカウントのボタンで使い、他のページ操作は引き続き制限します。
- `layer`: 既定値の `page`、または検索画面など一時的な領域を案内する `overlay` を指定します。必須の確認ダイアログは引き続きガイドを終了させます。`enter` と `waitFor` にはステップをまたいで有効な `sessionSignal` も渡され、完了・中止・提供元の解除時に終了します。
- `group`: 一時的な画面を共有する連続したステップに付ける任意の意味的な識別子です。`enter` と `waitFor` には `groupSignal` が渡され、グループを離れる前、セッション終了時、グループの最初へ戻った時に終了します。検索をこの期間に結び付けると、閉じるステップを飛ばしてもアカウントの案内に進む前に検索を終了できます。
- `preventNavigation`: ステップ中のリンク操作とルーターによる移動を防ぐ任意の真偽値です。ルーターが管理する履歴移動も対象で、既定値は false です。ガイド自身の `route` 移動は許可します。ステップ移行や破棄時に解除します。ダッシュボードのガイドでは、ナビゲーションの強調中に別ページへ移動しないよう有効にします。
- `advance` は `click`、`change`、`input`、`submit`、`keydown` に対応し、任意の `key` と同期・非同期の `accept(event)` を指定できます。連続入力でも進むのは一度です。非同期の判定は `true` を返す必要があります。
- `enter({ signal, target, stepId })` は信頼された準備処理で、解除関数を返せます。`waitFor` は同じ引数を受け取り、完了すると次へ進みます。両方とも十五秒で制限され、ステップの中止に従います。非同期の解除エラーは記録し、所有する非同期処理には signal を使用します。
- `route` はクエリを含まない内部パス、またはそのパスを解決する信頼された関数です。`ui:navigate` により認可、オフライン制約、未保存変更の保護を維持します。Study のパスは `study:tutorialTargets.route({ language, area })` が解決し、area は `overview`、`explore`、`flashcards` です。
- `missing` は `timeoutMs` を 0～15000（既定 5000）、`action` を `cancel`、`skip`、`retry` で指定します。Skip は欠けたステップを飛ばし、Retry は最初からやり直す操作と「次へ」を表示し続けます。待機中にページをロックしません。

定義にはバージョン 1、一意なステップ ID、翻訳されたタイトルが必要で、最大 100 ステップです。未対応のバージョン、フィールド、不正な設定は拒否します。コールバックは信頼されたコンポーネントコードです。ダウンロードしたスクリプト文字列を評価してはいけません。

## セッションとフロー

`await owner.register(play)` は `{ id, start, dispose }` を返します。`await tutorials.list({ page: { pathname } })` はそのページで利用可能なガイドを取得します。`refreshPage()` は再判定し、`openPage()` は唯一のガイドを開始するか、共通のフローティングメニューに候補を表示します。`start()` が返すセッションには `ready`、`finished`、`state()`、`next()`、`back()`、`restart()`, `retry()`、`skip()`、`cancel()`、`dispose()` があります。`current()` は読み取り専用の状態です。

有効なセッションは一つだけです。競合する開始は拒否し、明示的な `{ replace: true }` の場合だけ前のセッションを中止します。登録、対象、検索、ページ訪問、再生、開始、ステップ操作は `validate`、`execute`、`after` を持つ `ui:tutorial:<action>` フローで実行します。利用側は契約を迂回しません。

操作ボタンはすべて、共通のフローティングメニューの独立したインスタンスに表示します。初回は中止とスキップを表示せず、Escape でも終了しません。対象の待機中、非同期処理中、イベント待ちでも「次へ」が有効なので、繰り返し押せば最後まで進めます。再生時はスキップでガイドを終了します。無関係な移動、履歴操作、アカウントや権限の喪失、所有者の解除、必須ダイアログでは引き続きセッションを解除します。確認の承認、特権フォームの送信、通話開始は行いません。

完了と中止はオーバーレイ、フローティングメニュー、リスナー、監視、未完了処理を解除し、適切な場合にフォーカスを戻します。遅延した処理から古いステップを復活させません。完了したガイドの ID は、このブラウザー内でアカウント別に保存します。中断や失敗した初回は次の訪問時に再実行できますが、現在のページで失敗を自動的に繰り返しません。ブラウザーの保存内容を消すと未実行になります。`cognis:tutorial-presented` と `cognis:tutorial-finish` を監視できます。

## コンポーネントが所有するガイド

ページはコンポーザーの `tutorials` 配列でガイドを提供します。各提供元は所有者、定義、必要に応じて `minRole` を指定し、定義には対象ページ、翻訳済みの文章、コンポーネントが所有するセレクターを含めます。`scope` は表示中の領域に判定を限定します。ホストは寿命を限定した対象を公開し、`ui:tutorial:mountPage` で登録します。ページの解除時にはガイドも解除します。任意コンポーネントのプロバイダーは `ui:reuse` の `mountTutorialProvider` を使い、翻訳と寿命を自身で管理できます。

```js
createPageComposer(root, {
    signal,
    i18n,
    pageContext,
    elements,
    tutorials: [
        {
            owner: "example.page",
            minRole: "admin",
            definitions: [
                {
                    id: "review",
                    page: "/example",
                    scope: ".example-panel",
                    titleKey: "example.tutorial.title",
                    steps: [
                        {
                            id: "options",
                            highlightNext: true,
                            selector: ".example-options",
                            titleKey: "example.tutorial.options.title",
                            bodyKey: "example.tutorial.options.body",
                        },
                    ],
                },
            ],
        },
    ],
});
```

対応ページとアクセス要件は、各コンポーネントの既存の文書に記載し、別の総合一覧は作りません。

## チュートリアルの翻訳カタログ

チュートリアルの翻訳カタログは、宣言した翻訳キーに基づくリビジョンで読み込み、先に読み込んだページのカタログと分けて管理します。これにより、メモリ内の古いカタログが新しい説明文の登録を妨げることを防ぎます。同じガイドのカタログは、オフラインでも再利用します。優先言語の文言がない場合は英語を使い、英語のキーもない場合は登録に失敗して所有者の登録を取り消します。手順のキーには順番ではなく内容を表す名前を使います。

## 見えている範囲の強調

強調表示は、対象、スクロールや切り抜きを行う祖先要素、表示中のビューポートが重なる範囲を使います。ページ内の対象はヘッダーとフッターを避け、それらの操作部分を案内する場合は本来の範囲を使います。大きな対象が既に見えている場合はスクロール位置を維持します。説明は空いている側を優先し、配置できなければ見えている対象内に置きます。その場合、画面外を指す紛らわしい矢印は表示しません。操作メニューの領域を別に確保し、長い翻訳文もナビゲーションボタンを覆わずにスクロールできます。

独立した共通フローティングメニューは、標準のテーマ、枠、ボタン、余白、背景ぼかしをそのまま使います。ページ見出しから開く再生選択メニューも含め、チュートリアルの暗幕より上に表示します。暗幕は強調対象、フローティング操作項目、ブロードキャストバナーを除外し、説明パネルは表示中のバナーの下に配置します。明暗どちらのテーマでも操作項目を画面内に収めます。

説明は利用できる操作や作業に絞り、権限やガイドが実行しない操作についての不要な説明を省きます。

## ページの準備完了

ホストは `page:mounted` の後に、`prepare`、`blocking`、`ready`、`afterReady` の各段階を持つ `page:ready` を実行します。描画は完了させ、ブロック段階で起動時の処理を待ちます。遅延したログイン設定をリリースノートより先に処理します。変更履歴の所有元は設定、メタデータの取得、ポップアップが閉じられるまで待ってから準備完了を公開します。キャンセルされた古いポップアップは既読を保存せず閉じます。自動チュートリアルとページ見出しからの再生は準備完了まで延期します。移動時には旧ページを無効にし、古い処理が新しいページを準備完了にすることを防ぎます。

今後のポップアップの所有元は、ページのマウント前に共通の `page-readiness.js` の `registerPageReadinessBlocker` で処理を登録できます。所有元固有の `id`、任意の `order`、所有元の `signal` を指定し、確認やポップアップの終了まで待つ Promise を返します。コールバックの `input.signal` はページと所有元のキャンセルを統合します。登録の置換と終了処理も所有元の寿命に従います。通知などの後続処理は `ui:pageReadiness.isReady()` または `afterReady` 段階で実行を延期できます。

## ダッシュボードのパネルと操作

ダッシュボードのガイドは最大18ステップで、、実際のクリック処理で通知パネルとアカウントメニューを開きます。クリック練習中はホバーを防ぎ、パネルやメニューの説明中は削除やページ移動を行う操作を無効にします。設定、ドキュメント、役割に応じた管理リンク、ログアウトを説明し、ページ操作ドックの言語切り替え、表示、レイアウト編集も案内します。

一時的な画面は `ui:transientSurfaces.register(element, close, signal)` で要素、閉じる処理、所有元の期間を登録します。ガイドは `attachLifetime(element, groupSignal)` を使い、グループ終了時に対応する検索、通知パネル、メニューだけを閉じます。ガイドのボタン操作は背景の外側クリック処理に伝わらないため、説明中もメニューを開いたままにできます。

`missing.action: "skip"` を指定した操作項目がない場合、初回でも再生時でも飛ばします。役割によって非表示になっているメニュー項目も対象です。

ステップの経路には `minRole`、同期的な真偽値条件 `when({ firstTime, completed, skipped })`、`dependsOn: ["earlier-step-id"]` を指定できます。権限や条件で対象外になったステップは進捗の総数に含めません。依存先は前のステップに限り、不明、重複、自分自身、後続への参照は登録時に拒否します。操作ステップはイベントまたは待機条件が成功した場合だけ依存関係を満たします。「次へ」で操作を飛ばすと、その依存分岐も飛ばします。説明のみのステップは「次へ」で完了します。条件には変更できない結果の一覧を渡します。総数は現在有効な経路を表し、操作で分岐が開くと増える場合があります。「戻る」は戻り先以降の結果を取り消します。`restart()` と最初からやり直す操作は、同じセッションで全結果を消去し一時画面を閉じます。検索、通知、アカウントの分岐は対応する操作部を開いた場合だけ有効になります。管理項目は `minRole: "admin"`、省略可能なドック操作部は表示条件で制限します。強調枠はフッター境界より下の部分も含め実際のドック寸法に追従し、説明カードは予約された表示範囲を保ちます。

バナーのボタン、リンク、キーボード操作はチュートリアル中も利用できます。操作時は `ui:tutorial:priority` でチュートリアルを終了してから、その操作による画面遷移やダイアログを実行します。バナーの操作部には Tab キーで移動できます。

検索オーバーレイのステップはオーバーレイの表示範囲を使用し、ヘッダーやフッターで入力欄の強調枠が切れないようにします。どのフィルターをクリックしても絞り込みの練習を完了します。「次へ」や「完了」が必要なステップでは、常時表示の枠を使わず、その操作をゆっくり明滅するアニメーションで強調します。動きを減らす設定ではアニメーションを無効にし、待機中や自動で進むステップでは強調しません。

各ステップで `highlightNext` を明示します。「次へ」や「完了」が必要な説明では有効にし、操作や待機条件で進む練習では無効にします。動きを減らす設定ではアニメーションを無効にし、通常のキーボードフォーカスは維持します。検索結果と通知の説明を含むすべての既存チュートリアルを見直しました。

任意の真偽値 `highlightNext` は省略時に `false` です。ホストは操作や待機条件から自動判定しません。ステップ定義で明示してください。強調は準備が完了してから表示し、動きを減らす設定に従います。

完了したステップ群や依存分岐の外から「戻る」を選ぶと、分岐の開始点に戻り、その結果を取り消します。分岐内では前のステップへ順に戻ります。閉じた検索画面に戻って終了位置まで自動で飛ばされることを防ぎます。

ページのステップは `targetMatch: "first"` で、指定したセクション内の表示中かつ利用可能な最初の対象を選べます。省略時は一意の一致が必要です。存在しない対象や無効な対象は指定のスキップ方針に従います。操作説明の強調を、変更可能なスイッチ、役割選択、容量設定、通知テスト、共有、レコード、モジュール操作へ絞りました。コンポーネントでは変更可能な電源スイッチを示し、必須または非表示の操作部は対象外です。

最初からやり直す操作は最初の表示ステップの後で利用でき、再試行ボタンは表示しません。導入ステップも対象領域を強調し、空の Jitsi 会議一覧や参加者検索を示します。学習プロバイダーは公開された Study の言語対象とワークスペース対象を使います。説明では `highlightNext` を有効にし、操作で進むステップでは無効にします。

フローティングメニューはバージョン 1 の `ui:floatingMenus` と、段階付きフロー `ui:floatingMenu:request`、`present`、`dismiss`、`release` を使います。同じ優先度は要求順に処理し、高い優先度は低いメニューを一時停止します。予約は初回の許可または取消を示す `ready`、`present(element, { visible })`、`dismiss(element)`、`dispose()` を提供します。チュートリアルは完了、取消、所有者の解除まで、ステップ間も含め優先度 100 を保ちます。コンポーザーのスロットと再実行の選択も同じ待ち行列を使います。取り消した要求や古い表示処理は新しいメニューを置き換えません。空のスロットは表示を譲り、ページ解除時は監視と予約を破棄します。

ドックの説明はメニュー予約領域より下にある表示中の操作部もアンカーとして保ち、実際の操作メニューを避けます。再実行の説明は ? ボタン自体を強調します。ボタンはチュートリアル中もテーマの文字色を保ち、実行中のガイドを再実行で置き換えません。

完了は安定したアカウントと所有者・チュートリアル ID に紐付きます。内容やパッケージの更新でリセットしません。完了済みのガイドはページ見出しの ? から要求した場合だけ再実行します。改訂時も ID を維持し、完了はアカウントのブラウザーストレージに保存します。 プロバイダーの公開ハンドルから直接開始した場合も、完了したすべてのセッションでページの再検出より先に完了を保存します。

最初の表示ステップでは最初からやり直す操作を表示しません。再実行では最後の表示ステップより前だけスキップを表示し、最後は完了を表示します。1 ステップのガイドでは最初からやり直す操作とスキップを表示しません。初回のガイドは引き続きすべてのステップでスキップを表示しません。

? ボタンはページタイトルと同じ行に配置します。ホバー時のツールチップは表示せず、翻訳済みのアクセシブルなラベルは維持します。

非同期描画中に対象が失われた場合は、準備完了を通知する前に再取得します。再開や中止後の古い描画から復旧を再開せず、フローティングメニューを占有し続けません。

`scope` は対象と検出範囲を制限します。任意の `visibleWhen` は一意の表示要素を要求しますが、その子孫だけに対象を制限せず、コンポーネント内の対象を使えます。ライブラリー管理ではブラウザーの表示を確認し、サイドバーの検索を強調します。無効なセレクターは登録時に失敗し、所有者を解除します。

## 安定したガイドの設計

URL だけでなく現在の画面に検出を結び付けます。同じ URL のタブ、選択したデッキ、コンテンツ階層、ダイアログにはコンポーネント所有の可視マーカーが必要です。`scope` は全対象を含め、サイドバーが外側なら `visibleWhen` を使います。コンポーザーの要素 ID はレイアウト情報であり、DOM ID とは限りません。実際の機能要素を指定し、装飾されたスイッチでは隠し入力ではなく見えるラベルを強調します。

ブラウザーのセッションでは、表示中の画面につき自動開始するガイドは一つです。終了後に別のガイドを連続開始せず、? から選択できます。表示セクションが変わればそのガイドを検出できます。補足の紹介には `automatic: false` を指定します。完了 ID は維持し、紹介のために Explore から概要へ戻してはいけません。言語紹介は Study の概要に結び付け、各活動の説明はホストが担当します。

操作の依存関係が必要な場合を除き、画面の表示順に説明します。各段階は異なる操作や領域を強調し、同じ領域への重複説明はまとめます。利用者の目的と結果を説明し、変更できない場面で保存・破棄や変更確認を案内しません。予定のないカレンダー、空の一覧、省略可能な操作、権限、利用できない機能も確認します。

`targetMatch: "first"` は登録中に選んだ接続済み要素を維持し、ホバーによる候補順の変化で別のカードへ移りません。最初から存在しない対象は指定した欠落方針に従います。一度表示した対象が消えた場合は操作ボタンを残し、最大 15 秒間復帰を待ち、その後も次へや最初からやり直す操作で進めます。スクロールだけでガイドが完了してはいけません。

詳細への分岐では `interaction: "target"`、`suppressHover`、イベント条件、`group`、`dependsOn` を使います。開く前に次へを押すと分岐を省略します。省略可能な `popup` セレクターは想定した機能所有のダイアログだけを許可し、無関係のダイアログは引き続き中断させます。ページの `portal` は明示した同一文書内の画面に対象を限定します。所有ページが利用可能であることを維持してください。閉じる処理を `groupSignal` に結び付け、戻る、再開、完了、移動、所有者解除で片付けます。受動的な説明は `layer: "overlay"` でダイアログの上に表示し、データを変更しません。

シェルはプロバイダーによる直接開始も含め、開始の検証ステージでアカウントメニューを閉じます。準備ブロッカーの所有権は `ui:pageReadiness.registerBlocker(options, handler)` に集約し、バンドルと直接インポートで共有します。このメソッドまたは `registerPageReadinessBlocker` を使い、所有者 ID で置き換え、古い取消処理が新しい登録を削除しないようにします。モジュールごとの競合する登録マップを持たせません。

ソースと製品ビルドの両方で、公開契約を通じて実際の表示対象と進行を検証します。直接表示、SPA の再マウント、同じ URL の画面切替、空と通常のデータ、スクロールと再配置、ホバー、省略可能な操作、権限喪失、分岐の省略と戻る、再開始、所有者解除、ダイアログ終了を含めます。表示ステップ数とメニューの引継ぎも確認します。ブラウザーデモは一時的に扱い、共有の自動テスト補助は保持します。機能変更ではガイド、翻訳、所有コンポーネントの文書を一緒に見直します。

信頼された enter/waitFor コールバックには寿命のシグナルと公開 ctx を渡します。共通の動作はその能力から取得します。機能のダイアログは要素、所有者の閉じる操作、シグナルを ui:transientSurfaces に登録し、詳細分岐は内部の閉じるボタンを探さずにこの契約で groupSignal を結び付けます。

ポップアップのポータル対象は想定した有効なダイアログ内だけで解決します。閉じるアニメーション中の要素が DOM に残っていても、次の分岐の対象や省略可能な操作数に使ってはいけません。戻る、再度開く、再開始を素早く行う検証をソースと製品ビルドの両方で実施します。
