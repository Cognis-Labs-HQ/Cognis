# 外部モジュール

外部モジュールの初期化には、検証済みコンテンツパックの取り込みを完了してから機能を公開できるよう、標準で2分間の制限時間が設けられます。ホストが明示した制限時間は引き続き適用されます。失敗や時間切れの場合は登録済みの提供機能が削除され、モジュールは利用できない状態を維持します。再有効化時には保存済みのバージョン別録音を再利用し、不足するファイルはFilesゲートウェイ経由で復元します。変更のないパックも含め、ライブラリの項目と関係の整合処理は引き続き実行されます。

外部モジュールは、独立してインストールできるサーバーおよびブラウザー機能を Cognis に追加し、マニフェスト、ケイパビリティ、フロー、ルート、整合性、ライフサイクルの契約によって分離されます。

## 使用例

リポジトリは `manifest.json` で安定した識別子とブートストラップのエントリーポイントを宣言します。

<!-- prettier-ignore -->
```json
{
  "uuid": "123e4567-e89b-42d3-a456-426614174000",
  "id": "example-module",
  "version": "1.0.0",
  "entrypoints": { "bootstrap": "bootstrap.js" }
}
```

ブートストラップはスコープ付きコンテキストだけを通じて機能を提供し、所有するリソースのクリーンアップ処理を返します。

<!-- prettier-ignore -->
```js
export async function bootstrapModule(ctx) {
  ctx.registerFlow({ id: 'example-module:constructPage', stages: ['content'] });
  ctx.flow.extend('example-module:constructPage', 'content',
    { id: 'example-module:content' }, async () => ({ ready: true }));
}
```

管理者は **モジュール** からリポジトリをインストールし、整合性と依存関係を確認して明示的に有効化します。後から無効化すると、登録済みの UI とバックエンド機能が Cognis の再起動なしで削除されます。

## 技術仕様

## 安定したアイデンティティ

すべてのモジュールには、人間が判読できる `id` と RFC 4122 `uuid` があります。 ID の名前は変更できます。 UUID は決して変更したり、製品間で移動したり、再利用したりしてはなりません。すべての `requires` エントリはコンポーネント UUID です。 Cognis は、依存関係とライフサイクルの決定には UUID を使用し、表示と URL には名前のみを使用します。

### リポジトリ契約

1 つの Git リポジトリは 1 つのモジュールを提供します。そのルートには、`manifest.json`、`package.json`、`routes.json`、および必須の `bootstrap.js` と任意のエントリポイント`api/index.js`、`ui/index.js`、`cli/index.js` が含まれます。`bootstrap.js` は唯一のシステム統合エントリであり、`ctx` を受け取ります。インポートはリポジトリ内のファイルに限定し、ホストと他のコンポーネントの動作は ctx の機能とフローを通じて取得します。公開するケイパビリティとフローステージでは、ライフサイクルのクリーンアップが追跡できるよう、必ず `ctx` を使用します。セキュリティ上重要な登録は引き続き制限され、`privileged: true` が必要です。通常のインポート、API URL、共有スタイルクラスによってモジュールが特権扱いになることはありません。

`package.json` は `"type": "module"` を使用する必要があり、そのバージョンは `manifest.json` と正確に一致する必要があります。 `routes.json` は常に存在し、モジュールがルートを要求しない場合の空の配列を含む配列を含みます。宣言されたすべてのエントリ ポイントは、チェックアウト内の通常のファイルに解決される必要があります。宣言されたエントリ ポイントでオーケストレーションを維持し、指定された責務別ディレクトリに実装コードを配置します。 Cognis は他のモジュール パスをインポートしません。

すべての外部モジュールは `entrypoints.bootstrap` を宣言します。 Cognis はそのファイルのみをインポートし、モジュールが有効な場合に `bootstrapModule(ctx)` を呼び出します。スコープ付きコンテキストは、API ルート登録、モジュール静的ディレクトリ、SPA ルート、ナビゲーション、設定とページ拡張、機能貢献、フロー作成、ステージ インジェクションを提供します。ローカライズされたドキュメントは `docs/` に、モジュール リリース ノートは `docs/changelog/` に配置します。どちらも、コア パスの登録なしで、インストールされたリポジトリから検出されます。ブラウザー アセットはモジュール所有のままであり、`ctx.registerStaticDir` を通じてのみ公開されます。モジュールは `ctx.registerCapabilityProvider({ scriptUrl, providesCapabilities })` で専用のブラウザー機能プロバイダーを公開できます。Cognis はモジュールが有効な間だけそのプロバイダーをカタログに含め、ライフサイクルのクリーンアップ時に削除します。

有効なモジュールは、`ctx.registerSpaRoute` に `public: true` を渡すことで、匿名訪問者とログイン済み訪問者の両方へ意図的にページを提供できます。公開ルートにはロールベースの `access` ポリシーを宣言できません。Cognis は明示的に公開されたルート記述子だけを匿名ブラウザークライアントへ公開し、`/login` へリダイレクトせずに SPA シェルを提供します。既定ではすべてのルートに認証が必要です。

セキュリティ上重要なフローフックとゲートウェイ所有のルート提供には、モジュールマニフェストの `privileged: true` が必要です。SSO プロバイダーを名乗るだけではこのアクセス権は付与されません。ハードコードされた GitHub 組織 `Cognis-Labs-HQ` からインストールされた特権モジュールは信頼済みとして認識され、それ以外のソースが特権を要求すると明示的なセキュリティ警告が生成されます。モジュールは引き続き保護されたコアルートを直接登録できません。特権認証モジュールは、登録済み認証アダプターの制限付き `routeNamespace` および `registerRoutes(router)` 契約を通じてコールバックルートを提供します。

すべてのモジュール提供物は所有者単位で保護されます。API ルート、ケイパビリティ、フロー、フローフック、静的プレフィックス、UI 登録は、別の所有者による置換や競合を拒否し、記録された所有者とともにのみ削除されます。モジュール間統合では、`await ctx.getModuleAssurance(moduleId)` が対象の UUID、バージョン、特権の来歴、ソースリポジトリ、実行時整合性状態（`verified`、`unverified`、`failed`）を返します。インストール済みマニフェストはインストーラー所有の来歴に封印され、宣言済みファイルは実行時に再ハッシュされるため、利用側は別モジュールのケイパビリティを使う前に期待する UUID と `verified` 整合性を要求できます。

非特権モジュール同士は、ホストや他モジュールの名前空間を取得せずに連携できます。提供側は自身の `<provider-module-id>:` プレフィックスでケイパビリティまたはフローを公開し、利用側は `requires` に提供側 UUID を宣言して、名前空間付き契約を `ctx` から取得し、必要に応じて `getModuleAssurance` で検証します。たとえば Whiteboard モジュールは、Jitsi モジュールが利用する `nextcloud-whiteboard:openBoard` を公開できます。セキュリティ上重要でない公開フローの拡張も非特権のまま利用できます。自身のモジュール名前空間外への登録、または保護されたセキュリティフローの拡張にのみ `privileged: true` が必要です。

認証前にも必要な法的文書、サポート文書、その他の文書を公開するモジュールは、`ctx.registerAuthFooterPlugin({ scriptUrl })` を呼び出せます。Cognis はログインページと登録ページの両方で有効なコントリビューターを読み込みます。ブラウザーモジュールは非同期の `listAuthFooterLinks()` 関数をエクスポートし、信頼できる状態を確認して、公開済み文書など現在対象となるリンクだけを返します。Cognis はそのプロバイダーの以前のリンク一式を返された記述子で置き換え、認証パネル下部の共通ストリップに表示します。空の配列を返すと、そのプロバイダーの全リンクが取り下げられます。

`bootstrapModule` はディスポーザーを返すことができ、モジュールは追加で `teardownModule(ctx)` をエクスポートすることもできます。無効化またはアンインストールすると、Cognis はこれらのフックを呼び出して、スコープ指定されたコンテキストによって記録されたすべてのルート、静的ディレクトリ、UI コントリビューション、機能、作成されたフロー、および挿入されたフロー ステージを削除します。モジュールは、ディスポーザーの完了後にタイマー、リスナー、ソケット、またはその他の作業を保持してはなりません。コア内部のインポート、または提供された `ctx` のバイパスによって行われた貢献は追跡できず、サポートされていません。

マニフェストは、`uuid`、`id`、`name`、`version`、`publisher`、`class`、`coreApiVersion`、`summary`、`description`、`categories`、`recommended`、`license`、`homepage`、を宣言します。 `repository`、`support`、`capabilities`、UUID ベースの `requires`、`entrypoints`、および `assets`。アセット パスはリポジトリ相対です。 `assets.icon` は正方形のストア アイコンを示し、`assets.banner` は詳細ヒーローを示し、`assets.screenshots` は注文されたギャラリーを示します。パスはリポジトリ内に残す必要があります。

ローカライズキーでは、単語の区切りにピリオドを使用してください。`module.example.canvas_label` や `module.example.canvas-label` ではなく、`module.example.canvas.label` と記述します。ピリオド区切りのセグメントにより、所有関係、検索、検証、ツールの動作が予測可能になります。登録済みモジュール ID 自体にハイフンが含まれる場合、その不変 ID だけが意図された例外です。

### ソースとプライベート リポジトリ

Cognis には、デフォルトで、`https://github.com/Cognis-Labs-HQ` 組織が不変の信頼できるソースとして含まれています。管理者は、ユーザー メニューの [モジュール]、[モジュール ソース] から GitHub 組織または GitLab グループをさらに追加できます。 Cognis はプロバイダー API にクエリを実行し、有効なルート マニフェストを含む各リポジトリをモジュールとして処理し、カタログを動的に取得します。ソースは、サインインしている管理者のキーリングに保存されているオプションの PAT を参照できます。ソース レコードにはキーリング識別子のみが保存されます。リポジトリとメタデータへのアクセスには、最小権限の読み取り専用トークンを使用します。トークンは検出とクローン作成のためにのみ提供され、ソース構成に書き込まれることはありません。 **非公開リポジトリをスキャン** を有効にしない限り非公開リポジトリは除外され、有効にすると PAT が必須になります。

### プライベートスキャンに必要な GitHub PAT 権限

fine-grained PAT を推奨し、次のように設定します。

- **Resource owner:** Cognis のモジュールソースに設定した GitHub 組織を選択します。
- **Repository access:** **All repositories**、または Cognis が検出およびインストールする各非公開リポジトリを選択します。
- **Repository permissions:** **Metadata** と **Contents** を **Read-only** にします。Metadata はリポジトリ一覧取得、Contents はマニフェスト検出と認証済みクローンに使用されます。
- **Organization permissions:** どれも不要です。**Administration**、**Members**、**Secrets**、Copilot 関連権限は必要ありません。
- **承認と SSO:** 組織ポリシーで必要な場合は、組織の承認と SAML SSO 承認を完了します。

classic personal access token では `repo` スコープを付与し、該当する場合は組織 SSO 用に承認します。トークン所有者自身が選択した各非公開リポジトリへアクセスできる必要があります。トークンが非公開リポジトリを一覧取得して内容を読み取れない場合、Cognis はソース設定を拒否します。

### 設置と安全性

インストールでは、対話型の資格情報プロンプトなしで選択した HTTPS リポジトリのクローンが作成され、ダウンロードされたルート マニフェストと不変の UUID が検証され、それが外部モジュール ルートの下にアトミックに移動されます。チェックアウトをコミットする前に、Cognis はパッケージとマニフェストのバージョン、ルート宣言、エントリ ポイント、必要なアートワーク、安全なリポジトリ相対パス、および宣言されたすべての SHA-256 ファイル ダイジェストを検証します。チェックが失敗すると、一時チェックアウトが削除され、インストールされたバージョンはそのまま残ります。更新では、同じ UUID に対してその操作が繰り返されます。アンインストールすると、その UUID のチェックアウトが削除されます。有効化は別個のライフサイクル アクションのままであるため、コードを参照したりインストールしたりするだけではコードは実行されません。ルートは `routes.json` で宣言する必要があります。保護されたコア プレフィックスは要求できません。

リポジトリ所有者は、リリースに署名し、依存関係を固定し、`files` でチェックサムを公開し、生成されたシークレットを回避し、要求されたすべての機能を文書化する必要があります。スクリーンショットには資格情報や個人データが含まれていてはなりません。 Cognis 管理者は、サードパーティのコードを有効にする前にレビューする責任を負います。

### 抽出チェックリスト

バンドルされたモジュールを独自のリポジトリに移動する前に、UUID を変更せずにモジュール ディレクトリをコピーし、読み取り可能な ID を保持し、ルート `manifest.json`、`package.json`、および `routes.json` を保存します。リポジトリ URL、ホームページ、およびサポート リンクが新しいプロジェクトを指すようにします。マニフェストとパッケージのバージョンを同期させます。宣言されたすべてのエントリ ポイントとアセットがファイル名の大文字と小文字を正確に区別して存在することを確認します。最終変更後に `files` SHA-256 値を再生成します。モノリポジトリ相対インポートに依存せずにモジュール テストを実行します。 Cognis およびその他のコンポーネントとの実行時対話は、ブートストラップ `ctx` 機能およびフローを通じてのみ発生する必要があります。有効化、無効化、有効化およびアンインストールのサイクルをテストして、すべての貢献が明らかに削除可能で再現可能であることを確認します。

### アセットとタグを保存する

モジュールは、より広範な `categories` と一緒に `tags` を宣言できます。どちらもマーケットプレイスのフィルタリングに参加します。アートワークは `assets/` の下のリポジトリ ルートに保存されます。カタログ アイコンには `assets/icon.svg` または `assets/icon.png` を、詳細ページのヒーローには `assets/banner.svg`、`assets/banner.png`、または `assets/banner.jpg` を指定します。選択したパスを `manifest.json` で `assets.icon` および `assets.banner` として宣言します。オプションのギャラリー画像は `assets.screenshots` にリストされています。アートワークには秘密や個人データが含まれないようにしてください。 インストール済みモジュールの詳細ページは、現在の UI 言語に対応する `README.<locale>.md` を選び、続いて `README.en.md`、`README.md`、カタログ説明の順にフォールバックします。 ルートの任意の互換エイリアス `README.md` は必須ではなくチェックサム検証の対象にもなりません。ローカライズされた `README.<locale>.md` は引き続きマニフェストの整合性一覧に含められます。

モジュール画像はコードのインストールとは独立して取得します。公開 GitHub アセットは raw.githubusercontent.com からストリーミングし、非公開および Enterprise リポジトリは認証付き Raw 応答、GitLab は Raw ファイルエンドポイントを使用します。Cognis はバイト列とメディア種別を独立したハッシュキャッシュに保存し、認証付きカタログアセットエンドポイントから配信します。GitHub Contents JSON の埋め込みサイズ制限を回避し、空のアセットと既存の 10 MiB 上限を超えるダウンロードを拒否します。ログにはソース、リポジトリ、参照、パス、通信方式、処理段階、HTTP ステータスまたは失敗理由を記録します。失敗後はカタログを更新して再試行できます。欠落アイコンは疑問符 SVG を維持し、欠落またはデコード不能のバナーには翻訳された「画像を表示できません」を表示します。

### モジュールの設定

モジュールは `ui.preferences` で管理者が編集できる設定を公開できます。各フィールドは、安定した `key`、ローカライズ用の `labelKey`、任意の `descriptionKey`、`boolean`、`string`、`number` のいずれかの `type`、任意の対応する `default`、機密文字列を隠す `password` 型、およびモジュール所有の設定エンドポイントが値を返すまで有効化をブロックする場合の `required: true` を宣言し、`ui.stringsBaseUrl` がモジュール所有の翻訳を示します。省略した場合、Cognis は標準の `ui/languages/<locale>/strings.xml` バンドルを自動的に検出します。Cognis はこのマニフェスト契約をインストール済みモジュールの詳細画面に描画し、`GET /api/v1/modules/<id>/config` をポーリングして、変更を同じモジュール所有エンドポイントへ `PUT` します。モジュールは運用設定を検証、適用、永続化します。別の設定 UI を提供したり、Cognis のユーザー設定を構成保存先として使用したりしてはいけません。 モジュールの無効化や再起動では、この永続化された設定を保持しなければならず、削除できるのはアンインストールフローだけです。 保存済みパスワードごとに、設定レスポンスは秘密値の代わりに `<key>Configured: true` を返します。Cognis は `****` を表示して必須項目を満たしたものとし、マスクが変更されていない場合は空の値を送信して、モジュールが保存済みパスワードを保持できるようにします。

### ログ記録とユーザーフィードバック

サーバーのブートストラップおよびルートコードは、`ctx.log(level, message, meta)` を通じて構造化アプリケーションログを書き込みます。Cognis は各エントリをモジュールに関連付けてから Logging ゲートウェイへ転送します。ブラウザーコードは `uiCtx.capabilities` から `ui:log`、`ui:showToast`、`ui:openErrorPopup` を取得します。`ui:log` は認証済みエントリをサーバーログへ転送し、フィードバック機能はホストのテーマ対応かつアクセシブルな UI を使用します。モジュールは運用上の障害をブラウザーコンソール出力だけに任せたり独自の通知画面を実装したりせず、これらの仕組みを使用する必要があります。

### リリースチャンネル更新とブラウザークライアント

インストール済みモジュールでは、カタログ更新がインストール済みのブランチまたはリリースを最初に解決し、チャンネルが記録されていない場合だけリポジトリの既定ブランチを使用します。モジュールは宣言済みの `uiCtx.capabilities` クライアントを通じてゲートウェイ所有のブラウザーデータを利用します。現在のホストクライアントには `social:profileUiClient`、`social:messagesUiClient`、`files:uiClient`、`share:uiClient` があります。Cognis がモジュールルートをマウントする前に有効なプロバイダーを読み込めるよう、必要な UI 機能をすべて宣言してください。

Marketplace のインストールでは、選択したカタログのコミットだけを浅い Git チェックアウトで取得します。各転送の制限時間は15分で、転送速度が2分間 1 KiB/秒を下回ると中断します。一時的な障害は最大3回まで試行し、中断した Git 転送は再開ではなく最初からやり直します。ブラウザーはサーバージョブの結果を待ち、インストールのタイムアウトと接続確立時に確認されたタイムアウトを区別します。インストールの確定前には引き続きリポジトリーとマニフェストのチェックサムを検証します。

チェックアウト外に設定やコンテンツを保存するモジュールは、宣言済みの bootstrap エントリーポイントから `uninstallModule(ctx, { deleteContent })` をエクスポートする必要があります。フックは `deleteContent` が true の場合にのみモジュール所有のレコードとファイルを削除します。Cognis は `ctx.getCapability` から機能を利用できる間にフックを呼び出します。成功後に保存済みモジュール構成とチェックアウトを削除し、失敗時は管理者が再試行できるように両方を保持します。

アンインストールフックは、起動時と同じ境界を通じて現在の公開プロバイダー機能を解決します。ルートコンテキストが提供する機能を優先し、システムの非公開機能は公開しません。データ削除に必要なプロバイダーは、依存するモジュールのアンインストール中も有効にしておく必要があります。

### UI 表示領域の所有権

Cognis はダッシュボードシェルと、ホスト機能が出力するすべての再利用可能コンポーネントを所有します。これには構造用の `profile-capability-*` アバタークラスも含まれます。モジュールが所有できるのは、`mount()` に渡されたコンテンツルート内に自身が描画した子孫だけです。すべてのモジュールセレクターは、モジュール固有の名前空間を持つクラスまたは ID を対象として終わる必要があります。ホストのテーマセレクターは、そのモジュール所有対象の祖先としてのみ使用できます。モジュールは独自のレイアウトクラスをホストレンダラーへ渡せますが、ホストのスタイルシートを複製したり、ホスト機能のクラスを再定義したり、シェル要素を選択したり、`document.body` や `document.head` を変更したりしてはいけません。アプリ全体の動作は、取り外し可能なフックを持つ宣言済みの `uiCtx` 機能またはフローに属します。

ブラウザモジュールは、ホスト内部を直接インポートしたりスタイルを複製したりせず、`ui:reuse` 機能から再利用可能なホストユーティリティと共通 CSS を取得します。`importModule(path)` は `src/ui/reuse/` 配下の任意の本番モジュールを読み込み、`loadStylesheet(path)` と `loadStylesheets(paths)` は `src/ui/styles/reuse/` 配下のファイルを読み込みます。`loadCommonStyles()` は不変の `stylesheets` カタログ全体を読み込みます。別のホスト機能が URL を受け取る場合は、`moduleUrl(path)` と `stylesheetUrl(path)` を利用できます。パスは相対指定とし、想定された拡張子を使い、ディレクトリを遡ったりテストファイルを選択したりすることはできません。

```js
const reuse = uiCtx.capabilities.get("ui:reuse");
const { createPageComposer } = await reuse.importModule(
    "page-composer/index.js",
);
await reuse.loadStylesheets(["layout.css", "page-sections.css"]);
```

実行時スクリプトを読み込むモジュールは `ui:resourceLoader` を宣言し、検証と参照カウントを行う `loadScript({ id, src, globalName })` を呼び出します。アンマウント時に返されたハンドルを破棄し、ドキュメントへスクリプトを直接追加してはいけません。

## インストール依存関係

外部マニフェストでは、モジュールの UUID または ID の配列として `hardDependencies` と `softDependencies` を宣言できます。ハード依存関係は、続行前に管理者がインストールして有効化する必要があるため非推奨です。ソフト依存関係はインストールダイアログで任意に選択できます。

無効なモジュールは通常の Bootstrap をインポートも実行もしません。無効時にも設定を公開する必要があるモジュールは `entrypoints.disabledApi` を宣言します。この分離ファイルは `registerDisabledApiRoutes(ctx)` をエクスポートし、`allowWhenDisabled` を明示したルートだけを登録できます。 モジュール所有の設定フローと、そのフローへのフックも登録できます。更新時や設定処理の失敗時には登録が削除されます。公開 capability は有効化まで利用できません。

実行中のモジュールリクエストが完了してからフローを破棄し、新しいリクエストは有効化に失敗した場合も含めて再構成の完了まで待機します。他の Study モジュールを有効化している間も、同意確認のルートとフローのライフサイクルを維持します。

### 有効化後のガイダンス

Cognis の別の場所に設定画面を提供するモジュールは、空のモジュール設定フォームを作成する代わりに `ui.activationGuidance` を宣言できます。この契約には、ローカライズされた `titleKey`、任意の `descriptionKey`、順序付きの `steps` を指定します。各ステップには、安定した `id`、ローカライズされた `labelKey`、任意の `descriptionKey` と `targets` があります。アダプター対象は `{ "kind": "adapter", "gatewayId": "<gateway>", "adapterId": "<adapter>" }` を使用します。有効化に成功すると、Cognis はすべての手順を表示し、管理画面を開く選択肢を提示します。Core がプロバイダー名を認識しなくても、モジュールは複数のアダプター対象を列挙できます。

### 公開ケイパビリティの取得

外部モジュールは `ctx.contributePublicCapability(key, value)` で共有サーバーケイパビリティを公開します。`ctx.getCapability` と `ctx.capabilities.get`、`has`、`require` は、利用側の初期化後に公開されたものも含め、現在のシステムレジストリから公開ケイパビリティを取得します。非公開のシステムケイパビリティは公開されず、`system:ctx` はモジュールに渡されません。更新要求は順番に実行され、後処理と登録が重複するのを防ぎます。提供側を無効にすると登録が削除され、再度有効にすると再公開されます。更新に失敗すると呼び出し元にエラーが返されますが、後続の更新は妨げられません。

### テンプレートからの開発

新しいモジュールは必ず [cognis-module-template](https://github.com/Cognis-Labs-HQ/cognis-module-template) から作成し、製品 UUID、識別情報、リポジトリ、画像、サンプルを置き換えます。AGENTS.md と検証スクリプトを保持します。[開発標準](/docs/standard) に従い、API ハンドラーを `api/routes/<domain>/index.js`、CSS を `ui/styles/`、テンプレートを `ui/templates/`、リリース文書を `docs/changelog/` に配置し、テストは所有する層に置きます。Jitsi Meet は公開 URL を維持してこの構造を実証します。インポートはリポジトリ内に限定し、他のコンポーネントには ctx を使います。

### 登録のライフサイクル

サーバー登録が返す後始末関数を `ctx.registerDisposer(dispose)` で登録します。Cognis は更新、無効化、Bootstrap 失敗時に逆順で実行し、無効時の設定エントリーも対象にします。公開契約 `system:health:contribute(id, callback)` と `auth:registerKeyringDataOwner(id, purge)` は所有する解除関数を返します。Keyring の後始末は依存データのみをリセットし、アカウント識別情報や無関係な共有内容を削除しません。

ブラウザープロバイダーはインポート時に機能やリスナーを登録せず、`mountProvider(scopedUiCtx)` をエクスポートします。この限定コンテキストが機能、フロー、段階フックを所有し、AbortSignal がリスナーを停止し、返した解除関数が他の資源を解放します。カタログ同期は同じ URL が二つのカタログにあっても一度だけマウントし、再有効化時にキャッシュ済みスクリプトを再マウントします。ナビゲーションは `ui:navbarLinks.contribute(id, { href, label, visible })` でホストに登録します。ルートページは独自の `mount`/`unmount` 契約を維持します。

### コマンドとバージョンの範囲

npm スクリプトはリポジトリ内で実行します。`npm --prefix <module-checkout> test` で明示的に選択できます。導入済みモジュールの操作は `cognisctl modules:<module-id>:<action>` を使います。両者は別のインターフェースです。必須機能の宣言が可用性を決め、検証済みプロバイダーバージョンは診断情報であり強制的なバージョン制限ではありません。実際の依存関係を宣言し公開契約を検証し、コードにないバージョン判定を約束しないでください。

## モジュールIDの診断とブラウザープロバイダーの管理

管理者が、別のUUIDに属するIDのモジュールをインストールすると、競合情報として `moduleId`、`installedModuleUuid`、`requestedModuleUuid` を受け取ります。サーバーとモジュール管理UIはこれらのIDを記録します。管理者以外は参照できません。IDとUUIDが一致する場合は引き続き更新できます。この検証を回避するために公開済みUUIDを変更したり、競合するインストールを上書きしたりしないでください。ブラウザープロバイダーのライフサイクルは `ui:providerLifecycle` を通じて共有され、バンドルと直接配信されるローダーが同じカタログを管理します。同じプロバイダーを二重にマウントしません。

## スコープ付きブラウザー操作と管理者権限の検証

ブラウザープロバイダーはスコープ付きctxから `ui:scopedActions` を取得します。`(ctx, moduleId, actions)` を渡すと、各操作の実行可能なフローを登録し、公開用の操作関数を返します。管理画面の取得・更新にこれらの関数を使用します。ホストがフローの破棄を管理し、破棄後の古い関数は実行を拒否します。管理者権限は有効なアカウントの現在の役割から検証し、呼び出し側が渡した役割には依存しません。

ホストの `mountWhenDirect` は `mount(root, { signal })` にAbortSignalを渡し、確定したルート移動やページ離脱で中断します。ページはこのシグナルにクリーンアップを結び付け、非同期初期化後に確認します。マウント失敗時は所有するリソースを中断し、取り消された処理は移動先にエラーを表示しません。Markdownリンクのラベルではエスケープされた文字と通常文字を分け、曖昧なバックトラッキングを防ぎます。CIはリポジトリ内容の読み取り権限だけを要求します。

直接ページを中断すると、翻訳、プロバイダー、コンポーザーの初期化が保留中でも共通の読み込みトークンを直ちに解放します。リソースのクリーンアップは同じホストシグナルに結び付けます。

## 翻訳キーでモジュール ID を維持

翻訳キーには `module.<manifest.id>.<feature>.<label>` を使用します。複数の単語からなるモジュール ID はハイフンを含めてそのまま保持します。`terms-of-service` の場合は `module.terms-of-service.admin.title` を使用します。モジュール ID より後の接尾辞には、小文字の単語をピリオドで区切って使用します。マニフェストのメタデータ、XML ファイル、コード参照で同じ名前空間を使用します。

インストール済みモジュールが異なる名前空間を使用する場合でも、マーケットプレイスはキャッシュ済みの名前、説明、カテゴリー、タグを対応するカタログ翻訳と組み合わせて表示します。インストール済み設定は独自の翻訳 URL を維持し、カタログを再取得するとキャッシュ済みの表示情報を置き換えます。

### フッターの法的文書リンクを維持

個別に読み込まれる静的スクリプトやバンドルを含め、すべてのブラウザークライアントは `ctx` 所有のフッター登録先を使用します。フッターのディスクリプターで `target: "_blank"` を指定すると、描画側が `noopener noreferrer` を追加します。認証提供者は翻訳済みラベルと認証コンテキストを提供し、ログイン済みの法的文書リンクは明示的にアプリケーションコンテキストへ登録します。履歴やブラウザーキャッシュからの復元時に公開済み文書へのリンクを更新し、コアのライセンスや変更履歴のリンクは置き換えません。

Core共通の`createI18n`と`extendI18n`は、Core、モジュール、コンポーネントの各バンドルで選択言語の値が未定義または空の場合、キーごとに英語XMLから解決します。解決できないキーは`missing_translation:<key>`エラーになります。モジュールは独自の代替処理を実装せず、バンドルURLを渡してホストのリゾルバーを利用します。

Coreは登録時にモジュール所有のUI資源URLへインストール済みモジュールのリビジョンを追加します。モジュールのスクリプトと翻訳ファイルは、ホストの不変キャッシュ期限を引き継がず再検証されます。Service Workerはキャッシュの代替応答を使わずモジュール資源を直接取得し、資源キャッシュを更新します。モジュール更新時にエントリーポイントのインポートURLが変わり、古いスクリプトが削除済み依存先を要求するのを防ぎます。

独立した認証コールバックは、サーバードキュメントへの遷移に `page-entry.js` の `navigateToDocument(path, { signal })` を使用します。この関数は認証情報を埋め込まない同一オリジンの HTTP(S) URL を検証し、既存のナビゲーションガードを尊重して、キャンセル後の遷移を防ぎます。ダッシュボードの遷移とレンダラー不在時の動作は、変更のない SPA ルーターが引き続き担当します。`ui:log` は匿名リクエストを省略して配信失敗を処理し、ログエンドポイントは引き続き認証を要求します。

外部 SSO コールバックには、ホストの `page-entry.js` が提供する `mountWhenDirect` と `navigateToDocument` が必要です。ソースでは `npm run check:ui-host`、ビルド済みアセットでは `npm run check:ui-build` を実行します。配備後はホストに到達できるネットワークから `npm run check:ui-host -- --origin https://your-cognis-host.example` を実行します。リモート検証は公開 JavaScript の読み取りだけを行い、認証情報を送信せず、ダウンロードしたコードを実行せずにエクスポートを解析します。プロキシ環境では `NODE_USE_ENV_PROXY=1` で Node の環境プロキシ対応を有効にできます。

コールバックモジュールを更新する前に、UI アセットとアセットマニフェストを含む対応する Core ホストを配備し、旧リリースを使用しているプロセスを再起動します。公開ホストのエクスポート検証に成功してからコールバックページを再読み込みしてください。モジュールのバージョンだけでは配信中のホストアセットを確認できません。公開登録が無効な場合、未知の外部 ID には引き続き登録認可が必要ですが、既に関連付けられた ID はアカウント作成認可を繰り返しません。HTTP 403 だけでは拒否理由を特定できません。認証情報や Cookie を共有せず、応答のエラーコードと登録継続用フィールドを確認してください。

## コンポーネントの分離と稼働状態

APIは有効なゲートウェイが所有するポリシーを通じて拡張機能の名前空間を委譲し、言語の規則はStudyが所有します。LibraryアダプターまたはStudy内の依存先を無効にすると、公開機能を登録解除し、保持された関数参照も拒否します。有効化すると再登録します。Studyアダプターは稼働状態に連動する登録に `onAvailabilityChange(listener)` を使用し、起動に失敗した場合は登録を取り消します。

## オフラインナビゲーション

SPA ルートで `public: true` と `offline: { assets: [...] }` を宣言してください。言語カタログとデータファイルを含むすべての公開実行時依存関係を列挙します。API 要求、非公開のアカウントデータ、ホスト全体のプロバイダー検出なしで動作する必要があります。非公開ルートは対応を宣言できません。移動にはルートリンクを使用してください。未知または未取得の依存関係は利用できません。

Service Worker は API 応答、認証情報、認証済み HTML を保存しません。モジュールの無効化で公開ルートカタログとモジュールアセットを削除し、リビジョン付きアセットは現在のカタログと一致する必要があります。切断中はリモートの変更を検知できず、最後に確認した公開リビジョンのみ利用できます。復旧時はカタログを更新し、未保存の変更を確認して再読み込みし、最新のサーバー認可に戻ります。Worker の更新は既存タブが閉じるまで待機し、復旧アセットを準備してから有効になります。Worker が未導入の初回アクセスではオフライン起動できません。

リンクまたは `data-navigation-path="/route"` を持つボタンを使用してください。Cognis は未対応の移動先を無効にし、所有者が無効にした操作を有効にすることはありません。

### オフライン学習

設定のオフラインモードは既定で有効です。無効にすると従来の接続警告とエラー通知に戻り、ワーカーの代替表示を停止します。有効な場合は接続が切れるとエラー通知なしでオフラインモードに切り替わり、利用できない移動はエラーポップアップを出さずに制限します。

Study は現在のタブ内に容量制限付きの軽量 JSON スナップショットを保持します。対象はスキーマ、許可された文字・カードデータ、保存先、閲覧済み ID、お気に入り、以前開いたデッキです。言語スキーマは `metadata.offline: { cache: "lightweight" }` で対応を宣言します。Library キャッシュは最大 16 MB・100 件、その他の読み取りキャッシュは最大 4 MB・100 件です。音声バイト、辞書応答、認証情報、認証済み文書は永続保存しません。

非公開の Study では、同じタブ内で以前検証済みの、有効期限内の同じアカウントセッションが必要です。再読み込みと初回訪問では引き続き公開ページ専用のオフライン契約が適用されます。アカウント・セッション、設定、モジュールの状態が変わるか、プロバイダーが破棄されると非公開スナップショットを無効化します。切断中はサーバーでのアクセス取り消しを検知できません。復旧時には未保存変更を確認してから再読み込みし、サーバーの認可を更新します。
