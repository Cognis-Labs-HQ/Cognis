# 技術リファレンス

Page Composer は、要素配置、画面幅に応じた表示、DOM のライフサイクル、任意のレイアウトと下書き保存を管理します。

## インターフェース

createPageComposer(root, options) が画面の動作期間を作ります。要素が内容と描画を提供し、init で組み込み、refresh で記述を更新します。

Composer 内部の編集用ヘルパーは次の契約を提供します。ソース冒頭に呼び出し例があり、ページは通常 `createPageComposer` を通じて利用します。

| ヘルパー                                                                                                                            | 契約                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| [`createLayoutSaveHandler`](https://github.com/Cognis-Labs-HQ/Cognis/blob/HEAD/src/ui/reuse/page-composer/layout-save.js)           | 同時リクエストをまとめる段階的な保存ハンドラーを作成します。下記の永続化契約を参照してください。 |
| [`commitLayoutEdit`](https://github.com/Cognis-Labs-HQ/Cognis/blob/HEAD/src/ui/reuse/page-composer/layout-save.js)                  | 操作を保護して編集状態を確定し、保存失敗時は再試行できます。                                     |
| [`bindComposerPointerDrag`](https://github.com/Cognis-Labs-HQ/Cognis/blob/HEAD/src/ui/reuse/page-composer/pointer-drag.js)          | ポインターの捕捉、端でのスクロール、ドロップ・中断通知、操作終了時の解放を管理します。           |
| [`RESIZE_EDGES / resizePlacement`](https://github.com/Cognis-Labs-HQ/Cognis/blob/HEAD/src/ui/reuse/page-composer/resize-model.js)   | 8方向の辺・角を定義し、グリッドに合わせて制限した配置を計算します。重なりは検査しません。        |
| [`resolveResizeAvailability`](https://github.com/Cognis-Labs-HQ/Cognis/blob/HEAD/src/ui/reuse/page-composer/resize-availability.js) | 各辺・角について可能な方向の CSS カーソル、または `null` を返します。                            |
| [`appendResizeControls`](https://github.com/Cognis-Labs-HQ/Cognis/blob/HEAD/src/ui/reuse/page-composer/resize-controls.js)          | 所有側の座標変換と重なり検査をサイズ変更プレビュー・配置更新に結び付けます。保存はしません。     |
| [`findGridSwap / applyGridSwap`](https://github.com/Cognis-Labs-HQ/Cognis/blob/HEAD/src/ui/reuse/page-composer/swap-model.js)       | 入れ替え可能な相手を検索し、現在の状態を検証してから両方の位置を一括で確定します。               |

## 設定

createPageComposer に elements、pageManifest、i18n、signal と配置設定を渡します。画面に合わせる要素は対応する契約を使い、保存配置は preferenceKey に結び付きます。

## 動作

### 概要

`createPageComposer` はすべてのCognisページで使用されるレイアウトオーケストレーションユーティリティです。個々のページモジュールは*何を*レンダリングするかを宣言し（要素と呼ばれる名前付きコンテンツブロックのリスト）、コンポーザーはそれらのブロックをどのように配置、永続化、ナビゲート、再レンダリングするかを処理します。

### 責務

- 名前付き要素のセットを親DOMノードにレンダリングする。
- `allowCustomization: true` の場合、90pxの自由グリッドを管理する。
- 設定APIを通じて要素の配置と表示を永続化・復元する。
- `subPageNavigation: true` の場合、サブページナビゲーションを駆動する。

### 要素

要素は名前付きコンテンツブロックです:

```js
{
  id: 'my-widget',
  label: 'マイウィジェット',
  render: () => '<h2>コンテンツ</h2>',
  gridSize: { default: [4, 3], min: [2, 2] },
  pinned: false,
}
```

| フィールド | 必須   | 説明                                                  |
| ---------- | ------ | ----------------------------------------------------- |
| `id`       | はい   | 一意の文字列識別子                                    |
| `label`    | はい   | 人間が読めるラベル                                    |
| `render`   | はい   | HTML文字列を返す関数                                  |
| `gridSize` | いいえ | 90pxグリッド単位での `{ default: [w,h], min: [w,h] }` |
| `pinned`   | いいえ | `true` の場合、ユーザーが要素を削除できない           |

### グリッドレイアウト

現在のグリッドの保存済みプロファイルは、行の余白を再配分せず、明示した幅、高さ、間隔を保持します。メインと入れ子のレンダラーは小数グリッドの寸法処理を共有し、保存済みの入れ子グリッドは編集時のトラック間隔を保ちます。Composer の文書とコンテンツパネルはスクロールバーの領域を確保し、編集終了時に別の列プロファイルへ切り替わるのを防ぎます。`snapDragPlacement` はドラッグ中の候補だけを上方の隣接する占有行または原点まで移動し、他のカードを飛び越えません。黄色のプレビューが移動先を示し、ポインターを離すと「完了」の前に反映します。「完了」は最後に詰め直さず、表示中の配置を保存します。`resizeLimitAxes` はクランプ前に水平・垂直の制限超過を個別に報告し、角の混合操作にも対応します。オレンジ色のフィードバック中も各軸はそれぞれの制限内に保たれます。

マウス、タッチ、キーボードでの入れ替えは、`swap-model.js` の `findGridSwap` と `applyGridSwap` を共有します。ドラッグした要素が相手の正確な開始位置に収まり、相手も元の開始位置に収まる場合のみ入れ替えます。両方の矩形全体がグリッド内にあり、他の表示要素とも互いにも重ならないことが必要です。確定直前に現在の配置、表示状態、グリッド境界を再検証し、プレビューでは配置を変更しません。

両ヘルパーは `gridCols`、`layout.placements`、`layout.hidden` で現在の状態を受け取ります。`findGridSwap(state, col, row, w, h, sourceId)` は現在の相手の配置または `null` を返し、`applyGridSwap(state, sourceId, targetId)` は真偽値を返して、拒否時はどちらの位置も変更しません。キーボードのバインドには `findSwapCandidate` と `commitSwap` の両方を渡し、Composer は共通の入れ替えモデルからこれらを提供します。

要素の既定サイズと最小幅には、カードの余白と内容のための領域が必要です。ダッシュボードのブランドは最低3列、アカウント情報は既定で2行、挨拶と前回ログインのカードは最低3列を使います。現在の幅制限が保存済みの行に収まらない場合、Composer は保存されたプロファイルを上書きせず、その制限内に再配置します。メインと入れ子の表示で同じ規則を使います。正規化された行では各カードが指定されたグリッド列内に収まることを検証し、収まらない場合は再配置します。

メインと入れ子の編集画面は、`resize-model.js` と `resize-controls.js` による8方向のサイズ変更を共有します。左辺と上辺のハンドルは、反対側の辺を固定して開始位置を変更します。ポインターの移動量はグリッド単位に丸められ、すべての方向にサイズ制限、グリッド境界、重なりの検査を適用します。タッチ対象は44pxを維持し、削除ボタンは角のハンドルを操作できる位置に配置します。

編集用グリッドの行は90pxを基本の高さとし、列は利用可能なコンテンツ幅を共有します。トラック間の間隔は8pxです。`gridSize.max: 'full'` は要素をすべての利用可能な列にまたがらせます。

編集モードでは行の高さを固定し、カード、ドラッグプレビュー、サイズ変更ハンドルに同じ間隔を考慮したピクセル座標を使用します。半グリッド配置にも対応します。スクロール領域は計測前にスクロールバーの幅を確保し、ポインター座標から共通の内側余白を除きます。要素パネルは画面内で内容に合わせた幅を取り、実測した幅で初期位置と移動範囲を決めます。幅を計測する前に高さの上限を適用し、内部スクロールバーの幅を水平方向の配置に含めます。

ポインターキャプチャはカードをポインターの中央に移動せず、スクロール中もつかんだ位置を保持します。メインと入れ子の編集機能は、ポインターの識別、端でのスクロール、キャンセル、キャプチャの解除を共用します。ポインターのキャンセルや編集画面の破棄では、仮の移動とグリッドの拡張を取り消します。タッチ用のサイズ変更と削除には44pxの操作領域を確保します。「要素」を最小化すると、再び展開するまで内容と操作ボタンを非表示にします。 保存が成功するまで編集モードを維持し、書き込み中の画面サイズ変更で古い配置が復元されることを防ぎます。

サイズ変更ハンドルは、要素の制限内で、他の要素と重ならない変更が可能な場合だけ表示します。隣に別の要素があっても縮小は可能です。カーソルは拡大、縮小、角での異なる軸方向の変更を区別し、他の要素と重なる操作には `not-allowed` を表示します。要素の削除には共通の `btn-cancel` の外観を使用します。

### サブページナビゲーション

`subPageNavigation: true` の場合、一度に1つの要素のみが表示されます。`[data-composer-scroll]` を持つツールバーボタンがセクションセレクターとして機能します。

### DOM パーキング

DOM パーキングは既定では無効です。メディア DOM を composer の再レンダリング後も維持する必要がある場合に限り、page composer に `enableDomParking: true` を指定してください。有効にすると、iframe などのメディアを含むカードは DOM をそのまま退避して復元します。これは Jitsi Meet のような状態を持つ埋め込み向けです。通常のページでは、新しいレンダリングと一時的なフォーム状態の復元を利用し、古い退避 DOM がユーザーの更新内容を隠さないようにしてください。`refresh(elements)`は既存のカードDOMを保持して要素定義と配置を更新します。内容を再生成する場合はComposerの`refreshElements(ids)`を使用します。配置だけの変更では操作部と下書きを保持します。

### 永続化

レイアウトの保存は `ui:pageComposer:saveLayout` の `validate`、`persist`、`notify` ステージを通ります。同じ設定キーへの同時保存は、変更されないリクエストのスナップショットを共有します。「完了」、レイアウトのショートカット、リセット操作は、翻訳済みの成功または失敗の通知を表示します。HTTPエラーやセッションがない場合は成功として扱いません。保存中は編集操作を無効にし、失敗時は保留中の配置を復元して編集画面を維持します。ページの終了時は保存を中断し、遅れて届く通知を抑止します。診断には `ui:log` を使用します。

`createLayoutSaveHandler({ctx, save, notify, i18n, signal})` は `update(key, profiles, columns, layout)` を返します。注入する `save(key, profiles, columns, layout, signal)` は更新済みプロファイルを返し、書き込み失敗時は拒否する必要があります。`update` はそのプロファイル、または保存失敗・ページ中断時に `null` を返します。フローと翻訳のエラーは拒否として伝わります。ctx はフローの登録・実行と capabilities を提供し、`notify` は共通トーストのシグネチャを使い、`i18n.t` は成功・失敗のキーを解決します。

`commitLayoutEdit({state, prepare?, save, finish?, render})` は複製可能な `state.layout`、変更可能な `editing`/`saving` フラグ、同じ状態を操作するコールバックを必要とします。`layoutSnapshot` を管理し、任意の `container` または `contentGrid`、`elementsPanel`、`signal` が操作の無効化とページの生存期間を制御します。任意の `prepare()` はリセット時に配置を同期的に初期化し、通常の「完了」操作では省略します。`save()` は真偽値を返し、成功時に所有側のプロファイルを更新する必要があります。false は準備前の配置を復元し、true はスナップショットを更新して `finish` がある場合のみ編集を終了します。想定外のコールバックエラーは、操作を復元した後に呼び出し元へ伝わります。

配置は `PUT /api/v1/social/users/:accountId/preferences/:preferenceKey` に `{ layout: profiles }` を送信して保存します。`profiles.layoutsByGrid` は `cols-<count>` キーを `{ placements: [{id, col, row, w, h}], hidden: [] }` 形式の配置に対応付けます。同じパスへの GET は、シリアライズされたプロファイルを `data.layoutJson` に返します。保存には現在のアカウントとアクセストークンが必要です。

これに加えて、フォーム下書きはユーザー・ページパス・コンポーザーキー単位で `localStorage` に保存されるため、ページ再読み込みやレスポンシブ再レンダリング後も入力内容が復元されます。永続的な下書き保存はオプトイン方式です。最も近い祖先要素に `data-composer-include-form-memory="true"` が指定されているフィールドのみが localStorage に書き込まれます。オプトインされていないフィールドは、同一セッション内のレスポンシブ再レンダリングを乗り越えられるようにメモリ内の一時スナップショットには引き続きキャプチャされますが、永続ストレージには書き込まれません。`password` / `file` / `hidden` フィールド、および識別子に `password` / `secret` / `token` を含む項目は、オプトイン状態に関わらず常に永続的な下書き保存の対象外です。

大きなフォーム（永続化対象フィールドが6個以上）を含むカードには **下書きをリセット** ボタンが表示されます。このボタンはそのカードの保存済み下書きを削除し、現在のフィールドを既定値に戻します。

### テーマに従うポインター操作

共通のポインタースタイルボタンは、マウス・レーザー・照準のアイコンにテーマ標準の前景色（`--text`）を使います。埋め込みコンポーネントページにも適用し、参加者のポインター色は変更しません。

### レスポンシブレイアウト

Page Composer は端末名ではなく、利用可能なコンテンツ幅に合わせます。640 CSS ピクセル以下では、通常のカードを全幅の一列に並べ、行の高さを内容に合わせます。デスクトップの配置は保持されます。枠のない埋め込み画面は独自のサイズ設定を維持し、広い領域ではグリッドと列数別の保存済み配置を使用します。

スマートフォンやタブレットでもレイアウト編集を使用できます。タッチ用のサイズ変更ハンドルと削除ボタンを表示し、項目パネルの追加ボタンでドラッグせずに追加できます。ウィジェットにフォーカスして矢印キーで移動し、Shift と矢印キーでサイズを変更します。中断されたポインター操作は反映しません。入れ子の編集画面は利用可能な全幅を使い、表示幅の変更時にも既存のフォームを保持します。

900 CSS ピクセル以下ではツールバーを引き出し式のパネルで開きます。フィルターなどの画面内操作では開いたままにし、ページ移動で閉じます。Escape キーまたは背景を押すと閉じてフォーカスを戻します。ナビゲーション、ツールバー、検索、ポップアップでスクロール制御を共有し、重なった画面を閉じた後のスクロール不能やダイアログ背後のスクロールを防ぎます。

ワークスペースのガイドは狭い画面で表示中のナビゲーションボタンを強調し、タッチとキーボードによる配置操作を説明します。ブラウザーの回帰シナリオは 320、390、768、1024、1440 CSS ピクセル、画面回転、キーボード入力、再表示を対象とします。Chromium を起動できる環境で `COGNIS_BROWSER_TESTS=1 node --test src/ui/tests/page-composer/responsive-browser.test.js` を実行してください。エミュレーションだけでは iOS Safari、インストール済み PWA、実機の画面キーボードの動作は確認できません。

スマートフォンでは、ブランドとページ名をヘッダーの一段目に、ナビゲーションとアカウント操作を二段目に表示します。副題は支援技術で読み取れます。最も狭い画面ではブランドアイコンを残し、長いページ名の領域を確保します。閉じたツールバーのボタンは固定ヘッダーの背後をスクロールします。フローティングメニューは余白を抑えつつ、44 ピクセルのタッチ領域を維持します。ガイドの操作部は不透明な背景、対象は明瞭な枠線で表示します。縦の短い画面では、フッターの境界を保ちながら説明にヘッダー領域も使います。文字はページ全体を縮小せず、選択されたフォントとサイズに従います。

共通ヘッダーとガイドの検証には `COGNIS_BROWSER_TESTS=1 node --test src/ui/tests/page-composer/*.test.js` を実行します。組み込みページへの直接アクセスと SPA 遷移の検証には、実行中の隔離環境を `COGNIS_CORE_BROWSER_URL`、JSON 形式の認証情報ファイル（`username`、`password`、`provider`）を `COGNIS_BROWSER_CREDENTIALS` で指定し、`COGNIS_BROWSER_TESTS=1 node --test src/ui/tests/integration/core-pages-browser.test.js` を実行します。専用の管理者アカウントと有効な組み込みゲートウェイが必要です。外部モジュールのページは対象外です。

### 画面に合わせた作業領域

ページComposerが表示方法を選択します。各要素の描画関数は`compact`、`layout`、`drawer`、`touch`を持つ変更不可のコンテキストを受け取ります。サイドバーや入れ子のレイアウトによる変化を含め、カード内で利用可能な幅から選択します。表示の境界で別のマークアップが必要な要素は`responsive: true`を指定し、通常の状態を持つ要素はDOMを保持します。形状の更新には`onResize(presentation)`を使用します。ページ側の画面クエリーやサイズ変更リスナーは不要です。

デスクトップのツールバーは幅を制限した共通の列を使い、コンテンツの領域を確保します。列幅は選択した文字サイズを尊重し、スマートフォンとタブレットではComposerのドロワーを使用します。

共通の`layout`はカード内部の幅で決まり、640px以下の`compact`、900px以下の`medium`、それ以上の`regular`です。カレンダーなど情報量の多い画面は、前の二つの表示で予定一覧を使います。

Composerが管理する`data-composer-layout`、`data-composer-drawer`、`data-composer-touch`を使って表示と入力方式に合わせたスタイルを適用します。通常と入れ子の構成で同じコンテキストを受け取ります。Composerは内容とカードを監視し、フォーム値を復元し、ページ終了時に監視とイベント処理を解除します。

レイアウト更新は`onResize`で通知し、生成した内容への動作の設定には`onRender`を使います。レイアウトだけの変更では、変更のない操作部のイベント設定を保持します。明示的な内容更新では、指定した要素を一度初期化します。

分離した実行中の環境で画面を検証するには、`COGNIS_BROWSER_TESTS=1`、`COGNIS_CORE_BROWSER_URL`、`COGNIS_BROWSER_CREDENTIALS`を設定します。任意の`COGNIS_BROWSER_BYPASS_SERVICE_WORKER=1`でサービスワーカーのキャッシュを経由せずに表示を確認できます。オフライン動作とPWAは別途検証が必要です。

### ページとサイドバーの操作

ヘッダーのページグリッドで移動先を切り替えます。コンパクトなページ選択はキーボードのフォーカスを保持し、Escapeで閉じます。すべてのサイドバーはPage Composerが提供する左上の共通の二重山括弧SVGボタンを使用します。メッセージではこのボタンから会話を選択します。

`stackAt: "medium"`で共通のタブレット境界まで一列のフローレイアウトを指定できます。`readingOrder`は保存済みのデスクトップ配置を変えずに表示順を指定します。レイアウトを変更してもフォームの要素と下書きは保持されます。

単一の固定要素を持つページでは `fillViewport: true` を使用します。主な閲覧領域に `data-composer-viewport-body` を付けると、Composerはその領域に20remを確保し、周囲の余白と操作部を別に測定します。空きがあれば画面内に収め、最低高さが収まらない場合はページをスクロールできます。操作部のサイズ変更、内容の置換、文字の拡大で最低高さを再計算します。ドキュメントのスクロールでは表示の高さを増やしません。サイドバーボタンはComposerが提供し、`openToolbar(trigger)` と `closeToolbar()` は明示的な操作に使用できます。

内容に合わせて伸びる通常のドキュメントには `contentScrolling: false` を使用します。カレンダーとメッセージは画面に合わせ、閲覧領域の内部でスクロールします。

共通のダイアログは閲覧用の`surface: "reader"`を指定できます。Composerの表示属性を使い、ヘッダーとフッターの外側で本文だけをスクロールし、閉じるとサイズ監視を解除します。

ヘッダーとフッターは共通の枠幅を使い、スマートフォン、タブレット、デスクトップで両端を揃えます。

要素は安定した`data-composer-header`領域を指定できます。Composerはそこにサイドバーボタンを配置し、再描画でも同じボタンとフォーカス動作を保持します。非同期で置き換える内容は、この領域の子要素に配置します。共通の操作部は`data-composer-sidebar-trigger`属性で識別できます。カレンダーとメッセージはこの領域を使い、本文の表示高さを確保します。

Composerはグリッド内のコンテンツ全体でブラウザーのスクロールアンカーを無効にし、幅が変わっても内部のスクロール位置を維持します。コンテンツの追加や置換に伴うスクロールは、所有コンポーネントが制御します。

共通サイドバーの余白は利用可能な幅に合わせて調整します。デスクトップでは本文との間隔を一つに統一し、パネルの幅は大きな文字にも対応するrem単位にしました。各コンポーネントは、十分なタッチ領域を保ちながら操作部品の幅を調整できます。

共通サイドメニューの項目には選択行とキーボードフォーカスの表示があります。サイドバーの間隔とスクロールは個々のページではなくComposerが管理します。

サイドバーのメニューボタンは通常時の透明な背景と、テーマに合ったホバー、選択、キーボードフォーカスの表示を使います。フォーム欄は入力用のスタイルを、操作ボタンは意味に応じた色を維持します。明るい背景では文字色を薄く重ねてホバーを表示します。

### Composerのパネル表示

Composerはメッセージのパネル背景をサイドバーとメイン領域の両方に使います。ツールバーの各提供部分は保護された `composer-sidebar-section` で囲み、外側の内容を透明にしてComposerの間隔を使います。メインカードはパネル上に不透明な背景や影を重ねません。メニュー行は文字、ホバー、選択、フォーカスの表示を共通化し、明示的な確認・取消・中立の操作部品は意味に応じたスタイルを維持します。枠なしの埋め込み表示は透明のままです。ページのスタイルは保護されたパネルクラスや共通の `--toolbar-bg` を上書きできません。 カスケードレイヤー `composerSurfaces` はホスト専用です。

Composerはコンテンツセクションの内側余白を管理します。広い画面では28px、640px以下では14pxとし、表示領域を埋めるページにも適用します。枠なしの埋め込み表示には余白を設けません。サイドバーのリストを囲む要素は透明で内側余白を持たず、メニュー項目に余分なカード背景を重ねません。ページのスタイルは `--composer-grid-inset` の設定やホストの余白の上書きを行えません。

### フォントの読み込み

共通テキストは、選択した文字サイズを縮小せず、フォントの読み込み前後とも利用可能な幅に合わせて折り返します。

配列では、幅全体と利用可能な高さを使う `['full', 'fill']`、または幅全体と数値による高さの上限を指定する `['full', n]` を使用できます。メインと入れ子の Composer は、狭いグリッドでも広いグリッドでもこれらの寸法を適用します。端でのスクロール中は、一時的な最小行数を高さの設定前に適用し、グリッドとプレビューが途中で縮まることなく一緒に拡張されます。 拡張後は親要素のスクロール位置が変わる場合があるため、入れ子のドラッグプレビューはコンテナを再計測します。

## セキュリティ

構成機能は表示と DOM の期間を管理し、対象の認可は行いません。操作は担当元のフローを使い、共有のメニューとパネルの境界を守ります。
