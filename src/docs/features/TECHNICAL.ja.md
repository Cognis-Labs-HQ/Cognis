# 技術リファレンス

プラットフォーム機能 の公開インターフェースと運用規則を説明します。

## インターフェース

公開契約は各担当元に属し、Auth はセッション、Study は教材と活動、Social はプロフィールやルーム、Calendar は予定、Share は委譲アクセスを管理します。すべての画面機能に独立した HTTP API があるわけではありません。OIDC と SAML はクライアントの注入が必要で、設定項目だけでは外部認証を実装しません。

## 設定

### 確認済み設定のスナップショット

Profileの設定保存が成功すると、再送時やオンライン専用の保存時も、次の読み込み前にプロバイダー所有の容量制限付きスナップショットを更新します。オフラインでの設定統合は確認済みの項目を保持し、残りの保留変更を反映します。遅延した読み込みは新しい確認済みデータを上書きせず、アカウント変更、プロバイダー終了、保存失敗によって古いデータが公開されることもありません。

## 動作

### 容量制限付きスナップショットの置換

成功した置換データが読み込みキャッシュの容量上限を超える場合やシリアライズ可能な値がない場合は、古いスナップショットを削除してオフラインでの誤使用を防ぎます。遅れて完了した共有読み込みも古いデータを再保存しません。他のキャッシュ済みキーは保持し、大きすぎる応答もキャッシュせずオンラインで利用できます。

### アカウントIDによる通知配信

ロール宛ての通知とStudy Libraryの申請・コンテンツ通知は、不変の `accountId` を宛先に使用します。公開ユーザー名が異なるSSOユーザーにも配信できます。申請の判断では同じIDで操作したアカウントを除外し、公開ユーザー名は表示用データとして扱います。

### 概要

Cognisは、構造化された学習コンテンツ、ソーシャル機能、プラグイン可能な認証、柔軟な永続化、リアルタイムコラボレーション対応レイヤーを組み合わせたセルフホスト型言語学習プラットフォームです。

### コア機能

- **認証とアイデンティティ** — プラグイン可能な認証アダプターがローカル認証情報、LDAPディレクトリサービス、SAML 2.0、OAuth2/OIDCプロバイダーをサポート。
- **モジュラー言語コンテンツ配信** — モジュールシステムでカリキュラムユニットをモジュールとしてパッケージ化し、実行時にインストール可能。
- **設定可能なUIページ** — すべてのページが `createPageComposer` でユーザーごとのレイアウトスロットと設定永続化を提供。
- **軽量ソーシャルネットワーク** — 公開プロフィール、マイクロブログスタイルの投稿、フォロワー/フォローグラフ、ブロック管理。
- **APIファーストアーキテクチャ** — 安定した `{ data }` / `{ error }` レスポンスエンベロープを持つバージョン管理されたHTTP APIで全機能にアクセス可能。

### 学習モード

- **独立した学習者** は自分のペースでモジュラー言語コンテンツを学習。
- **教師とチューター** は `teacher` ロールでセッションを指導。
- **コミュニティ** はソーシャル機能で共同学習リズムを組織。

### 登録と検索

管理画面は、ローカルアカウントの公開登録の許可を登録アダプターとは別に保存します。公開アダプターを有効にしたままローカル登録を無効にすると、ユーザー名とパスワードによる公開登録を許可せずに SSO アカウントを作成できます。アダプターを無効にするとこの作成経路も閉じます。招待トークンは専用アダプターで利用できます。全体検索は途中結果を表示し、置き換えられた検索を中断し、提供元の実行時間を制限します。文書の本文より先に見出しを表示し、ライブラリー全体を同時取得する代わりに、中断可能な四つの処理で本文を索引化します。

### 接続とアカウント

オフラインワーカーのポリシーとルート情報は、アセットとは別の制御キャッシュを使用します。カタログ要求を統合し、ポリシーの更新順を保ち、メッセージのポートを閉じます。バックグラウンドのアセット整理は応答を妨げません。インストール時の同時取得は最大四つです。ログインは公開キャッシュの保守を待たず、資格情報、TFA コード、SSO 認可の要求中に共通の読み込み表示を出します。対話的な設定操作は引き続き利用できます。接続確認は即座に応答し、詳細なコンポーネント診断は `/api/v1/system/health` に残ります。

この動作については[共通の契約](/docs/adapters/registration/token/technical)を参照してください。

### ユーザー一覧の構成

ユーザー一覧は Composer の利用可能な幅全体を使います。各アカウントは独立した開閉式の行となり、見出しにユーザー名、ロール、状態、管理操作を並べ、その下に詳細を行全体の幅で表示します。詳細はラベルと値のレスポンシブなグリッドで整理し、ローカライズしたロール名と認証元名、メインアドレスと確認状態のバッジ付きメール行を表示します。狭い画面では見出しの操作を折り返し、詳細を一列に並べます。

### オフライン状態とナビゲーションの復旧

常時表示される単一のヘッダー通知は共通のコールアウトスタイルを使い、オフラインモードであることを表示します。再接続後は自動的に再読み込みせず、更新ボタンを表示し、未保存の変更と送信待ちの変更の保護を維持します。利用できないページでは、まず直前の使用可能なページへの復帰を試みます。失敗した場合だけ、再接続後の保護付き自動更新を有効にします。同一オリジンの絶対リンクと相対リンクは SPA ルーターを使用します。オフラインの一覧は、キャッシュされた公開ページと提供元が許可した非公開ルートの両方を保持します。

### オフラインの定期確認の制限

オフラインモードでは、同意確認と通常の接続復旧の定期確認を停止します。ブラウザーのオンラインイベントが繰り返されても、軽量のサーバーヘルスチェックだけを十五分ごとに実行します。オンラインでの接続確認の失敗時は最大十五分まで間隔を延ばします。同意確認は失敗時に最大五分まで間隔を延ばし、オフラインでは完全に停止して再接続後に再開します。必要な文書へのキャッシュ済みの同意は引き続きオフラインアクセスの条件です。

### 突然の接続断

現在のページがオフラインに対応していない場合、ホストはページのライフサイクルを停止し、エラーダイアログを出さずに前のオフライン対応ページへの復帰を試みます。復帰できない場合はヘッダー通知で利用できないページを説明して内容を消去し、再接続時にナビゲーション保護を適用した自動更新を行うよう設定します。プレゼンスのタイマーはオフライン中に停止し、復旧後に再開します。読み込み済みの公開翻訳はタブ内で再利用します。保護されたカタログには引き続き認証済みリクエストが必要です。

### Dashboard と Study の利用

Dashboard はセッション内限定の非公開オフラインアクセスを宣言し、アカウント概要とキャッシュ済みの予定を引き続き利用できます。オフラインで開き直す際はサーバーから取得する任意の拡張機能を省きます。Study のプロバイダーはハブルートを登録し、`study:navigation` フローを通じて言語一覧、学習設定、モジュールリンクのアカウントとセッションに紐付いたスナップショットを使用します。ナビゲーションバーの読み込み時に軽量なハブ情報を先行取得します。Explore とフラッシュカードは引き続き各プロバイダーがルートを宣言し、未対応ページには静かな復帰処理を適用します。学習言語の変更には接続が必要です。 シェルを開き直してもテーマ設定を自動で書き込まなくなりました。明示的な UI 設定変更には有効な Profile クライアントを使用し、オフラインバッファーに保存できます。遅延した設定の結合ではアカウントも確認します。

### 単一のオフライン通知

オフライン状態と利用できないページの説明を、閉じる操作のない単一のヘッダー通知にまとめます。再接続後は接続復旧のメッセージと、共通のボタンスタイルと操作間隔を使用した更新ボタンだけを表示します。シェルの既定スタイルは、明示的に指定された確認・キャンセル・中立のボタンスタイルを維持します。ヘッダーのないページでは、内容内に一つの通知を表示します。

### オフライン資産とカレンダー

本番用アセットの解決は、ルートに必要なスクリプトやスタイルシートの配列にも適用されます。公開アセットはバージョン付き・なしの URL でワーカーのキャッシュキーを共有し、モジュールのリビジョン境界は維持します。二つのバックグラウンド処理で対応ページのコードと非表示のスタイルを準備し、ページ自体はマウントしません。オフラインリンクには準備済みコードと各所有者が必要とするアカウント・セッション別スナップショットが必要です。ナビゲーションを再描画しても無効状態を維持するため、Meetings は無効のままです。非公開 API と認証済み HTML は引き続きワーカーに保存しません。

認証確認後、Calendar はカレンダー一覧、招待、所有する予定を最大二つの同時バックグラウンド要求で保存します。キャッシュを無効化した場合も、ログインを妨げず再取得します。保存済み予定を閲覧でき、予定の作成・編集・削除・回答、状態設定、カレンダーの編集は共通の送信待ちバッファーに入ります。保留中の作成と編集は保存済み一覧に反映します。作成には固定の操作 UUID を使用し、再送では既存の予定を返すため、繰り返し予定や招待通知を重複作成しません。内容の変更や別アカウントでの ID 再利用は拒否します。再送時にはサーバーが権限を再確認します。

予定のスナップショットはタブ内限定で 4 MB・100 件の読み取りまでです。共通の送信待ちキューは従来どおり 1 MB・1,000 件・七日間までです。新しい繰り返し予定は、サーバーで展開するまで最初の予定だけを表示します。カレンダー自体の作成、会議の生成、共有とパスワードの管理、ゲスト資格情報には接続が必要です。共有パスワードはバッファーに保存しません。オフラインナビゲーションを有効にするには、Messages は保存済みルーム一覧、Study は保存済みの言語・設定情報が必要です。

### ログインと保留中の送信

パスワードまたは TFA のログイン成功後は、既存の SPA ナビゲーション機能でログイン画面を Dashboard に置き換えます。検証済みタブと保留中の変更を維持し、ブラウザーのページ終了警告を発生させません。移動完了まで読み込み表示を維持し、任意のタイムゾーン同期はその後に実行してアカウント変更を拒否します。認証済みタブを閉じるか再読み込みする際は、実際に保留中の変更がある場合に引き続き警告します。

保留中の送信は、セッション認可と必要な同意が成功した後にバックグラウンドで開始します。タブ間の送信は専用のブラウザーロックで直列化し、スナップショットと確認処理にはネットワークを待たない短いストレージロックを使います。送信が遅くても読み込みと新しい保留書き込みを継続でき、確認時にストレージを再取得するため同時書き込みも維持されます。認証時に空のキューを書き直さず、未認証ページでは別アカウントの保留変更について警告しません。

### オフライン確認と警告

オフラインバナーの「接続を再確認」は直ちに `/api/v1/system/healthcheck` を呼び出し、同時確認をまとめ、接続できればセッションを再認可して保留中の送信を試みます。必要な同意は引き続き必須です。失敗時はエラーポップアップを出さずオフラインを維持します。共通ボタンスタイルと処理中表示を使用し、復旧後には更新ボタンが表示されます。自動確認は15分に1回のままで、明示操作ではそれ以前でも確認できます。

この動作については[共通の契約](/docs/api/technical)を参照してください。

### 再読み込み時の解錠とモジュール

ホストのルートアセット準備は、共通の ctx ごとにフローとキャッシュ機能を一度だけ登録します。バンドルされたスクリプトと外部モジュールのソースインポートは登録と準備済みルートの状態を共有し、Meetings を開く際の `offline:prepareRouteAssets` 重複エラーを防ぎます。

### フラッシュカードの事前準備

### 確認済みのお気に入り

オンラインで成功したお気に入り変更と再送の確認時に、Studyの容量制限付きオフラインスナップショットをサーバー応答で置き換えます。進行中の古い読み込みでは上書きできません。オフラインで画面を開き直しても確認済みの追加と削除を保持し、未送信の変更は引き続きスナップショットに重ねて表示します。

### 独立した絵文字使用記録

Messagesの再利用可能なリアクション選択機能は、リアクション変更とは独立して絵文字の使用頻度を記録します。最終的な有効状態はメッセージのリアクション要求だけに含めます。使用記録に失敗してもログに残すだけで、選択したリアクションや更新コールバックを妨げません。

### アカウント別のユーザーメニュー

ユーザー管理の操作メニューは公開ユーザー名ではなく、不変のアカウントIDで行を特定します。SSOアカウントのTFAリセット項目と設立者状態を維持し、外部で管理されるパスワードのリセットは無効のままにします。古い選択や不明な選択ではアカウント操作を開きません。

### 完全なアセットのキャッシュ

範囲指定リクエストはファイル全体のキャッシュを経由せず、完全なHTTP 200応答だけが公開アセットを保存または置換できます。部分応答で既存の完全なデータを変更しません。内容ハッシュ付きのフォントは、スクリプトや画像と同じ不変キャッシュと世代間の再利用を使い、ワーカー更新後の不要な再取得を防ぎます。

## セキュリティ

### アカウントのプライバシーとキーリングの分離

SSO アカウントにはプロバイダーを示さないランダムな ID を使用します。プロバイダー ID は別に保存し、管理者だけに表示します。公開ユーザー名には含めません。Auth はプロフィールやメールの変更前にユーザー名を確保します。同じプロバイダー内の重複名は拒否し、別プロバイダーとの重複には短いランダムな接尾辞を付けます。ユーザー一覧と操作 API は公開用の `username` と内部用の `accountId` を区別します。

従来の SSO レコードが存在していても、既存のローカルアカウントは引き続き使用できます。起動時にデータベースのリセットは必要ありません。従来の SSO アカウントのログインと作成処理だけを個別に拒否し、不透明な ID での再作成を必要とします。アカウント ID、関係、会議の自動移行や自動削除は行いません。

この動作については[共通の契約](/docs/api/technical)を参照してください。
