# SMTP TFA 分離

## SMTP TFA アダプター識別子を改名

Auth アダプターの内部 ID とパッケージ識別子を `email-tfa` から `smtp-tfa` に変更し、ユーザー表示名は「Email TFA」のまま維持しました。

## 認証ゲートウェイの固定アダプターID依存を除去

認証ゲートウェイの TFA アダプター解決は固定 ID ではなく機能フックで判定するように変更し、アダプター駆動の構成にしました。

## 設定ポップアップでアダプター依存を表示

アダプター設定ポップアップで依存リンクを表示し、コンポーネント依存リンクと同じ挙動でアダプター対象にも遷移できるようにしました。

## SMTP TFA の検証をアダプターテストへ移動

SMTP TFA 挙動の検証を認証ゲートウェイテストから外し、`src/adapters/auth/smtp-tfa/tests/` に専用アダプターテストを追加しました。

## 管理画面にTFA制御を追加

Administration → Security に新しい TFA 領域を追加し、利用可能方式と有効方式のテーブル、ドラッグ＆ドロップでの有効化、利用可能方式がない場合に無効化される強制スライダーを実装しました。

## 新規ユーザーのTFA設定を必須化

強制設定が有効な場合、新規ユーザーは TFA オンボーディングを完了するまで進めないようになりました。設定状態 API と、閉じられない設定ポップアップを追加し、SMTP TFA 有効化前に検証済みメールを必須にできます。
