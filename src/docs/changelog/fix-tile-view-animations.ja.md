# 教室ワークスペース修正

## 教室SPAスタイルを復元

教室のSPAルートはアプリ内遷移でもワークスペース用スタイルシートを読み込むようになり、黒板ワークスペース、サイドバーの余白、チャットタイル、アジェンダ操作がハードリロードなしでも正しく表示されます。

## ワークスペース切替を安定化

タイル表示とスライドショー表示の切替は、アクティブなワークスペースを正しい見た目の順序で保ち、チャットを開いてもレイアウト切替ボタンを表示し続け、チャットとホワイトボードを一貫して初期化し、先生が退出したときはトーストを表示して生徒を教室ビューへ戻します。

## 教材アップロードを改善

教師用ライブラリアップロードは `teacher-materials/` 保存パスを使うようになり、ファイル選択ポップアップでは共通のアップロードSVGを使い、ポップアップの二重起動を防ぎ、教室教材向けの大きなドキュメント上限を利用します。

## Notepadの責務をNotepadアダプターへ移管

教室アジェンダとNotepadファイルのAPIロジックは study/notepad アダプターへ移動し、classes アダプターは共有される教室リソース機能のみを公開する構成になりました。Notepad アダプターがアジェンダのスナップショット、ノートファイル用ルート、そして最大ファイルサイズ設定を管理します。

## Nextcloud Whiteboard の管理設定を追加

Nextcloud Whiteboard モジュールに Administration 用の設定ポップアップと、`/api/v1/modules/nextcloud-whiteboard/config` の永続設定ルートを追加しました。URL、署名シークレット、トークン有効期限はデータベースへ保存され、実行時の埋め込みトークン生成に使用されます。

## チャット開くボタンを統合して「チャット」に改名

黒板アクションツールバーから重複していた「チャットを開く」ボタンを削除しました。ワークスペースタブに残るボタンは簡潔に「チャット」という表記になりました。

## アクティブなタイルは選択時に他のタイルと入れ替わる

コンテンツ領域を持つのはアクティブなタイルのみです。非アクティブなタイルをクリックすると、現在アクティブなタイルと位置が入れ替わり、アクティブなタイルが常にスタックの末尾に表示されます。

## 教師のビュー状態の同期をスナップショット取得から分離

生徒はデータ更新時およびSSEイベント発生時に専用のAPIエンドポイントへ教師の現在のボードフォーカスとタイルレイアウトを問い合わせるようになりました。これによりスライドショービューとタイルビューの両方で同期が機能します。

## チャットウィンドウのスタイルをMessagesアダプターが管理

教室チャットパネルのCSSルールをすべてMessagesアダプターへ移動しました。これにより、チャットパネルがメッセージページと一貫した外観で表示されます。

## 教材ライブラリに元のファイル名を保持

教師用教材ライブラリへのアップロードは、元のファイル名とコンテンツタイプをライブラリのメタデータとして保存するようになりました。これにより、ピッカーや関連付けられた授業教材に生のUUIDキーではなく分かりやすい名前が表示されます。

## 授業教材を教室内で開く

授業教材を開くと、サイドバー内でファイルを描画しようとする代わりに、教室ワークスペース内のインラインビューアへ切り替わるようになりました。これにより、認証なしのインライン読み込みを避けつつ、アクティブな教材を授業の主表示面に保てます。

## ミーティングは長いアイドル間隔に耐える

Jitsi の教室ミーティングは、バックエンドが参加者不在と判断する前にプレゼンス情報をより長く保持するようになりました。これにより、ブラウザーの heartbeat 遅延による誤ったミーティング終了が減少します。

## スライドショーのナビゲーション矢印に共通ボイラープレートを使用

ナビゲーション矢印は、初期レンダリングと動的タイル更新処理で共有される単一のヘルパー関数から生成されます。チャットビューでは矢印が自動的に非表示になります。

## メタデータファイルが教師の教材リストに表示されなくなった

メタデータインデックスファイル（`.library-metadata.json`）が教材リストに誤って表示されており、アップロードしたファイル名が UUID の生のキーとして表示されていました。どちらの問題も、ローカルファイルゲートウェイのパス二重スラッシュバグが原因でした。ゲートウェイは、相対ファイルキーを生成する前に末尾のスラッシュを正規化するようになりました。

## ノートパッドのファイルピッカー操作が正常に動作するようになった

ノートパッドのファイルピッカーのコールバックは、サポートされていない `onMount` キーではなく `onOpen` に登録されていなかったため、「開く」「名前変更」「削除」ボタンが一度も機能しませんでした。保存ダイアログには「保存」の隣に不要な緑色の「開く」ボタンもありました。どちらの問題も修正され、「名前変更」ボタンは赤ではなくニュートラルなスタイルになりました。

## 生徒のファイルアクセスにクラス所属の確認を強制

教師の教材ファイルは、リクエストするユーザーがそのクラスに在籍しているかどうかを確認するクラス限定ルートを通じて提供されるようになりました。生徒と教師は、汎用ファイル API の代わりに `/api/v1/study/classes/:id/materials/files/:key` を使用します。キーはクラスリソースリストに対して検証され、パストラバーサルを防ぎます。
