# PostgreSQL接続プール

## PostgreSQLが上限付き接続プールを使用

通常のデータベース操作は `pg.Pool` で並行実行され、各トランザクションはコミットまたはロールバックまで同じクライアントを使用します。環境設定でプールサイズ、接続、アイドル、および任意のステートメントタイムアウトを制限できます。

## サーバー終了時に接続を排出

PostgreSQLアダプターは ctx のライフサイクル機能にプール終了処理を登録し、サーバーが新しい要求の受付を停止してからプールを安全に閉じます。

## Dockerセットアップが明示的な環境プロファイルを使用

共通、PostgreSQL、開発、本番用のEnvファイルがコンテナのデフォルト値を保持します。Composeは未設定のプール変数を補間せずに適切なプロファイルを選択するため、空変数の警告が解消されます。

## MariaDBも同等の接続プールを使用

MariaDBアダプターは同時クエリ用の上限付き `mysql2` プールを使用し、トランザクションを1つの接続に固定し、ライフサイクル終了時にプールを排出します。最大サイズ、アイドルタイムアウト、接続タイムアウトには検証済みの範囲が適用されます。

## Dockerプロファイルがデータベースドライバーを選択

PostgreSQLとMariaDBに個別の本番および開発用ComposeファイルとEnvファイルを追加しました。管理画面は設定済みデータベースアダプターだけを有効として表示し、すべてのドライバー切り替えをロックして、データベースゲートウェイの見出しにDocker管理であることを表示します。

## 本番コンテナは起動前に秘密情報が必須

PostgreSQLとMariaDBのコンテナエントリポイントは、不足しているデータベース設定とデータ暗号化キーを直ちに拒否し、各値を設定するEnvファイルを表示します。

## 環境プロファイルが古い例を置換

リポジトリルートの古い環境変数例を削除しました。`docker/env/` 配下で選択するファイルと翻訳済みDevOpsガイドが、完全なセットアップ資料になります。

## コンテナがデータベース接続URLを構築

各データベースプロファイルはエンジン固有のホスト、ポート、データベース、ユーザー名、パスワードをコンテナエントリポイントに渡します。エントリポイントが値を検証し、Compose補間に依存せず `DATABASE_URL` を構築します。ルートの `.env` は共通デフォルトプロファイルにリンクし、デフォルトのComposeリンクは最もサポートされているPostgreSQLデプロイを選択します。

## ドライバーのデフォルト値をエンジン別に分離

PostgreSQLとMariaDBのホスト、ポート、データベース、ユーザー名、プールのデフォルト値は、それぞれのドライバーEnvプロファイルだけに配置されます。共通デフォルトプロファイルには、エンジンに依存しないアプリケーション設定のみが含まれます。

## ユーザー管理の秘密情報ファイルを追跡対象外に変更

本番用の秘密情報EnvファイルはGitで無視され、追跡される `.example` テンプレートを持つようになりました。Composeの検証エラーには、不足している各値を設定する正確なプロファイルファイルが表示されます。
