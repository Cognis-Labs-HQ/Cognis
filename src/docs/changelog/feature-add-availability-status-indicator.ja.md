# 在席状況ステータス

## 在席状況をひと目で確認

ナビゲーションバー、プロフィールプレビュー、メッセージ、会議のアバターに、空き、予定あり、仮予定の状態が表示されます。

## 状態を手動で設定

カレンダー予定の開始時、または現在の時間帯に予定を作成した時点で状態が設定されます。その後、プロフィールメニューから進行中の予定による状態を上書きできます。

## プロフィールメニューで状態を操作

プロフィールメニューは、ポインターを合わせるかクリックすると開き、別の場所をクリックするまで表示されます。先頭行には、色付きの点が対応する「空き」「取り込み中」「仮予定」の枠なし状態メニューが表示され、各メニュー項目はポインターを合わせると輪郭が強調されます。

## 必要な場所で状態を確認

アバターのステータス表示にポインターを合わせると状態を確認できます。コンポーネントは ctx ケイパビリティを通じて、カレンダーを考慮したユーザーの空き状況も照会できます。

## 状態の選択肢でメニューが動かない

状態セレクターを開くと選択肢がプロフィールメニューの左側に表示され、下にあるプロフィール操作は元の位置に保たれます。

## カレンダー状態の制御

ユーザー設定の「一般」に、カレンダー予定による空き状況の変更を防ぐオプションを追加しました。

## 離席状態と拡張可能なカレンダー状態

プレゼンス検出が操作なしを報告すると、プロフィールアダプターは現在のユーザーの状態ランプを灰色にし、操作を検出すると直ちに元に戻します。離席中は自動で適用され、手動では選択できません。カレンダー予定の状態はプロフィールアダプターの ctx ケイパビリティから取得し、空き予定の背景は透明になります。

## 公開範囲に応じた状態の共有

プロフィールページとプレビューでは、相手の公開範囲に従って状態を表示します。コミュニティは全員、友達はフォロワー、非公開は本人がフォローしている相手だけが確認できます。ブラウザーがフォーカスを失うと直ちに離席中を通知し、アクティブなセッションは定期的にハートビートを送り、プレビューのアバターは状態ランプの下でも角丸を保ちます。

## 一貫したカレンダー状態の背景

予定あり、空き、仮予定の背景が、すべてのカレンダー表示の予定カード、カレンダーの今後の予定一覧、保留中の概要、ダッシュボードの今後の予定概要に一貫して適用されます。空きのカードは透明のまま、仮予定のカードは枠線を変えずに縞模様の背景を使用します。

## 予定状態を確実に更新

既存のカレンダー予定の状態を更新するとき、利用できないルート状態を参照せず、その予定からフォールバック値を解決するようになりました。状態だけを変更する PATCH リクエストで内部サーバーエラーが発生しません。

## 必要な場所だけでカレンダースタイルを読み込み

カレンダー状態のスタイルは、カレンダーページのスタイルシートまたはダッシュボードからの明示的な要求によって読み込まれるようになりました。管理など無関係なページでは、グローバルなカレンダーナビゲーションクライアントを通じてカレンダー状態の CSS を要求しません。

## ホバー時も状態の背景を維持

カレンダー予定カードにポインターを合わせても、予定あり、空き、仮予定の背景が置き換わらなくなりました。今後の予定では、状態の効果を角丸の予定カード内に保ち、ホバーのフィードバックを枠線だけに限定します。

## コンパクトな今後の予定カードとカレンダー見出し

今後の予定では、大きすぎるリストコンテナーではなく、枠付きの予定ボタンに状態の背景を適用し、状態固有のホバー背景が共通ツールバーのホバーを上書きします。「マイカレンダー」の見出しは「新規」ボタン用の列を確保し、操作項目が重ならないようになりました。

## ホバーでは予定のアクセントだけを強調

カレンダー状態の背景が共通ボタンのホバー背景に明示的に上書きされないようになりました。ホバー時もカードの背景と外枠を維持し、カレンダー色の縦棒だけを強調します。

## 参加者を確実に更新

カレンダー予定の PATCH リクエストで参加者一覧を再び更新できるようになりました。予定ルートが担当するカレンダー正規化関数を明示的にインポートし、所有者の参加を維持しながら、関数不足によるサーバーエラーを防ぎます。

## カレンダー更新後に状態表示を更新

カレンダー予定の更新が成功すると、UI ctx を通じてプロフィールアダプターの在席状況レンダラーを呼び出します。レンダラーは在席状況のキャッシュを消去し、ページを再読み込みせずに表示中のユーザー状態ランプを直ちに再描画します。

## プロフィールメニューも有効な状態に追従

在席状況の更新が、アバターランプだけでなくプロフィールメニューにも通知されるようになりました。カレンダーが有効な状態を変更すると、メニューの選択も直ちに移動します。自動の離席中では選択可能なすべての項目を未選択にし、灰色の離席中概要を表示します。

## 在席状況が有効な予定の境界に追従

すでに開始中のカレンダー予定を作成すると、在席状況を直ちに更新します。カレンダーページは予定の開始時刻と終了時刻にも ctx 経由の更新を予約し、ページを再読み込みせずに状態ランプとプロフィールメニューを切り替えます。

## 在席状況の連携を安定化

カレンダーは遅れて起動した設定を使用時に解決し、ダッシュボードの予定データに UI コンテキストを使用し、Social が無効でも空き予定の動作を維持するようになりました。在席セッションは期限切れ処理とアカウントごとの上限により、サーバーメモリの際限ない増加を防ぎます。

## 不明な在席状況を中立表示

在席状況を読み込めない場合、プロフィールの公開範囲でアクセスが許可される前に空きと誤表示せず、ステータス表示を「不明」の灰色で示すようになりました。

## 表示中のステータスを最新に維持

他のユーザーの在席状況は、プロフィールプレビュー、会議、ホワイトボードなどで表示されている間、10 秒ごとに更新されるようになりました。プロフィールのヒーローではアバター上の在席ランプを非表示にし、役割バッジと重ならないようにしました。

## 在席状況連携の信頼性

カレンダーは設定ストアが利用できない場合もエラーなく処理し、UI クライアントが設定リクエストを管理するようになりました。自分のステータス表示は最新に保たれ、再利用可能なプレゼンス購読も完全に文書化されました。

## 明確なカレンダーステータス更新設定

カレンダーの状態更新は既定でオンのスライダーになり、一般設定の最後に常に表示される危険ゾーンより前に配置されるようになりました。
