# より安全なキーリング設定

## 新しいキーリングパスワードの確認

初回ログイン時およびキーリング再作成時の設定で、独自のキーリングパスワードを再入力するようになり、入力内容が一致しない場合は作成されません。

## 一貫したパスワードフォーム

すべてのキーリングパスワードポップアップで共通のフォームコンポーザーを使用し、必須項目を明示して、検証とレイアウトを統一しました。確認条件は、成功のチェックが表示されるときにパスワードが一致していることを示します。 「ユーザーパスワードを使用」操作では、ログイン時に検証済みの認証情報を適用するため、以降のパスワードログインで追加の入力なしにキーリングを自動解除できます。キーリングの破棄は再作成より先に完了し、再作成を取り消した場合も設定が必須のままになります。 キーリングダイアログを開く前にパスワードフォームのスタイルを読み込み、バランスの取れた全幅フィールドと検証条件のアニメーションを復元しました。削除済みアカウントの保管庫消去は他の依存データ消去後に実行され、LDAP ユーザーを繰り返し削除する場合も検証されます。 キーリング作成時に自動ロック時間を選択できるようになりました。手動解除に失敗しても、設定ページを再読み込みせず再試行できます。手動で破棄した後は「キーリングが見つかりません」バナーを表示し、作成だけを操作できます。パスワードログイン時の解除失敗は通知せず、設定したセッション時間を維持します。 Settings はキーリング状態を表示する前に、有効なブラウザーセッションの解除状態を復元します。破壊的な消去確認には常にキャンセル操作のスタイルを使用します。手動解除に失敗しても再試行できます。

## 削除ユーザーのキーリングを初期化

ユーザー削除後はサーバーの空のキーリング状態を優先します。同じユーザー名を再利用した場合、ブラウザーに残った古い暗号化コピーではなく初回設定が表示されます。 アカウント削除によって有効なセッションが無効になった場合、ブラウザー内のキーリング状態も消去されます。アクセス拒否時はサーバーのセッション判定を経由するため、削除されたユーザーには一般的なセッション期限切れ通知ではなく「アカウントが削除されました」と表示されます。
