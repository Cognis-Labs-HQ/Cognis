# TFAゲートウェイとTOTP

**Feature Branch:** copilot/create-tfa-gateway-totp-adapter

## 新しいTFAゲートウェイ

`src/adapters/tfa/*` 配下のアダプター検出、ユーザー方式API、復旧コードAPI、管理者リセットAPIを備えた専用 `tfa` ゲートウェイを追加しました。

## TOTPアダプターを追加

`src/adapters/tfa/totp` に、セットアップ検証とログインコード検証を行う `totp` アダプターを追加しました。

## ログインとセキュリティ統合

二要素プロンプト、設定強制リダイレクト、Administration の TFA 強制トグル、ユーザー単位の TFA リセット操作に対応するようログイン/セキュリティ動作を更新しました。

## TOTPアルゴリズムドロップダウン

TOTP アダプターの管理設定ポップアップに、編集不可のメタデータの代わりに HMAC アルゴリズムドロップダウン（SHA1・SHA256・SHA512）が表示されるようになりました。選択したアルゴリズムは QR コード生成とコード検証に使用されます。

## TFA 方式テーブルレイアウト

「利用可能な方式」と「優先方式」のパネルが言語設定と同じテーブルベースのドラッグ＆ドロップレイアウトになりました。空のプレースホルダーの幅の問題とドロップゾーンの描画問題が修正されています。

## TFA 方式変更の遅延適用

方式を「利用可能」と「優先」の間でドラッグしても、変更はローカルに保留されます。セットアップポップアップと API 呼び出しは設定を保存するまで行われません。

## 復旧コードのツールチップ

「復旧コード」見出しの横にツールチップアイコンが追加されました。設定した方式が利用できない場合に復旧コードでアカウントにアクセスできることが説明されています。

## 方式無効化の警告トースト

TFA 方式を「優先」から「利用可能」に移動すると、方式名を含む警告トーストが表示されるようになりました。チェックマーク（✓）は「優先」テーブルの方式にのみ表示されます。

## 強制セットアップダイアログの余白修正

必須 TFA セットアップポップアップの説明文と方式ドロップダウンの間の余白が修正されました。

## レビュー反映の追加調整

TOTP の既定アルゴリズムを SHA256 に変更し、ユーザー向け TOTP アダプター名を短縮し、TFA/TOTP ドキュメントを拡充しました。さらに、QR SVG の object URL 生成を `src/ui/reuse/qr-image-source.js` へ移動し、Security 設定スクリプト登録先を `/static/gateways/auth/security-prefs/index.js` に更新しました。

## 強制適用と責務配置の修正

TFA アダプターの無効状態が再起動後も維持されるようになり、復旧コード消費は原子的に行われ、TFA 設定必須アカウントには非 TFA 保護 API を呼べない設定待ちトークンだけが発行されます。あわせて、TFA 関連のブラウザー文字列・ヘルパー・スタイルを TFA ゲートウェイと TOTP アダプターの静的アセットへ移動しました。

## TFA 設定をセキュリティセクションに統合

二要素認証の設定がユーザー設定 → セキュリティに表示されるようになりました。`auth:registerSecuritySection` ケーパビリティ経由で TFA ゲートウェイが提供するため、独立したナビゲーション項目ではなくなりました。

## 管理ページの修正

ナビゲーション時に管理ページが失敗する原因となっていた `extendI18n` のインポート漏れを修正しました。

## Users の TFA リセット文言を修正

Users ページのアクションメニューとリセット成功トーストが正しくローカライズ表示されるよう、`ui.app.users.reset_tfa` と `ui.app.users.tfa_reset_done` の不足キーをコア UI 言語ファイルに追加しました。

## ログイン回帰を修正

ログイン直後の必須メール検証フローを復元し、実装を Notify ゲートウェイ所有のログインヘルパーへ移動しました。これにより Login ページはメール系ルートを直接配線せず、必須検証の挙動を維持します。

## TFA セットアップ遷移とセキュリティアクセス

TFA 設定待ちトークンのユーザーは `/settings#security` へ直接遷移します。設定ページの完全なクローム（ナビゲーションバー、トップバー、フッター）は強制セットアップ中も表示されるため、ユーザーは正しくレンダリングされたページで第 2 要素を設定できます。Auth セキュリティサブセクション一覧と TFA に関するすべての API パスは設定待ちトークンでも許可されます。また、サブコンポーザーの ResizeObserver が初期カラム数で初期化されるようになり、最初の観測時のレイアウト計測が冗長な再レンダリングを引き起こしてセットアップポップアップを再表示するという問題が解消されました。

## 管理TFAをセキュリティへ移動

Administration の TFA 設定は、独立した最上位セクションではなく、再び Administration → Security の中で表示されるようになりました。

## 管理TFA文言を修正

Administration → Security 内の TFA カードは、既存のローカライズ済み gateway/admin 文字列キーを使うようになり、セクション見出し、強制ラベル、説明文が再び正しく表示されます。
