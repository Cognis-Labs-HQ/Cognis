# メッセージ本文の選択を維持

**機能ブランチ:** feature-message-selection-recovered

## ライブ更新中の選択を維持

メッセージ、リアクション、閲覧者のメタデータが変化しても、変更のない本文の DOM ノードを保持します。順方向、逆方向、隣り合うメッセージ間の選択は同じ本文に残ります。選択した本文の変更や削除には標準の選択規則が適用されます。

## 読み込み済みの履歴とリアクション状態を維持

ライブ更新と過去のメッセージの読み込みを統合し、読み込み済みの行を保持します。送信待ちメッセージをサーバーのページ分割に含めません。確認済みの古いリアクションを直ちに反映し、既存の対象ページを更新します。読み取り失敗時に変更操作を再試行しません。

ライブ更新や履歴の応答が遅れて届いても、消去済みまたは確認済みの項目を含め、新しい送信待ち投影を保持します。変更のないポーリングでもスナップショットの所有順序を更新し、破棄した投影のキャッシュ署名を無効にします。リアクションの更新が失敗した場合も、新しいメッセージと古いメッセージの確認済み状態と本文の選択を保持します。

古い最新ページの応答で、新しく表示した確認済みメッセージ、メタデータ、リクエスト状態を置き換えません。明示的な履歴リクエストは引き続き統合します。古い読み取りエラーでも、新しい表示内容を保持します。

重複する履歴読み取りと確認済みリアクションに、表示が管理する同じ順序を適用します。古い結果でも、新しい行のメタデータと確認済みの削除を維持します。置き換え済みの後続読み取りエラーは表示せず、現在の読み取りと変更操作の失敗は表示します。範囲情報は進行中の読み取りに対する優先順位で統合し、終了後に解放します。タイムスタンプの境界は保守的に扱います。

キャッシュ応答や進行中の通信を共有する応答を、新しいサーバー観測とは扱いません。既知の行を維持し、ライブ結果が確定した履歴の終端を復活させずに未読の古い部分を補います。ページ分割では、確認の順序とライブ読み取りの根拠を区別します。ソース付き署名により、後の新しい読み取りで同じ生データも照合できます。回帰テストでは、オフライン復元、確認前から共有された通信、両方の完了順序、変更のない読み取りの単調な順序、停止中の読み取りに対する保持量を検証します。

すべてのレンダラー呼び出し元で、無効になった表示結果と現在の読み取り失敗を区別します。同じルームでスタイル、鍵、コンテナーを置き換えた後に古い処理が成功または失敗しても、古い操作エラーや既読・入力状況の後続処理を開始しません。

## 実 DOM の動作を検証

Messages 2.7.43 では、公開されたレンダラーとオフラインクライアント契約を通じて、バージョン固定のテスト専用 jsdom による検証を追加します。各言語の履歴ガイドで選択と過去のメッセージの読み込みを説明します。寸法を使う検証の対象はスクロール方針であり、ブラウザーのピクセルやクリップボードではありません。
