# Composer のグリッド寸法

**機能ブランチ:** feature-composer-grid-dimensions

## 一貫した全幅表示

全幅の配列指定が、メインと入れ子の Composer で利用可能なすべての列を使用するようになりました。ログインと登録フォームにも適用されます。数値による高さの上限と高さを埋める動作は、それぞれ独立して機能します。

## グリッドの外へドラッグ

ウィジェットを現在のグリッドの下へドラッグすると、コンテンツ、グリッドの表示領域、ドロップ先の影が一緒に拡張されます。拡張された領域はドロップするまで維持されます。

## 正確なプレビューと操作しやすいパネル

ドラッグプレビューとサイズ変更ハンドルが、半グリッド配置を含めて、表示されたカードと同じ間隔を考慮した寸法を使用するようになりました。編集用の計測はコンテンツの余白とスクロールバー幅を反映します。要素パネルは利用可能な幅を使い、デスクトップ、タブレット、スマートフォンで操作ラベルを読みやすく表示します。 パネルの配置には、高さの上限を適用した後の幅を使用し、内部スクロールバーも含めます。 黄色のプレビューは、離す前に上方向の有効な吸着先を示します。離すと編集画面を開いたまま直ちに反映し、他の占有カードを飛び越えません。

## 安定したタッチ編集

ウィジェットがポインターの中央へ飛ばず、つかんだ位置を保持するようになりました。メインと入れ子の編集機能は、画面端でのスクロール、ポインターのキャンセル、タッチ用のサイズ変更領域に対応します。要素パネルは内容に合った幅を使い、見出しだけに最小化できます。画面サイズが変わっても、保存が成功するまで編集状態を維持します。

## 正確なサイズ変更操作

要素の削除に共通のキャンセルボタンの外観を使用するようになりました。サイズ変更ハンドルは、サイズ制限、グリッド境界、隣接する要素を確認します。拡大ができなくても縮小できるハンドルは残し、方向カーソルで可能な操作を示します。他の要素に重なる拡大操作には操作不可のカーソルを表示します。 最小値、最大値、グリッド原点の制限を超えようとするとプレビューがオレンジ色になります。水平、垂直、角の操作で制限超過を個別に報告し、候補の寸法は制限内に保ちます。

## 全方向のサイズ変更と保存通知

メインと入れ子の編集画面で、すべての辺と角から8方向のサイズ変更が可能になりました。左辺と上辺からの変更では反対側の辺を固定し、サイズと重なりの制限を適用してタッチのプレビューをつかんだ位置に合わせます。「完了」、レイアウトのショートカット、リセット操作は、共通の保存フローで翻訳済みの成功または失敗の通知を表示します。失敗時は変更内容を保持して再試行でき、同時保存は1つのリクエストを共有し、ページ終了後の通知を抑止します。 保存失敗は短い翻訳済みの通知で伝えます。

## 編集ヘルパーの契約

再利用可能な編集モジュールに、公開エクスポート、呼び出し例、入出力契約、解放処理の責任を記載しました。技術リファレンスでは、保存結果、編集状態、実際の列数別の保存形式を対応する4言語で説明します。

## 読みやすいワークスペースの既定サイズ

ダッシュボードのブランドにアイコンと名前全体の領域を確保し、挨拶とログインのカードは読みやすい幅、アカウント情報はコンパクトな既定の高さを使います。保存済みの行を再配置するときは、プロファイルを上書きせず、現在の最小幅と最大幅に従って表示します。 正規化した配置を描画前に検証し、右端に保存されたカードが広がる場合は指定されたグリッド内へ再配置します。 保存した幅、高さ、間隔を、列プロファイルに応じてメインと入れ子のグリッドで維持します。「完了」は最後に詰め直したり幅を再配分したりせず、表示中の寸法と位置を保存します。スクロールバーの領域を安定させ、編集と表示で列の選択を一致させます。

## 衝突を防ぐウィジェット交換

メインと入れ子の編集画面は交換時に両方のウィジェットのサイズを維持します。左右の交換ではペアの外縁と間隔を保ち、隣接する同じ高さで幅が異なる要素をどちらの方向にも交換できます。高さが異なる場合も、両方の移動先の完全な矩形が上下の隣接要素を含む他の表示要素と重ならなければ交換できます。矩形の交差判定は占有するグリッド面積ではなく配置数に応じた処理量になります。両方の移動先について互いの重なりとグリッド境界を確認し、離した時点でも現在の配置を再検証してから位置を変更します。共通のテーマに沿った移動先ラインは、有効な交換では緑、妨げられた交換では赤になります。マウス、タッチ、キーボードは同じモデルを使います。入れ子の端でのスクロールは仮のグリッド高さを保持し、拡張で親のスクロール量が変わった後にプレビューを再計測します。

## 説明的な実行時バインディング

構文木による名前検証は、書式に依存せず、宣言、エクスポート、分割代入、実行時と型シグネチャの引数、コンストラクターのパラメータープロパティ、catch のバインディング、インポート、名前付き関数とクラス、実行時の enum と名前空間、非公開メンバーを検証します。既存違反の除外やファイル別の例外を設けず、ソース、ツール、テスト、フィクスチャを走査します。不明瞭な省略名、省略語の複数形、番号付きの仮名、無視するバインディングの値の使用は検証に失敗します。`args`、`db`、LDAP の `dn`、HTTP の `req`/`res`、`env`、`opts`、`params` などの一般的な開発用語は有効で、用語集が完全な一覧を定義します。他の短い例外は未使用かつ非公開の `_`、`id`、対応する算術更新を持つ数値カウンター `i`・`j`・`k` です。座標と寸法には説明的なローカル名を使います。所有するヘルパーとストアの API は宣言、エクスポート、インポート、呼び出し元で説明的な名前を直接使用し、名前を変えるだけのインポート・エクスポート別名は検証に失敗します。利用側は省略別名ではなく正規のエクスポート名を使う必要があります。公開ペイロードのキー、機能の識別子、型専用の識別名は契約上の役割を維持します。各言語の技術文書、貢献指針、コンポーネントのバージョン、依存関係の上限、ロックファイル、バージョン索引を同期します。
