# 安定した共有カレンダー

## 招待と回答が一貫して動作

書き込み可能な共有カレンダーから作成した予定に共有対象者全員が含まれ、通知が各受信者のカレンダーへ移動し、読み取り専用の受信者も共有画面から回答できるようになりました。

## 再共有でもアクセス設定を維持

既存の受信者にカレンダーを再共有しても、書き込み権限や有効期限がリセットされなくなりました。

## ソースファイルが構成上の制限に準拠

動作を変更せずに、カレンダー、会議、ホワイトボードのソースファイルを規定のサイズ制限内に整理しました。

## 共有ポップアップを正常に読み込み

リンク共有ポップアップは、存在しないアダプター内のファイルではなく、共有ゲートウェイに登録された静的アセットのパスから API コールバックを読み込むようになりました。

## ログイン時にキーリングの解除を無効化

アカウントへのログイン完了時に、ブラウザーセッションの解除キーを破棄するようになりました。別のパスワードを使うキーリングは、そのパスワードを端末上で入力するまでロックされたままです。通常のページ再読み込みでは、明示的に解除したセッションを引き続き保持できます。

## 鍵の復旧前にチャットでキーリングを解除

会話を開く際、紛失したルーム鍵を要求する前にローカルキーリングを確認して解除するようになりました。ルームのメタデータから鍵を配布せず、解除済みキーリングで鍵がないことを確認した後に限り、明示的かつ認証済みの入室要求で鍵を復旧します。

## 破棄ですべてのローカル鍵を削除

キーリングを破棄する際、保留中の保存を完了してからローカルのエンベロープとセッション鍵を削除し、代替保管庫を作成する前にコンポーネントの鍵キャッシュを無効化するようになりました。破壊的な確認にはキャンセルの表示を、安全な取り消し操作には確認の表示を使用します。

## シークレットの一度限りの配布と同期されたチャットプレビュー

キーリングの作成と破棄で、成功通知と警告通知を個別に表示するようになりました。ルームキーがキーリングに入るとチャットプレビューが直ちに更新され、サーバーはメンバーごとのルームキー配布を記録します。これにより、認証済みメンバーが生成済みルームキーを受け取れるのは一度だけとなり、失われたキーは手動または新しい参加者招待を通じて再追加する必要があります。ミーティングパスワードは保存時に暗号化され、招待された各参加者が初めて参加するときにのみ配布されます。

## 意図された空白とドキュメントを復元

回帰修正を動作変更に集中させるため、キーリング、カレンダー、ホワイトボード各コンポーネントの既存の空白と、ミーティングページのマウント契約に関するドキュメントを復元しました。

## ルームキーと会議パスワードは安全に保存されるまで復旧可能

移行された会話にルームキーがない場合は新しく生成し、配信済みのルームキーと会議パスワードは、クライアントがキーリングへの保存成功を確認するまで再試行できます。
