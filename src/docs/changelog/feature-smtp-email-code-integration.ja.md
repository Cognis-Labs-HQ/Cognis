# メールコード長の共通設定

**機能ブランチ:** feature-smtp-email-code-integration

## メールコードを一つのSMTP設定で管理

通知SMTPのコード長設定を、メール確認とメールコードTFAの設定・ログインで共有します。翻訳済みの情報ツールチップで、共有ポリシー、既定の6桁、4～10桁の範囲を説明します。利用側はコード発行時に現在のSMTPポリシーを読み取り、別のコード長設定を保存しません。空の数値設定フィールドは既存の値を維持します。

## 発行済みチャレンジの長さを保持

SMTP設定の変更は、再送による置き換えを含む、新しく発行するコードに適用されます。保留中の設定・ログイン用コードは、使用・置き換え・有効期限切れまで発行時の長さを保持します。設定とログインの入力は有効なチャレンジの長さのメタデータを使います。必須メール確認では、別の固定入力上限を設けず、保留中のコード全体を受け付けます。

ページの再読み込み後に保留中のログインを再開しても、コードを再送せずに発行時の入力長を保持します。その後の提供元ポリシーの変更は新しく発行するチャレンジに適用され、古い応答が新しいログイン入力を置き換えることはありません。

## 送信元が利用できない場合は明示的に失敗

メール確認とメールコードTFAのコード発行には、利用可能で設定済みのSMTPポリシー提供元が必要です。提供元が存在しない場合や無効な場合に、利用側の既定値で暗黙に代用することはありません。SMTP方式やゲートウェイの無効化で保留中のチャレンジを削除し、再有効化では新しい状態から開始します。

## 拡張機能の契約と安全な設定

独立した機能 `notify:emailCodeLength` は削除されます。拡張機能は `notify:emailDeliveryPolicy().codeLength` を参照し、通知ゲートウェイと両メールアダプターを一緒に展開する必要があります。提供元の設定は実行時に適用する前に正規化・保存します。適用に失敗すると提供元を無効化し、以前の保存済み設定を無効状態で復元して管理者による復旧を必要とします。通常のSMTP認証とメール確認への同意は変更しません。

設定の保存と更新、有効状態の変更、保存済み設定の再読み込みは、保存失敗時の復元を含めて送信者ごとに順番に実行します。異なる送信者は独立して処理します。設定処理中の登録済み送信者を置き換える操作は明示的に失敗し、処理完了後に置き換え可能になります。設定リスナーはトランザクション解放後に実行するため、後続の更新を待機できます。`notify:onSenderConfigChange` のデータからは、提供元のスキーマで `password` と宣言したフィールドと `getConfiguredSecretFields()` が列挙したフィールドを、新しく送信された値も含めて除外します。公開可能な正規化済みフィールドと有効状態は引き続き含まれますが、リスナーは未加工の認証情報に依存できません。
