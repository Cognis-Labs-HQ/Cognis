# 信頼できるモジュール文字列

## 欠落文字列のポーリングを停止

モジュールカタログは、必須の英語文字列アセットがサーバーキャッシュに存在することを確認した場合にのみ、ローカライズリソースを通知するようになりました。定期的なマーケットプレイスのポーリングで、404 しか返せない文字列 URL への要求が繰り返されることはありません。

マーケットプレイス UI もこの抑制を維持し、ローカライズアセットを利用できないカタログ項目に対して従来形式の静的 URL を再構築しないようになりました。

## 起動時にモジュールソースを更新

Cognis は API の起動時に、モジュールソースを一度だけ強制スキャンするようになりました。マーケットプレイスのポーリング開始前にキャッシュ済みのローカライズアセットが更新されるため、有効な文字列ファイルを持つモジュールでは再起動後に翻訳済みの名前と概要が表示されます。

## モジュール更新時の表示を安定化

定期的なマーケットプレイス確認では、キャッシュとソースの両方のデータが揃うまで現在のモジュールカードを表示し続けるようになり、途中で文字列が点滅しなくなりました。有効なモジュールのアセットは UI 提供情報の更新中も直接取得できるため、有効化直後のナビゲーション依存関係に関する一時的なエラーも防止されます。

## すべてのモジュール翻訳を取得

公開 GitHub モジュールの文字列は、Nextcloud Whiteboard が言語ファイルを Cognis に渡す方式に合わせて、リポジトリの raw コンテンツエンドポイントから取得するようになりました。並列検出中の API リクエスト上限を回避できるため、Jitsi Meet、Nextcloud Whiteboard、Study 言語モジュールのメタデータが、上限到達前に完了した言語リクエストに左右されず一貫して解決されます。

## 不完全なモジュールキャッシュを診断

モジュールがローカライズを宣言しているにもかかわらず英語リソースがキャッシュにない場合、API はモジュール、言語、アセット識別子を含む構造化警告を記録します。ソースを再スキャンするとキャッシュを補充できます。モジュール作成者は引き続き `ui/languages/en/strings.xml` と、対応する他言語の翻訳を提供する必要があります。

## 検証前にモジュールを設定

モジュールが無効時にも利用可能と明示したルートを、制限された設定用ブートストラップで登録するようになりました。その他のルート、UI 提供、機能、フローフックは無効なままです。これにより管理者は、有効化検証で設定を確認する前に Jitsi Meet などのモジュールを設定できます。

## 無効なモジュールを読み込まないように変更

無効な外部モジュールは、ルート更新時にインポートもブートストラップもされなくなりました。これにより、トップレベルおよびライフサイクルのコードが実行されません。

## 非公開ソースのスキャンは認証情報を待機

起動時の検出では公開モジュールソースのみをスキャンするようになりました。認証情報が必要な非公開ソースは、認証済みの Marketplace ポーリングで利用でき、認証情報のない試行によって次の更新が遅延することもありません。
