# プロフィール下書きの保護

**機能ブランチ:** feature-profile-draft-recovery

## 保存失敗時に下書きを保持

プロフィール編集は、サーバーが保存を確認するか、アカウントに紐づくオフラインバッファーが永続的に受け付けるまで、入力内容をそのまま保持して開いたままになります。要求の拒否、応答の読み取り失敗、バッファーへの書き込み失敗ではエラーを表示し、下書きを破棄せずに保存を再び有効にします。保存の連続クリックや Enter でも処理中の要求は一件だけです。処理中は入力欄を一時的に無効にします。カード、ナビゲーション、ローカル表示名の更新に失敗しても、受け付け済みの保存を失敗とは扱いません。

## 編集画面の有効期間を尊重

破棄、閉じる、Escape、背景のクリックでは、共通の未保存変更確認を使用します。確認画面でキャンセルするとフォームを保持します。破棄を確認すると閉じ、遅れて返る結果を無視します。送信済みの要求は閉じても取り消せないことを通知で伝えます。保存結果は、開いている破棄確認の決定を待ってから画面に反映します。ページ移動、再マウント、アカウントやセッションの切り替え、ダイアログの破棄により、以前の編集結果は画面に反映されなくなります。再度開くと最後に受け付けられたプロフィールを使い、以前のダイアログの終了アニメーション中でも入力欄とラベルの識別子は重複しません。未送信の下書きはページ移動や再読み込みを越えて保存されません。

プロフィール所有のエディターは既存の `social:profile:request` ctx フローを使用し、フィールド検証、共通ポップアップのフォーカス管理、オフライン配信ポリシーを維持します。合成 DOM テストでは実際のページマウント、ポップアップ、フォームビルダー、登録済み要求フローを、制御された通信とストレージで実行します。実ブラウザーのレイアウトやサーバー・データベースの動作を確認するものではありません。

UI公開チェックは、投稿フォームに実際に接続されたビルダーを、所有コンポーネント内のファクトリー関数の戻り値まで追跡します。静的な正常例と異常例で、欠落・未使用・隠蔽・再代入されたファクトリー、共有ビルダーを迂回する戻り値、対応する接続のない送信ハンドラーを拒否します。直接生成するフォームのチェックと走査範囲は変更しません。
