# コンポーネントの復旧

**機能ブランチ:** feature-component-recovery

## 障害の隔離

ブラウザーのカタログは、ホストの登録情報から提供元と導入バージョンを特定します。任意のコンポーネントが失敗した場合は、その部分的な機能、フロー、リスナーを取り消し、正常な提供元の読み込みを続けます。明示的な更新やリビジョン変更で再試行できます。必須ホストコンポーネントの既存の保護は維持します。外部モジュールは常に任意です。モジュールのマニフェストで Cognis 全体を利用不能にしたり、ホストの必須依存先にしたりすることはできません。

予期しないサーバー例外は登録済みの所有元に帰属させます。想定された入力エラーや不正な JSON は集計しません。管理者が五分以内に観測した異なる三回の障害で、通常の認証付き無効化操作を実行します。報告は重複を除き、メモリ量を制限し、導入バージョン別に集計します。一般利用者の報告では全体的な無効化を行えません。サーバー再起動や集計期間の終了で回数をリセットします。再度有効にする前に修復または更新してください。

## 管理操作

`component:info`、`component:release-channel get|set|list`、`component:upgrade`、有効化、無効化は、単一対象と `--all` を扱い、種類やアダプターのゲートウェイで絞り込めます。名前付き `component:*` フローは API 所有のバージョン一の `component:management` 契約と既存の認証付き管理経路を使います。ホストの既存の必須・固定状態と依存関係の検証を維持します。直列化した変更はロック取得後に状態を読み直します。アダプター一覧の障害は所有ゲートウェイと該当する一括結果の取得失敗として表示し、正常な対象の管理や、その任意のゲートウェイの無効化を妨げません。認可エラーでは操作を中断します。

## 公開先と更新

マーケットプレイスのブランチとリリースから公開先を選び、`config/component-channels.json` に原子的に保存します。更新では既存の認可、整合性、インストーラー、依存関係の検証を維持します。有効だったモジュールは一時的に無効化します。インストール失敗時の検証付き復旧には、呼び出し元が指定した免責確認を引き継ぎます。タイムアウトして状態が不確かな場合は無効のままにします。成功時は再起動の要否を表示します。同梱ゲートウェイ、アダプター、コアモジュールはホストとともに更新し、独立した公開先を持たず、一括更新ではスキップします。設定変更やリポジトリの取り込みは個別対象に限ります。

## 実行時の識別子

アダプターの探索では依存関係用の正式なマニフェスト ID を保持し、提供元の帰属用には別の実行時 ID を記録します。Social の profile、messages、call は、マニフェスト ID に `social-` が付いていても、導入バージョンと任意の状態を正しく引き継ぎます。

## CLI の出力と進行状況

すべての CLI コマンドは標準では簡潔な結果を表示します。一覧は最大二十件とし、大きな項目や入れ子のデータは要約します。管理操作の結果は、対象ごとの成功、スキップ、失敗、導入バージョン、再起動の要否を示します。空の結果も明示します。完全な応答が必要な場合は、コマンド名の前または後に `-v` または `--verbose` を付けます。登録済みのゲートウェイ、アダプター、モジュールのコマンドにも適用されます。グローバルオプションと同じ文字列を通常の引数として渡す場合は、その前に `--` を置きます。

`-v` は詳細出力を意味するようになります。CLI のバージョン表示には `--version` を使います。スクリプトは構造化された応答を stdout から読み取ります。進行状況は stderr に出力し、実行開始時と長い処理の経過時間を知らせます。モジュール更新では選択、一時的な無効化、インストール、待機、復旧、結果の実際の状態も逐次送信します。ダウンロード率を推測して表示しません。JSON 応答のみの古いサーバーでも経過時間の表示は使えます。通信が途中で切れた場合はエラーで終了し、再試行前にコンポーネントの状態を確認するよう案内します。一括操作で失敗した場合は、どちらの出力モードでも終了コードはゼロ以外になります。

```sh
cognisctl component:upgrade module study-language-en
cognisctl component:upgrade module --all -v
cognisctl -v component:info module study-language-en
cognisctl --version
```

## 状態が変わらない操作

状態メッセージは文として自然な大文字表記に統一し、コンポーネントの識別子は変更しません。有効化と無効化は、対象が既に指定状態なら処理を省略します。更新では無効化やインストールの前に、導入済みコミットと選択したカタログのブランチまたはリリースのコミットを比較します。バージョン番号が同じでもコードが同一とは限りません。公開先を明示しない場合は導入済みの公開先を維持します。新しいソースのリビジョンを検出するにはマーケットプレイスのカタログを更新してください。リビジョン情報がない場合は無条件に再インストールせず、明示的な `--force` を要求します。有効化、無効化、更新の `--force` は `--all` とも併用でき、認可、整合性、依存関係、必須ホストの保護を維持したまま操作を再実行します。

```sh
cognisctl component:upgrade module analytics --force
cognisctl component:disable module analytics --force
```

## チュートリアルの表示と説明

親ブランチの更新を含み、55ガイド・167ステップ、うち管理者向け22ガイドを提供します。説明ステップではホバーや操作を防ぎ、ダッシュボードでは実際の検索を使います。ステップグループは次へ進んだ時や早く終了した時に一時的な画面を解放します。表示領域、ブロードキャスト、移動制御、ページ準備の方針も維持します。
