# 共有の受信者がログイン状態を維持

## 保護された共有を未検出扱いにせずパスワードを要求

共有ゲートウェイは、有効なパスワード保護トークンと無効なトークンを区別するようになりました。共有ページは認証要求を受け取り、暗号化キーリングを確認し、必要な場合だけ入力を求め、確認済みパスワードを保存してから共有オブジェクトを読み込みます。

## 通知からのアクセスでログイン状態を置き換えない

ログイン済みの受信者は、共有通知を開いてもアカウントトークンを維持します。共有 API 操作用の別の限定トークンがコンポーネントのレンダラーへ直接渡されるため、ユーザーをログアウトさせずにカレンダーの書き込み権限を制御できます。
