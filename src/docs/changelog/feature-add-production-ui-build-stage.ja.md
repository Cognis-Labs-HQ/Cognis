# 本番 UI ビルド

**機能ブランチ:** feature-add-production-ui-build-stage

## ハッシュ付き本番アセット

本番イメージは生成されたマニフェストを通じて、縮小済みでコンテンツハッシュ付きの JavaScript と CSS バンドルを配信し、開発環境では引き続きソースモジュールを配信します。

## 事前圧縮配信

テキストアセットを Brotli と gzip の形式で生成し、中立的な UI ルートが不変キャッシュと正しい MIME メタデータを付けてネゴシエーションします。

## コンパイル済みサーバー

Docker ビルドで TypeScript をコンパイルし、開発用の `tsx` ローダーを使わずに JavaScript を直接起動します。

## コンパイル済みコンポーネントの起動

本番用のゲートウェイおよびアダプターローダーは、すべての TypeScript ソースエントリポイントをコンパイル済み JavaScript 出力へ解決し、Study アダプターへ起動時にプラットフォームのフロー API を渡します。

## 確定的なブラウザフロー

組み込みブラウザフロー契約は、バンドルされたゲートウェイフックが拡張する前に、共有 UI コンテキストと同時に初期化されます。

## 本番起動でコンパイル済みアセットを使用

本番起動コマンドは、コンパイル済みサーバーを開始する前に、生成された UI マニフェストとコンパイル済みのゲートウェイ、アダプター、モジュールのルートを設定するようになりました。

## コンテンツエンコーディングで品質設定を尊重

静的アセットのネゴシエーションは、品質値がゼロのため拒否されたエンコーディングを除外し、利用可能な Brotli または gzip 表現から許可品質が最も高いものを選択するようになりました。

## コンポーネント登録を検証

本番ビルドですべてのコンパイル済みアダプターエントリポイントを検証するようになりました。データベースとローカルファイルのマニフェストは実際のエントリモジュールを参照し、ファイルゲートウェイは設定されたコンパイル済みルートからアダプターを解決し、メッセージアダプターは正しいストアモジュールからルームキー提供処理を読み込みます。
