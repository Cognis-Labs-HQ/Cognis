# ファイル名前空間とクォータ

**Feature Branch:** copilot/expand-file-gateway-support-namespace

## ファイルゲートウェイがすべてのコンテンツを名前空間に整理し、ACLとクォータを実施

すべてのファイル操作は、特定のコンポーネント（`profile`、`chats`、`classes`）またはコア（`default`、`user`）が所有する独立したコンテンツ領域である名前空間にスコープされるようになりました。名前空間は、その中に保存されるオブジェクトが公開できる範囲を制限するACL上限（`private-owner`、`private-group`、`component-managed`）を宣言し、オブジェクトごとの許可（所有者、コラボレーターグループ、または公開読み取り）はこの上限を超えることはできません。名前空間へのコンポーネント横断アクセスは、名前空間が呼び出し元のコンポーネントを明示的に許可リストに登録しない限り拒否されます（コアは常に許可されます）。

## 名前空間ごとおよびグローバルなストレージクォータ

新しいファイルクォータアダプターが、名前空間ごとに管理者が設定可能なデフォルトストレージクォータと単一のグローバルデフォルトを追跡し、アカウント作成時にそれらをユーザーごとのオーバーライドにスナップショットするため、ユーザーのクォータは登録時に適用されていたものを反映します。管理者は、ユーザーページの新しい「ストレージクォータ」アクションから、個々のユーザーのクォータを後で調整できます。いずれかのクォータを超える書き込みは、`413 quota_exceeded` エラーで拒否されます。

## プロフィールのアバターとバナーが新しい「profile」名前空間に移行

social/profile アダプターのアバターおよびバナーのアップロードは、古い汎用的で名前空間のないファイルバケットルートに代わり、広く読み取り可能な `profile` 名前空間に対するファイルゲートウェイの名前空間ベースの `files:store`/`files:delete` 機能を経由するようになりました。`social/messages` および `study/classes` アダプターは、それぞれ将来の添付ファイル機能に備えて基本的な `chats` および `classes` 名前空間を登録します。

## クォータ管理ルートがファイルオブジェクトルートと衝突しなくなりました

Files ゲートウェイは、名前空間オブジェクトの catch-all より前にクォータ管理ハンドラーを登録するようになりました。これにより `/api/v1/files/admin/...` へのリクエストは、`admin` 名前空間内のファイルとして解釈されず、確実に管理者クォータ API に到達します。

## 新規ユーザーは新規インストールでも名前空間クォータのスナップショットを受け取ります

アカウントプロビジョニングは、ユーザーのクォータをスナップショットする前に、登録済みの各名前空間のデフォルトクォータ行を作成するようになりました。これにより、管理者がクォータデフォルト画面を開く前でも名前空間クォータの強制が維持されます。

## 制限付き共有リンクは受信者を強制します

共有トークンの解決は、ゲストアクセスを発行したりペイロードを返したりする前に、トークンの受信者を確認するようになりました。受信者制限付きトークンでは、要求者がトークン所有者または指定されたユーザー受信者である必要があり、任意のリンク所有者が受信者リストを迂回できません。

## バージョンドキュメントはローカライズされたままです

コンポーネントのバージョンドキュメントは、サポートされるすべての言語で一貫して翻訳されたルール本文を持つようになりました。
