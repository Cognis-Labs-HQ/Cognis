# 共有ポップアップを復元

## 一貫した共有ポップアップ

ホワイトボードはリソース識別子と機能を指定して共有ゲートウェイの共通ポップアップを開き、他のコンポーネントと同じゲートウェイ統合を使用するようになりました。共有方法とトークン要求は引き続きゲートウェイが担当します。

## プレゼンスアバターの配置を維持

ページプレゼンスのプロフィール画像は共有プレゼンススタイルシートから表示スタイルを受け取るようになり、未装飾の画像レイヤーとしてホワイトボードキャンバス上に表示されず、ツールバーのアバターとして維持されます。

## 共有ゲストの認証を維持

ホワイトボードの共有リンクを開いた際、限定されたゲストセッションが維持されるようになりました。Cognis は一時的なゲスト識別子を通常のユーザーアカウントとして検証せず、トークンを削除したり、アカウントが削除されたと表示したりしなくなりました。

## ゲストセッションに対応したダッシュボードデータ

共有ページは、プロフィールおよびダッシュボードのリクエストを選択する際に Share ゲートウェイのゲストセッション機能を使用するようになりました。これにより、ホワイトボードを開いている間に不要なアカウント専用リクエストが失敗しなくなります。

## 保護された共有でゲスト鍵束を維持

共有ページは、組み込まれたコンポーネントの初期化時に新しいゲスト識別子を解決せず、ライフサイクル全体で一度解決したゲストセッションを再利用するようになりました。ゲスト鍵束はセッション内だけに保持され、保護された会議の認証情報を維持し、アカウント鍵束やリリース変更履歴の API を呼び出さなくなりました。 SPA ナビゲーション時には、移動先ページのコンポーザーマニフェストでポインター追跡が有効な場合を除き、ポインタースタイルの操作ボタンも削除されます。 ユーザー共有の通知は Share ゲートウェイの正規ページを開くようになり、ゲスト識別子ではアカウント検証や Social 在席状況のリクエストを実行しなくなりました。 サインイン済みのユーザー向け共有の受信者は、ゲスト識別子へ切り替えられず、アカウントセッションを維持したまま Share ゲートウェイ経由でリソースへアクセスできるようになりました。 新しいユーザー共有では、公開ゲスト URL を配布せず、共有レコード識別子を含むリソース固有の内部リンクを送信するようになりました。 コンテンツ提供元は Share を開く際に通常の内部コンテンツ URL だけを渡し、Share ゲートウェイがその URL を検証・保存・配信しながら受信者アクセスの唯一の権限元となります。 公開 Share URL は Share ゲートウェイで解決され、許可された閲覧者を保存済みの内部ルートへ転送します。利用できないルートでは Share のエラーページに留まります。Share トークンはデータベース外部キーでゲートウェイ所有のリソース行を参照します。 アクティブな共有は、リソース要求でアクセスの取り消しが報告されると、直ちに Share のアクセス拒否画面へ移動するようになりました。共有元は読み取り専用対応を明示し、会議は書き込みアクセスのみ、ホワイトボードとカレンダーは読み取りと書き込みを提供します。読み取り専用ホワイトボードは保護された書き込みを試行せずに読み込まれます。 共有ゲストは、ルーターがホワイトボードを開く間も解決済みのゲスト ID と内部共有コンテキストを保持するため、プロフィールハンドルは不要です。読み取り専用ゲストも読み取り権限でポインターのプレゼンスを送受信でき、ホワイトボードを離れるとプレゼンスポーリングを直ちに停止して非アクティブ状態を送信します。
