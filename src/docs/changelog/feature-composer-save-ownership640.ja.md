# レイアウト保存の保護

**機能ブランチ:** feature-composer-save-ownership640

## 保存待ち中の編集を保護

メインと入れ子の編集画面は、完了またはリセットの応答を待つ間もページを離れる際の保護を維持します。リクエスト中はレイアウト変更と重複送信を停止します。成功が確認された保存は、変更可能な下書きデータを共有せず、送信した列数別プロファイルをそのまま保持します。 確認には HTTP `200` と JSON の `data.saved === true` が必要です。アカウントまたはアクセストークンがなければ書き込みは送信しません。

## 下書きを失わずに対処

HTTP エラー応答やリクエストエラーでも下書きの保護を維持し、翻訳済みの対処方法を表示します。再試行や破棄は明示的に選択します。応答が失われた場合、サーバー側の結果は不明であり、自動再送は行いません。共通ドキュメントには現在の設定 URL とプロファイルのデータ形式を記載しました。 確認できない応答でも保護を維持します。破棄は以前のローカルの基準に戻しますが、その基準はサーバーで確認済みとは限りません。再試行は新しいリクエストを送信します。非アクティブな入れ子のサブページには遅れた通知を表示せず、破棄済みの Composer は完了を反映しません。

再試行、変更の破棄、セクションの移動、ページの終了時には復旧案内を閉じます。古い案内が別の編集セッションに再表示されることはありません。
