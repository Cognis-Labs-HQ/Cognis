# アカウントとセッションの修正

**機能ブランチ:** fix-account-and-navigation-errors

## 安定したユーザー管理

ユーザー画面は保存済みのアカウントIDで本人を識別し、不透明なSSOセッションにも対応します。本人への操作はサーバーの保護に従います。詳細取得の失敗にはユーザー画面専用の翻訳を使用します。更新後の再取得に失敗しても、確認済みの保存を失敗として扱わず、以前の一覧と更新警告を表示します。

## プロフィール編集とロール

プロフィール編集は、表示名、自己紹介、所在地、ウェブサイトについて、そのコンポーネントが定める上限を使用します。ロール同期は不変のアカウントIDから公開プロフィール名を解決し、ロールと公開範囲を更新します。

プロフィールの保存時は、編集画面を閉じる前に既存のフォーム検証を実行します。表示名は必須で、空白のみの値も拒否します。

## 応答性の高い画面移動

ログアウトは公開ルートのサービスワーカー保守を待たずに非公開セッションデータを消去します。同一のポリシー要求は通信を共有しますが、変更されたアクセス判断は統合しません。言語切り替えはカタログ提供元の準備を待ち、ログアウト時はアカウント専用操作を非表示にします。バンドル版と直接読み込み版のルーターはドキュメント状態、リスナー、表示の中断を共有し、設定からダッシュボードへの移動にも対応します。

## SSO登録試行の有効期限

招待が必要なSSO識別情報は、アカウント、プロフィール、メールの作成前に保留します。取り消し済み、期限切れの試行は再開できません。登録と二要素認証は期限ちょうどで失効します。公開登録アダプターが有効なら、通常アカウントの公開登録設定とは別にSSOアカウントを作成できます。既存のアカウントを提供元や経過時間だけで削除することはありません。

## 用途別のメール送信間隔

共有SMTP認証間隔は15秒です。宛先を正規化し、用途ごとに制限するため、メール確認、ログインコード、ログインリンク、招待、テストが互いを遅延させません。同じ用途の予約は設定された間隔と実際の送信成功時刻を使用し、直接送信に失敗しても待機時間を消費しません。

## 共有ソースと設定保護

モジュールのソース認証情報と検出キャッシュを全管理者で共有し、秘密はサーバー内に隠して保存します。認証情報欄を空白で保存しても既存値を保持します。キーリング設定は正式な状態を待ち、未完了の TFA 設定では破棄確認を表示します。設定画面と共有画面の内部リダイレクトは SPA 遷移を維持します。キーリングは **2.1.1**、TFA は **1.1.20** です。

接続済みフォームの暗黙的な送信は画面内で処理し、ブラウザーのドキュメント要求を発生させません。コンポーネントの送信処理には引き続きイベントを渡します。内部リダイレクトは SPA ルーターを使います。サーバーで描画するページへの明示的な移動にも未保存の変更確認を適用し、再開時にオフラインでの利用可否を再確認します。

管理者によるアカウント作成では、準備フローを通じて完全なロール名をアカウントストアへ渡します。管理者、モデレーター、教師のアカウントが通常ユーザーのロールに戻らなくなります。

## ブートストラップ時の用途

SMTP の用途はゲートウェイまたはモジュールのブートストラップ中に `ctx` で登録します。`notify:registerSmtpPurpose` を取得し、ローカルな用途名で呼び出して完了を待ち、返された所有元に結び付いた識別子を保持してください。登録ごとに専用キューと受信者別の待機状態を作成します。アダプターには固定の用途一覧を持たせません。

すべての `notify:sendEmail` 呼び出しは登録済みの `purpose` を指定する必要があります。未指定や未知の用途は SMTP 通信前に拒否し、送信時に暗黙で用途を作成しません。ブートストラップの完了、失敗、時間切れ後は、保持されたコールバックや分離した非同期処理からも登録できません。起動後に有効化したモジュールは自身のブートストラップ中に登録できます。無効化やアンインストールではキューを破棄し、保留中の送信を拒否して SMTP 接続を閉じます。

既定の間隔は用途ごとに正規化した受信者あたり十五秒です。用途別のキューは並行処理するため、ある用途の遅い接続、再試行、待機時間が他を妨げません。待機時間は送信成功後だけ更新します。キュー一覧は全用途をまとめて識別子を表示し、各キューの完了済み履歴を最大 200 件メモリーに保持します。

汎用エンベロープには `purpose` を含めます。SMTP 専用の送信・キュー関数は用途を第一引数で受け取ります。ゲートウェイのテスト関数は `(senderId, purpose, recipientEmail, config)` を使います。既存の通知ゲートウェイの補助関数は自身が登録した用途を指定します。汎用呼び出しを使うコンポーネントやモジュールはブートストラップ中に用途を登録し、実行時には返された識別子を再利用します。
