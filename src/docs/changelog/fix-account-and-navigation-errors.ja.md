# アカウントとセッションの修正

**機能ブランチ:** fix-account-and-navigation-errors

## 共有とテストの信頼性

Calendar と Flashcards の共有フックは、ほかのリソースプロバイダーが結果を返さない場合にも対応し、すべてのプロバイダーが有効な状態でリンク共有とアカウント共有を作成・解決できます。読み込み画面、アカウント共有の状態画面、ゲスト用カレンダーは、8 列を必須とせずレスポンシブな最小サイズを使用し、狭い画面でも表示できます。共有メンテナンスは順番に実行し、重複した呼び出しをまとめ、失敗した処理回を終了して次の 15 分間隔で再試行します。無効化は後続処理を停止し、再有効化はスケジュールを再開します。

SMTP 設定テストは、通常の配信を有効にせず、送信機能が無効でも実行できます。テストにはブートストラップで登録した専用診断キューと段階的なフローを使用し、ゲートウェイの無効化時にキューを停止します。空のパスワード上書きは、非表示の保存済みパスワードを維持します。診断ログには安全な通信エラーコードとプロトコル応答コードを記録し、認証情報やサーバー応答文は含めません。

ゲストの Flashcard 練習では一時的なモード選択を使用し、アカウント拡張機能とレイアウト設定の保存を無効にします。アカウントの練習設定は読み書きしません。

## アダプターが所有する契約

ゲートウェイは `ctx.capabilities` を通じて、同じ `system:contracts` レジストリをアダプターへ公開します。アダプターは `defineContracts(ctx)` をエクスポートでき、ホストは初期化前のアダプターブートストラップで呼び出します。既存のブートストラップ関数から直接宣言することもできます。Auth、Notify、TFA、Social、Study、Calendarはアダプタースコープを使用し、DB、Files、Registrationのファクトリーローダーも定義フックを扱います。各定義の所有者は `adapter:<gateway>:<adapter>` で、ゲートウェイのロールバック、無効化、再有効化に従います。入れ子のアダプター権限は、切り離された非同期処理も含め親ブートストラップの終了時に失効します。実行時のリクエストでは新しい契約を登録できません。提供元の公開 `contracts/` ディレクトリへの型専用インポートは開発補助として利用でき、実行可能なコンポーネント間呼び出しはctxを使います。

SMTPは自身のブートストラップでメール用途、配送、ポリシー、テンプレートファクトリーの契約を宣言します。実行時定義は `contracts/declarations.ts`、任意の公開アクション型は `contracts/action-delivery.ts` に置きます。通知ゲートウェイはこれらの提供元APIを宣言せず、汎用の送信者と配送結果の型を保持します。他のアダプターもCoreにファイルを追加せず、同じホスト登録機構を使えます。

## メールのコントラストとKeyring状態

生成したブロックを段落で囲まず、ブロックコンテナーに配置します。段落、コード、リスト項目、表のセルにテーマの文字色を明示します。ダークモードのフッターとライトモードのリンクにも十分なコントラストを確保します。

Keyring設定は、ログインや再読み込み後の最初の表示を含め、セクションを開く時点で現在の状態を取得します。設定一覧の構築時に「存在しない」という結果を保存しません。確認済みの状態を使って表示し、作成や削除時は表示中のセクションを更新します。アカウント変更や画面移動時は、遅れて返った描画や機密情報のダイアログを引き続きキャンセルします。

## 拡張可能なプロバイダー契約

Authの確認モードは独自の関数、利用可否、UIメタデータとともにctxへ登録します。管理画面は利用不可の保存済み選択肢を保持し、変更時に検証します。汎用のバージョン付き実行時レジストリにより、ゲートウェイ、アダプター、外部モジュールはCoreのドメインファイルなしでコントラクトを公開でき、モジュール権限とライフサイクルによる失効を維持します。確認ヘルパーは共通サーバー再利用層とAuthへ移動します。SMTPは設定スキーマと、モジュール独自のオプションを含む合成可能なテンプレートファクトリーを所有します。メールは受信者のテーマを使い、未設定時はライトモードとし、安全なHTMLとプレーンテキストを生成します。TFAはメソッド表示メタデータとメール提供元のコード長・再送間隔ポリシーを使います。AI向け指示にもこの拡張方針を明記します。

## 安定したユーザー管理

ユーザー画面は保存済みのアカウントIDで本人を識別し、不透明なSSOセッションにも対応します。本人への操作はサーバーの保護に従います。詳細取得の失敗にはユーザー画面専用の翻訳を使用します。更新後の再取得に失敗しても、確認済みの保存を失敗として扱わず、以前の一覧と更新警告を表示します。

## プロフィール編集とロール

プロフィール編集は、表示名、自己紹介、所在地、ウェブサイトについて、そのコンポーネントが定める上限を使用します。ロール同期は不変のアカウントIDから公開プロフィール名を解決し、ロールと公開範囲を更新します。

プロフィールの保存時は、編集画面を閉じる前に既存のフォーム検証を実行します。表示名は必須で、空白のみの値も拒否します。

## 応答性の高い画面移動

ログアウトは公開ルートのサービスワーカー保守を待たずに非公開セッションデータを消去します。同一のポリシー要求は通信を共有しますが、変更されたアクセス判断は統合しません。言語切り替えはカタログ提供元の準備を待ち、ログアウト時はアカウント専用操作を非表示にします。バンドル版と直接読み込み版のルーターはドキュメント状態、リスナー、表示の中断を共有し、設定からダッシュボードへの移動にも対応します。

## SSO登録試行の有効期限

招待が必要なSSO識別情報は、アカウント、プロフィール、メールの作成前に保留します。取り消し済み、期限切れの試行は再開できません。登録と二要素認証は期限ちょうどで失効します。公開登録アダプターが有効なら、通常アカウントの公開登録設定とは別にSSOアカウントを作成できます。既存のアカウントを提供元や経過時間だけで削除することはありません。

## 用途別のメール送信間隔

共有SMTP認証間隔は15秒です。宛先を正規化し、用途ごとに制限するため、メール確認、ログインコード、ログインリンク、招待、テストが互いを遅延させません。同じ用途の予約は設定された間隔と実際の送信成功時刻を使用し、直接送信に失敗しても待機時間を消費しません。

## 共有ソースと設定保護

モジュールのソース認証情報と検出キャッシュを全管理者で共有し、秘密はサーバー内に隠して保存します。認証情報欄を空白で保存しても既存値を保持します。キーリング設定は正式な状態を待ち、未完了の TFA 設定では破棄確認を表示します。設定画面と共有画面の内部リダイレクトは SPA 遷移を維持します。キーリングは **2.1.1**、TFA は **1.2.0** です。

接続済みフォームの暗黙的な送信は画面内で処理し、ブラウザーのドキュメント要求を発生させません。コンポーネントの送信処理には引き続きイベントを渡します。内部リダイレクトは SPA ルーターを使います。サーバーで描画するページへの明示的な移動にも未保存の変更確認を適用し、再開時にオフラインでの利用可否を再確認します。

管理者によるアカウント作成では、準備フローを通じて完全なロール名をアカウントストアへ渡します。管理者、モデレーター、教師のアカウントが通常ユーザーのロールに戻らなくなります。

## ブートストラップとチャネル

SMTPがアクションの登録、メッセージの生成、キューを管理します。`notify:registerEmailPurpose`にはローカル識別子と、変数からメッセージを生成するアクション関数を渡します。ゲートウェイ、アダプター、外部モジュールは、それぞれのブートストラップ中にのみ登録でき、識別子には所有者が含まれます。Auth、Registration、TFA、Shareが各メッセージの内容を所有し、SMTPにアプリ固有の用途一覧やテンプレート一覧はありません。

`notify:sendEmail`には、登録済みの用途と変数を渡します。`templateId`は使用しません。用途が未指定または未登録の場合は拒否し、非同期アクションはキュー投入前に再確認します。ブートストラップの完了、失敗、タイムアウト後は登録できません。ゲートウェイの完了フックは、プロバイダーの起動後に同じ所有者の権限で実行します。

通知カテゴリには既存の`notify:registerCategory`を使用します。SMTPは登録時にキューを作成し、登録先に結び付いた配送関数をゲートウェイへ返します。ゲートウェイは送信方式に依存しません。送信時に用途を作成または推測することはなく、SMTPへの直接送信には登録済みの用途を明示する必要があります。

ゲートウェイの無効化やモジュールの解除時は、その所有者のアクションと保留中の配送を破棄します。再有効化時には新しいキューを復元し、中止したメールを再送しません。共有カテゴリは、他の登録済み所有者が有効な間は維持します。SMTP送信アダプターの無効化でもセッションを閉じて保留中の配送を中止し、再有効化では存在する登録だけを復元します。

既定の送信間隔は、各キュー内で正規化した宛先ごとに15秒です。独立したキューは並行処理し、配送成功時だけ間隔を更新します。履歴は各キューにつき完了済み200件までメモリに保持します。`sendEmail`は実際のキュー受付情報を返し、受付時点でSMTP配送の成功を示すことはありません。

送信アダプターの契約は共通の`test(recipient, config)`と、任意のブートストラップ、チャネル、ライフサイクル用フックです。ゲートウェイは`testSender(senderId, recipient, config)`を呼び出し、SMTP固有のテスト、確認、招待、ログイン用メソッドを持ちません。従来のSMTP専用ゲートウェイ補助メソッドと、独立したテンプレート登録は廃止します。

## レビュー修正

GitLabのリポジトリ検証は、配備先のURLプレフィックスを考慮し、オリジンと名前空間の制限を維持します。ゲートウェイのライフサイクル操作は非同期で直列実行し、呼び出し元は有効化と無効化を待機します。ブートストラップのリソースは所有者の無効化まで保持し、有効化が失敗した場合は復元処理を取り消します。アダプターには独自のブートストラップ識別子を割り当てます。SMTP TFAは**1.1.0**です。

## 実行時リクエストの修正

通常のHTTPリクエスト中にCalendarが通知登録を試みることによる、言語切り替えと同意状態の更新の失敗を修正しました。Calendarは通知プロバイダーの起動後、ブートストラップ完了時にカテゴリを一度だけ登録します。Shareは登録済みのカテゴリを使用し、Authは早期の重複登録を行わず完了フックを使用します。SMTPの登録は引き続きブートストラップ中に限定し、実行時のハンドラーは既存の配送機能を取得して使用します。Calendarは**1.5.5**です。

## Study通知の配送

Studyの申請、コンテンツ、削除の通知は、Libraryのブートストラップ時に登録したカテゴリを使用します。実行時には現在の通知機能を取得するだけで登録処理は行わず、SMTPのブートストラップ制限によって配送や公開範囲変更の通知が止まることを防ぎます。

## インストール認証情報の束縛

インストールは、リポジトリURLの検証に使用したものと同じプロバイダー、エンドポイント、名前空間のスナップショットに対して認証情報を取得します。取得前にソースの束縛が変更された場合はチェックアウト前に中止し、新しいエンドポイントの認証情報を以前のホストへ送信しません。GitHubのAPIホストからリポジトリホストへの対応付けは、GitHubソースにだけ適用します。

## TFA破棄確認の段階的処理

登録の中止がサーバーで確認された後、残りのページ保護機能にもナビゲーションを確認させます。登録を破棄しても、無関係な設定変更は破棄しません。変更を保持すると移動を停止し、明示的に破棄した場合だけ続行します。破棄済みのページから保存していた登録中のナビゲーションを再開することはできません。

## コンポーネントの境界

メール操作は転送方式に依存しない `notify:registerEmailPurpose` を使用します。送信者の契約は公開 Core 型となり、アダプターのブートストラップは具体的なゲートウェイではなく ctx を受け取ります。確認コードの桁数はメールプロバイダーから取得し、TFA を必須としません。可用性の確認は認証必須で設定を公開しません。メールの確認は送信者の要件に従い、配送がなくても保存済みアドレスは閲覧できます。ポリシーは `email` を使用し、既存の確認要件を暗黙に解除しません。

登録と共有のアダプターは自身のブラウザー機能を宣言します。TFA はアダプターの言語リソースを検出して共通の確認エラーを使用し、発行元設定はアダプターが所有します。Share の保守処理はゲートウェイの停止と再開に従います。Share UI のテストは所有コンポーネントごとに分離します。

## 静かなマーケットプレイス更新

マーケットプレイスは管理者専用の `/api/v1/modules/marketplace-state` スナップショットを15秒ごとに再検証します。ETag にはソース、インストール状態、キャッシュ済みの検出結果、おすすめ、再起動の要否が反映されます。変更がない場合は本文なしの `304` を返し、翻訳の再取得や再描画をせず、準備済みのカタログを保持します。ソースの検出は画面のマウント後に一度、その後は毎時およびソース変更時に行います。手動の更新は引き続きスキャンを強制します。非表示、オフライン、処理中のページではポーリングを一時停止し、アンマウント時に要求を中止してタイマーを解除します。

カタログの表示情報にはコンテンツから算出した `ui.stringsRevision` を含めます。`extendI18n(base, stringsBaseUrl, { revision })` は、同じアカウントとセッション内でバージョン付きの認証済み言語パッケージを再利用できます。リビジョンが変わると新しい文字列を取得します。識別情報が変わると非公開パッケージを消去し、遅延した応答が別のセッションを再投入することを防ぎます。失敗した読み込みは再試行できます。公開パッケージは従来のキャッシュとライフサイクルに伴う無効化を維持します。

おすすめフィードはマーケットプレイスサービスで共有し、同時の読み取りをまとめて5分間保持します。更新に失敗した場合は最後に取得できた一覧を維持し、次の試行まで1分待ちます。設定 URL が変わると別の結果に切り替え、手動の更新は有効期間を無視します。
