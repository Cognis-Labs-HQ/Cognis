# SMTPコードの配送

**機能ブランチ:** feature-smtp-challenge-recovery

## 配送を所有チャレンジに結び付ける

Email Codeの「送信待ち」はまだ配送が完了していない状態です。最新のコードを待ってください。再送が受け付けられた場合だけ前のコードを置換し、拒否時は維持します。配送失敗後は試行の期限内に明示的に再送するか、新しくログインしてください。ログイン試行は5分、設定は10分です。設定の中止はその設定だけに影響します。ログイン再開で追加メールを送ったり期限を延長したりしません。

メソッドアダプターには設定開始、ログインチャレンジ、ログイン検証で必須の `lifetime: { id, expiresAt, signal }` を渡します。`tfa:getLoginMethods(accountId, lifetime)` と `tfa:verifyLogin(accountId, methodId, payload, lifetime)` の呼び出し元は移行が必要です。設定は最初の非同期読み取りより前に固有IDと10分期限を持ちます。Authは `auth:getPendingLoginLifetime` バージョン1でログインの有効期間を提供します。中止、期限切れ、保存失敗、アカウントのメソッド無効化、リセット、ゲートウェイ破棄は対象操作を無効化します。再有効化後も古い読み取りは拒否します。登録書き込み開始前の検証は中止可能です。書き込み開始後は、表示されたままの書き込み・後処理バリアを中止とリセットが待ちます。復旧コードも非同期消費後に有効期間を確認します。再起動でメモリー内の未完了チャレンジは失われます。再開されたログイン記述は受付時の記録であり、現在の配送状況を証明しません。

## プロバイダーの必須移行

SMTP TFAは公開契約レジストリから `notify:deliverEmail` バージョン1を必須とし、`notify:sendEmail` や無視されるオプションへの代替処理はありません。新しいコードの受付が成功してから対応する旧配送を置換・中止します。受付拒否なら以前のコードを維持します。後の配送失敗は新しいコードを無効化し、試行の有効期限内に明示的に再送して回復できます。同時再送は同一所有操作内だけでまとめます。独立した設定やログインには別のIDと中止処理を使います。コードは所有者期限と15分の早い方まで有効で、一度だけ使用でき、遅い通知でも復活しません。送信待ちと送信済みを区別します。Notification SMTP 0.5.5、SMTP TFA 1.1.3、TFA 1.3.12、Auth 2.2.11を同時に導入し、代替プロバイダーも使用前にこの契約を実装してください。

`auth:getPendingLoginLifetime` バージョン1は一次認証済みの既存試行から `{ id, accountId, expiresAt, signal }` を読むだけの公開契約です。権限の作成や延長はできません。Authは自動的な要素準備より前に試行を作りますが、セッション発行やプロフィール有効化はしません。不変の5分期限が配送にも適用されます。消費、中止、期限切れ、継続の置換、ログアウト、所有者の後処理でチャレンジ資源を中止します。Cookieに結び付いた継続、古い試行の保護、再配送なしの再開は維持します。要素検証の成功でチャレンジを終了しても、別の最終セッション確定は中止しません。この契約がなければTFAは処理を拒否します。

`notify:deliverEmail` バージョン1は登録済み用途、宛先、変数に加え、必須の `signal: AbortSignal` と絶対ミリ秒時刻 `expiresAt` を受け取ります。既存の validate/render/enqueue フローと用途別キューを再利用します。受付時に `{ receipt, completion }` を返し、`completion` は最終的な `sent` または `failed` の結果を返します。待機中、制限中、送信処理中は配送完了を意味しません。中止、期限切れ、用途の破棄でキューと通信を中止し、遅い成功結果が失敗を上書きすることはありません。通常の `notify:sendEmail` の遅延配送は変更しません。既定のグレイリスト再試行は5分待機を2回ですが、所有者の期限が先ならそこで停止します。宛先SMTPサーバーが受領済みのメールは取り消せません。

## 終了処理の状態変更を調整する

アカウント、メソッド、ゲートウェイの終了処理は、後処理と状態書き込みが完了するまで新規受付を止めます。重複する操作はそれぞれ独立したバリアを所有し、1つの終了で別の操作を再開しません。登録書き込みの失敗は検証失敗のままですが、後処理はその終了を待ち、後続のリセットや無効化による状態変更を妨げません。
