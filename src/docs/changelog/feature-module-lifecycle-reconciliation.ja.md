# モジュール操作の結果

**機能ブランチ:** feature-module-lifecycle-reconciliation

## モジュール操作の結果

有効化と無効化は、変更要求とその後の状態確認が続く間、処理中になります。状態の読み取りで分かるのは現在の観測状態であり、この要求が確定したことの証明ではありません。モジュール画面を離れても送信済みの変更は取り消されず、古い画面が遅れて通知したり新しい画面を書き換えたりすることはありません。アカウントが変わると、待機中の操作と遅れて届いた結果の権限が無効になります。応答が失われた場合は、5秒の期限で状態を1回だけ読み取り、変更を自動で繰り返しません。結果が不明な間は「状態を確認」が操作ボタンの代わりに表示されます。後の読み取りやSPA内の再訪でも、反対の状態が続く間は操作をロックしたままにし、要求した状態を観測してから操作を戻します。任意の設定ガイドや中止されたカタログ更新によって、確認済みの有効化が拒否扱いになることはありません。必須設定を取り消した場合の無効化は1回だけ行います。応答が失われた場合は、正式な読み取りで無効状態が確認できたときだけ無効として照合し、それ以外は結果を不明のままにします。

マーケットプレイスのチュートリアルでは、利用可能な場合だけ「状態を確認」を説明し、結果が不明な間は通常の操作を省略します。既存の所有者と完了の識別子、設定ポップアップとチュートリアルの有効期間は維持されます。ホストのモジュール画面には独立してバージョン管理されるパッケージやマニフェストがないため、API、Core、任意のプロバイダーのバージョンやハッシュは変更しません。

照合によるライフサイクルイベントは observed-state として、応答確認済みの acknowledged-response と区別されます。観測した状態だけでは、この要求が確定した証明にはなりません。APIには永続的な操作結果の記録がなく、不明な状態の管理はSPA内では維持されますが、ブラウザーの完全な再読み込みでは失われます。その後はサーバーの現在の状態だけが取得でき、以前の要求の最終結果や実際のStudyの起動は確認できません。

無効化や設定の取り消しを含め、モジュール操作が処理中、または結果が不明な間は、そのモジュールを依存関係の条件として利用できません。繰り返しの操作やSPA内の再訪でも制限を維持し、待機中の有効化は実行開始時に準備状態を再確認し、任意の依存モジュールの選択は繰り返しません。有効状態の観測と設定の完了は別であり、取り消しが拒否された場合も設定は未完了です。設定の保存で設定完了を確認できても、不明な変更結果は解消しません。期待された無効状態を正式な読み取りで確認した場合は、通常の明示的な有効化を行えます。

依存モジュールの準備状態に関する警告の翻訳がない場合は、繰り返しの操作でも内部エラーテキストを表示せず、明示的なエラーにします。エラー後もボタンの処理中表示は解除されます。

設定、更新、チャネル変更にも、アカウントに結び付いた同じ処理中・結果確認を適用し、一時的な有効化、無効化、取り消しを含めて管理します。有効化と復元の直前には、選択された依存関係を再確認します。インストール後の復元は、送信の明確な拒否または処理の最終結果を確認した場合に限ります。送信や状態確認の応答が失われたり、処理結果の記録が見つからなかったりした場合は不明のままとし、復元や再試行を行いません。結果を失ったインストールはページのセッション中はロックされます。「状態を確認」でカタログを更新しても処理の完了は証明できません。完全な再読み込みはこのローカルな不確実性の記録を破棄しますが、完了の証明にはなりません。永続的な処理結果の記録や完全な再読み込み後の復旧は追加しません。
