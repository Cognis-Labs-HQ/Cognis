# LDAP 有効化の安全性向上

## 有効化前にサーバーを設定

LDAP サーバーが少なくとも 1 台設定されるまで、LDAP アダプターの有効化スライダーを無効にし、不正な有効化リクエストを防止します。

検証済みサーバーを追加した後にアダプターを有効化すると、保留中のサーバー設定が自動的に保存されます。未保存の新規サーバーを破棄する際には確認が必要になりました。

ユーザー検証手順で Enter キーを押す場合を含め、保存すると必要に応じて認証テストが自動的に実行されます。認証テストに失敗した場合、修正できるよう管理者を LDAP バインド項目に戻します。

最後の LDAP サーバーを削除する際に確認が必要になり、続行するとアダプターが無効になります。LDAP テストの失敗時には、サーバー URL、ディレクトリ DN、バインド資格情報、検索フィルターなど、原因となり得るすべての設定項目が強調表示されます。

LDAP セットアップのすべての文言をアダプター所有のローカライズ済み言語リソースから取得するようにしました。ユーザー認証、および LDAP サーバーの作成や更新が成功するとトーストで通知されます。

認証ゲートウェイが各アダプターの言語リソース URL を公開するようになりました。LDAP 言語パックは登録済みの静的 UI ディレクトリから配信されるため、管理画面はセットアップを開く前に読み込めます。

LDAP ユーザー認証のテスト時に必須の資格情報項目が空の場合、ローカライズされたエラートーストを表示します。LDAP フォームコンポーザーに渡すすべてのラベルキーを、アダプター所有のローカライズキーにしました。

LDAP の無効化またはソースの削除時に、そのソースに依存する全ユーザーのセッションを失効します。分離ソースのアカウントは依存データとともに削除され、統合アカウントは保持されて次回ログイン時に別の設定済み LDAP ソースの新しい識別情報を関連付けられます。

「テストして検出」が正常に接続して LDAP ディレクトリデータを返したとき、ローカライズされた成功トーストで通知するようになりました。
