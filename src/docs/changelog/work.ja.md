# インストール済みモジュールのページを復旧

## 外部モジュールのインストール先から UI ルートを読み込む

インストール済みモジュールは、外部モジュールディレクトリ内で安定した UUID により解決されるようになりました。宣言されたページとナビゲーション項目は、同梱モジュールのパスを検索する代わりに、起動時に自動的に読み込まれます。

## リクエスト前に起動を完了

Cognis は、保存済みモジュール状態の復元とモジュールの起動が完了してからリクエストを受け付けるようになりました。これにより、外部モジュールのスクリプトとスタイルは、ページから要求される前に登録されます。

## 認証ケイパビリティを提供

認証ゲートウェイは、リクエスト認証とロールアクセスの関数をケイパビリティバスへ公開するようになりました。外部モジュールはゲートウェイ内部をインポートせずに保護された API ルートを起動でき、UI アセットとナビゲーション登録が維持されます。

## 宣言された UI 機能のみ読込

モジュールはマニフェストで `requiresCapabilities` を宣言できます。モジュールルートをマウントする前に、Cognis は宣言された `ui:*` ケイパビリティの登録済みプロバイダースクリプトだけを読み込み、無関係な統合へのアクセスを与えずに必要な UI サービスを準備します。

## ケイパビリティの確認と文書化

Owner は `GET /api/v1/system/capabilities` または `cognisctl system:capabilities` ですべての登録済みケイパビリティ ID を一覧できます。モジュール、認証ゲートウェイ、プロフィールアダプターの文書に、要件宣言と各プロバイダーが提供するケイパビリティを記載しました。

## リリース版の方向を表示

インストール済みモジュールのカードと詳細表示では、選択中チャネルの異なるバージョンを現在のバージョンの下に表示します。アップグレードには上向き矢印を使い、まれなダウングレードには薄いオレンジ色のピル内で下向き矢印を表示します。

## モジュール詳細を安定表示

モジュール詳細表示を開く場合や更新する場合に、ページ位置が維持されるようになりました。表示するすべてのバージョンに `v` 接頭辞を付け、有効なモジュールの更新では、無効化、インストール、再有効化を一回の操作で実行します。

## 詳細操作を安定表示

モジュール詳細ページは Page Composer 内に留まりながら、ルーター対応の UUID ディープリンクを使用するようになりました。有効なモジュールをアップグレードのため一時的に無効化している間も、ライフサイクル更新によって表示中のボタン構成が変化しません。

## 直接表示を一度だけ起動

外部モジュールの SPA ルートを直接表示する場合、宣言されたケイパビリティプロバイダーをモジュールルートより先にインポートする Core エントリポイントを使用するようになりました。プロバイダーとルートの URL はルーターナビゲーションと同じアセット版を使うため、断続的なケイパビリティ不足とナビゲーションバー項目の二重登録を防ぎます。

## 同梱モジュールの切出し準備

Analytics と Nextcloud Whiteboard は、専用リポジトリ情報、ライセンス、README、完全な整合性一覧、翻訳済み配布ガイド、UUID 依存関係、明示的なケイパビリティ要件を備えた自己完結型の外部モジュールリポジトリになりました。

## モジュールのスクリーンショット閲覧を改善

モジュール詳細のスクリーンショットを、前後の操作、隣接画像のフェード表示、スライドアニメーション、自動切り替えを備えた大きさの制限されたカルーセルにしました。任意の `template: true` フィールドを持つマニフェストは、マーケットプレイスの結果と直接の詳細表示から除外されます。

## マーケットプレイスのモジュールを一意化

Analytics と Nextcloud Whiteboard は専用リポジトリへ移行し、同梱されなくなりました。マーケットプレイス検出は各モジュール UUID の最初のリポジトリを採用し、後続の重複を記録して拒否します。また、インストール済みのライフサイクル状態を維持しながら、採用したリポジトリの表示メタデータへ更新します。

## Gateway インフラ用ディレクトリを除外

Gateway の自動検出は Gateway マニフェストを含むディレクトリだけを起動するようになり、本番ビルドで `gateways/reuse` インフラ用ディレクトリが Gateway としてインポートされなくなりました。

## モジュールのライフサイクル通知を明確化

モジュールの無効化を警告レベルで記録し、外部モジュールの削除も明示的に記録するようにしました。マーケットプレイスの更新完了通知はクリックごとに一度だけ表示され、マニフェストで `template` が明示的に `true` に設定されていないモジュールは引き続き表示されます。

## Cognis HQ モジュールを推奨

組み込みの推奨リストに、Cognis Labs HQ 組織が公開する Jitsi Meet、Nextcloud Whiteboard、Analytics のモジュール UUID を追加しました。

## モジュールのログを拡充

モジュールソースの追加、更新、削除、スキャン、および検出件数を適切なレベルで記録し、検証と有効化の失敗をエラーとして記録するようにしました。マニフェストが存在しない拡張子を指定している場合、マーケットプレイスの画像検出は同名の PNG など対応画像へフォールバックします。これにより、マニフェストが未配置の SVG を指している間も Jitsi Meet の画像が表示されます。

## モジュール画像のちらつきを防止

更新された各画像が有効な寸法を取得するまで、モジュールカードと詳細メディアを非表示にするようにしました。アイコン領域も読み込み前から固定寸法で確保し、マーケットプレイス更新時に未整形または特大の画像が一瞬表示されることを防ぎます。

## 不確かなスキャンでもモジュールを保持

マーケットプレイスのスキャンは、空のリポジトリ応答、一時的に取得できないマニフェスト、一時的な不正応答、またはソース要求の失敗を、以前に検出したモジュールが削除された証拠として扱わなくなりました。ソースが明示的に削除されるまでキャッシュ項目を表示し続け、警告ログに失敗したスキャンと保持件数を記録します。

## 安全で効率的なモジュール検出

マーケットプレイスの更新を認証付きの単一スキャンに集約し、信頼済みソースで GitHub ユーザートークンを設定できるようにしました。また、外部コード実行前の依存関係と確認の検査を復元し、GitHub Enterprise のマニフェスト取得に設定済み API を使用します。

## 直接読み込みを完了

モジュールページを直接読み込む際、ページ構築の完了または失敗後に追跡中の読み込み処理を必ず終了するようにし、ブラウザー更新後も読み込み表示が残り続ける問題を修正しました。

## スキャンの保存と制限

サーバー再起動後は、保存済みのマーケットプレイスカタログを最初のモジュール情報源として使用します。ページ読み込み時と起動時の自動スキャンによるプロバイダー枠の消費をなくし、スキャン試行を1時間間隔で保存して、繰り返し更新時はディスク上のカタログを再利用します。
