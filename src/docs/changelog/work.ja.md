# 状態表示と更新の安定化

## プロフィール状態ランプを復元

ゲストセッション機能が通常の認証済みセッションを示す場合、ダッシュボードシェルがサインイン済みアカウントの拡張機能を正しく初期化するようになり、ナビゲーションのアバター上に在席状態ランプが再表示されます。

## リリースチャンネルをキャッシュせず更新

Marketplace のリポジトリページ取得が中間 HTTP キャッシュを迂回するようになり、手動更新で新しく作成されたモジュールのブランチとタグを直ちに取得します。

## 共有機能と操作表示を統一

共有ゲスト用レンダラーは、マウント前に独立したプロフィール機能と読み込み済みのアバタースタイルを受け取るようになりました。ゲートウェイ提供の共有操作には、標準の共有アイコンとローカライズされた「共有」ラベルが常に並んで表示されます。

## UI の所有権を明確化

SPA ルートのクリーンアップで、シェル所有のスタイルシートを保持するようにしました。モジュール契約では、ホスト所有の再利用可能 UI とナビゲーションを、モジュール固有の名前空間を持つコンテンツスタイルから明確に分離します。

## インストール失敗を保護

モジュールインストールのポーリングは、ファイルシステム、リポジトリ、検証の内部詳細を公開せず、安定した公開エラーコードを返すようになりました。

## モジュール前提条件を復旧

ルートの慣例的な README エイリアスをモジュール整合性検査の対象外とし、無効なモジュールへの設定確認では想定内のルート未登録をエラー表示せず、Share ゲートウェイが依存モジュール向けの標準ブラウザートリガー Capability を公開するようにしました。

## 共有ページの Provider を更新

共有ページはスコープ付きゲストセッションの有効化後にホスト Capability Provider を再取得し、Cognis はモジュールページ向けの検証済み実行時リソースローダーを公開するようになりました。
