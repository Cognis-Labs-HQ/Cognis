# 共有管理を改善

## 有効な共有を取り消しゲスト表示を限定

共有を削除すると、アクティブなタブと削除通知を受け取ったサインイン済み受信者へ取り消しイベントが送られ、対象の閲覧者は直ちにアクセス拒否画面へ戻ります。削除確認の重複を防ぎ、ゲストセッションにはリリース概要を表示せず、別の共有の所有者判定前に退避済みのアカウントセッションを復元します。

## 共有所有者と概要操作を確実に処理

共有所有者は共有パスワード要求を省略し、アカウントセッションのままコンテンツ URL へ直接進むようになりました。受信者は設定済みの共有認証を引き続き完了します。ゲートウェイ所有の共有ページは、絞り込みや先行削除後の行を明示的に再描画し、先頭列を内容に合わせてコンパクトにし、操作ボタンの寸法と余白を統一します。

## 共有認証を要求された SPA ルートに固定

ルーターは正確な遷移先パスをセッション認証へ渡し、Share ゲートウェイは変更されないルート入力からユーザー共有トークンを取得するようになりました。同時に URL が変化しても、有効なユーザー共有がトークンなしと判定されたり、受信者が公開読み込み画面に残されたりしません。

## 共有解決リクエストでアカウント認証を維持

共有の解決は、共有パスワードヘッダーを保持しながらサインイン済みアカウントのトークンを必ず付与する認証済み API クライアントを使用するようになりました。想定されるパスワード要求をグローバルなアクセス拒否処理から分離し、ゲストセッションへの遷移や重複したロック解除を防ぎます。

## SPA 検証前に遷移先の共有認証を登録

SPA ナビゲーションは、ルートを認証する前に遷移先エントリーのフロー拡張を読み込むようになりました。これによりユーザー共有の受信者は、ルーターによる一度の認証処理で Share ゲートウェイに解決され、ゲストページへ移行せず完全なアカウントセッションを維持します。

## Router が解決したアカウント共有を再利用

共有ページは認証を二度実行せず、SPA ナビゲーションがすでに解決した認証済み共有コンテキストを使用するようになりました。ユーザー共有は直接アカウントとしての分類を維持し、ゲストアクセスとして再解釈されずに完全な移動先ページを開きます。

## 直接の受信者をアカウント表示に維持

サーバーが検証した直接ユーザー共有は、ローカル検証段階でアカウント情報を返さなかった場合でも必ずアカウントセッションを構成するようになりました。ゲスト表示へフォールスルーしません。削除または拒否した共有は、リクエスト完了前に表示中の表から直接削除されます。

## ユーザー共有を一つのフローで解決

ユーザー共有をクリックすると、別のクライアント経路でトークンを事前解決せずに共有ページへ移動するようになりました。セッションフローがアカウント検証、パスワード入力、配信を一度だけ処理します。削除した行は即座に消え、サーバーが削除を拒否した場合のみ復元されます。

## 共有のデータベース更新を修復

共有アクセス日時、共有の編集、期限切れ通知の記録で、データベース Gateway が対応する更新契約を使用するようにしました。有効な共有の解決を中断していた null オブジェクトエラーが解消されます。

## アクセス監査の失敗で共有を止めない

任意の最終アクセス日時を古い、または一時的に利用できないデータベース列へ保存できない場合でも、共有の解決が失敗しないようにしました。まだ開かれていない共有には「無期限」ではなく「未アクセス」と表示されます。

## 成功した共有を正しく扱いアクセス日時を表示

ユーザー共有の検証後に移動先ページで失敗しても、その共有を無効または期限切れとして表示しないようにしました。共有一覧には作成日時と最終アクセス日時が表示され、Whiteboard の権限は「読み取り専用」と「読み取り + 書き込み」に統一されます。

## 保護された共有ナビゲーションとカレンダーのゲスト操作を完成

通知アクションを処理する共有ハンドラーを一つに限定し、パスワード入力の重複と誤った無効共有エラーを防ぎました。カレンダー受信者は追加を確認し、受信カレンダーの削除には適切な説明が表示され、カレンダーのゲストは表示を切り替えて現在時刻へ自動スクロールできます。書き込み権限の表示は「読み取り + 書き込み」になりました。

## 保護されたユーザー共有を二重解決なしで続行

対象の受信者がパスワード保護されたユーザー共有を解除すると、検証済みの結果が次のアプリ内ナビゲーションに引き継がれるようになりました。Cognis はパスワードなしで解決リクエストを繰り返さないため、401 エラーと無効な共有の通知で終わらず、完全なアカウントページが開きます。

## アカウント共有を直接開く

共有ページおよび通知のユーザー共有リンクは、認証済みアカウント経由で一度だけ解決し、完全な移動先ページへ直接移動するようになりました。ゲスト用ランディングページを経由せず、制限付きゲスト表示も有効にしません。

## ユーザー共有をアカウント専用に

Cognis ユーザー宛ての共有では、ゲストセッションを発行または有効化できなくなりました。明示的に指定された認証済み受信者または共有所有者だけが解決でき、公開リンク共有のみがゲストアクセスを提供します。

## 編集と保護されたユーザー共有を予測可能に

共有更新には具体的な変更だけを含め、共有方式を切り替えると編集モードを終了し、共有ページの高さをテーブルに合わせます。パスワード付きユーザー共有の通知では一度だけ入力を求め、確認済みパスワードを対象受信者のキーリングへ保存できます。公開リンク共有はアカウントのキーリングから分離したままです。

## アカウント共有とゲスト共有の動作を簡素化

ユーザー共有の通知では指定アカウントのセッションを維持し、パスワード付き公開リンクではゲストモードへ入る前にアカウントのキーリングを解除または保存せずパスワードを求めます。空の更新項目は既存値を維持し、モジュール所有の共有ダイアログでは修正済みのパスワードおよび削除文言を一貫して使用します。

## ユーザー共有を保護し、操作を明確化

ユーザー共有では、譲渡可能なゲストアクセスを作成せず、指定されたアカウントを引き続き要求します。共有操作は中立表示になり、権限は「読み取り専用」と「読み取りと書き込み」を明確に区別し、パスワードダイアログには受信者向けの簡潔な案内を表示します。削除されたゲスト共有は、リダイレクトや通知を繰り返さず正常に終了します。

## 共有更新と滑らかなページ移動を復元

対象を絞った共有エディターで有効期限の変更を一貫して送信し、更新操作に標準の確認表示を使用するようになりました。アプリ内移動では移動先の構築が完了するまで現在のページのスタイルを維持し、移動前のコンテンツが一瞬スタイルなしで表示されることを防ぎます。

## 共有を絞り込み、すぐに削除

「合計」、「送信済み」、「受信済み」の概要ピルで共有テーブルを絞り込めるようになりました。正常に拒否または削除された共有はすぐに消え、各行の破壊的操作には競合するクラスを付けず、標準のキャンセル表示だけを使用します。

## 所有または受信した共有でアカウントアクセスを維持

ホワイトボード共有を作成者が開いた場合や、ミーティングのユーザー共有を受信者が開いた場合に、アプリ内移動でも更新後でも認証済みアカウントセッションを維持するようになりました。移動先では完全なアカウントページが構築され、すべてのナビゲーションが保たれ、制限付きゲスト表示へ移行しません。

## 移動先ページの操作とスタイルを分離

ホワイトボードページと共有ページでは、レイアウト編集を無効のままにしました。アプリ内で移動するたびにページ操作ドックを再構築し、移動先が提供しない操作を破棄して、完全なスタイルシート一式を読み込み、不要になったルートのスタイルを削除します。

## 1 件の共有だけを管理

共有ページから、選択した共有のフォームだけを含む簡潔な編集画面を開けるようになりました。共有方式は固定され、更新対象はそのデータベースレコードだけです。また、アプリ内移動時にダイアログが二重に開く問題も解消しました。

## 共有操作の外観を統一

共有ページのカード外側に余分な縦方向の空間を追加しないようにしました。アクセスを減らす可能性がある共有ボタンには、常にキャンセル用の表示を使用します。

## 共有コンテンツのルートを復元

登録されたゲートウェイおよびモジュールのページは、ブラウザーの再読み込み時とアプリ内移動時の両方で、それぞれのダッシュボード用エントリーポイントと完全なスタイルシート一式を読み込むようになりました。これにより、共有、ミーティング、ホワイトボードの各ページでトップバー、フッター、レイアウト、コンポーネントのスタイルが維持されます。

## 設定された有効期間中はミーティング共有を維持

ミーティング共有は、ミーティングのインスタンスが変わった場合やセッションが終了した後も解決できるようになりました。共有自体が期限切れ、拒否、または取り消しになるまでアクセスを維持し、認証フローが繰り返された場合は、解決済みの共有セッションを再利用します。

## ユーザー共有はアカウントセッションを維持

ユーザーへの直接共有は、コンテンツプロバイダーが指定した不透明な宛先を対象の受信者へ届けるようになり、公開共有 URL の公開やゲストセッションの発行を行いません。リンク共有は、独立した公開リンクとゲストアクセスのライフサイクルを維持します。

## 有効な共有アクセスを強制

共有パスワードが正しくない場合はエラーが表示され、すぐに再入力できるようになりました。保護されたユーザー共有は開く前に解除され、共有ページの項目は通知と同じアクセスゲートを使用し、リンク共有またはユーザー共有が取り消されると受信者はアクティブなコンテンツから速やかに退出します。

## 共有項目の操作を安定化

保護されていないユーザー共有の通知はコンテンツを直接開き、保護された項目はパスワード入力前に共有ページの一回限りの操作を消費し、解除成功後は内部アプリルートで移動します。ユーザー共有が重複した場合は競合を通知し、設定が変更されていれば既存の共有を更新します。

## 長時間開いたタブの応答性を維持

共有の取り消し確認は、0.5 秒ごとの反復ポーリングではなく、表示状態を認識する単一のモニターを使用するようになりました。バックグラウンドタブではネットワーク確認を停止し、再びフォーカスされた時点ですぐに検証するため、長時間開いた共有ページがブラウザーやサーバーのリソースを使い果たしません。

## 保存済み共有パスワードを再利用

パスワードで保護されたユーザー共有は、同じ安定したキーリング識別子 `share:<share-id>` でパスワードを保存・取得するようになり、保存後に再度共有を開いても入力を求めません。

## 非表示のホワイトボードを停止

ホワイトボードのプレゼンスポーリングとリアルタイムソケットは、タブが非表示の間は停止し、再表示時に新しい接続で再開するようになりました。コラボレーションスクリプトの読み込みにも適切なタイムアウトを設け、停止した外部リクエストによって再読み込みが無期限に続くことを防ぎます。

## 必要な場合のみキーリングへのアクセスを要求

SPA ナビゲーションでキーリングを先回りして解除しないようになりました。アカウント共有は、まずパスワードが必要かを確認し、その保護された共有についてのみキーリングへのアクセスを要求します。確認画面には共有へのアクセス目的と共有識別子が表示されます。

## 必要な場合にのみキーリングへのアクセスを要求

キーリング設定のコントリビューションは、描画時に解除要求を予約しなくなりました。これにより、ダッシュボードの読み込みやページ間の移動で汎用的なプロンプトが表示されません。保護された共有のパスワードダイアログでは、内容を明示したキーリング解除が成功した場合にのみ保存オプションが表示されます。

## バックグラウンド処理と停滞した要求を制限

非表示タブでは在席状況のポーリングを停止し、重複する更新とハートビート要求をまとめるようにしました。Node と Nginx は停滞した HTTP 処理を終了し、PostgreSQL は有限のステートメントタイムアウトを適用し、MariaDB は待機クエリ数を制限するため、依存サービスの不調によってページやサービスが応答不能になるまで処理が蓄積しません。

## ページが非アクティブになったらプレゼンス通信を停止

プレゼンストラッカーは適応型ポーリングで頻度を下げ、ユーザーがアイドル状態になった場合、ウィンドウがフォーカスを失った場合、またはタブが非表示になった場合に、すべての定期要求を停止します。ホワイトボードのコンポーザーは自身のナビゲーションシグナルにクリーンアップを結び付け、SPA ナビゲーション時にプレゼンス、ポインター、キャンバス、リアルタイムのフックを即座に解除し、後続のマウントには影響しません。

## 所有者アクセスをパスワード不要にし、保留中のブラウザー要求を制限

アカウント配信型ユーザー共有の認証済み所有者は、受信者用パスワードを再入力せずに自身の共有を解決できるようになりました。パスワードをキーリングへ複製せず、所有者のアカウントトークンを権限として使用します。ブラウザー API とローカライズ要求に有限の期限を設け、同時実行されるローカライズ要求とプレゼンス要求をまとめ、ナビゲーションのクリーンアップ時に残ったプレゼンス処理を中止します。

## アクティブなホワイトボードのプレゼンス通信を削減

アクティブ時のプレゼンス更新は最短 2.5 秒、ハートビート送信は最短 10 秒とし、変化がなければどちらも 30 秒まで間隔を延ばします。ポインター更新は 1 秒に 1 回へ制限し、サーバーの最終確認時刻だけの変化では適応型ポーリングを最高速度に維持しないようにしました。

## 既存および保護されたアカウント共有の強化

アップグレード時に既存の共有をリソース登録へ移行します。パスワード保護されたアカウント共有ではプロバイダーへのアクセス前にサーバー側の永続的なロック解除が必要になり、有効期限の解除が保持され、移動後は取り消し確認を停止します。

## 共有カレンダーと有効なミーティングリンクを復元

ユーザーカレンダー共有は受信者のカレンダーへ直ちに配信され、プロバイダー管理の移動先で解決されます。有効なリンク共有ミーティングは古い終了状態を引き継がず、リリース概要はゲストセッション中を通して表示されません。
