# 学習ライブラリーの改善

**機能ブランチ:** feature-update-external-package-contract-definitions

カード編集では、変更を破棄する前にキャンセルの確認を求めます。カルーセルから同じカードを複数回配置でき、各配置をドラッグで並べ替えられます。文の発音プレビューでは各構成カードを枠で囲み、重複する入力表示を省きます。カルーセルのホバープレビューは主要な発音と定義だけを表示し、画面内に収まります。

## 解除可能な音声取得を登録

両方の Study モジュールが同じ解除可能な音声プロバイダー契約を使い、制限付きのローカル読み込みで同梱録音を取得します。認可、キャッシュ方針、合成再生はホストが所有します。

## 初期カードの発音音声を同梱

発音対象の初期カードに、重複を除いたオフライン生成 MP3 と帰属表示を含めました。文は引き続き構成要素を順番に再生します。

## ホバーヒントでプレビューを隠さない

長押しのヒントは予約済みの下部領域に一行で表示し、必要に応じて見た目を省略記号で切り詰めます。翻訳された全文はツールチップ内に保持し、英語のプレビュー内容に重ならないようにします。

## 空白を含む文の構成要素をリンク

文の詳細見出しでは、正規の単語リンクや選択した変形の間の空白を保持します。英語の文から構成単語を開けるようにし、不完全な構成は引き続き拒否します。

## 変形カードのナビゲーションを分離

変形カードの詳細では元のカードに戻る操作を独立した行に置き、その下に前へ・次への操作を並べます。

## アダプターのナビゲーションラベル

Study のナビゲーションは、リクエストなどのアダプターリンクを宣言済みのローカライズされたルートラベルから描画します。Study のホーム画面でアダプターの言語バンドルを要求しません。ゲートウェイ所有の XML 翻訳が欠落した場合の厳格なエラーを維持し、アダプターリンクの重複も防ぎます。

## 中断時に読み込み状態を解放

直接ページを中断すると、翻訳、プロバイダー、コンポーザーの初期化が保留中でも共通の読み込みトークンを直ちに解放します。リソースのクリーンアップは同じホストシグナルに結び付けます。

## 直接ページのライフサイクルと制限された解析

ホストの `mountWhenDirect` は `mount(root, { signal })` にAbortSignalを渡し、確定したルート移動やページ離脱で中断します。ページはこのシグナルにクリーンアップを結び付け、非同期初期化後に確認します。マウント失敗時は所有するリソースを中断し、取り消された処理は移動先にエラーを表示しません。Markdownリンクのラベルではエスケープされた文字と通常文字を分け、曖昧なバックトラッキングを防ぎます。CIはリポジトリ内容の読み取り権限だけを要求します。

## PiPの閉じるボタン

フローティングウィンドウの閉じるボタンは、配信される共通の閉じるSVGとテーマに対応する色を使用します。ホバー時のツールチップには、親の画面タイトルではなく、アクセシブルな名前と同じ翻訳済みの操作ラベルを表示します。

## 閲覧済みコンテンツの永続キャッシュ

Cognis は、閲覧済みライブラリ項目の UUID をアカウントごとに保存するようになりました。カードへのホバー、直接表示、または関連項目経由の表示で閲覧済みとなり、他のユーザーの履歴は公開されません。

## 新着表示と通知

未閲覧で移動履歴のない項目には、プレビューと詳細ポップアップで一度だけ **新着** ピルを表示します。新しいグローバルカードと新しいプロバイダー項目は有効なユーザーへ通知しますが、既存カードの公開範囲の移動では通知しません。

## スコープ別投稿と審査フロー

ユーザーは個人カード、教師はさらに自身のクラスのカード、管理者はグローバルカードを作成できます。承認された昇格リクエストは教師所有のクラスまたはグローバルコレクションへカードを移動し、権限のある降格は元の投稿者へ戻します。プロバイダー保護カードは移動も削除もできません。

## 検索可能で構成可能なライブラリ UI

言語プロバイダーは ctx ケイパビリティでレイヤー所有の作成項目を構成できます。グローバル重複検出は確認のため作成を一時停止し、インポート項目には永続検索インデックスを付与します。ライブラリ検索は全レイヤーを対象とし、任意の定義をカード内容の下に表示でき、複数選択コントロールを指定されたカード境界へ配置してフローティング操作を復元しました。

## 言語定義の作成フローを完成

言語パックは、作成可能な各レイヤーに検証済みの `cardConstructor` を宣言するか、公開 ctx ケイパビリティ `study:library:provider` から登録できるようになりました。Cognis はプロバイダー項目とロール対応の公開範囲・クラス制御を合成し、必要な場合だけクラス選択を表示して、権限のある教師と管理者へ審査リクエストを提供します。

## カード内に収まる状態表示と状況別の公開操作

カード端の公開範囲、新着、選択コントロールを各カードの左右境界内に収め、狭いプレビューでは主値へ大部分の幅を割り当てるようにしました。複数選択にはホバー式の「公開先」メニュー、内容のあるローカライズ済み削除ボタン、保留申請の取り下げ、権限付き差し戻しを追加し、不要な閉じるボタンを削除しました。

## 簡潔なリンクと高度な発見

関連項目の操作には各カードの主要値だけを表示するようになりました。子カードは表面をより明確にし、背景との分離を強め、独立してホバーできる新着マーカーを備えます。詳細ポップアップは文字、語彙メタデータ、共通の関係を基に同じレイヤーの類似項目を提案し、言語プロバイダーは追加のメタデータフィールドを学習者向けフィルターとして公開できます。

## 正式な外部パッケージ契約

Study Library は、ローカライズ済みおよびプロバイダー固有のメタデータ、宣言的に検証される拡張可能なフィールド型、アセット一覧、パッケージの所有権と保護、意味表現、定義のローカライズ、関心情報、アクティビティ互換性を検証して保持するようになりました。合成パッケージフィクスチャは本番プロバイダーの構造を再現し、公開プロバイダー機能は実際のパックをインストールせずに検査できます。

## Library 閲覧とプロバイダーライフサイクルの修正

Library の検索および編集コントロールをコンパクトでテーマに依存しない表示にしました。右クリック選択を確実に捕捉し、入れ子の子カードのホバー領域を維持し、文字以外のカードでは不要な省略をせず読みと定義を完全に表示します。コンテンツプロバイダーが言語の利用可否を正式に管理するようになりました。コンテンツレコードは名前空間付きクラスに対応し、メディア一覧は取り込み後も利用でき、カスタムエディターは検証契約に従い、組み込み制約を適用し、インストール受領情報にプロバイダーメタデータを保持します。

## 安定した Library 操作と均整の取れた文カード

文カードは一貫した上限付きの高さを使い、重複する発音プレビューを省略し、主テキストと定義をそれぞれ 2 行に制限します。検索のクリア操作を 1 つに統一し、編集アイコンは明示的なテーマ別アセットで表示し、削除ダイアログをローカライズし、語彙詳細にかな読みを表示します。右クリック選択はマウント済みの各 Study ページでドキュメント境界から捕捉され、正式なプロバイダー更新では、部分パックが明示的に無効化しない限り最新パックにないレコードを削除します。

## 公開リクエスト専用ナビゲーション

公開確認を Library ページのツールバーから Study サブナビゲーションの専用リクエストページへ移しました。確認可能な保留リクエストがある場合は、視差効果を減らす代替表示付きの赤い呼吸状輪郭でリンクを強調し、最後の確認が完了すると表示を解除します。Library の検索クリアアイコンはライトテーマとダークテーマの両方に対応しました。

## 言語単位の管理とガイド付きカード編集

Library 管理画面は選択中の言語のレイヤーを平坦なメニューで表示します。カードクラスを表示して安全に編集でき、定義と複合項目には所定のクラスを強制し、定義は学習者から常に非表示にし、助詞とプロバイダーがロックしたレコードは編集できません。ダイアログは表示と編集を明確に区別し、保存操作と未保存変更保護を備えます。カード作成は学習者向けページのガイド付き `+` アクションへ移動し、送信者は申請状態を確認でき、ポップアップタイトルの読みはプロバイダーリンクを保持し、Study 言語の可用性はページ読み込みごとに再取得されます。

## 学習カード操作の信頼性向上

削除権限にかかわらず学習カードに選択コントロールを保持するようにし、ブラウザーのメニューを開かず右クリックで確実に複数選択へ移行できるようにしました。作成操作はプロバイダーが提供するカードコンストラクターを検出し、ページ操作用 CTX ケイパビリティーを通して「+」ボタンを登録します。

## 初回読み込み時のリクエストナビゲーションをローカライズ

「リクエスト」ナビゲーション項目が、それを所有する Library ルートからローカライズ済みの代替ラベルを受け取るようになりました。翻訳バンドルの読み込み中でも、サーバーやブラウザーの初回読み込み時に内部パス `/study/library/requests` が表示されません。

## 順序付きシーケンスの関係ロール

コンテンツパック検証では、合成関係だけから順序付きシーケンスのラベルを再構築するようになりました。発音および代替表記の関係は字句レコードを対象にして独自の位置列を使用でき、`ordered_sequence_content_unresolved` を発生させません。これにより日本語学習プロバイダーのコントラクトと一致します。

## コンテンツクラスと逆リンクを明確化

詳細ビューでは構造用の composite クラスを隠し、プロバイダーのクラス末尾を読みやすい Pill に変換し、複合見出しを二列にして読みを主要テキストの下に配置します。同じラベルの逆引き語彙リンクは、作成済みの順方向表記関係を削除せずに抑止します。

## 子カード分岐へのフォーカス

子カードの分岐を開くと、無関係なカードの表示範囲アイコンをぼかし、他の親カードのホバー時の浮き上がりと強調を無効化します。アクティブな分岐は鮮明で操作可能なままです。

## 同一所有者による安全なスキーマ更新

権威あるコンテンツパックの新しいリリースが、同じ互換バージョンで自身の保存済みスキーマを改訂できるようになりました。所有権チェックによるスキーマ衝突防止を維持し、トランザクション取り込みの成功後にのみスキーマキャッシュを更新するため、最新の日本語パックを以前のリリース上で正常に有効化できます。

## 信頼できる複数選択コントロール

Study Library は、削除可能なプロバイダーレコードがない表示を含め、カードが複数選択モードに入れる場合にフローティング操作メニューを常に用意するようになりました。選択チェックボックスにはポインターカーソルも使用し、操作可能であることを明確にします。

## 無効言語の非表示と学習状態の維持

ライフサイクル更新中に古いプロバイダー capability が一時的に残っていても、無効化された言語モジュールは Study から完全に除外されます。コンテンツパック更新では閲覧済み状態を維持し、パック全体を再通知せず、実際に新規追加された安定レコードだけを通知します。

## リンク付きタイトル詳細の重複排除

Library の詳細見出しは、主要タイトルと二次表記詳細の間で正規化文字列とリンク先を比較するようになりました。主要タイトルですでにリンクされている表記は詳細行から除外しつつ、同じ文字列でも実際に異なるレコードへのリンクは維持します。

## 依存専用の読み関係

外部パッケージ契約では、resolverRole と presentationRole を持たない関係を依存専用エッジとして扱うようになりました。タイトル構成とは推論せず、逆方向ナビゲーションと削除保護のために保持し、日本語プロバイダーの `reading-kana-dependency` グラフに対応します。

## 逆方向関係の統合

Library 詳細では、語彙での使用とその他の受信依存関係を 1 つの「使用元」セクションに統合しました。見た目が同じ正規化ラベルは 1 つのリンクにまとめ、語彙関係を優先します。

## バランスの取れたタイトル配置

複合ポップアップタイトルは行間を狭め、読み詳細との距離を近づけました。関係の重複排除で隣接項目がなくなった場合も、カードプレビューのタイトル、読み、定義は中央揃えを維持します。

## 予測可能な複数選択

表示中のカードをすべて選択すると、フローティング操作が「すべて選択解除」に変わります。選択解除時や SPA ページ移動時には複数選択モードを確実に終了します。

## リクエストを目的別に表示

リクエストページに状態別・所有者別フィルターを追加し、レビュー一覧は管理者と教師にのみ表示します。

## より安全なカード編集

音声を任意項目にし、カードから決定的に生成したキーで保存します。タグ入力中の Enter ではフォームを送信せず、チェックボックスには Cognis スタイルを適用し、キャンセル操作にはキャンセル用スタイルを使用します。また、文字レイヤーの項目は作成・編集できません。

## Library の自然スクロール

Library 画面でページコンポーザーの自然スクロールを有効にしました。

## ガイド付き複合カードデザイナー

複合カードの各関係レイヤーに、選択順を保持する横型カルーセルを追加しました。作成操作は常に表示され、入れ子のカードコンポーザーを開けるため、親の下書きを失わずに不足している構成要素を作成できます。自由入力では一致する構成要素を提示し、一致しない文字列を明示します。

## 安全な構成要素の公開範囲と音声再生

参照する構成要素が複合カードの公開先から見えない場合、サービスが作成を拒否します。無効な旧形式の音声プレースホルダーによる失敗リクエストも抑止します。

## 確実な「すべて選択」の切り替え

「すべて選択」はチェックボックスの状態からクリック動作を推測せず、明示的な操作状態を持つようになりました。最初の操作ですべての表示カードを選択して「すべて選択解除」に切り替わり、後者を押した場合にのみ複数選択を終了します。表示項目の検出は学習カードと管理行の両方に対応します。

## レイヤー選択と未一致テキストのガイド付き作成

作成フローの最初に、許可されたカード種類を選択できるようになりました。一致しない自由入力テキストを選ぶと、適切な入れ子コンポーザーが開き、そのテキストがカード名へ自動的に引き継がれます。

## 公開範囲に応じた編集と更新レビュー

管理行は管理エディターだけを開き、独立した編集ボタンを維持します。ユーザー向け詳細ダイアログでは、対象カードに限り右上に編集操作を表示します。所有者は自分のカードを編集でき、管理者はグローバルカードを編集できますが、保護されたプロバイダーコンテンツは変更できません。作者によるグローバル公開カードの変更は更新リクエストとして保存され、承認後にのみ反映されます。リクエストページでは更新を区別し、完了済み状態も保持します。

## 作成操作の表示

文字レイヤー以外のすべてのユーザー向けレイヤーに作成操作を表示します。プロバイダー固有のコンストラクターがない場合は、スキーマに基づく汎用コンストラクターを使用します。

## 無効化された言語プロバイダーを即時非表示

Study は、設定、ダッシュボードカード、検索グループ、子ページを描画する前に、保存済みの学習言語設定をゲートウェイの現在有効なプロバイダー一覧と照合します。無効化されたプロバイダーは保存設定を削除せずに「有効な言語」と Study ダッシュボードの両方から消え、管理者が再度有効化すると自然に復元されます。

## クラス表示と編集操作を常に確認可能に

複合項目と順序付き文の詳細には、読みやすいクラスピルを常に表示します。保存済みクラスがない旧データには「Composite」を補完します。Library 管理画面では表示中の全レコードに編集操作を復元し、管理者はプロバイダー管理レコードも編集できます。学習カードにはサーバーがユーザー向け編集を許可した場合に編集操作を表示し、対象の詳細ポップアップにも右上へ同じ操作を表示します。サーバー由来の権限情報により、管理者のグローバル編集、所有者編集、レビューが必要な作者更新を、古いブラウザー内ロール状態に依存せず一貫して扱います。

## キーリングのペイロード容量を拡大

保管庫の標準容量は2 MiBで、プロセス内処理の絶対上限は8 MiBです。有効なポリシーをクライアントに返します。PUTはバッファリングやJSON解析の前に受信バイト数を数え、過大なリクエストを拒否します。GETは解析前に保存サイズを確認します。暗号化済みのデータは基本行とサイズ制限付きの追加行に保存し、置換と削除をアトミックに行い、結合した単一のクエリで読み取ります。各行はUTF-8最大60,000バイトで、サーバーは引き続き秘密情報を復号しません。

## 構造化されたカード作成と編集

カードの編集操作は詳細ダイアログ内だけに表示し、テーマ対応の編集アセットを使用するようにしました。幅を広げたエディターでは、内容、関連、集約された定義をタブで分け、ローカライズされた定義には対応するすべての UI 言語を表示し、関連付けられた定義をその場で編集できます。作成時のラベルは解決済みの構成要素から自動生成され、一致しないテキストは解決または新規作成が必須です。横方向カルーセルのスタイルも復元し、テーマ対応の作成操作を拡大しました。

## 作成コントロールを改善

Library の作成操作は通常のボタン寸法を維持し、プラス記号だけを 2 倍にしました。作成タブを正しく初期化し、ユーザースコープを既定値にしました。権限のある管理者は全体公開を選択でき、教師には有効な言語と一致する書き込み可能なクラスがある場合だけクラス公開を表示します。コンテンツクラスは関連する役割でのみドロップダウン表示し、構成フィールドを「入力」に変更して、フォーカス時に関連カルーセルを表示します。

## より賢い常設コンポジション

入力および発音の各セクションでは、コンストラクターがそのセクションのカルーセルを宣言している場合、選択済みカード欄を常に表示します。既存の選択内容で欄を初期化し、カルーセルの変更を即時反映し、表示中のカードを選ぶと同じカルーセル状態を通じて削除できます。

## 複数値カルーセル構成と安全な削除

プロバイダーフィールドは `multi_value` で複数値構成を有効化できます。コンポーザーはフィールド別の保存操作と確定値ピルを追加し、置換のための再編集、設定済みカルーセル内カードだけを対象とするテキスト候補、未解決自由入力の拒否、専用 × 操作による確認付き削除を提供します。既存項目の編集画面にも、作成フォームと同様に宣言済みカルーセルを表示します。

## 複数値ステージングで確定済み値を変更しない

フィールド直下の `multi_value` を正式な契約として取り込むようになりました。確定済みピルは空で始まるステージング欄から分離され、表示中の保存操作だけがステージ中の参照を確定します。小型の × 操作は確認なしでステージ中カードだけを削除し、保存済み値を変更しません。確定済みピルをクリックしてもステージングへ再読込しません。

## 正規ラベルと即時プレビュー

定義以外のカードフォームでは、独立したラベル欄を表示しません。ラベルは順序付きの主要 Input 構成から生成され、直接編集を保存するとカードブラウザーを直ちに再描画して、プレビューを保存済み項目と一致させます。複数値フィールドが受け付ける契約はフィールド直下の `multi_value` だけです。このブランチで導入したネスト形式は互換コードとして残さず削除しました。

## 切れないツールチップとプレビュー

音声不足ツールチップはカード内の絶対配置ではなく、ビューポートを考慮する body ポータルを使用します。これにより、ポップアップやカードのオーバーフローで文字が切れません。追加の定義文がない場合も含め、すべてのカルーセル項目でホバー時とキーボードフォーカス時のプレビューを再表示します。

## グループ化した複数発音

Library 契約を日本語学習プロバイダーのグループ化発音グラフへ合わせました。関係は `grouped: true` を宣言でき、項目は関係 ID をキーとする `referenceGroups` を持てます。各入れ子の順序付き文字配列は、それぞれ独立した発音に属します。コンテンツパック検証、ハッシュ化、保存、API、作成・編集コンポーザー、タイトルリンク、派生音声の走査まで、その境界を一貫して保持します。

## 非表示カードを候補から除外

コンポーザーカルーセル、自由入力のカード候補、発音候補から、非表示に設定された項目を除外します。既存カードにすでに設定された非表示依存関係は基礎となる関係値として維持しますが、選択可能なカルーセルカードとしては公開しません。

## 発音グループの欠番による読込失敗を修正

ライブラリストアは各グループを並べ替える前に、グループ化参照番号の欠番を詰めるようになりました。保存済みグループ番号に欠番があるエントリも例外なく読み込め、発音順は一定に保たれます。

## カードの発音表示を簡潔化

ライブラリカードには先頭2件の発音だけを表示するようになりました。それ以外の発音は、完全なエントリ詳細画面で引き続き確認できます。

## グループ化された発音の重複を修正

発音ラベルを比較する前に、入れ子の文字列を完全な読みに連結するようになりました。カードの値と一致するグループ化された読みが重複表示されなくなりました。

## 表示された発音リンクのタイトル重複を修正

発音の重複判定で、リンクされた文字カードのラベルを連結し、表示中のカード値と比較するようになりました。空白とUnicode表現を正規化するため、保存されたフィールド形式にかかわらず同じリンク読みは省略されます。

## 複数関係にまたがる発音グループを正しく検証

複数のフィールドリンク関係で一致するグループ番号を、同じ複数値フィールド項目として扱うようになりました。並行する関係のグループ数を合計せず最大値で検証するため、最新の日本語コンテンツパックを正常に有効化できます。

## 発音詳細を深く解決し再描画の比率を維持

カード値と一致する発音は同じ表記を繰り返さず、リンク先カードの発音値まで解決するようになりました。描画練習では、開いたウィンドウが異なる列数のパターンを読み込む際にステージ比率を再適用し、キャンバスを同期します。

## Escapeで描画練習を閉じる

アクティブな描画練習ウィンドウをEscapeキーで閉じ、通常のアニメーション付き後処理を実行できるようになりました。

## 読みタイトルで完全な表記グループを維持

タイトルの重複除去は、発音内の個別文字ではなく、完全に重複する参照列だけを削除するようになりました。主値と一致する表記は文字レイヤーの発音へ解決され、部分的な読みや主値との不一致を防ぎつつ、プロバイダーが記録した漢字の読み一覧を維持します。

## 削除範囲を限定し定義不足時の入力を保持

ステージ中のカードはコンパクトな×ボタンだけで削除され、構成フィールドの他の部分では削除されなくなりました。作成ポップアップを閉じる前に関係の最小数を検証するため、定義不足ではトーストを表示し、修正用にすべてのComposer入力を保持します。

## 読みやすい見出し詳細と作成上限

長い発音と定義は主値の横で幅 40% 以内に収まり、追加の行へ折り返されます。定義の先頭にはダッシュを表示して区別を明確にしました。カード作成ではタグ 8 件、定義 10 件、発音 16 件を上限とし、各上限をローカライズされたトーストで通知します。

## 密な見出し配置と編集上限

発音によって拡張される見出しでは、スピーカーをスコープアイコンの下に配置し、読みを幅 40% の折り返しブロックに収め、定義を右側の独立した行として表示します。タグ、定義、発音の同じ上限を作成と編集の両コンポーザーで適用します。

## 子カードの適応的な斜め配置

展開した文字の子ブランチは、優先方向が境界を越えるか衝突する場合に両側の斜め位置を試します。表示中のルートカードも衝突判定に含めるため、子カードと接続矢印をライブラリのキャンバス内に保ちながら、実際に空いている斜めスロットを選択します。

## 文の構成要素と変形ツリー

言語プロバイダーは文の接続表現にプロバイダー所有のタグを付け、文専用のフィルター済みカルーセルで提供できます。繰り返し使える句読点は 1 行の読み取り専用カルーセルに表示されます。タグで絞り込むレイヤービューは動詞と副詞を通常の語彙ページから分離し、ウィジェット幅いっぱいの変形ツリーページに移します。スキーマの宣言的な変形セットは、すべての活用をカード化せず、基本形カードから接尾辞ベースの状態経路を生成します。

## 成熟した文構成・変形ワークフロー

文の接続表現カードは専用のフィルター済みコンポーザーカルーセルだけに表示され、編集時には繰り返し句読点が作成順に復元されます。変形ノードは生成形のインラインプレビューを更新します。スキーマ検証では、曖昧または無効な句読点・変形宣言も拒否します。

## 書き取りパッドの文字間隔を縮小

複数文字の書き取りパッドは、各文字の筆画の範囲に合わせて余分な横方向の空白を取り除き、小さく均等な文字間隔を保ちます。ウィンドウの幅をコンパクトなパターンに合わせて縮め、サイズ変更やカード切り替え時も文字の縦横比、筆順、時間情報、筆圧、ポインターの位置合わせを維持します。

## 書き取りパッドの初期高さを調整

パッドの初期高さは、画面の高さの70％を上限とする固定の余白ではなく、描画キャンバス、見出し、操作ボタンに合わせて決まります。高さの低い画面では、筆画の縦横比を保ちながらキャンバスの高さを調整し、リセットボタンが常に見えるようにします。別のカードを読み込むと、内容に合わせてサイズと位置を調整します。

## 連続したカード選択でガイドを更新

書き取りパッドを開いた状態で描画可能なLibraryカードを選択すると、連続するカードのキャンバスサイズが同じ場合も、新しく読み込んだパターンを毎回再描画します。サイズ変更やウィンドウの開き直しをせずに、カードを切り替えるたびにガイドがすぐ更新されます。

## 書き取りパッドをメインページ内に配置

書き取り練習はメインページ内に表示されるようになりました。移動とサイズ変更はスクロール可能なページ内容の範囲に制限され、ヘッダーやフッターを覆いません。高さの低いウィンドウでも自然な描画高さを保ち、メインページを縦にスクロールして操作ボタンにアクセスできます。

## インライン作成の文字リンクと読みを修正

インラインでのカード作成では、保存前に仮選択中の発音用文字を確定します。検索ですでに取得した読みを保存すると、発音を重複させずに選択した文字へのリンクを付けます。検索結果は発音一覧の改行形式ですぐ再表示され、主入力を変更しても自動生成した語彙と文の読みが表示されます。詳細見出しは一覧内の位置ではなく読み全体で文字グループを照合し、未リンクの読みも正規の文字カードに結び付けられます。

## 変形と複合かなのリンク

変形した語彙の見出しと読みは、表示中の形を構成する正規の文字単位にリンクします。「使用元」には完全に解決できる正規の表記と読みの構成も含まれるため、保存済みの参照がより小さな単位を指す場合でも、複合かなから語彙へ戻れます。保存済みの関係は引き続き表示され、不完全な構成から部分的なリンクは生成されません。

## 詳細の直接関係

詳細の関係一覧には直接隣接する項目を表示します。「使用元」、使用例、関係ツリーでは、別の表記や読みの親項目を経由して到達する項目を除外します。グループ化された参照も対象です。直接のリンクは引き続き利用でき、循環参照による繰り返し探索は発生しません。類似項目には引き続き同じ階層の項目を表示します。

## 並行する直接リンクの保持

同じカードに中間項目を経由して到達できる場合でも、直接の関係は表示されます。保存された参照、グループ化された参照、見出しを構成する正規の文字単位は直接リンクを保持し、あ → ある + あるく と あ → ある → あるく の両方に対応します。別の親項目を経由する場合にのみ到達できる関係だけを除外します。

## 変形カードの読みと元の形

変形したカードでは、正規化後に表示中の見出しと一致する読みを省略します。異なる読みの文字リンクは保持されます。翻訳された「{{ verb }} に戻る」操作で元のカードを表示し、選択中の変形を解除します。通常のカード移動は引き続き利用できます。

## 依存関係の公開範囲と削除

依存関係の保存では、グループ化された参照を含む各リンクの公開範囲を検証します。個人用カードは閲覧可能な共有カードと自分の個人用構成要素を使用できます。クラス用カードの構成要素は全体公開または同じクラス用、全体公開カードの構成要素は全体公開である必要があります。変更申請は送信前に参照スキーマを検証し、公開の承認時には最新の依存関係を再確認します。変更によって審査中の公開申請を無効にすることはできません。共有カードや審査中の申請が広い公開範囲を必要とする場合、個人用への変更を禁止します。作成と編集の応答には、クラスの書き込み権限に対応した操作権限を含めます。

削除時には、グループ化された参照を含め、連鎖削除と削除制限の対象となる削除可能な依存カードをすべて確認します。参照を切り離すだけのカードは保持します。トランザクションは、削除前に対象カードすべての所有者、クラス権限、保護状態、審査状態を検証します。別の連鎖削除で対象になる制限付きカードは、探索順序によって失敗しなくなります。共有カードの作成時に依存項目の公開範囲が狭い場合、個人用としての保存を選択できます。公開支援では、非表示の定義を含む公開可能な末端の構成要素を先に申請し、承認後に親カードを申請できます。

削除の確認はサーバーが保存済みのスキーマバージョンを使って計画し、現在のページに表示されていない依存カードも含めます。Study ゲートウェイクライアントはデータを変更しない削除事前確認を提供します。

## 辞書のインポートと下書き

辞書の検索結果を確認してから、発音、分類、タグ、参照、語義ごとの定義を適用できます。インポートした発音は、手動で保存した発音と同じ操作部品ですぐに表示されます。自動生成した発音は主入力の変更に追従し、ユーザーの別の発音を保持します。必須タブの印は一つになり、定義の追加ボタンも小さくなります。

不足している翻訳を取得する操作は `{ translations, languages }` を `POST /api/v1/study/library/definitions/localize` に送信します。`localization:translateString` で不足する UI 言語を取得し、既存の翻訳を保持します。プロバイダーがない場合や失敗した場合は `missingLanguages` を返します。不足する訳文は編集でき、英語を別の言語の欄にコピーしません。定義を手動で追加する場合にも利用できます。

## 管理者のカード作成と筆順検索

管理者は公開チェックボックスなしでグローバル名前空間にカードを直接作成します。インライン作成や辞書インポートの定義も同じ公開先を使い、非公開の依存カードは保存前に公開する必要があります。筆順欄の検索は辞書プレビューを開かず、提供された筆順をすぐに適用します。

関連するスタイル、検証、永続化、コンストラクター調整、テストのコードを分割し、リポジトリのファイルサイズ検査に対応しました。文書の構造とUIテストの探索も修正しました。

## 検索結果を開いている編集画面に反映

辞書検索は結果ポップアップや適用操作を挟まず、開いているカード編集画面に値を直接反映し、返された定義と発音をすべて確定します。既存の値がある場合は検索前に置き換えを確認します。キャンセルや結果なし、検索失敗の場合は現在のカードを保持します。筆順検索に成功すると検索ボタンを非表示にします。辞書の出典URLはリンクとして表示せず、非表示の出典データに保存します。

## 参照を解決するインポートと定義の編集

辞書インポートは、通常のリンクやグループ化したリンクを追加する前に、提供元のレコードIDをアクセス可能なインストール済みカードに対応付けます。参照先が見つからない、または曖昧な場合は警告し、保存を妨げずに値をリンクなしで保持します。確定した定義は既存の権限確認付きカード編集画面で編集でき、保存すると編集画面の要約も更新されます。辞書出典データなどの非表示スキーマフィールドはフォームに表示せず、保存された値を保持します。

## カード編集の検索修正

取得した筆順がある場合、辞書の検索結果や保存済みカードから読み込んだ場合も筆順検索ボタンを非表示にします。筆順を消去すると検索が再表示されます。定義編集では翻訳を「内容」に表示し、不要な「定義」タブを省きます。セミコロンで区切られた辞書の意味を個別の確定済み定義として取り込み、対応する翻訳と元の出典メタデータを保持します。構造化された意味がある場合、まとめられた出典定義へのリンクを置き換えます。

## 辞書の発音リンク

辞書から取り込む発音は、全体を構成できる最長の一致を使ってインストール済みの仮名に解決します。きょやっくなどの複合文字と同じ文字の繰り返し位置を保持します。読みグループには正規の項目IDを順序付きで保存し、不足する文字がある読みを部分的にリンクしません。定義は一致するカードを再利用し、必要な場合は通常の編集処理で作成します。下位カードの作成は引き続きカルーセルを中心に行います。文字と助詞は提供元のみが作成する読み取り専用のレイヤーを維持します。文の編集画面では辞書検索を提供しません。

## 辞書の候補を選択

語彙作成では、不要な「入力」見出しを省き、組み合わせたカードの入力欄を一つ使用します。辞書検索をその直下に表示し、選択した構成カードを含む全体の文字列を検索します。語彙の発音は漢字の読みから自動生成せず、手動入力または辞書からの取り込みで設定します。一件の結果は直接編集画面に反映し、複数の結果は「複数の候補が見つかりました」という見出しの下にカードのプレビューを横並びで表示します。候補をクリックして確認すると、項目、発音、定義、タグ、関係を取り込みます。候補を選択するまで確認ボタンは無効です。キャンセル時は現在の編集内容を保持し、定義を作成しません。辞書で確認したカードの文字列は送信でき、その後文字列を変更すると再度解決が必要です。文の発音は引き続き構成要素から導出し、文の辞書検索は無効のままです。

## 語彙の入力を保持

語彙の辞書検索は、入力したテキスト、構成要素の順序、選択した入力カードを保持しながら、補足フィールド、発音、定義を取り込みます。フォームはAPIと同じ正規化比較で一致する定義を再利用します。新しく取り込んだ定義は直ちにキャッシュされ、同じ意味の繰り返しによる競合を防ぎます。再利用時は保存先の公開範囲を守り、既存の定義の翻訳を保持します。

## 変換した文と公開範囲の移動

文の作成、編集、詳細表示では、順序付き参照ごとに選択した変換から発音を導出します。同じ語根の繰り返しにも個別の位置と変換経路を保持します。定義済みの句読点は隣接するタイトルリンクを妨げずに表示されます。タイトルと発音のリンクは選択した形を開き、語根に戻る操作を保持します。公開範囲の移動は登録済みのStudy Libraryフローを実行し、更新した権限を返します。自分のカードは移動後も表示されます。共有カードは元の作成者のユーザー範囲に戻るため、操作名は「移動先: ユーザー」です。プロバイダー所有コンテンツ、共有の依存カード、審査待ちの申請、アクセス制限は引き続き不正な移動を防ぎます。開発者向け指示では、実行可能な実装のない機能、操作、ルート、フローの公開を明示的に禁止しています。

## 簡潔なコンポーネント実装

入力検証、識別子のパターン、定義言語、派生方向は共通の役割別ヘルパーを使用します。コンテンツ音声処理は専用モジュールに分離し、コンテンツパックは安定したレコード識別子を直接使用します。

## 移動先を直接選択

選択したカードに「移動先:」と、利用可能な公開・クラス・非公開の移動先アイコンを表示します。各アイコンから対応する範囲変更を直接開始できます。クラスを選ぶとクラス選択画面が開きます。

## 辞書検索とキャッシュ

辞書提供元は `searchable: true` と `dictionary` 機能でナビゲーション検索を有効にします。辞書検索が許可された対応レイヤーのみを検索し、文は対象外です。専用の検索結果ページにカードのプレビューと全定義を表示し、元データは非表示のメタデータとして保持します。明示的なインポートには通常のカード作成画面を使用します。Cognis は提供元、スキーマの版、正規化した検索語ごとに結果を24時間保存し、同時検索をまとめ、再起動後もキャッシュを保持します。更新すると提供元に再問い合わせします。ローカルカードと発音リンクは現在アクセス可能な Library で解決します。Jisho に差分配信 API はないため、新しい項目は更新または期限切れ後に検出します。

## レビューと範囲変更

管理者とオーナーは個人カードを権限のある共有範囲へ直接移動し、学習者はレビューを申請します。移動先の文字とアイコン全体がボタンになります。申請には提出したカード、変更案、範囲、作成者、日時、状態、権限に応じた操作を表示します。取り下げを含む判断履歴を保持します。カードの変更と判断を同一のデータベーストランザクションで確定し、保留状態からの条件付き更新で重複操作を防ぎます。検証に失敗した判断は取り消され、古い申請や重複操作にはエラーを表示します。提出時の内容を保持し、元カードが変更された後の承認を防ぎます。

## 効率的な辞書参照解決

辞書結果は参照カードの読み込み前に表示されます。プレビューでは参照先のエントリーIDまたは提供元IDと、発音に必要な基本文字だけを取得します。カルーセル用の全ライブラリは編集画面やリンク先カードを開く際に読み込みます。カード一覧の参照はカードごとではなく一括取得します。申請一覧は取得済みの行を利用し、権限のない申請や完了済み申請の元カードを再取得しません。検索と審査プレビューでは非表示フィールドに同じ表示条件を適用します。期限切れの辞書キャッシュは期限インデックスを使用し、書き込み時に削除します。承認による移動も、判定トランザクション内で直接移動と同じ登録済みフローを実行します。

キャッシュに一致した場合も登録済み検索フローを実行するため、拡張フックが一貫して適用されます。

学習ナビゲーションは保留中の審査項目だけを取得し、申請ページではすべての状態の履歴を保持します。

## コンパクトなStudyナビゲーション

辞書検索をコンパクトな検索アイコンとともに一行で表示します。保留中のレビューは赤い枠ではなく、ナビゲーションのアクセント色の下線で示します。

## 安定した辞書検索

Jisho はホストからの要求に応じて最新の語彙と漢字データを取得します。単語や読みの完全一致を関連候補より優先し、通常かなで書く語はかな表記を維持します。Wikipedia の記事名だけの候補は除外します。読みがない場合に定義を発音として表示したり、発音を作り出したりしません。定義と元データは分けて保持し、すべてのキャッシュ方針は Cognis が管理します。

Cognis core は `core:cache` で辞書キャッシュを管理します。保存した検索は一時間後にコールド状態となり、次の利用時に提供元の変更を確認します。変更結果は十二時間の反映時刻まで保留し、変更のない内容は維持します。同時検索は一つの確認を共有し、確認失敗時は最後に成功した結果を保持します。状態は再起動後も残ります。モジュールは提供元のデータを取得するだけで、検索のスケジュールや独自の応答キャッシュを管理しません。Jisho に軽量な変更通知 API はないため、確認には通常の検索応答が必要です。手動の更新ボタンはありません。発音とカードのリンクは常に現在アクセスできる内容から解決します。

## 整理された申請と移動

自分の申請は提出した全状態を読み取り専用で表示します。保留中が唯一のレビュー一覧です。ヘッダーには申請者と確認者のプロフィール画像とリンクを表示し、決定時刻は状態バッジで確認できます。カード名、主要な発音、定義を展開可能な一行の概要にまとめ、関連カードを関係ごとに整理します。公開範囲を狭める操作にはキャンセルボタンのスタイルを使用します。移動方向が相反する選択や変更のない移動先では、該当する選択を解除するまで操作を無効にします。

## 辞書の読みのグラフ

辞書の元データは作成画面と詳細画面で非表示のメタデータとして保持します。取得した発音には親カードと同じ公開範囲の非表示語彙カードを使用します。複数の読みを持つ漢字では各読みに非表示カードを作り、名前を元の漢字へ、発音を順序付きのかなへリンクします。読みが一つの漢字は直接かなへリンクします。単語全体の読みは利用可能な最も近い漢字の読みの構成要素と残りのかなで構成します。定義は非表示の読みへ直接リンクします。Cognis は提供元の識別子を解決し、通常のフィールド、レイヤー、依存関係、ACL の検証を通してグラフを一括保存します。文字と助詞の作成は提供元に限定します。同じひらがなの読みを繰り返すだけのカタカナ候補は、辞書がそのカタカナ表記を示す場合を除いて除外します。漢字の正式な音読みと実際の外来語の読みは保持します。

## 検証済みの操作ステージ

辞書の再取り込みは一致する非表示の読みカードを再利用し、重複競合を起こしません。所有者の検証と保存は対応する ctx ステージで実行し、編集には更新フローを用意します。フックの拒否時は書き込みをロールバックします。不正な検索入力には安全な検証コードを返し、予期しない内部障害には一般的なサーバーエラーを返します。共通の定義検証はコンポーネント内の reuse に配置します。 Core 0.3.109 は `FlowRunOptions` に呼び出しごとの任意の `handlers` を追加します。所有者の処理は登録されたステージの拡張フックより先に実行し、結果を `stageResults` に加え、その呼び出しだけの `data` を共有します。不明なステージは実行前に拒否し、ステージの失敗は後続処理を止めます。コンポーネントは自身のトランザクション内で保存し、拡張フックの失敗時に書き込みを取り消します。呼び出し別の処理はグローバルフックとして保存しません。

## 構成と移動

カルーセルのカードにポインターを重ねると、位置番号の代わりに一致する配置すべてが強調されます。ポインターでドラッグすると、文字を選択せずに各配置を並べ替えられます。入力した動詞の候補も、幅を広げた２列の活用選択を開きます。登録済み定義はごみ箱から関連付けを外せ、辞書の意味順を維持します。画面の再登録では以前のイベントリスナーを解除し、一括削除の確認は１回だけ開きます。

共有カードを個人領域へ移動するには、管理者自身も確認と管理者審査への申請が必要です。承認時にアクセスを失う依存カードを再計算し、その連鎖削除と移動を同一トランザクションで行います。利用可能な個人カードは残ります。保護カード、プロバイダーのコンテンツ、依存する審査中申請がある場合は承認できません。通常の削除権限は変わりません。申請成功はトーストで通知し、削除されたカードの所有者にはStudyカテゴリの通知を送ります。move-to-personalエンドポイントは、移動済みカードではなく、審査中申請をHTTP 201で返します。

## 辞書と活用

活用カード内では見出し、読み、定義を同じ列に揃えます。原形を使う操作は中立スタイルのボタンです。ドラッグ中は移動先の前後に縦の挿入マーカーを表示します。Jishoから読み込む語彙には対応する活用グループのタグを保存し、新しく作った動詞は親の構成に配置する前に活用選択を開きます。副詞の品詞も保持しますが、現在の日本語スキーマには副詞の活用セットはありません。

辞書プロバイダーはprerequisitesとして{ key, layer, label }の配列を返せます。作成画面で候補を選択した後、Cognisは指定の公開範囲で既存の複合文字カードを解決し、なければ辞書から取得して定義と読みのグラフを含むカードを作成します。この経路では原子的な文字と助詞を作成できません。主カードと非表示の読みの参照では、別名キーを正式なIDに置き換えます。語彙の入力は変更せず、読み込んだ表記リンクは入力が検索語と一致する間だけ使用します。検索結果を見るだけでは依存カードを作成しません。

不足する必須フィールドは、保存前に登録済みの補助検索プロバイダーから取得します。漢字の筆順パターンにはKanjiVGを使います。各漢字、定義、非表示の読みは、公開範囲を検証した１つのグラフとして保存します。

## 書き取りパッドの位置を保持

開いている書き取りパッドに別の文字を読み込んでも、ドラッグで移動した位置を含め、現在の位置を保持します。初期位置は新しいパッドを開くときだけ適用します。

## カード識別とインポート

重複カードの統合は登録済みフローで実行します。管理者は追加内容を即時反映し、学習者は共有カードのレビューを申請します。元の入力構成と単一値を保持し、別の読み・意味・タグと許可された非表示読みカードを追加します。個人用の依存カードを共有グラフに追加することはできず、失敗時は下書きを保持します。同じ構成の辞書結果は読みと意味をまとめます。異なる長い表記を選ぶと即時適用し、続行または閉じる操作では完全一致の構成を使います。取り込んだ読みは非表示カードをたどって個別の仮名に解決し、編集時は古いグループ参照を置き換えます。作成成功時は通知を表示します。同じ関係のカルーセルは、文構造カードを含む互いの選択を保持します。

フィルターは選択中のレイヤーの表示内容に合わせます。移動ではカード識別子を保持して `relocatedAt` を記録し、個人用と共有の範囲を繰り返し移動しても新規カードとして表示・通知しません。新しい公開カードと新しいプロバイダーのレコードは通常どおり通知します。申請には元の下流カードの詳細と意味を保存します。権限のある履歴では移動後もその文脈を保持し、元のカードを削除した場合は利用不可と表示します。

## 入れ子の子カード配置

展開した子カードはアクティブな枝の近くの空き位置に配置します。暗く表示された背景カードが子カードをグリッドの端へ押し出すことはありません。さらに深い子カードを開いても、配置済みの祖先は移動しません。縦方向の空間が不足する場合は、グリッドにスクロール可能な余白を確保し、閉じると解除します。ウィンドウやカードのサイズが変わると配置を再計算します。ポインターとキーボードのフォーカスで枝の表示を一貫して制御し、子カードの長押しは現在の枝を継続します。保留中の配置処理はまとめて実行し、枝を閉じるとキャンセルします。

## 探索ナビゲーション

学習用の層は「探索」のサイドメニューに移動し、URL は `/study/explore/<ISO 言語>/<navigationSlug>` です。モジュールは各層に一意の `navigationSlug` を指定でき、省略時は層 ID を使います。ライブラリと申請の URL は変わりません。長い表題や定義の省略表示は文のプレビューだけに適用します。

## 構造化 JSON インポート

カード種別選択画面の左下にある **インポート** から JSON をアップロードします。バッチ全体の書き込み先範囲を選びます。形式は `format: "cognis-library"`、`version: 1`、空でない `entries` 配列です。

`references` や `referenceGroups` の `entryId` には別項目の `key` を指定できます。Cognis は UUID を先に割り当ててキーを置換し、依存先が揃った項目を層ごとのバッチで処理します。既存 UUID の参照先は移入先範囲で閲覧可能である必要があります。参照先欠落、層の不一致、循環、不正な筆順、必須項目不足、重複内容はトランザクション全体を取り消します。応答には作成項目と UUID 対応表 `ids` が含まれます。

## 辞書インポートの上限

カードの上限はタグ 8 件、読み 16 件、定義 10 件です。フィールド長と各層の関連数制限も適用します。JSON インポートでは検証し、辞書インポートでは余分な値を保存前に削減します。作成画面では 11 件目の定義を追加できません。

## フラッシュカードアダプター

Study のフラッシュカードアダプターを有効にすると、閲覧可能な任意の層から名前付きデッキを作成し、Anki 対応 TSV ノートを取り込めます。ルート、保存、描画、学習予定、画面、翻訳はすべてアダプターが所有します。カードを裏返すと読みと定義を表示します。「もう一度」は 1 分後、「良い」は 1 日から倍増、「簡単」は 4 日から 3 倍の間隔で復習します。

デッキのリソース種別は `studyDeck`、閲覧権限は `study:flashcards:read` です。標準の Cognis 共有はユーザー宛て共有、公開リンク、有効期限、パスワード、取り消しに対応します。編集と削除は所有者だけが行えます。受信者は学習とエクスポートが可能で、復習予定はアカウントごとに保存します。リンクのゲストは一時セッションで学習し、アカウントの予定を変更しません。各操作で期限と共有状態を確認します。

入出力は UTF-8 の引用符付きタブ区切りテキストで、列は Front、Back、任意の Pronunciation です。出力には Anki 用の区切り文字、デッキ、プレーンテキスト指定と、省略可能な Cognis コンテキスト列を含めます。Anki では追加列を無視できます。引用符、タブ、改行を保持します。これは TSV 交換であり `.apkg` ではありません。個人の復習履歴は出力しません。

## 描画操作

描画ウィンドウの閉じるボタンは標準のテーマ別 SVG を使います。全筆順ガイドが見えている間はガイドボタンを無効にします。文字を切り替えてもユーザーが移動したウィンドウ位置を保ちます。

## 背景レイアウトの安定化

詳細ポップアップは既存のスクロールコンテナーとスクロールバーの余白を保持し、サイドメニューの位置を維持します。描画パッドは独立したフローティング領域を使用し、背景ページの高さやオーバーフローを変更しません。

## Study の閲覧とお気に入り

Flashcards は所有するデッキ、アカウントに共有されたデッキ、有効な言語プロバイダーの完全なスターターデッキを一覧表示します。共有リンクのアクセス規則は維持され、公開ディレクトリーにはなりません。ウィジェット右上の + メニューでデッキの作成とインポートを選択します。Explore、Library、Flashcards はアカウントに保存される Study のお気に入りと並べ替え（提供順、A–Z、Z–A、新しい順、古い順）を再利用します。星はお気に入りだけを表示すると金色になります。Library 項目、デッキ、個々の学習カードのお気に入りは独立しています。お気に入りはアクセス権を追加しません。描画パッドは画面遷移時にセッションを終了し、composer や shell のクラスを上書きしません。

## プロバイダーのスターターデッキ

言語記述子は `starterDecks` に `{ key, name, schemaId, sourceRecordIds }` の配列を宣言できます。`key` はパック内で安定し、`name` は言語別の名前、`sourceRecordIds` は学習順の最大500件の重複しない既存レコードキーです。Cognis がグローバル Library のキーを正規 Library ID に解決します。デッキIDはコンテンツ改訂後も維持され、不完全なデッキと無効なプロバイダーは除外されます。スターターデッキは読み取り専用で、進捗とお気に入りは個人ごとに保持します。閲覧時は所属だけを解決し、開いた時にカード詳細を読み込みます。

## 辞書検索結果

辞書検索はURLパラメーターなしで `/study/library/search` を開きます。ゲートウェイクライアントは検索語・言語・辞書をアカウントごとのサーバー設定に保存し、認証済みセッションを通して取得します。他のアカウントはこの状態を読めません。複数の候補は横スクロールのプレビュー列に表示され、選択するとスクロール位置を保ったまま単一の詳細表示を更新します。候補が1件なら詳細を直接表示します。バッジの重複と辞書の生データ表示を避け、カード作成には既存のコンポーザーと依存関係解決を使います。キャッシュの期限と更新方針はCognis coreが管理します。

デッキ作成・インポート成功時は保護された編集画面を閉じてから更新済み一覧へ移動するため、保存後に破棄確認が表示されません。お気に入りのみのLibrary一覧では子カードを独立して表示し、プロバイダー順に戻すと元の入れ子配置を復元します。

## レビューとライフサイクル

Library 2.26.0 は公開プロバイダー能力で `deleteContentPack(root)` を提供します。プロバイダーのレコード、依存カード、パッケージの記録、アセットを削除フローの単一トランザクションで削除し、監査フックの失敗時は全体をロールバックします。連鎖削除は既存の Study 通知を使います。独立したユーザー作成コンテンツのためにスキーマを保持します。削除時にコンテンツをブロックしないため、再インストールで復元できます。

Study のテストは所有するアダプターまたはゲートウェイに配置します。読みの抽出、完全なラベルの分解、JSON 応答、画面テストの入力を共有して重複を除きます。コンテンツ取り込みと閲覧状態の処理を役割ごとのファイルに分け、ファイルサイズ上限を緩めずに宣言間の空行を検査します。並べ替えは `theme-select` を使い、お気に入りはテーマに沿った正方形のアイコンボタンにします。

## デッキ一覧とお気に入り

Flashcards 1.2.0 は、表示可能なすべてのデッキを、提供元、言語、カード数、新規・復習予定数を示す可変幅のタイルで表示します。デッキ検索は既存の Study 検索処理を使い、並べ替え、お気に入り絞り込み、フィルターの配置はゲートウェイで共有します。一覧と詳細のマークアップは Flashcards 所有の HTML テンプレートに置きます。明確なタイトルと情報の配置は [Brainscape](https://www.brainscape.com/subjects) と [Knowt](https://knowt.com/explore) を参考にしています。

Library のプレビューの星は選択操作の隣に置き、子カードのヒントに隠れないようにします。お気に入りの変更成功時はトーストを表示します。ポップアップが先にキーを処理していない場合、Escape で複数選択を解除します。デッキ詳細ではデッキの星を表示し、学習中は現在のカードの星に切り替えます。エクスポート操作は `canExport` が作成者または管理者を許可する場合だけ表示し、管理者が閲覧するプロバイダーデッキも対象にします。

## デッキ練習の統合

デッキ練習と共有スナップショットは同じリンク付き回答描画とインポートノート変換を使います。使われない反転・評価描画、スタイル、表示文言を削除し、デッキ内のライブラリ読み込みを共通化します。表示条件、ctx の段階、共有、評価権限は維持します。複数字の描画パターンは提供者の文字境界を保持します。

## 共通の言語ページ

内容プロバイダーに子ページがなくても、言語選択は Cognis の探索ページを開きます。言語を切り替えると同じ書字・語彙・文の役割を保ち、フラッシュカード・ライブラリ・申請では共通のページを維持します。英語はアルファベット・文字の組み合わせ・語彙・文を独自のパス名で宣言します。中断したお気に入り読み込みはマウントを終了し、誤解を招く失敗通知を表示しません。

## 任意の語形と到達可能なプレビュー

プロバイダーの変換セットは、例えば `plural` を `optInTag` として宣言できます。Cognis が語形を表示・受理するには、カードに系列の `matchTags` とこの有効化タグが必要です。編集画面には該当系列のプロバイダー名付きスイッチを表示し、保存した文の参照には基本カードの UUID と `{setId, path}` を保持します。有効化を解除すると、新たな変換参照は受理しません。可算性、不規則な綴り、読みの変化はプロバイダーが定義し、選択・保存・検証は Cognis が担当します。入れ子の分岐は親への経路を遮らない最も近い衝突しない位置に配置します。文のプレビューはタイトルと定義の表示を制限し、グリッドの大きさを変えません。

## 言語別ギャラリーと両面の練習

デッキ一覧は `/study/<iso>/flashcards`、個別デッキは `/study/<iso>/flashcards/<deck-id>` を使います。言語を切り替えると該当言語の一覧を開き、他言語を除外します。新しいデッキはインポートしたノートを含め言語を保存し、ライブラリー由来のデッキは言語を導出して矛盾する指定を拒否します。表には問題を、裏には定義と読みを表示します。新しいカードでも読み・書きの練習をすぐに開始できます。前のカードに戻る際はセッションの回答を保持して評価を重複記録せず、正解済みのカードは表のプレビューを表示して操作時に裏返します。ライブラリーへの正規リンクはテーマに従うボックスと離脱確認を使用します。

## テーマに従うポインター操作

共通のポインタースタイルボタンは、マウス・レーザー・照準のアイコンにテーマ標準の前景色（`--text`）を使います。埋め込みコンポーネントページにも適用し、参加者のポインター色は変更しません。

## テンプレートに基づくモジュール標準

新しいモジュールはモジュールテンプレートから作成します。ドメインルート、スタイル、マークアップ、テスト、リリース文書の配置を定め、開発指針を同期し、古い文書標準を使用例と現行契約に置き換えます。

## 限定された資源のライフサイクル

所有するブラウザープロバイダー、カタログ同期、ナビゲーション、解除可能な Health と公開 Keyring 登録を追加します。Bootstrap 失敗時に部分的な資源とルートを除去します。Messages は別々のルーム作成と保存済み ID の解決に対応し、名前変更や参加者による再割り当てを避けます。

## モジュール画像を Raw で取得する

画像をコードのインストールと分離してストリーミングし、GitHub の JSON 埋め込みサイズ制限を回避します。認証付き非公開アクセスと上限付きハッシュキャッシュは維持します。空のダウンロードを拒否して取得・キャッシュの失敗を記録し、不明アイコンを維持しつつバナーには翻訳された利用不可表示を使います。

## モジュールIDの診断とブラウザープロバイダーの管理

管理者が、別のUUIDに属するIDのモジュールをインストールすると、競合情報として `moduleId`、`installedModuleUuid`、`requestedModuleUuid` を受け取ります。サーバーとモジュール管理UIはこれらのIDを記録します。管理者以外は参照できません。IDとUUIDが一致する場合は引き続き更新できます。この検証を回避するために公開済みUUIDを変更したり、競合するインストールを上書きしたりしないでください。ブラウザープロバイダーのライフサイクルは `ui:providerLifecycle` を通じて共有され、バンドルと直接配信されるローダーが同じカタログを管理します。同じプロバイダーを二重にマウントしません。

## 連携元の排他的な参照設定

`social:messages:sourceBinding` は `{roomId, actorAccountId, sourceType, sourceId}` を受け取る `bind` と `release` を提供します。グループ解決は `source: {sourceType, sourceId}` も受け取ります。権限のあるルームメンバーは未設定のルームを参照元に関連付けられます。別の参照元には `source_conflict` を返し、既存の設定を上書きしません。同じ参照元からの再設定は冪等です。条件付き更新で同時リクエストを制御し、解除は一致する参照元だけを対象とします。グループ解決と参照設定は登録済みのctxフローで実行します。

## スコープ付きブラウザー操作と管理者権限の検証

ブラウザープロバイダーはスコープ付きctxから `ui:scopedActions` を取得します。`(ctx, moduleId, actions)` を渡すと、各操作の実行可能なフローを登録し、公開用の操作関数を返します。管理画面の取得・更新にこれらの関数を使用します。ホストがフローの破棄を管理し、破棄後の古い関数は実行を拒否します。管理者権限は有効なアカウントの現在の役割から検証し、呼び出し側が渡した役割には依存しません。

## 検索エラーを出さずに不明な在席状態を返す

リリース 2.0.14 — 在席状態の GET は、存在しないプロフィールとプライバシーで制限されたプロフィールのどちらにも成功応答で unknown を返します。応答の形を揃え、手動設定やカレンダーの状態は読みません。所有者、ブロック、コミュニティ、友達、非公開の既存ルールを維持し、変更は引き続き所有者だけが行えます。アバターの表示は不明となり、見つからないエラーを繰り返しません。

## 学習詳細の使いやすさを維持

フローティング描画領域はページ操作ドックより上に表示します。関連カードの一覧は5行まで折り返し、それを超えるとスクロールバーを隠して横方向にスクロールします。サイズ変更時に判定を更新し、ポップアップを閉じると監視を解除します。IPA の発音値は元の表記を維持し、読みやすい発音用の書体で表示します。

## 学習の発音表示を統一

Study は公開の発音分類とスタイルを提供し、Library のプレビュー、詳細見出し、変化形、学習カードの答えと読み方の選択肢、描画領域で再利用します。IPA は元の表記を維持し、通常の読み方は選択したアプリ書体を維持します。日本語と英語の文スキーマはいずれも最低2つの単語参照を必要とします。

## 翻訳キーでモジュール ID を維持

翻訳キーには `module.<manifest.id>.<feature>.<label>` を使用します。複数の単語からなるモジュール ID はハイフンを含めてそのまま保持します。`terms-of-service` の場合は `module.terms-of-service.admin.title` を使用します。モジュール ID より後の接尾辞には、小文字の単語をピリオドで区切って使用します。マニフェストのメタデータ、XML ファイル、コード参照で同じ名前空間を使用します。

インストール済みモジュールが異なる名前空間を使用する場合でも、マーケットプレイスはキャッシュ済みの名前、説明、カテゴリー、タグを対応するカタログ翻訳と組み合わせて表示します。インストール済み設定は独自の翻訳 URL を維持し、カタログを再取得するとキャッシュ済みの表示情報を置き換えます。

## フッターの法的文書リンクを維持

個別に読み込まれる静的スクリプトやバンドルを含め、すべてのブラウザークライアントは `ctx` 所有のフッター登録先を使用します。フッターのディスクリプターで `target: "_blank"` を指定すると、描画側が `noopener noreferrer` を追加します。認証提供者は翻訳済みラベルと認証コンテキストを提供し、ログイン済みの法的文書リンクは明示的にアプリケーションコンテキストへ登録します。履歴やブラウザーキャッシュからの復元時に公開済み文書へのリンクを更新し、コアのライセンスや変更履歴のリンクは置き換えません。

## 法的リンクの標準ナビゲーションを復元

新しいタブを指定する内部リンク、修飾キー付きクリック、ダウンロードではブラウザー標準の動作を保ちます。戻る操作でログインなどのサーバー描画ルートへ移動すると、検索パラメーターとフラグメントを含む文書を読み込み、直前のSPA画面が残らないようにします。

## 文字列の直接指定を禁止し翻訳キーを必須にする

AI向け指示では、すべての経路で英語のユーザー向け文字列の直接指定を禁止します。選択言語に値がない場合は英語のXMLリソースの同じキーを使用できます。英語の代替値も未定義または空の場合は、英語の直接指定、キー名、空の文字列を表示せず、明示的に失敗させます。翻訳の欠落によるエラーを握りつぶしてはいけません。

## 言語フォールバックをCoreに集約

Core共通の`createI18n`と`extendI18n`は、Core、モジュール、コンポーネントの各バンドルで選択言語の値が未定義または空の場合、キーごとに英語XMLから解決します。解決できないキーは`missing_translation:<key>`エラーになります。モジュールは独自の代替処理を実装せず、バンドルURLを渡してホストのリゾルバーを利用します。

## 画像取得エラーのイベント名を統一

マーケットプレイスの画像取得ログは、既存の構造化されたエラー項目とともに安定したイベント識別子を使用します。

## モジュール資源を独立して更新

Coreは登録時にモジュール所有のUI資源URLへインストール済みモジュールのリビジョンを追加します。モジュールのスクリプトと翻訳ファイルは、ホストの不変キャッシュ期限を引き継がず再検証されます。Service Workerはキャッシュの代替応答を使わずモジュール資源を直接取得し、資源キャッシュを更新します。モジュール更新時にエントリーポイントのインポートURLが変わり、古いスクリプトが削除済み依存先を要求するのを防ぎます。

## 辞書音声とホストのキャッシュ

要求された発音が同梱されていない場合、English Study は English Dictionary API で単語を検索し、その発音メディアエンドポイントから一致する MP3 を取得します。優先 IPA の読みが指定されている場合は一致が必須で、異なる発音で代用しません。`api.dictionaryapi.dev` の HTTPS メディアだけを許可し、リダイレクトを拒否します。検索とダウンロードは一つの制限時間を共有し、両方の応答をストリーミング時のバイト数で制限します。録音がない場合は明示的なエラーを返します。Google の音声サービスは使用しません。

録音キャッシュはモジュールではなく Cognis が管理します。認可後、非公開の Files キャッシュで取得済み録音をカード間および再起動後も再利用します。同時再生要求は取得と保存を共有します。キーには提供元の識別子、リビジョン、言語、役割、ラベル、読みを含め、読みや提供元リビジョンが変われば別途解決します。要求や保存の失敗は再試行できます。モジュールが辞書に接続するのは、再生要求時にキャッシュがない場合だけです。

## 間を付けた合成と手動置換

初期録音は多言語ニューラルモデル Kokoro をオフラインで使用し、英語に `bf_emma`、日本語に `jf_alpha` を使用します。クリップは 128 kbps、開始前の無音 200 ms、終了後の無音 180 ms、上限付きピーク正規化、遅めの発話速度で生成します。モデルの帰属表示と Apache ライセンスは `data/audio/VOICE-LICENSE.txt`、声と処理設定は録音一覧に記録します。

文カードには任意の音声フィールドがあります。初回再生時に Cognis は全構成要素へのアクセスを認可し、最初の発音グループだけを選び、指定の変形を適用して、開始前の無音と単語・読点・文末の間を持つ一つの連続 WAV を生成します。録音は非公開でキャッシュし、構成音声のバイト列、読み、変形、間の変更で識別子が変わります。新規カードと既存カードの両方で必要時に生成します。通常の作成画面で音声をアップロードすると生成音声を即座に置き換え、明示ファイルを削除すると自動合成に戻ります。提供元は語の録音を提供し、Cognis が合成とキャッシュ方針を管理します。

## 参照データの収録範囲

日本語の参照カタログは同梱する公式 KANJIDIC2 データの全 13,108 字、英語のカタログは Open English WordNet の全 135,969 語彙項目（正規化キー 127,311 件）を収録します。別の遅延読込辞書プロバイダーであり、149,077 件のカードを起動時に一括取り込みするものではありません。Study 検索で参照辞書を選び、対応項目を通常のグラフ検証経由で取り込みます。意味や使用可能な読みがない項目は不明のままとし、発音・翻訳・筆順を捏造しません。全 Unicode 漢字や存在し得る全英単語の網羅を意味しません。

漢字の読みは JMdict の一般的な用例と利用可能な頻度情報に基づき、送り仮名形も含めて並べます。グループ参照と初期音声は同じ順序に従い、漢字再生は常に最初の読みを使います。既存英単語カードには一つの IPA を収録し、参照項目は優先する英国発音内の原資料の順序を他の方言より先に維持します。発音頻度は文脈に依存し、原資料は全ての読みの普遍的順位を提供しません。

## 文の活用形音声を維持

文の結合では、複数段階の経路を含む選択済み活用形の表記と第一発音を要求します。派生形の録音がない場合、基本形の発音リンクをたどらず明示的に失敗します。派生形の直接再生と入れ子の構成要素にも同じ規則を適用します。

## 書き取りの答えを隠す

パッドの見出しは最初に文字を隠し、共通ボタンをクリックすると表示します。別の文字を読み込むと再び隠します。フローティングセッションは解除可能な `study:drawing:observe` 機能で現在のカードを通知します。一致するLibraryプレビューは開いたままぼかして操作不能にし、パッドの文字変更または終了時に解除します。読みと意味はパッドに残します。埋め込みの書き取りにも同じ処理を適用し、文字の表示を補助付き試行として通知します。
