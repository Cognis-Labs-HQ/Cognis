# トークンのライフサイクル保護

**機能ブランチ:** feature-token-lifecycle-enforcement

## 制限付きトークンの管理

保存形式2ではセキュリティ項目の明示が必要です。未対応の形式、不正または曖昧なレコードは拒否されます。拒否されたセッションでは再ログインが必要で、形式の自動変換は行いません。有効な通常、制限付き、失効済みの認証情報は再起動後も権限状態を維持します。保存に失敗した場合は成功として扱わず、エラーを報告します。

## TFAポリシーの変更

すべてのTFA強制設定の変更は担当コンポーネントのポリシーフローを使用します。強制設定の無効化では、操作した管理者の古い認証情報を含む、設定待ちのすべての認証情報を失効させます。通常のセッションは維持します。失効処理はポリシーの保存前に行い、再試行できます。必要なプロバイダーがない場合や保存に失敗した場合はエラーになります。トークンファイルとデータベースは単一トランザクションではありません。ポリシーの保存に失敗すると、厳格なポリシーを維持したまま設定待ちの認証情報が失効している場合があります。ローカルのアトミックなファイル置換は、ハードウェア障害への耐性や複数サーバープロセス間の同期を保証しません。

無関係な設定の保存ではTFAポリシーを適用しません。TFA読み取りケイパビリティがある場合、システムの読み取りとTFA項目を省略した保存では、その現在のポリシーを使用します。読み取り失敗時は強制設定が無効と表示せず、エラーを返します。この任意のケイパビリティがない場合、保存された設定は古い可能性のあるコピーにすぎません。明示的なポリシー変更には引き続き担当コンポーネントのケイパビリティが必要です。

ポリシーフローには、担当コンポーネントが保持する一回限りの操作と実行状態が必要です。フローの直接呼び出しや取得済み操作の再実行は、変更前に拒否されます。連携機能はポリシーケイパビリティを呼び出してください。

## テスト認証情報の分離

`npm test` と `npm run ci:test` は実行ごとに一時トークン保存ディレクトリを作成し、各テストワーカーに別々の書き込み可能なファイルを割り当てます。静的な事前読み込み処理がテストモジュールの読み込み前にパスを設定し、継承した本番トークン保存先は使用しません。再起動や障害のテストでは、その後に各テストが自分のパスを明示的に変更できます。子プロセスの成功または失敗後に一時ディレクトリを削除し、通常の終了シグナルを転送します。強制終了やホスト障害では一時ファイルが残り、OSによる削除が必要になる場合があります。本番のトークン保存は変更せず、保存失敗時に成功として扱いません。
