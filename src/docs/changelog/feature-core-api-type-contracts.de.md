# Core- und API-Typverträge

**Feature-Zweig:** feature-core-api-type-contracts

## Typisierte öffentliche Verträge

Zugriffsrollen vereinheitlichen, Modulanforderungen und Kontokennungen deklarieren und typisierte Komponentenmetadaten erhalten. Fähigkeitsabfragen und Verzeichniserkennung entsprechen ihren Laufzeitverträgen.

Namespace-Zugriffslisten akzeptieren schreibgeschützte Komponentenkennungen und erhalten damit die unveränderlichen Registereinträge des Files-Gateways. Flow-Ergebnishelfer akzeptieren eine nicht vorhandene Ergebnissammlung und liefern null entsprechend ihrem bestehenden Laufzeitverhalten.

## Typisierte API-Testdaten

Vollständige Moduldaten, registrierte Fähigkeitsspeicher und eine API-eigene Dokumentdatenbank für Tests verwenden. Rollen bei der Kontoerstellung und Belege für Quellenzugangsdaten in Tests korrigieren, ohne Routen-Nutzdaten zu ändern.

## Versionen

Core auf 0.6.3 und API auf 0.13.32 anheben, einschließlich passender Lockdatei-Einträge und Core-Abhängigkeitsgrenzen.
