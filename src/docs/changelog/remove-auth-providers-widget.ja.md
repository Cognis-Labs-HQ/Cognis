# 認証とパスワードポリシーの更新

**機能ブランチ:** copilot/remove-auth-providers-widget

## 管理画面から重複する認証プロバイダーウィジェットを削除

認証プロバイダーウィジェットは、コンポーネントページにすでに表示されているため、管理画面の認証セクションから削除されました。認証管理セクション全体が廃止されました。

## パスワードポリシーを管理画面 → セキュリティに移動

パスワードポリシーの設定ウィジェットは、旧認証セクションから管理画面のセキュリティセクションに移動しました。標準のダーティ状態トラッカーと統合されており、変更内容は専用の保存ボタンではなく、統一された変更バーで保存またはキャンセルできます。

## パスワードポリシーで文字クラスに数値の最小値を使用

大文字、数字、特殊文字の要件は、トグルスイッチではなく数値入力を使用するようになりました。値を 0（デフォルト）に設定するとその要件が無効になり、正の整数を設定するとパスワードに含まれる必要があるその文字クラスの最小文字数が指定されます。

## 登録ページ：ユーザー名のインラインバリデーション

登録フォームでは、印刷可能な ASCII 文字以外の文字や大文字を入力した直後に、ユーザー名フィールドの下にインライン警告が表示されるようになりました。警告はフォーム送信時ではなく、入力時に即座に表示されます。

## 登録ページ：常に表示されるパスワードポリシーの箇条書き

登録ページのパスワードフィールドの下に、適用されるすべてのポリシー要件が常に箇条書きで表示されるようになりました。各項目はユーザーが入力するたびにリアルタイムで更新され、要件を満たした場合は緑色のチェックマーク付きで、満たしていない場合は赤色で表示されます。

## 構造化基準に対応したフォームビルダー

登録フォームの描画と検証は、新しい再利用可能なフォームビルダーで処理されるようになりました。`ctx` 経由で渡す構造化フィールド／基準定義を使うため、今後のフォームでも入力基準をデータとして宣言できるようになりました。

## ユーザー名の25文字制限を警告方式に変更

ユーザー名入力は25文字で強制的に停止しなくなりました。25文字を超えると、その時点でインライン警告が表示されます。

## 必須項目のアスタリスクをフィールドタイトルの横に表示

必須フィールドのアスタリスクは、入力欄の下ではなくフィールドラベルの横に赤色で表示されるようになりました。アスタリスクの色はテーマ対応の危険色変数を使用しており、ライトモード・ダークモードのどちらでも見やすく表示されます。

## ユーザー名の基準をフォーカス時に表示されるフローティングパネルに移動

ユーザー名の要件は、パスワード基準と同じフローティングパネル形式で表示されるようになりました。パネルはユーザー名フィールドにフォーカスしたときにフィールドの直下に表示され、フォーカスが外れると非表示になります。

## 基準パネルがフィールドの幅に追従

フローティング基準パネルは右端に配置されるのではなく、フィールドの幅に合わせてスナップするようになりました。小さい画面では、フォーカス時にパネルがフィールドの下にインラインで表示されます。

## 基準パネルが正しいテーマカラーを使用

フローティング基準パネルは `--surface`, `--border`, `--text-muted`, `--color-success-outline-text`, `--color-danger-outline-text` などの正しい CSS テーマ変数を使用するようになりました。ライトモード・ダークモードのどちらでも正確な色で表示されます。

## ユーザー名を英字・数字・ハイフン・アンダースコアのみに制限

ユーザー名バリデーションは英数字、ハイフン、アンダースコアのみを受け付けるようになりました。`!@#$%^&*()` のような特殊文字は使用できなくなりました。バリデーションメッセージもこれに合わせて更新されています。

## 基準行が全体の背景色と目立つアイコンで表示される

各バリデーション基準の行は、条件を満たすと背景全体が緑色に、満たさない場合は赤色にハイライトされるようになりました。従来の文字色の変化のみから改善されています。ステータスアイコンも太いチェックマーク（✔）と太いバツ印（✘）に変更され、一目で状態が分かります。

## 確認用パスワードの不一致は入力後にのみ表示される

確認用パスワードの不一致エラーが早期に表示されなくなりました。確認フィールドに入力があるまでは中立のままで、フィールドが空の状態で誤ったエラー表示が出ることはありません。

## パスワード一致判定の表示タイミング

パスワード確認の基準は、パスワード欄に文字が入力されるまで中立表示のままになります。これにより、主パスワードが空の段階で一致判定が早期表示されることを防ぎます。

## 確認欄の不一致状態を即時反映

どちらかのパスワード入力が変わるたびに確認欄を再検証するようになり、不一致状態が入力中に即座に赤で反映されます。

## 基準文言を肯定表現に変更

確認基準の文言を「パスワードが一致します。」に変更し、緑/赤の基準表示のどちらでも同じ行が自然に読めるようにしました。

## 確認欄空値時の不具合修正

登録時のパスワード確認基準を修正し、主パスワードに入力がある場合は確認欄が空の値を一致扱いしないようにしました。

## 事前判定の中立状態

パスワード一致基準は、パスワード欄に入力があるまで中立（達成/未達成のいずれでもない）を維持し、早すぎる「一致」表示を防ぎます。
