# 統合学習ライブラリ

**機能ブランチ:** feature-create-multi-layered-library-adapter

## 追跡可能な教材階層

Study ライブラリアダプターに、文字体系、定義、言語教材、練習、ワークアウト、ルーティン、コレクションの固定階層を追加しました。有向参照により、すべての教材を構成要素まで追跡できます。

## 安全な範囲と公開

グローバル、クラス、非公開ユーザー範囲に、役割と所属状況に基づくアクセス制御を追加しました。公開申請は公開先の承認を必要とし、参照する依存項目もまとめて複製します。

## インポート、エクスポート、画面

ctx と認証済み API を通じて、検証付きグローバル JSON インポート、JSON・Anki エクスポート、Unicode 単語分解、深い参照検索、全ユーザー向け Study 画面を提供します。

## 選択可能なテンプレート

言語・活動モジュールは、標準テンプレートから必要な階層だけを複製できます。階層間リンクのメタデータが正しい関係を保ち、必須の依存関係を示し、文字から単語、単語から文へのリンクを推定します。

## 関係フレームワークの再設計を定義

固定ライブラリレイヤーを利用側所有のスキーマへ置き換え、汎用関係制約、交換可能な解決・lookup flow、完全な詳細 UI、deep link、ロールバック可能な移行を実現する段階的な実装計画を追加しました。

## 再設計を実装

固定レイヤーを永続化されたバージョン付き利用側スキーマへ置き換えました。型付きフィールド、多重度、順序付きエッジ、スキーマバージョン、可視な関係対象を検証し、Unicode 書記素解決と、出典を持ち解除可能な lookup プロバイダーを追加しました。

## 関係を完全に閲覧

中立なスキーマ、詳細、追跡、解決、lookup API とスキーマ駆動 UI により、任意のレイヤー、フィールド、構成要素、使用元を再読み込み可能な詳細 URL で表示します。

## 互換性のない capability 変更

互換性のないスキーマ capability はアダプター 2.0.0 で導入され、宣言的パック取り込みにより 2.1.0 になりました。利用側はスキーマを登録し、削除された固定カタログ、テンプレート複製、レイヤー固有の import・export メソッドに代えてスキーマ ID と関係 ID を指定する必要があります。

## 宣言的言語パックを追加

言語パックはデータ専用ディレクトリをライブラリ capability に渡し、決定的な検査と原子的な取り込みを行えるようになりました。Cognis は安全なパス、manifest、license、schema、全レコードと関係を検証し、安定した名前空間 ID とバージョン付き導入 receipt を保存します。言語 framework には必要な manifest、schema、レイヤーディレクトリ、レコードファイルと、実行可能 resolver・lookup アダプターとの境界を記載しました。

## ローカライズ済み定義レコード

定義レイヤーがモジュール所有の文字列キーマッピングを宣言するようになりました。ライブラリ作成フォームは Cognis の全 UI 言語を提示しつつ英語のみを必須とし、定義エントリー ID に結び付く安定したキーを生成します。また、将来のプロバイダー向けに任意の ctx 翻訳ケイパビリティを提供します。

## ライブラリ閲覧画面の成熟化

ライブラリをレイヤータブ、カード形式の項目、再利用可能なポップアップ詳細で再構成しました。項目の選択と関連項目の移動は、レコード識別子をブラウザーの URL に表示せず内部で管理します。前後の操作には、同じ幅の明確な方向矢印を使用します。また、学習サブナビゲーションの各操作に十分な領域を確保し、ホバー時の切り取りを防ぎます。

## 補助コンテンツの統合

定義と助詞をライブラリの直接閲覧から除外しました。項目詳細では、ローカライズ済み定義を見出しの下に配置し、文の助詞を読み取り専用の関連詳細として含め、バッジ用メタデータをピルで表示し、アクセシブルな SVG アイコンで範囲を示し、すべてのバッジフィールドをカードの絞り込み条件として提供します。

## 絞り込みと詳細表示の改善

ライブラリのメタデータ選択欄に共通テーマのスタイルを適用し、変更を即時反映するようにしました。詳細ポップアップでは見出しを大きくし、定義と意味をタイトルの下に配置し、認識済みの構成要素を独立したコンポーネント区画ではなく見出し内の移動可能なサブボックスとして表示します。

## ピル絞り込みと共有音声

メタデータ選択欄を任意にグループ化できる絞り込みピルへ置き換え、学習ナビゲーションを左側のページと右側の言語操作に再分離しました。書記単位スキーマでは発音と音声を必須とし、モジュールはローカル音声または HTTPS ソースを提供できます。Cognis はそれをアクセス制御された共有ローカルキャッシュへ一度だけダウンロードします。

## 読み込みとゲートウェイ保存の復旧

ネイティブ `Map.groupBy` がないブラウザーでもライブラリを表示できるようにしました。学習言語コードを正規化して登録済みの旗を言語操作に維持し、リモート音声の永続化をコンポーネント所有のファイルゲートウェイ名前空間へ完全に移しました。ライブラリはキャッシュファイルを直接書き込まず、独自の音声サイズ上限も設けません。

## upstream Development ブランチとの整合

upstream Development ブランチの最新変更を統合しました。廃止された登録招待アダプターの競合は upstream のトークンベース実装を優先して解決し、学習ライブラリ機能を現在のアプリケーション構成に適合させました。

## 学習アダプターの互換性を更新

ライブラリおよび進捗アダプターで検証済みのゲートウェイ上限を upstream のゲートウェイ版へ引き上げ、両アダプターの版を更新しました。また、完全なワークスペース記録をロックファイルへ復元し、統合後もクリーンな依存関係インストールが成功するようにしました。upstream のレジストリ整合性メタデータも修正し、固定された依存関係一式を再現可能にしました。

## 変更をライブラリ範囲に限定

無関係なコア、API、ルーター、アダプター、ゲートウェイ、機能の変更を削除しました。このプルリクエストには学習ライブラリ、その学習統合、および各コンポーネントに必要な再利用可能 UI 機能だけが含まれます。

## Study のグループ化ページをルーティング

グループ化されたサブページの検出、キャッシュ、無効化、ルート解決を行う汎用 UI 機能を追加しました。Study は、言語ごとのページ一覧、選択言語のサブメニュー、ハブカード、子ページの読み込みに同一のプロバイダーモデルを使用し、ナビゲーションでは選択言語を非公開の履歴状態に保持します。

## ライブラリ操作の仕上げを復元

スクロール開始時のヘッダー折りたたみを安定させ、初回読み込みから Study のレイヤーナビゲーションを表示し、言語ボタンのはみ出しを除去して、コンパクトなポップアップ見出しを復元しました。管理者用ライブラリでは、簡略化した参照概要を持つ読み取り専用の行詳細と右クリックによる複数選択を提供します。学習カードでは発音と定義のプレビュー、深層リンクを復元し、詳細の重複区画をなくしました。アクティブなレイヤー状態、中央配置の選択マーク、テーマ対応の編集操作も一貫して表示されます。

## プロバイダー主導の Library 編集

Library の行全体で読み取り専用の詳細を開き、テーマ対応の編集操作を行末に配置しました。プロバイダーのスキーマが、フィールド名、入力方式、作成後に変更できない分類、ディープリンク関係、言語別の音声ブラウザーを定義します。タグは Enter で確定し、選択肢は再クリックで解除でき、必須項目は送信前に検証され、フローティング操作には翻訳済みラベルが表示されます。カードと Study サブナビゲーションのホバー表示を安定したテーマ対応表示にし、複合要素は原子的な文字より先に最も近い上位レコードを選びます。

## Library プレビューと管理者確認を改善

学習カードを主ラベルと発音の簡潔な 1 行表示にし、範囲アイコンを分離して、定義とメタデータをプレビューから除きました。管理者の行をクリックすると、学習者向け詳細ポップアップではなく、編集時と同じスキーマ駆動フォームを無効化した読み取り専用モードで開きます。

## コンパクトなカードと語彙リンクを明確化

学習カードの表面を暗くし、バリアント案内用に内容を隠さない小さな領域を確保し、関係リンクの重複するホバー表示を削除しました。語彙関係のラベルにはプロバイダー提供の発音を含め、意味のある 1 文字語を対応する書記単位レコードと区別できるようにしました。

## 入れ子のバリアント分岐を表示

Library グリッドのクリップ境界は維持します。展開した分岐はプロバイダー指定方向と代替方向を描画境界に対して評価し、入れ子のカードをカードグリッド内に収めます。長押し案内のアニメーションとぼけをなくし、文字を 25% 大きくしました。

## プロバイダー指定のバリアント配置を境界内に制御

境界外への描画を、境界を考慮する実行時配置へ置き換えました。プロバイダー指定方向を第一候補にしつつ、表示中の入れ子分岐を測定し、必要な場合だけ方向を変更して、すべてのカードを Library グリッドとウィジェット内に保ちます。

## 入れ子カードの基準位置を維持

配置調整では対象カードだけを測定するため、子孫が配置済みの親カードを移動することはありません。枝刈りされた経路の周囲に十分な枠がない場合、兄弟カードは距離を広げながら同じ方向を再利用し、同じ行または列に積み重ねられます。

## 語彙タイトル詳細の重複を削除

語彙ポップアップでは、メインタイトルを語彙単位のラベル専用とし、タイトル詳細には現在の言語向けにローカライズされた定義だけを表示します。別表記、発音、派生元の注記が語彙見出しを重複させることはありません。

## 文脈に応じた語彙定義を継承

関連エントリのカードから語彙へ移動した場合、移動元カードのローカライズ済み定義をフォールバックとして引き継ぐようにしました。語彙レコード自身の定義を常に優先し、それ以外のポップアップ移動ではフォールバックを消去して、閲覧経路間で意味が混在しないようにします。

## 順序付きの複数定義を表示

カードはプロバイダーの定義順序を保持するようになりました。最初のローカライズ済み定義はタイトルと重複しない場合にタイトル横へ表示され、残りは存在する場合だけ「追加の定義」セクションに表示されます。移動元カードのフォールバックは、語彙に定義がない場合だけ使用されます。

## 兄弟の子カードを別々の枠に配置

実行時のバリアント配置で、ルートカードと配置済みの表示中の各子カードを占有矩形として追跡するようにしました。空いている境界内のプロバイダー希望位置は維持し、埋まっている場合は重なりが最小の境界内候補を選ぶため、兄弟カードが同じ枠に重なることがなくなります。

## 信頼性とコンポーネント分離

パッケージ資産はstudy_library_asset_chunksに保存し、発行者、パック、版、完全な資産パスから生成するSHA-256識別子と整数の位置をキーにします。公開URLと元のバイト列は維持します。パックの索引で削除範囲を限定します。スキーマはスキーマと版の識別子を維持し、基本断片とstudy_library_schema_partsを使います。両方の内容をUnicodeの境界でUTF-8最大60,000バイトの断片に分割します。読み取りでは順序どおりに復元し、インポートでは既存のトランザクション内で置換します。版の競合、単独の発行者による更新、ロールバック、短い内容への置換の意味は維持します。

ライブラリのJSON変更要求は最大5 MiBとし、それを超えるストリームは変更処理の前にHTTP 413で拒否します。カード項目のJSONと検索用の正規化済み表現には、それぞれUTF-8で50,000バイトの上限を設け、検索用データに見出しとタグの余地を残します。音声添付は正確なアップロードパスを必要とし、ディレクトリ移動や入れ子のパスは保存先へのアクセス前に拒否します。作成と編集は同じ正規参照の書き込み処理を共有し、グループ、位置、選択した活用を維持します。保存場所の読み込み失敗は翻訳されたトーストで通知し、中止された画面の応答は現在の操作部を更新しません。

報酬の状態は参加者のリビジョン検査を維持し、基本断片とengagement_participant_partsを使います。コミットではリビジョンの検査と増加、すべての断片の置換を単一のトランザクションで行います。基本行と順序付き断片を単一の結合クエリで読み取り、リビジョンと内容が別のコミットから混在しないようにします。各断片はUTF-8最大60,000バイトです。失敗時はリビジョンと内容を元に戻し、競合する書き込みはengagement_state_conflictになります。テストは無制限の文字列を許容せず、実際のテキスト容量制限を検査します。

進捗のイベント、利用者、投影、ケイパビリティの共通型はgateways/study/reuse/progress.tsにあります。ゲートウェイはこの契約のために任意のアダプターの入り口をインポートしません。アダプターは同じケイパビリティと公開エクスポートを維持します。イベントと訂正のJSONは60,000バイトを上限とし、超過した要求は記録前に413になります。既存のプライバシー、クラスの検査、訂正、報酬、再構築のフローは維持します。

未認証の定義・順位要求は注入された認証検査を呼び出し、データを読む前にHTTP 401で終了します。ルートの引数は既存の型付きHTTP契約と権限検査を使います。

評価要求のJSONは最大16 KiB、デッキの書き込みは最大5 MiBです。超過した要求はデッキや予定を変更せずHTTP 413になります。読み、書き、再試行のキュー、インポートしたノート、ライブラリに基づくカードの動作は維持します。

保管庫のPUT要求はAPIの共通JSONストリーム読み取り処理を使い、有効な保管庫容量と追加の1 KiBを上限にします。ポリシー、413エラー、直列化済みデータの検査はアダプターが引き続き担当し、別のバッファ処理は維持しません。

Studyの各画面はコンポーザーのサブナビゲーション枠を共有し、4言語すべてでui.reuseの共通操作・ナビゲーションラベルを使い、描画時点のルートを選択します。中止済みのルーターのスコープは置き換えても中止状態を維持します。画像プレビューの失敗は翻訳されたエラートーストで通知し、再試行できるように開いた状態のロックを解除します。

## 上限付きデッキ文書

デッキの所属項目、インポートしたノート、学習予定は、最大60,000 UTF-8バイトのUnicode境界を守る断片で保存します。単一の結合クエリで確定済みの文書を復元し、置換と削除はデッキのトランザクション内で実行します。学習者行へのupsertで、Repeatable Readを含めスナップショット読み取り前に復習とデッキ編集を直列化します。試行の受領記録は予定と同時に確定し、Progressへの配信はトランザクション外で実行します。応答とエクスポートのカードやスキーマは最新のLibrary項目IDを参照し、保存時にLibraryカードの内容を重複保存しません。

## 拡張可能なブラウザー操作

Libraryプロバイダーはライフサイクルに紐づくctxから`study:library:client`を公開します。すべてのゲートウェイクライアント操作は`study:library:<clientFunction>`の`before`、`execute`、`after`を通ります。例えば`study:library:createLibraryEntry`の`before`を拡張すると、`input.args`（クライアント関数の位置引数）を確認・変更でき、エラーを送出するとリクエスト前に拒否できます。`after`は`data.result`を受け取り、戻り値を調整できます。サーバー側の認可と検証は引き続き適用されます。読み取り、辞書解決、インポート、公開リクエスト、メディア変更に同じ境界を使用します。プロバイダーの解除時は実行中のリクエストを中止し、機能、フロー、フックを削除します。古いハンドルは拒否され、再有効化時には新しい操作が登録されます。

## 通知テキストを一度だけ復号

リクエスト通知はXMLエンティティを単一の走査で復号し、アカウントとリクエストの値をリテラルデータとして一度だけ挿入します。符号化されたエンティティ文字列をさらに復号しません。優先言語の文字列が空または存在しない場合は英語を使用し、英語もない場合は明示的なエラーにします。4つのリソースカタログは通知処理のインスタンスの有効期間中キャッシュされ、読み取り失敗時は再試行できます。

## Studyの認証契約を適用

Studyはルート登録前にAuthenticationゲートウェイと`auth:routeContext`機能を必要とします。アダプター管理、言語の検出、描画の各ルートは、独自のアクセス制御も含めて注入されたコンテキストを使用します。認証契約がない場合は既定の制御を選ばず、起動を失敗させます。

## 練習の選択を均等化

描画ガイドとフラッシュカードの解答シャッフルは`randomIndex`ヘルパーを共有します。Web Cryptoとマスク付き棄却サンプリングにより、1から2^32までの整数範囲で剰余による偏りを防ぎます。選択肢が1つの場合は乱数を消費しません。決定的なテストのために乱数源を注入できますが、通常の練習では常にWeb Cryptoを使用します。

## テスト設定をデータとして保持

Studyの検出テストは静的なアダプターモジュールをコピーし、設定可能な識別子と依存関係をJSONに保存します。シリアライズした値から実行可能なソースを組み立てません。共通の準備処理を使用し、実際の検出と起動の動作を維持します。マーケットプレイスの画像テストは、非公開GitHubリクエストも含め、解析したURLのオリジンとパスを完全一致で検証します。

## 文中の変化形を選択

動詞、副詞、複数形を持つ項目を繰り返し選択する場合も、文へ追加する前に変化形の選択を開きます。キャンセルしても文の構成は変わりません。秘密情報を削除せずにキーリングの操作履歴を制限し、絶対上限内の既存の保管庫は履歴縮小のために読み取れます。バックグラウンド同期の失敗も通知します。

## 動的に生成される活用形

各活用セットは文法上の `matchTags` と必須の `flag`（例：`transform:verb`、`transform:plural`）を宣言します。対応するフラグを持つ基本カードだけが活用を有効にします。不明または生成不能なフラグは検証に失敗します。活用形は基本カードの正規UUIDと `{setId, path}` で識別する読み取り専用ビューです。独立したカードとして作成、インポート、同梱することはできません。文法クラスの異なる独立した同形語は保持できます。

規則は接尾辞の削除・追加、任意の接頭辞操作、順序付き `suffixes`、不規則変化を表す見出し語別の `forms` により表記と発音を変換します。例外指定は汎用の文字列操作を置き換えます。複数語の表現を含めて状態を連結でき、増大する循環は拒否します。定義テンプレートの補間は一度だけ行い、挿入した文字列を再解釈しません。

詳細表示、文の検証、音声は同じ解決処理を使います。生成ビューは参考画像を保持し、基本形の音声・筆順フィールドを除去します。生成した表記と第一発音で音声を検索し、再生成しても基本カードを変更しません。書字練習は生成した表記の文字パターンを合成し、筆画グループを保持して空白を無視します。録音テストでは有効な各規則に経路付きのクリップを必須とします。活用形カードの保存表現や互換用の別名はサポートしません。
