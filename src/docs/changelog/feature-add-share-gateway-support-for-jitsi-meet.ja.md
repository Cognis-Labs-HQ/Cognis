# ゲスト向け共有コンポーネントウィンドウ

## 共有ページが同期コンポーネントウィンドウを自動的に開くようになりました

共有ゲストは、ブラウザーの操作ジェスチャーなしでも、マウントされた共有ページが要求するコンポーネントウィンドウを受け取れるようになりました。これにより、ミーティングのホワイトボードと同期する周辺動作が、サインイン済みの Cognis 参加者と同様にゲストにも開きます。コンポーネントページブローカーは、要求されたホスト要素とライフサイクルシグナルの検証を引き続き行います。

## 連携境界の明確化

コンポーネントウィンドウの認可は、子コンポーネントの API へのアクセスを許可するものではありません。同期を一貫して動作させるには、Jitsi Meet がホワイトボード状態ルートで共有ゲストを受け入れてミーティングとホワイトボードの関連付けを公開し、Nextcloud Whiteboard が検証済みミーティング共有からの委譲アクセスを受け入れる必要があります。

## 主催者が同期された会議コンポーネントを開けるようになりました

サインイン済みの主催者や直接アクセス権を持つ参加者は、有効な共有リソースの閲覧中にコンポーネントウィンドウのリクエストを受信できるようになりました。これにより、同期処理が最初のブラウザー操作後にリクエストを行った場合でも、会議ホワイトボードを開くとコンポーネントウィンドウがマウントされ、会議ペインがピクチャーインピクチャーへ移行できます。

## ゲスト用コンポーネントルートを認証後に読み込み

Share ページはゲスト認証後に SPA ルート探索を更新するようになりました。匿名でのページ起動中には利用できなかったホワイトボードのコンポーネントルートが有効なゲストセッションで解決され、同期されたホワイトボードウィンドウを会議内にマウントできます。

## ゲストコンテキストを埋め込みホワイトボードへ渡す

Cognis は、有効な Share コンテキストをコンポーネントページフロー経由でゲストのコンポーネントマウントへ渡すようになりました。埋め込みホワイトボードは委譲された会議共有を認識し、ゲスト認証を維持して、アカウント専用経路へ入ることなく同期ボードを読み込めます。
