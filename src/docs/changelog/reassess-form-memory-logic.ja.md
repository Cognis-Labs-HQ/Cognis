# ユーザーとメッセージのフォームメモリ修正

**Feature Branch:** copilot/reassess-form-memory-logic

## ロールのドロップダウンをフォームメモリから除外

ユーザーページのロール選択フィールドが、ページコンポーザーのフォームドラフトメモリから除外されるようになりました。以前は、ユーザーテーブルの再レンダリング時（例：ロール変更が失敗してコンポーザーが更新された場合）に、ドラフトストアから古いロール値がドロップダウンに復元される可能性があり、サーバー側の現在の状態が隠れてしまうことがありました。

## 部屋ごとのメッセージ下書きの保存

メッセージコンポーザーは、アカウントと部屋IDをキーとして、部屋ごとに下書きを保存するようになりました。ある部屋で文字を入力し、別の部屋に切り替えて戻ると、以前の下書きが復元されます。メッセージを送信すると、その部屋の下書きが削除されます。これにより、コンポーザー内のテキストがどの部屋向けのものかに関わらず部屋をまたいで保持されるという従来の動作が改善されました。

## フォーム下書きメモリがオプトイン方式に変更

ページコンポーザーの永続的なフォーム下書き保存が、オプトアウトからオプトイン方式に変更されました。最も近い祖先要素に `data-composer-include-form-memory="true"` が指定されているフィールドのみが localStorage に書き込まれます。オプトインされていないフィールドは、同一ブラウザセッション内のレスポンシブ再レンダリングを乗り越えられるようにメモリ内の一時スナップショットには引き続きキャプチャされますが、永続ストレージには書き込まれません。これにより、サーバー側で管理されるコントロール（ロールドロップダウン、トグルスイッチ、設定セレクト）がクライアント側にキャッシュされることを防ぎます。

## 下書きのない部屋に切り替えた際にコンポーザーのテキストエリアをクリア

以前は、未送信テキストのある部屋から下書きが保存されていない部屋に切り替えた場合、前の部屋のテキストがコンポーザーに残り続けていました。切り替え直後に発生する合成入力イベントがその古いテキストを新しく開いた部屋の下書きキーで保存してしまい、誤ったメッセージを送信するリスクがありました。開いた部屋に保存済みの下書きがない場合、入力イベントが発生する前にコンポーザーのテキストエリアが明示的にクリアされるようになりました。
