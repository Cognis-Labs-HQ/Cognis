# モジュールストア

## 明確なリリースチャンネル状態

リリースチャンネルの選択肢は中立的な操作表示になり、選択中の項目が明確に分かるようになりました。モジュール詳細にはインストール済みチャンネルと実際のマニフェストバージョンが並んで表示され、更新済みモジュールには Cognis コンテナを再起動して追加ルートがすべて有効になるまで再起動警告が表示されます。

## 一貫したモジュール操作メニュー

インストール済みモジュールの詳細では、詳細操作に共通の固定型ハンバーガーメニューを使用するようになり、Cognis のほかの操作メニューと外観や操作性が統一されました。

## 専用アプリストア

モジュールに独立した管理ページを追加し、インストール済み、利用可能、おすすめ、カテゴリー別の表示と、設定可能な GitHub・GitLab ソースを提供します。

## 外部リポジトリ

管理者は、キーリングで保護する任意の PAT を使って公開・非公開リポジトリを検出できます。インストール時にはマニフェストと不変 UUID を検証します。

## UUID 依存関係

すべてのコンポーネントマニフェストは読みやすい名前と ID を保ちつつ、依存関係には安定した UUID を使用します。

## 確実に動作するストア操作

モジュールカード、フィルター、ソース設定、ライフサイクル操作は、周囲のページレイアウトを初期化せずにストア内容を即座に更新するようになりました。モジュール詳細でもストアナビゲーションを維持し、カードの寸法を統一して説明とライフサイクル操作を揃えています。

外部チェックアウトは、既存のインストールを置き換える前に、パッケージとルートの契約、入口、画像、安全なパス、任意のファイルチェックサムを含むリポジトリ準備検証を通過するようになりました。

インストール済みリポジトリを完全なランタイムコンポーネントとして検出するようになりました。ブートストラップ入口は追跡対象の `ctx` スコープを通じてルート、UI、文書、変更履歴、ケイパビリティ、フローステージを提供でき、無効化またはアンインストール時にすべての提供物を解除します。

Jitsi Meet を同梱ソースツリーから削除し、今後はマーケットプレイスから提供します。GitHub の Cognis Labs HQ は変更できない信頼済みモジュールソースとして常に利用できます。

## 無効なリポジトリを除外

モジュールマーケットは、完全で有効なモジュールマニフェストを提供しないリポジトリを無視するようになりました。設定済み組織内の無関係なリポジトリや利用できないソースが、モジュールページの読み込みを妨げることはありません。

## 不足アイコンの代替表示

モジュールカードは、利用できない外部画像をテーマ対応の疑問符アイコンに置き換え、実行時エラーのポップアップを表示しないようになりました。

## モジュールソースを更新

モジュールページの「モジュールソース」の隣に更新操作を追加し、設定されたすべてのプロバイダーを再照会して表示中のカタログを再構築できるようになりました。

## ソースの管理と段階的な検出

モジュールソースは、専用の一覧・編集マネージャーとして開くようになりました。既定の信頼済み組織は表示されたまま読み取り専用となり、カスタムソースは追加、編集、削除できます。モジュールページは既知のモジュールですぐに表示され、設定済みソースから応答が届くたびに検出結果を個別に追加します。

## ブランチ選択と更新検出

マーケットプレイスの詳細にリポジトリの全ブランチを表示し、既定ブランチを自動選択するようになりました。インストール時に選択したブランチとコミットを記録し、そのブランチが進んだ場合はモジュールカードと詳細に更新操作を表示します。

## Marketplace 画像を安全に配信

Marketplace 画像はサーバーが取得し、推測困難な同一オリジン URL で配信します。画像がない場合は Content Security Policy を緩和せず、同梱の疑問符アイコンを使用します。

## おすすめモジュールを管理

おすすめ状態はモジュールマニフェストではなく、管理者が設定できる公開 UUID リストから取得します。Marketplace 設定でおすすめとソースの両方を管理できます。

## モジュール導入を完了

導入したモジュールは直ちにランタイムへ取り込み、管理者が有効化するまで無効のままにします。Marketplace 画像は推測困難な公開同一オリジン URL から読み込みます。

## Marketplace 詳細を改善

ライセンスをタグから分離し、詳細画面は結果領域の全幅を使用します。戻る操作と更新操作は簡潔な SVG コントロールになりました。

## インストールと有効化を分離

インストールしたモジュールは、管理者が明示的に有効化するまで無効のままになります。有効化または無効化するとブラウザーのナビゲーションプラグインを直ちに更新し、再読み込みなしで新しいナビゲーション項目を表示します。

## Marketplace 操作をテーマ対応

戻る操作と更新操作は、現在のダッシュボードテーマに応じて専用のライトおよびダーク SVG アセットを使用します。

## 検出済みモジュールを維持

Marketplace マニフェストを設定済みソースごとにキャッシュします。アンインストールしたモジュールは直ちに利用可能へ戻り、一時的なソース障害ではキャッシュを維持し、すべての設定済みソースが不在を正常に確認した場合のみ一覧から消えます。

## Core をモジュールから除外

プラットフォームの Core はインストール可能なモジュールではないため、Cognis Core をモジュール管理一覧から除外しました。

## 宣言済みライセンスを検証

リポジトリ直下に認識可能なライセンスファイルがある場合のみライセンス情報を表示します。その証拠がないライセンス宣言はインストール検証で拒否します。

## モジュール導入時間を確保

Marketplace のインストール要求を 10 分間待機し、Jitsi Meet のような大きなリポジトリのクローンと検証が共通 API の 30 秒タイムアウトで失敗しないようにしました。

## 最初にすべてのモジュールを表示

モジュール状態フィルターに「すべて」を追加して既定値とし、ページを開いた際にインストール済み、利用可能、おすすめのモジュールをまとめて表示します。

## 進行状況を表示してリリースをインストール

モジュール検出でブランチに加えてリポジトリのタグも取得するようになりました。詳細画面の選択肢は引き続き既定ブランチを初期値にします。ライフサイクル操作ボタンには処理中のスピナーが表示され、インストール要求は2分で適切に制限されます。

## Marketplace 設定を統合

モジュールソースは Marketplace 設定ダイアログ内の専用セクションに集約されました。提供元とバージョンはカテゴリタグから分離して表示され、設定アイコンはライトテーマとダークテーマの両方に対応します。

## 有効化前にモジュールをテスト

モジュールを有効化するとき、実行状態を変更する前に、そのチェックアウトが提供する標準の JavaScript および TypeScript テストをすべて実行するようになりました。テストの失敗またはタイムアウト時は有効化を拒否し、モジュールテストの失敗を報告します。

## Core のテストコマンドに外部モジュールを追加

ルートの `npm test` は Cognis のソースツリーと、設定された外部モジュールのチェックアウトルートの両方からテストを検出するようになりました。`COGNIS_EXTERNAL_MODULES_ROOT` を使ったリポジトリ外のチェックアウトにも対応します。

## Marketplace カタログを即時復元

モジュールページはバックグラウンド検出を始める前に、ソースごとの保存済みカタログから表示を復元するようになりました。画面移動後やサーバー再起動後も既知のモジュールが表示されます。Repository の更新は成功した候補ごとに反映し、個別の確認が不確定な場合はキャッシュ済み項目を維持します。

## Jitsi Meet のインストールを復元

リリースタグのメタデータが導入される前に保存されたカタログからもインストールできるようになりました。欠落した `releases` によって Jitsi Meet のインストールが失敗する回帰を解消し、Repository ごとの独立した確認によって組織内の別 Repository が Jitsi Meet を非表示にする問題も防ぎます。

## インストールエラーを局所的に処理

想定されるモジュールインストールの失敗では、グローバルな「接続が中断されました」状態や永続トーストを表示しなくなりました。Marketplace の操作自体は引き続き失敗内容を通知します。

## モジュールのライフサイクル変更を即時通知

インストール、有効化、無効化、更新、アンインストールの完了時に Marketplace を直ちに更新し、構造化されたライフサイクルイベントを通知して、ナビゲーション登録とサーバー上の正式な状態をページ再読み込みなしで反映するようになりました。詳細画面のバージョン選択も有効なテーマに従います。

## モジュール操作の状態を同期

モジュールのライフサイクル処理状況を、クリックされた DOM 要素だけでなくモジュール UUID ごとに保持するようになりました。カード表示と詳細表示を切り替えても、無効化された操作とスピナーが維持されます。成功時は次に利用できる操作へ直ちに切り替わります。リリース選択から競合するライトモード用クラスを削除し、インストール失敗時は正確なサーバーエラーを表示して、構造化されたサーバーおよびブラウザログを記録します。

## マーケットプレイスのインストールを堅牢かつリリース対応に改善

モジュールのインストールをポーリング式バックグラウンドジョブにし、正常なクローンがリバースプロキシで 504 にならないようにしました。サーバー起動時のソース更新、マニフェスト版による更新判定、リリースチャンネル切替、ダウングレード確認、高度な強制更新に対応します。

## メディアギャラリーとテーマ対応コントロールを追加

モジュールリポジトリ直下の `media/` に対応画像・動画を配置できます。詳細画面では横スクロールギャラリーとして表示し、ネイティブのリリースチャンネル選択には競合クラスを使わず明示的なテーマ色を適用します。

## 中断されたモジュールダウンロードを再試行

モジュールのインストールでは互換性の高い Git の HTTP/1.1 通信を強制し、接続リセット、タイムアウト、DNS 障害、TLS 転送中断など一時的なクローン失敗を再試行するようにしました。各試行は空のステージングディレクトリから始まり、永続的なリポジトリまたは検証エラーは正確な診断を保持したまま直ちに停止します。

## GitHub タイムアウトを診断

モジュールダウンロードは、停止した GitHub クローンを30秒後に終了し、一時的な障害を再試行して、既知のコンテナネットワーク MTU 原因を構造化サーバーログへ記録します。Cognis が配備ネットワークを上書きする代わりに、管理者にはホストまたは Docker ネットワークの MTU 確認を促す専用トーストを表示します。

## 外部モジュールを完全に読込

外部モジュールのブートストラップコンテキストは、対応するすべての HTTP メソッドに加え、ナビバー、SPA ルート、設定、管理、ページ、認証入力文、静的リソース、フロー、ログ、スコープ付きケイパビリティの登録を取り込むようになりました。外部会議プロバイダーも組み込みコンポーネントと同じ解除可能な契約でナビゲーションとルートを登録できます。

## モジュール詳細操作を整列

詳細用ハンバーガーメニューをモジュール詳細上部の「戻る」操作と同じナビゲーション行へ移動し、インストールとライフサイクル操作は独立した操作行に残しました。

## 導入済みモジュールと画像を保持

Docker 配備では、設定済みの外部モジュールルートにマウントした専用の名前付きボリュームへ外部モジュールを保存するようになり、アプリケーションコンテナを再構築しても導入済みモジュールが保持されます。Marketplace の状態調整でも、導入済みマニフェストの状態を統合するときにカタログ経由のアイコンとバナー URL を維持し、ページを更新するまで画像が消える問題を防ぎます。

## 強制更新中も有効状態を保持

「強制更新」は、有効なモジュールのチェックアウトを置き換える前に一時的に無効化し、処理後に再び有効化します。ダウンロードまたは検証に失敗した場合も既存のチェックアウトを再有効化するため、強制更新の失敗によってモジュールが意図せず無効のままになることを防ぎます。

## リリースチャンネルを明示的に変更

導入済みモジュールのリリースチャンネル選択を詳細メニューへ移動しました。管理者がスクロール可能なボタン一覧から選択して確認すると、Cognis がそのチャンネルを自動的にインストールします。処理中のライフサイクルボタンは読み込み表示とともに「インストール中」「アップグレード中」「ダウングレード中」または「リリースチャンネルを変更中」を示し、成功後は「インストール済み」になります。

## 外部モジュールのインストール先から UI ルートを読み込む

インストール済みモジュールは、外部モジュールディレクトリ内で安定した UUID により解決されるようになりました。宣言されたページとナビゲーション項目は、同梱モジュールのパスを検索する代わりに、起動時に自動的に読み込まれます。

## リクエスト前に起動を完了

Cognis は、保存済みモジュール状態の復元とモジュールの起動が完了してからリクエストを受け付けるようになりました。これにより、外部モジュールのスクリプトとスタイルは、ページから要求される前に登録されます。

## 認証ケイパビリティを提供

認証ゲートウェイは、リクエスト認証とロールアクセスの関数をケイパビリティバスへ公開するようになりました。外部モジュールはゲートウェイ内部をインポートせずに保護された API ルートを起動でき、UI アセットとナビゲーション登録が維持されます。

## 宣言された UI 機能のみ読込

モジュールはマニフェストで `requiresCapabilities` を宣言できます。モジュールルートをマウントする前に、Cognis は宣言された `ui:*` ケイパビリティの登録済みプロバイダースクリプトだけを読み込み、無関係な統合へのアクセスを与えずに必要な UI サービスを準備します。

## ケイパビリティの確認と文書化

Owner は `GET /api/v1/system/capabilities` または `cognisctl system:capabilities` ですべての登録済みケイパビリティ ID を一覧できます。モジュール、認証ゲートウェイ、プロフィールアダプターの文書に、要件宣言と各プロバイダーが提供するケイパビリティを記載しました。

## リリース版の方向を表示

インストール済みモジュールのカードと詳細表示では、選択中チャネルの異なるバージョンを現在のバージョンの下に表示します。アップグレードには上向き矢印を使い、まれなダウングレードには薄いオレンジ色のピル内で下向き矢印を表示します。

## モジュール詳細を安定表示

モジュール詳細表示を開く場合や更新する場合に、ページ位置が維持されるようになりました。表示するすべてのバージョンに `v` 接頭辞を付け、有効なモジュールの更新では、無効化、インストール、再有効化を一回の操作で実行します。

## 詳細操作を安定表示

モジュール詳細ページは Page Composer 内に留まりながら、ルーター対応の UUID ディープリンクを使用するようになりました。有効なモジュールをアップグレードのため一時的に無効化している間も、ライフサイクル更新によって表示中のボタン構成が変化しません。

## 直接表示を一度だけ起動

外部モジュールの SPA ルートを直接表示する場合、宣言されたケイパビリティプロバイダーをモジュールルートより先にインポートする Core エントリポイントを使用するようになりました。プロバイダーとルートの URL はルーターナビゲーションと同じアセット版を使うため、断続的なケイパビリティ不足とナビゲーションバー項目の二重登録を防ぎます。

## 同梱モジュールの切出し準備

Analytics と Nextcloud Whiteboard は、専用リポジトリ情報、ライセンス、README、完全な整合性一覧、翻訳済み配布ガイド、UUID 依存関係、明示的なケイパビリティ要件を備えた自己完結型の外部モジュールリポジトリになりました。

## モジュールのスクリーンショット閲覧を改善

モジュール詳細のスクリーンショットを、前後の操作、隣接画像のフェード表示、スライドアニメーション、自動切り替えを備えた大きさの制限されたカルーセルにしました。任意の `template: true` フィールドを持つマニフェストは、マーケットプレイスの結果と直接の詳細表示から除外されます。

## マーケットプレイスのモジュールを一意化

Analytics と Nextcloud Whiteboard は専用リポジトリへ移行し、同梱されなくなりました。マーケットプレイス検出は各モジュール UUID の最初のリポジトリを採用し、後続の重複を記録して拒否します。また、インストール済みのライフサイクル状態を維持しながら、採用したリポジトリの表示メタデータへ更新します。

## Gateway インフラ用ディレクトリを除外

Gateway の自動検出は Gateway マニフェストを含むディレクトリだけを起動するようになり、本番ビルドで `gateways/reuse` インフラ用ディレクトリが Gateway としてインポートされなくなりました。

## モジュールのライフサイクル通知を明確化

モジュールの無効化を警告レベルで記録し、外部モジュールの削除も明示的に記録するようにしました。マーケットプレイスの更新完了通知はクリックごとに一度だけ表示され、マニフェストで `template` が明示的に `true` に設定されていないモジュールは引き続き表示されます。

## Cognis HQ モジュールを推奨

組み込みの推奨リストに、Cognis Labs HQ 組織が公開する Jitsi Meet、Nextcloud Whiteboard、Analytics のモジュール UUID を追加しました。

## モジュールのログを拡充

モジュールソースの追加、更新、削除、スキャン、および検出件数を適切なレベルで記録し、検証と有効化の失敗をエラーとして記録するようにしました。マニフェストが存在しない拡張子を指定している場合、マーケットプレイスの画像検出は同名の PNG など対応画像へフォールバックします。これにより、マニフェストが未配置の SVG を指している間も Jitsi Meet の画像が表示されます。

## モジュール画像のちらつきを防止

更新された各画像が有効な寸法を取得するまで、モジュールカードと詳細メディアを非表示にするようにしました。アイコン領域も読み込み前から固定寸法で確保し、マーケットプレイス更新時に未整形または特大の画像が一瞬表示されることを防ぎます。

## 不確かなスキャンでもモジュールを保持

マーケットプレイスのスキャンは、空のリポジトリ応答、一時的に取得できないマニフェスト、一時的な不正応答、またはソース要求の失敗を、以前に検出したモジュールが削除された証拠として扱わなくなりました。ソースが明示的に削除されるまでキャッシュ項目を表示し続け、警告ログに失敗したスキャンと保持件数を記録します。

## 安全で効率的なモジュール検出

マーケットプレイスの更新を認証付きの単一スキャンに集約し、信頼済みソースで GitHub ユーザートークンを設定できるようにしました。また、外部コード実行前の依存関係と確認の検査を復元し、GitHub Enterprise のマニフェスト取得に設定済み API を使用します。

## 直接読み込みを完了

モジュールページを直接読み込む際、ページ構築の完了または失敗後に追跡中の読み込み処理を必ず終了するようにし、ブラウザー更新後も読み込み表示が残り続ける問題を修正しました。

## スキャンの保存と制限

サーバー再起動後は、保存済みのマーケットプレイスカタログを最初のモジュール情報源として使用します。ページ読み込み時と起動時の自動スキャンによるプロバイダー枠の消費をなくし、スキャン試行を1時間間隔で保存して、繰り返し更新時はディスク上のカタログを再利用します。

## ソースキャッシュの修正

組み込みの Cognis Labs HQ ソースで、識別情報をロックしたまま PAT を更新できるようにしました。重複するモジュール UUID は Cognis ソースを優先し、カタログ、スキャンメタデータ、アセットを設定済みモジュールディレクトリの .cache に保存します。

## GitHub 認証を即時適用

設定済みの PAT 欄には秘密を公開せずマスク値を表示します。新しい認証情報を保存すると、そのソースのスキャン待機時間を解除し、次のマーケットプレイス要求から新しい GitHub 認証を直ちに使用します。

## プロバイダートークン検証

新しいマーケットプレイス PAT は保存前に設定済みプロバイダー名前空間で検証します。無効、未承認、確認不能、または権限不足の認証情報にはローカライズ済み警告を表示し、修正できるようソース編集画面を開いたままにします。

## PAT 設定を保持

マーケットプレイスの認証情報 ID をモジュールディレクトリのキャッシュにも保存します。PAT 自体をユーザーのキーリング外に保存することなく、サーバーまたはコンテナ再起動後も組み込み Cognis ソースの設定済み PAT 表示を復元します。

## PAT 権限を参照

UI の認証情報警告を簡潔にしました。サーバーログには検証問題の詳細、必要な GitHub のきめ細かな権限（リポジトリアクセス、Metadata 読み取り、Contents 読み取り）、プライベートリポジトリ用の従来型 repo スコープ、組織 SSO 承認、公式資料への参照を記録します。

## リリース変更を安定化

リリースチャンネル変更、アップグレード、ダウングレードでは、再起動前に選択したブランチ、コミット、バージョンを保存します。再起動警告は以前有効だったモジュールだけに表示し、対象モジュールは再起動まで追加操作を拒否します。変更なしまたはキャンセルしたチャンネル変更も後続操作と競合しません。

## モジュール詳細を維持

モジュール詳細の操作をコンポーザーのフローティングメニューに移し、状態とカテゴリのナビゲーションにはバランスの取れたスクロール可能なサイドツールバーを使用します。更新、ライフサイクルイベント、トースト後も詳細選択を維持し、明示的な移動時だけ詳細表示を終了します。

## モジュール操作を整列

フローティングのモジュール操作は、戻る操作を含め高さと縦位置を統一しました。詳細ハンバーガーメニューはポップアップを安定して配置できるよう詳細ヘッダー内に戻し、軽量な操作更新によって無関係なクリック時のモジュールカード全体の再描画を避けます。

## モジュール操作を明確に対応付け

モジュールカードの操作を読みやすいグリッド列に折り返し、インストール済み、アップグレードまたはダウングレード、有効化、アンインストールの各ラベルが別々の操作に明確に対応するようにしました。モジュールの有効化時には無効なゲートウェイ依存関係を有効化して保存し、本当に不足している依存関係には汎用的な 400 エラーではなく具体的で対処可能な応答を返します。

## リリースチャンネルのバージョンを更新

明示的なカタログ更新では通常のプロバイダースキャン待機時間を迂回し、各ブランチのマニフェストを再取得します。選択中のブランチがインストール済みバージョンに追いつくと、古いダウングレード操作を直ちに削除します。実際のダウングレードでは選択したブランチをインストールし、「ダウングレード中」と「モジュールをダウングレードしました」をアップグレードとは別に表示します。

## 選択したダウングレードリビジョンをインストール

ダウングレードでは、インストール開始前にブランチが進んだ場合でも、更新済みカタログが示す正確なコミットをインストールします。ダウングレード表示には専用のダークテーマを追加し、モジュール詳細では固定アプリヘッダーの背後にバナー画像が透けないよう不透明な背景を適用しました。

## コミットでブランチバージョンを解決

Marketplace の検出では、変更可能なブランチ名ではなく、プロバイダーが返す不変のコミット SHA を使って各ブランチとリリースのマニフェストを読み取るようにしました。GitHub Contents API や中間キャッシュの古い応答を避け、カタログのバージョン、表示される更新方向、インストールされるリビジョンをプロバイダーのブランチコミットと一致させます。

## インストール前にモジュール依存関係を検証

モジュールマニフェストで、必要なコアコンポーネントを安定した UUID または従来の ID により宣言できるようにしました。Cognis はインストール済みモジュールを置き換える前に、チェックアウトしたリポジトリの正式なマニフェストを検証します。参照コンポーネントが存在しないか無効な場合は具体的なエラーでインストールを失敗させ、有効な UUID 依存関係は通常どおりインストールします。

## アダプター UUID 依存関係を解決

Jitsi Meet と Nextcloud Whiteboard は Social Profile アダプターの UUID を正しく要求し、Jitsi はさらに Social Messages アダプターの UUID を要求します。インストール時にアダプターマニフェストを自動検出し、所有ゲートウェイを通じて UUID を解決するようにしました。ゲートウェイが有効なら受け入れ、無効または存在しない場合は拒否します。

## 有効化時のアダプター依存関係を解決

モジュールの有効化でも、インストールと同じ検出済みコアコンポーネントカタログを使用するようにしました。Social Profile や Social Messages などのアダプター UUID 要件を所有する Social ゲートウェイへ解決し、利用できないゲートウェイとして誤報しないようにしました。

## 意図的に無効化された依存関係を尊重

モジュールのマニフェストを満たすために、無効なゲートウェイを自動的に有効化しないようにしました。依存関係を無効なまま維持してモジュールの有効化を拒否し、Profile Adapter や File Gateway など人が読めるコンポーネント名を返すため、モジュールページで明確な修正案内をトースト表示できます。

## モジュール操作をカード幅に配置

モジュールカードの操作ボタンが、使用可能な行全体を均等に分割するようになりました。1、2、または3個の操作を持つカードで、ボタン分の空白が残ったり、1つの操作が次の行に回り込んだりしません。

## モジュール SPA 遷移を安定化

モジュール提供の SPA ページで、モジュールのエンドポイントだけが認可エラーを返した場合でも、認証済みセッションを維持するようになりました。Cognis はセッション切れとして扱う前にアカウントセッションを検証します。プロフィールの在席状況メニューは、ダッシュボードシェルの更新後に重複なく再マウントされ、スタイルシートの読み込みを待つため、在席状況コントロールの欠落や二重表示を防ぎます。モジュールナビゲーションは独自の縦スクロールバーを持たず自然な高さまで伸び、対応するメインコンテンツがその高さを超えた場合はコンテンツパネル内でスクロールします。

## モジュール見出しとポインター初期化を修正

モジュールのコンテンツカードは固定の「モジュール」見出しを表示し、状態フィルターはナビゲーション内に残るようになりました。共有ポインター追跡が CTX ケイパビリティバスを明示的にインポートするため、モジュール提供ページの直接マウント時に失敗しなくなりました。

## 同梱の言語モジュールを削除

Cognis English と Cognis Japanese は、それぞれ独立した Marketplace リポジトリからのみインストールされるようになりました。同梱モジュールのワークスペースを削除し、実行時検出、UI ルーティング、整合性検査、CLI プラグイン、Study 言語登録は `COGNIS_EXTERNAL_MODULES_ROOT` 配下の UUID 指定インストールのみを使用します。共通の Study ナビゲーション資産は Study ゲートウェイが所有するようになりました。

## モジュールナビゲーションに標準スタイルを使用

モジュールのサイドナビゲーションはページ固有の上書きを行わず、ページコンポーザーが提供する既定のツールバーレイアウト、余白、選択状態、レスポンシブ動作、スクロール設定をそのまま使用するようになりました。

## モジュール設定

モジュールは `ui.preferences` で管理者が編集できる真偽値、文字列、数値の設定を宣言できます。インストール済みモジュールの詳細画面には、その項目が存在する場合だけ設定ボタンが表示されます。値は宣言済みキーに限定され、Cognis の設定ストアへ管理者ごとに保存されます。

## より安全なライフサイクル操作

外部モジュールの有効化ではテスト実行前に確認が必須になり、アンインストールは正規 UUID のインストールパスだけを受け付けます。正常なストア走査では撤回済みリポジトリを削除し、判定不能な更新では最後の既知エントリを保持します。

## モジュールローダー内部の整理

Core に残っていたモジュールのライフサイクルサービスとテスト実行サービスをすべて `services/module-loader/` にまとめ、テストも同じ構成にしました。外部モジュールおよび Study 言語フレームワークの文書は、対応するすべての言語で包括的かつ同じ構成になりました。

## モジュールナビゲーションをコンパクトに

モジュールページでページコンポーザーのサブページナビゲーションレイアウトを有効にしました。サイドメニューはナビゲーション内容に必要な幅だけを使用し、残りの幅をモジュール一覧に利用できます。

## マーケットプレイス読み込みの安全性

モジュールページはルーターによるインポート中の直接マウントを抑止し、リポジトリ認証情報をキーリング経由で解決するようになりました。これにより、非公開リポジトリの検出やインストール前にロック済み保管庫を解除できます。GitHub のリポジトリファイルと表示用アセットは、GitHub Enterprise を含む各ソースに設定された API ホストを使用します。

## コンパクトなナビゲーションと依存関係

モジュールページのサイドメニューは固定幅ではなく、ドキュメントのナビゲーションと同様に最長の項目へ動的に幅を合わせるようになりました。管理画面では UUID のみで保存されたコンポーネント依存関係を、インストール済みのゲートウェイ、アダプター、同梱または外部モジュールの名前に解決し、対象コンポーネントへのリンクも維持します。 ステータスとカテゴリのフィルターは有効な選択をすべて明示し、管理者は複数のカテゴリを組み合わせ、選択したいずれかのタグに一致するモジュールを含めることができます。

## ランタイムモジュールの有効化を強化

外部モジュールのブートストラップに安全なタイムアウトを設け、失敗したモジュールを無効化し、宣言されたサーバー機能を有効化前に検証するようにしました。SPA ルートは無効なプロバイダーの機能を読み込まず、Study の言語記述子はモジュール更新後に再同期されます。タイムアウトしたブートストラップは、期限後にルートや機能を登録することもできません。

## モジュール設定をすばやく開く

管理者が編集できる設定を宣言したインストール済みモジュールでは、詳細オプションメニューのすぐ右にテーマ対応の SVG 設定コントロールを表示するようにしました。このコントロールから既存の設定ポップアップを開き、値を変更して保存できます。

## 全コンポーネント依存関係を解決

依存関係を持たないコンポーネントでも、ゲートウェイのブートストラップがマニフェストの UUID メタデータを保持するようにしました。これにより、管理画面ではすべての UUID をコンポーネント名とリンクに解決します。アダプターリンクは所有ゲートウェイを展開して対象へスクロールし、モジュールリンクは詳細を開き、リポジトリ検査は UUID のみのマニフェスト依存関係を強制します。

## ブラウザー機能の検証を分離

モジュールの有効化では、サーバー機能とブラウザー機能をそれぞれの所有ランタイムコンテキストで検証するようにしました。`ui:` 名前空間のブラウザー専用要件は、有効化時に UI レジストリのアクティブなプロバイダーに対して解決し、SPA ルートのマウント前にも再確認します。要件を迂回したり、サーバーコンテキストで検索したりすることはありません。

## モジュール設定フィールドを安定化

モジュール設定ポップアップで、一貫した全幅フィールドと整列した真偽値コントロールを使用するようにしました。宣言された各フィールドの説明は、フォームの高さや入力位置を変えず、ラベル横の再利用可能な情報ポップアップに表示されます。

## 在席状況コントロールを一つに維持

プロフィールアダプターは、スタイル、翻訳、テンプレートを読み込む前に在席状況メニューのスロットを同期的に確保するようになりました。同時に動作するナビゲーションバープラグインはそのスロットを再利用し、古い重複を削除し、失敗した確保を再試行できるよう解放します。これにより、モジュールや SPA の更新後に在席状況ドロップダウンが重複しません。

## モジュール設定を明示的に適用

モジュール設定では説明を自動表示せず最初のフォームコントロールにフォーカスし、保存完了後だけ成功通知を表示します。Cognis はマニフェストで宣言されたフィールドを描画し、モジュール所有の `GET /api/v1/modules/<id>/config` エンドポイントから値を読み込み、同じエンドポイントへ `PUT` で変更を書き込むため、検証、適用、永続化の権限はモジュールだけが持ちます。

## モジュール所有の構成エンドポイントを使用

Cognis はモジュールマニフェストで宣言されたフィールドを描画し、各モジュール所有の `GET` および `PUT` 構成エンドポイントを通じて値を読み書きするようになりました。運用設定の検証、適用、永続化は引き続きモジュールが担い、Cognis は設定ストアを使った並行構成を保持しません。

## モジュールにホストのログ記録とフィードバック機能を提供

モジュールのサーバーコンテキストは、モジュールに関連付けたエントリをアプリケーションログへ書き込むようになりました。ブラウザーモジュールは、運用上の障害をブラウザーコンソールだけに残さず、認証済みサーバーログ、テーマ対応トースト、ランタイムエラーポップアップのホスト機能を使用できます。

## インストール済みリリースチャンネルを更新

Marketplace の更新では、リポジトリの既定値より先に、インストール済みモジュールのアクティブなブランチまたはリリースを参照し、マニフェスト、バージョン、README、表示用アセットもそのチャンネルから取得します。更新時はホーム表示を維持し、開いている詳細表示の選択を保ち、最新のライフサイクル状態からフローティングアクションを再描画します。

## モジュール UI クライアントとローカライズ済み構成を提供

Profile、Messages、Files、Share はブラウザークライアントを有効な UI 機能として公開するようになりました。外部ルートはナビゲーションバーの起動と競合したりゲートウェイエンドポイントを直接呼び出したりせず、ゲートウェイ所有データを利用できます。インストール済みモジュールの言語バンドルはブートストラップ前でも利用でき、モジュール設定はそれらの文字列を解決しながら、モジュール所有の `/config` エンドポイントを読み書きします。

## すべてのモジュール用ブラウザークライアントを待機

直接またはルーター経由のモジュールマウントは、モジュール UI をインポートする前に、すべての有効なナビゲーションバー機能プロバイダーを待機します。これにより Files、Profile、Messages、Share、フィードバック、およびその他の宣言済みホストクライアントが確実に利用可能になります。ドキュメントには非公開の標準構造と、変更履歴以外のすべての実ドキュメントを対象とする自動見出し規約監査を追加しました。

## スタンドアロンと Navbar の Capability Provider をまとめて読み込み

ブラウザの Provider カタログに、Navbar ベースのクライアントとスタンドアロンのホスト Provider の両方が含まれるようになりました。これによりモジュールルートは、Navbar の検出だけに依存せず、マウント前に Files クライアントとフィードバック Capability を受け取ります。

## モジュール設定を一度だけマウント

Modules ページは SPA の再マウント前に、以前の直接読み込み用インタラクションスコープを中止するようになりました。モジュール詳細ルートを開いてもホーム表示の設定ハンドラーが残らず、1 回のクリックで開くポップアップは 1 つだけです。
