# 設定可能なログインセッション有効期間

## 管理者がセッションの上限を管理

管理 → セキュリティで、ログインセッションのデフォルトかつ最大の有効期間を設定できるようになりました。

## ユーザーはより短いセッションを選択可能

各ユーザーは設定 → セキュリティで、より短い有効期間を選択できます。新しく発行されるログイントークンは保存された設定を使用し、アプリケーションやデータベースの再起動後も有効です。

## 時間単位を選択

ログインセッション期限を、分へ換算せずに分・時間・日・週間から指定できるようになりました。

## 期限のないセッションを許可

管理者は「なし」を選んでセッションの期限切れを無効にできます。本番環境では推奨されない設定であることを明確に警告します。

## セキュリティ設定を整理

ユーザーのセキュリティ設定で、ログインセッション期限が管理画面と同様に独立したサブセクションとして表示されるようになりました。

## 期限の変更を確実に追跡

管理画面とユーザー設定の両方で、セッション期限のフィールドが未保存の変更として追跡されるようになりました。ユーザー設定では、パスワード操作と期限の見出しの間にも一貫したセクション間隔が設けられます。

## ユーザーの選択を保持して期限切れを通知

管理画面で互換性のある期限変更を行っても、各ユーザーが保存した期間は維持されます。一時的に上限を短くした場合も、保存値を上書きせずに適用時だけ制限します。API セッションが期限切れになると、直ちにログイン画面へ戻り、既存のセッション期限切れメッセージを表示します。

## グローバルな期限に戻す

ユーザー設定の期間単位の横に、元に戻すアイコンのボタンを追加しました。リセットすると独自の期間指定が解除され、現在および今後の管理画面のデフォルト値にセッション期限が追従します。

## 期限の変更を安全に適用

「なし」を選ぶと数値フィールドが非表示になり、検証エラーなく保存できるようになりました。期限が全体で無効な場合、ユーザー設定には選択できない「なし」が表示されます。個人の期限を保存またはリセットすると、そのユーザーの既存セッションがすべて取り消されます。

## リセット時にグローバルな期限を更新

リセット操作を常に利用できるようにしました。クリックするたびに管理画面の最新の期限を再取得し、実効値またはデフォルトへの追従状態が異なる場合だけ変更として扱います。

## ログイン時に「なし」を維持

認証の初期化処理で、保存されたグローバル期限の 0 分を 12 時間の代替値に置き換えず保持するようになりました。同期したユーザーには期限のないセッションが発行されます。

## 現在のセッションのカウントダウンを表示

ユーザーのセキュリティ設定で、期限の操作項目の横に現在のセッションの残り時間を表示するようになりました。カウントダウンにはセッション発行時に記録した期限を使用し、期限のないセッションでは表示しません。

## カウントダウン処理を認証内に配置

カウントダウンの整形処理をコア UI の再利用領域ではなく認証ゲートウェイ内に移しました。現在のセッションは、週・日・時間・分・秒を使って読みやすく表示されます。
