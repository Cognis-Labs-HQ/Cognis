# オフラインナビゲーション

**機能ブランチ:** feature-offline-navigation

## UI の言語を即時反映

言語ショートカットは有効な UI 言語だけを切り替え、最後の選択から二秒後に段階付きフロー `ui:languageCatalog:select` と `ui:redraw` で表示を更新します。ブラウザー文書、URL、履歴、非公開のオフラインキャッシュは維持します。未保存の編集には移動確認を適用し、古い処理や描画失敗では別の言語を確定しません。表示言語はタブ内のアカウント・セッションに紐付き、有効な言語や設定済みの順序を変更しません。設定の保存・破棄は従来どおりで、保存した優先順も二秒後に再描画します。オフラインでは利用可能な言語の表、表をまたぐ移動、ブラウザーとの同期を無効にし、選択済みの言語だけを並べ替えて通常の設定キューに保存できます。有効な言語についてコアと公開コンポーネントの翻訳を準備します。キーごとの英語へのフォールバックを維持し、英語にもないキーは明示的に失敗します。ワーカーはホストの全コンポーネントの翻訳 XML と言語の旗 SVG を準備し、未訪問でも準備済みのページをオフラインで再描画できます。共有シェルと提供済みの基本ナビゲーションも、プロバイダーを破棄せずに翻訳し直します。ページ終了やバインドの置き換え時にはタイマーを解除します。

## オフライン時の移動先表示

利用できない移動先も、メインナビゲーション、ユーザーメニュー、Study サブメニューに共通の無効表示で残します。Library と管理・申請へのリンクはオフライン中も一覧に残り、無効になって再接続後に有効に戻ります。表示する項目は引き続き Study の権限に従います。無効なリンクからはルートの読み込みや復旧通知を開始しません。Study の状態を引き継ぐ言語・設定リンクも同様です。キャッシュ済みの Explore と Flashcards は利用できます。

## 一貫したオフライン表示

オフラインで保存した場合も、接続中と同じ成功メッセージと表示種別を使用します。メッセージ、投稿、画像アップロード、メールアドレスの変更ではキュー専用の通知を追加せず、メッセージの状態も通常の表示を使用します。実際の保存失敗や変更の拒否は引き続き表示します。共通の警告バナーは、明暗のテーマに対応する意味ベースの配色で、不透明な琥珀色の背景、文字、枠線、操作ボタン、控えめな縞のアクセントを統一します。オフラインモードから個別の背景スタイルを渡す処理は廃止しました。折りたたみのアニメーション、キーボード操作、動きを減らす設定への対応は維持します。

## マーケットプレイスの一括更新

マーケットプレイスは独立したモジュール情報を準備し、各モジュールの翻訳を読み終えてから表示中のカタログを置き換えます。別のモジュールの翻訳を読み込み中でも、モジュールの更新後に安全に再描画でき、タグはホストではなく所有するモジュールの翻訳で解決します。翻訳が本当に欠けている場合は明示的に失敗し、最後の完全なカタログを表示したままにします。ライフサイクル操作は古い更新結果を無効化し、操作や依存関係の確認中は定期取得を停止します。インストール済み情報と異なる場合も、カタログ情報には対応する翻訳を使用します。

## 滑らかな復旧と画面遷移

オフライン通知は、不透明なテーマ色の面の上に細いオレンジと白の帯を表示します。折りたたみバナーは文書内の自然な領域を保持し、切り抜く外枠の高さと本文の透明度をアニメーションさせます。キーボードで展開でき、動きを減らす設定では遷移を無効にします。起動時に準備するウェブマニフェストを含む公開アセットは、法的同意の前でもキャッシュを利用できます。非公開文書と API データの認可条件は維持します。オフラインモードを明示的に無効化した場合はネットワークを使用します。個別のリソース失敗だけではオフラインにせず、ヘルスチェックの失敗を確認します。確認後は復旧時のカタログ更新までワーカーの追加チェックを停止します。Study のナビゲーションは確認済みセッションのスナップショットをすぐに利用し、再検証を集約して最大三十秒に一度行います。初回のメタデータ取得は五秒、任意の辞書検出は三秒で打ち切ります。明確なアクセス拒否でスナップショットを無効化し、登録言語やモジュールの変更でナビゲーションデータを破棄します。失敗した子ページ検出は再試行できます。

## 上部バナーの設定

`ui:broadcast.publish` の記述子は、CSS の色やグラデーションを指定する `background` と、既定値が false の真偽値 `collapsible` を受け取ります。不正な型や宣言を分割する背景値は拒否します。折りたたみ可能なバナーは下へスクロールすると高さ 2px の模様付きの帯となり、上へスクロールすると展開します。キーボードでフォーカスでき、ホバーやキーボードフォーカスでも本文と操作を表示します。スクロール位置の跳ねを防ぐため、展開時の領域を文書内に確保し、実際に表示している高さに合わせて固定ヘッダーとサイドバーを下へずらします。折りたたまないバナーは全体を表示し続けます。最後のバナーを削除すると監視、スクロールリスナー、配置のずらしを解除します。オフラインモードはオレンジと白の警告模様を使って折りたたみを有効にし、復旧時は保護された再読み込み操作を維持します。

## 個人設定のオフライン対応

認証済みログイン時に、設定画面を開かずにメール一覧と信頼済みドメインの方針を準備します。アドレスの追加、削除、主要アドレス変更はローカル表示に反映し、`notify:emailClient` と保護対象の `notify.emails` キュー所有者を通して保存します。最終的な検証はサーバーが行います。メール確認、再送、アカウントの削除や無効化には接続が必要で、確認コード、監視トークン、パスワードはキューに含めません。追加したアドレスはオンライン確認が済むまで未確認のままです。送信成功時にはメールのスナップショットを更新し、任意の再取得に失敗しても保存済みの操作を失敗扱いにしません。容量を制限した非公開スナップショットはタブとセッションに紐付きます。

## フラッシュカードの事前準備

Flashcards は登録済みの学習・指導言語で表示対象となる全デッキを、2 ワーカーで準備します。80 件の打ち切りはありません。専用キャッシュは 64 MB、10,001 件の読み取りに制限し、ギャラリーと通常のデッキ集合を一緒に保持します。大きな集合には引き続きこの上限が適用されます。未登録言語は対象外です。共通スキーマ一覧は言語未登録でも準備し、任意の Library コレクションが未取得でも準備済みデッキで練習できます。

## Orbitron のオフライン利用

Google Fonts の Orbitron を、ウェイト 400–900 の可変フォントとして同梱します。ライセンスは `src/ui/styles/fonts/OFL.txt` の SIL Open Font License です。オフライン移行前に、公開ワーカーがスタイルシートとフォントファイルを準備します。公開アセットはオンライン・オフラインともキャッシュを優先し、既存の集約されたバックグラウンド再検証で変更可能なファイルを更新します。Orbitron は実行時の Google リクエストに依存しません。他の任意の Google フォントは分離して読み込み、ローカルフォントを遅延させません。

## バナーの背景

共通の上部バナーは、スクロール中もテーマに合わせた不透明な背景を維持します。接続回復、警告、危険の通知には既存のテーマ色を使用します。

## オフライン対応の契約

本番ビルドは中立的な復旧ページを準備します。ライセンスとエラーページはオフラインで動作し、利用できないルートのリンクは無効になります。利用できないページへの直接移動ではエラーポップアップを表示しません。ブラウザーが接続中と表示していても、実際のサーバー接続失敗で代替動作を開始します。

SPA ルートで `public: true` と `offline: { assets: [...] }` を宣言してください。言語カタログとデータファイルを含むすべての公開実行時依存関係を列挙します。API 要求、非公開のアカウントデータ、ホスト全体のプロバイダー検出なしで動作する必要があります。非公開ルートは対応を宣言できません。移動にはルートリンクを使用してください。未知または未取得の依存関係は利用できません。

Service Worker は API 応答、認証情報、認証済み HTML を保存しません。モジュールの無効化で公開ルートカタログとモジュールアセットを削除し、リビジョン付きアセットは現在のカタログと一致する必要があります。切断中はリモートの変更を検知できず、最後に確認した公開リビジョンのみ利用できます。復旧時はカタログを更新し、未保存の変更を確認して再読み込みし、最新のサーバー認可に戻ります。Worker の更新は既存タブが閉じるまで待機し、復旧アセットを準備してから有効になります。Worker が未導入の初回アクセスではオフライン起動できません。

## リマインダーの選択

標準のチェックボックスで複数のリマインダーを選択し、まとめて保存できます。すべての選択を解除すると、カレンダーに既定値があってもリマインダーは無効になります。既存の独自の通知間隔も編集時に保持されます。

## オフライン学習

設定のオフラインモードは既定で有効です。無効にすると従来の接続警告とエラー通知に戻り、ワーカーの代替表示を停止します。有効な場合は接続が切れるとエラー通知なしでオフラインモードに切り替わり、利用できない移動はエラーポップアップを出さずに制限します。

Study は現在のタブ内に容量制限付きの軽量 JSON スナップショットを保持します。対象はスキーマ、許可された文字・カードデータ、保存先、閲覧済み ID、お気に入り、以前開いたデッキです。言語スキーマは `metadata.offline: { cache: "lightweight" }` で対応を宣言します。Library キャッシュは最大 16 MB・100 件、その他の読み取りキャッシュは最大 4 MB・100 件です。音声バイト、辞書応答、認証情報、認証済み文書は永続保存しません。

Explore のプレビューは認可済みのキャッシュデータを使います。描画とフラッシュカード練習はローカルで動作します。完了、評価、閲覧済み ID、お気に入りの最終状態を送信待ちとして保存し、進捗・XP・報酬はサーバー確認後に確定します。音声・辞書・ElevenLabs の要求は停止します。編集・削除・共有には接続が必要です。容量制限内で以前読み込んだ内容のみ利用できます。

非公開の Study では、同じタブ内で以前検証済みの、有効期限内の同じアカウントセッションが必要です。再読み込みと初回訪問では引き続き公開ページ専用のオフライン契約が適用されます。アカウント・セッション、設定、モジュールの状態が変わるか、プロバイダーが破棄されると非公開スナップショットを無効化します。切断中はサーバーでのアクセス取り消しを検知できません。復旧時には未保存変更を確認してから再読み込みし、サーバーの認可を更新します。

## 送信待ちと同意

ホストは ctx 経由で `offline:outbox`、`offline:state`、`offline:accessPolicy` を提供します。各コンポーネントはプロバイダーの有効期間中に送信処理を登録し、安定した操作 ID を `offline:enqueue` に渡します。`offline:flush` が認可と送信を行います。永続キューはアカウント別で最大 1,000 件・1 MB・7 日間、トークンは保存しません。元の ID と時刻を維持し、一時的な失敗を再試行し、確認済みまたは恒久的に拒否された項目を削除します。拒否は翻訳済みの警告で通知します。ログアウトで当該アカウントのキューを消去し、他のアカウントのデータは送信しません。オフラインモードを無効にすると新規保存を停止します。既存の項目はオンラインで送信できます。

復旧ではプロバイダーを更新し、`authenticate-session` の最終段階 `afterSession` で送信します。必須プロバイダーはサーバーカタログに `offlineAccessGuard` を宣言します。要件が不明または未同意の場合はオフライン利用を拒否します。Terms of Service は最後に取得した文書の版とサーバー確認済みの同意をアカウント別に保存します。新しい未同意の版を取得すると、オフラインの読み取り・移動・書き込みを直ちに禁止し、オンラインで同意するまで送信も停止します。オフラインでは同意できません。非公開コンテンツはタブ内のみで、再読み込み後も残るのは容量制限付きのキューと法的文書です。 各認証の前に、最初の `beforeSession` 段階で以前の送信検証を消去します。

## オフラインのソーシャル変更

Profile と Messages のプロバイダーは ctx 経由で有効期間に対応した HTTP 操作を登録します。検証済みのタブでは、読み込み済みのプロフィール・投稿・ルーム一覧・暗号化された履歴を利用できます。プロフィール文、在席状態、フォロー・ブロック状態、バナー配置、投稿の作成・削除、既存ルームの暗号化メッセージ、リアクションの最終状態、既読通知をアカウント別に送信待ちとして保存します。後のオンライン編集も同じ所有者の保留項目を待ちます。準備中やキューの待機中にアカウントやセッションが変わると操作を中止します。メッセージと投稿は安定した `operationId` UUID を使い、内容の相違や他のアカウントからの再送を拒否します。メッセージの再送で通知は重複しません。既読通知は元の閲覧時刻を維持します。

チャットは保存前に暗号化し、平文・ルームキー・認証情報をキューに追加しません。プロフィール文と投稿内容は現在のアカウントのブラウザーストレージに保存します。最大 350,000 バイトのアバター・バナーは既存の 1 MB・1,000 件・7 日間のキューを共有します。大きな画像には接続が必要です。容量不足では翻訳済みのエラーを表示し、メッセージと投稿の下書きは永続保存に成功した後にのみ消去します。制限は各コンポーネント単位ではなくキュー全体に適用します。

変更はサーバー確認まで保留します。メッセージには送信待ち状態を表示し、プロフィール・投稿・メディアには標準の送信待ちトーストを使います。現在のアカウントに保留項目があれば、無効なプロバイダーの項目を含め、閉じる操作や再読み込みでブラウザー標準の未保存変更の確認を表示します。確認済みまたはアカウントの消去後に警告は解除されます。文言や事前のユーザー操作の要否はブラウザーが決めます。保留項目は再読み込み後も残り、警告によって破棄されることはありません。

ソーシャルのキャッシュはタブ内のみで、同意が必要です。初回訪問、非公開ページのオフライン再読み込み、ルーム作成、メンバー・キーの管理、通話、大容量アップロードには接続が必要です。入力中状態や一時的な在席通知は再送しません。送信時には現在のサーバー認可を確認し、切断中のキャッシュでは遠隔の権限取り消しを知ることはできません。アクセスと再送の前に ToS への同意が引き続き必要です。

## オンラインのアイコン表示

Modules のツールバーは共通のボタンスタイルが後から読み込まれてもアイコンの寸法を保ちます。取得済みの更新・設定 SVG がボタンの余白によって細い線に縮む問題を修正しました。

## プロフィールの初期化

プロフィールの在席処理は、送信待ち対応クライアントの登録とアバターのスタイル読み込みが完了してからプロバイダーのマウントで開始します。インポートだけでは在席コールバックやポーリングを開始しません。無効化やマウント失敗では購読・ページリスナー・タイマー・在席キャッシュを解除し、古い非同期処理が後のプロバイダーを更新しないようにします。これによりオンラインの管理ページ初期化中の `profile_client_unavailable` を防ぎます。

## 登録と検索

SSO リダイレクト後に復元した場合も含め、認証済みセッションは `/api/v1/auth/setup-status` を確認します。通知側は `auth:getSetupIntegrations(accountId, role)` を通じ、`enforceSetup({ accountId })` を公開する同一オリジンの設定スクリプトを返します。設定完了後に画面移動とオフライン利用が許可されます。SMTP 障害でも必須の確認は免除されません。最初の創設者管理者は引き続き対象外です。

SMTP による確認は SSO とローカルの両アカウントに適用されます。再送には設定済みの通知配信サービスを使います。確認コードとリンクは、名前空間を含む SSO ID も含め、完全なアカウント ID とメールアドレスの組に結び付けられます。設定画面で確認を取り消しても既存のメールアドレスは保持されます。

管理画面は、ローカルアカウントの公開登録の許可を登録アダプターとは別に保存します。公開アダプターを有効にしたままローカル登録を無効にすると、ユーザー名とパスワードによる公開登録を許可せずに SSO アカウントを作成できます。アダプターを無効にするとこの作成経路も閉じます。招待トークンは専用アダプターで利用できます。全体検索は途中結果を表示し、置き換えられた検索を中断し、提供元の実行時間を制限します。文書の本文より先に見出しを表示し、ライブラリー全体を同時取得する代わりに、中断可能な四つの処理で本文を索引化します。

## 接続とアカウント

オフラインワーカーのポリシーとルート情報は、アセットとは別の制御キャッシュを使用します。カタログ要求を統合し、ポリシーの更新順を保ち、メッセージのポートを閉じます。バックグラウンドのアセット整理は応答を妨げません。インストール時の同時取得は最大四つです。ログインは公開キャッシュの保守を待たず、資格情報、TFA コード、SSO 認可の要求中に共通の読み込み表示を出します。対話的な設定操作は引き続き利用できます。接続確認は即座に応答し、詳細なコンポーネント診断は `/api/v1/system/health` に残ります。

公開 SSO プロフィール名には認証元の名前空間を含めません。既存の認証元付き名称はプロフィール初期化時に置き換え、重複時はランダムな接尾辞を付けます。すでに認証元を含まない名称は維持します。アカウント ID、ID の対応付け、投稿、関係は変更しません。名称変更に伴い公開プロフィールの URL は変わります。認証元の情報、メール、ログイン履歴は管理者専用のユーザー一覧に表示します。アカウントごとの開閉式詳細は共通スタイルを使い、開く際に認可済み情報を取得します。

管理者と所有者は創設者でなくても `/invite` を開けます。招待の発行には引き続き招待ポリシーが適用されます。有効な登録トークンアダプターは、SMTP で送信しない単独トークン用の `cognisctl invite:token:generate` と、招待メール用の `cognisctl invite:email:send person@example.com` を提供します。メールアドレスの引数を省くと CLI 入力画面が開きます。どちらも認証済みの登録 API を使い、ロール、ドメイン、配信の制限に従います。

## ユーザー一覧の構成

ユーザー一覧は Composer の利用可能な幅全体を使います。各アカウントは独立した開閉式の行となり、見出しにユーザー名、ロール、状態、管理操作を並べ、その下に詳細を行全体の幅で表示します。詳細はラベルと値のレスポンシブなグリッドで整理し、ローカライズしたロール名と認証元名、メインアドレスと確認状態のバッジ付きメール行を表示します。狭い画面では見出しの操作を折り返し、詳細を一列に並べます。

## アカウントのプライバシーとキーリングの分離

SSO アカウントにはプロバイダーを示さないランダムな ID を使用します。プロバイダー ID は別に保存し、管理者だけに表示します。公開ユーザー名には含めません。Auth はプロフィールやメールの変更前にユーザー名を確保します。同じプロバイダー内の重複名は拒否し、別プロバイダーとの重複には短いランダムな接尾辞を付けます。ユーザー一覧と操作 API は公開用の `username` と内部用の `accountId` を区別します。

アカウント ID の移行は行わない非互換の変更です。更新前にインスタンスを停止し、プロバイダー名を含む SSO アカウント ID があるデータベースをリセットしてください。Authentication はそのような ID を公開せず、`provider_account_ids_require_clean_database` で起動を拒否します。既存の関係や会議は移行しません。

暗号化したブラウザーの保管庫は、オリジン、アカウント ID、サーバーのアカウントインスタンス ID ごとに分けてキャッシュします。読み込み前にサーバーがアカウントとインスタンスを確認します。パスワードと復号鍵はメモリーだけに保持し、古い IndexedDB の解除鍵は削除します。再読み込み後はキーリングのパスワードが必要です。ただしパスワードログインで復号できた場合を除きます。アカウントを切り替えると、待機中のダイアログと暗号処理を中止します。解除操作でキーリングを新規作成することはありません。明示的なセットアップまたは作成操作が必要です。

## オフライン資産とカレンダー

本番用アセットの解決は、ルートに必要なスクリプトやスタイルシートの配列にも適用されます。公開アセットはバージョン付き・なしの URL でワーカーのキャッシュキーを共有し、モジュールのリビジョン境界は維持します。二つのバックグラウンド処理で対応ページのコードと非表示のスタイルを準備し、ページ自体はマウントしません。オフラインリンクには準備済みコードと各所有者が必要とするアカウント・セッション別スナップショットが必要です。ナビゲーションを再描画しても無効状態を維持するため、Meetings は無効のままです。非公開 API と認証済み HTML は引き続きワーカーに保存しません。

認証確認後、Calendar はカレンダー一覧、招待、所有する予定を最大二つの同時バックグラウンド要求で保存します。キャッシュを無効化した場合も、ログインを妨げず再取得します。保存済み予定を閲覧でき、予定の作成・編集・削除・回答、状態設定、カレンダーの編集は共通の送信待ちバッファーに入ります。保留中の作成と編集は保存済み一覧に反映します。作成には固定の操作 UUID を使用し、再送では既存の予定を返すため、繰り返し予定や招待通知を重複作成しません。内容の変更や別アカウントでの ID 再利用は拒否します。再送時にはサーバーが権限を再確認します。

予定のスナップショットはタブ内限定で 4 MB・100 件の読み取りまでです。共通の送信待ちキューは従来どおり 1 MB・1,000 件・七日間までです。新しい繰り返し予定は、サーバーで展開するまで最初の予定だけを表示します。カレンダー自体の作成、会議の生成、共有とパスワードの管理、ゲスト資格情報には接続が必要です。共有パスワードはバッファーに保存しません。オフラインナビゲーションを有効にするには、Messages は保存済みルーム一覧、Study は保存済みの言語・設定情報が必要です。

認証確認後、Study は言語一覧、設定、選択済み言語のモジュールリンクをバックグラウンドで準備し、モジュールへの同時リクエストは最大2件に制限します。サブナビゲーションも同じ所有者のキャッシュを使用するため、ハブへの初回アクセスをオフラインで行えます。キャッシュが無効化されると、ログインを妨げずに再準備を行います。

## ログインと保留中の送信

パスワードまたは TFA のログイン成功後は、既存の SPA ナビゲーション機能でログイン画面を Dashboard に置き換えます。検証済みタブと保留中の変更を維持し、ブラウザーのページ終了警告を発生させません。移動完了まで読み込み表示を維持し、任意のタイムゾーン同期はその後に実行してアカウント変更を拒否します。認証済みタブを閉じるか再読み込みする際は、実際に保留中の変更がある場合に引き続き警告します。

保留中の送信は、セッション認可と必要な同意が成功した後にバックグラウンドで開始します。タブ間の送信は専用のブラウザーロックで直列化し、スナップショットと確認処理にはネットワークを待たない短いストレージロックを使います。送信が遅くても読み込みと新しい保留書き込みを継続でき、確認時にストレージを再取得するため同時書き込みも維持されます。認証時に空のキューを書き直さず、未認証ページでは別アカウントの保留変更について警告しません。

## オフライン確認と警告

オフラインバナーの「接続を再確認」は直ちに `/api/v1/system/healthcheck` を呼び出し、同時確認をまとめ、接続できればセッションを再認可して保留中の送信を試みます。必要な同意は引き続き必須です。失敗時はエラーポップアップを出さずオフラインを維持します。共通ボタンスタイルと処理中表示を使用し、復旧後には更新ボタンが表示されます。自動確認は15分に1回のままで、明示操作ではそれ以前でも確認できます。

ブラウザーの終了・再読み込み警告は、現在のページとセッションで新たに作成された保護対象レコードだけを対象にします。実際に再読み込みすると警告は解除されますが、キューは再送用に保持します。新たな実際の編集で再度有効になります。Study の閲覧済みマーカーと分析はバックグラウンド活動であり、警告を有効にしません。他のタブのレコード、以前から保存されたレコード、ページの表示だけでは警告しません。プロバイダー停止後も、現在のページの変更は送信または削除されるまで保護します。

## 再読み込み時の解錠とモジュール

同じ認証済みタブとセッションでは、再読み込み後も解錠を維持します。保管庫は引き続きパスワードで暗号化し、パスワードや平文の復号鍵は保存しません。セッションストレージには、現在のセッション秘密値から HKDF で導出した鍵で AES-GCM 暗号化した解錠情報だけを保存し、オリジン、アカウント、サーバーのアカウントインスタンス、セッションに結び付けます。復元前にサーバーによる確認が必要です。有効な自動ロック期限は認証され、再読み込みで延長しません。明示的なロック、ログアウト、アカウント・インスタンス・セッションの変更、期限切れで復元を無効にします。タブを閉じるか新しいセッションを始めると再解錠が必要です。旧式の平文 IndexedDB キャッシュは引き続き無効です。

ホストのルートアセット準備は、共通の ctx ごとにフローとキャッシュ機能を一度だけ登録します。バンドルされたスクリプトと外部モジュールのソースインポートは登録と準備済みルートの状態を共有し、Meetings を開く際の `offline:prepareRouteAssets` 重複エラーを防ぎます。

## 共通の最上部バナー

ホストはページやプロバイダーのマウント前から `ctx.capabilities.get("ui:broadcast").publish(id, descriptor, { signal, priority })` を提供します。記述子には平文の `title`、無害化済みの `bodyHtml`、信頼できる `actionsHtml`、`info`・`success`・`warning`・`danger` の表示種別を指定できます。戻り値は `element` と `remove()` を持ちます。同じ ID はその通知だけを置き換え、古い解放処理は新しい通知を削除しません。`signal` で寿命を管理し、小さい優先度から表示します。タイトルはエスケープされ、リッチテキストは呼び出し元が無害化します。

オフラインモードと Broadcast は、アプリのヘッダーより上の文書最上部に共通の固定バナースタックを表示します。オフラインモードを優先し、閉じる操作は設けず、接続再確認と復旧後の更新操作を維持します。お知らせを削除してもオフライン表示は消えません。Broadcast は切断中の通信を省略し、プロバイダーの終了時にバナーとタイマーを解放します。

## オフライン学習の空画面

準備済みの Study ページは、検証済みで必要な同意を満たすオフラインセッションなら非公開コンテンツの保存がなくても開けます。未保存の言語や設定は空のナビゲーションになります。Explore は通常の空の一覧を表示し、ルート利用不可やエラー通知の代わりに「オフライン用に保存されたコンテンツはありません」と案内します。Flashcards もデッキや必要な表示リソースがなければ空画面を維持します。通知は現在のページに限定し、重複表示しません。キャッシュ不足を理由にアクセス拒否や同意拒否を隠しません。Library と Flashcards は公開の翻訳や軽量テンプレートをオンラインで準備し、非公開データは容量制限付きのタブ内キャッシュに留めます。

## 保存済みキューの結果

変更がキューへ永続保存された後は、任意の活動記録や表示更新の失敗で変更自体を失敗扱いにしません。カレンダーは、キャッシュ済みの予定一覧から詳細を表示し、新規の保留予定や後続の編集も反映します。同時の予定送信は一つのリクエストを共有します。メッセージはサーバー確認または永続保存後にのみ下書きを消し、チャットの表示更新に失敗しても送信結果を維持します。プロフィールの文章、投稿、画像も表示更新の失敗で完了結果を失いません。在席状況の更新は完了済みのカレンダー変更を待たせません。

提供元のライフサイクルエラーでは、クエリ情報を除いたスクリプトのパスと、失敗したインポートまたは初期化の段階を記録します。任意の活動記録の失敗は、永続保存済みのユーザー操作と分けて記録します。

## オフライン利用の維持

オフラインのルート登録は、バンドル版と直接配信版の繰り返し読み込みでも保持されます。スクリプト、スタイル、機能提供元が同じルート記述を再構築しても準備状態を維持し、アセットが変わった場合は再準備が必要です。メッセージは認証済みログイン後にチャット一覧、翻訳、絵文字カタログを準備します。初めてオンラインで訪問する前でもオフラインでページを開けます。自動で開くのはチャット情報と履歴がキャッシュ済みの場合だけで、未保存の履歴を選ぶと専用の情報トーストを表示します。Exploreは別のコレクションや閲覧済み情報が欠けていても、利用可能なキャッシュ済み項目を維持します。権限や同意の拒否は引き続き伝播します。バナーのボタンは共通の操作行に直接配置し、継承した上下のずれを解消します。

## 学習お気に入りの共有

Study提供元は、ライフサイクルに従う `load`、`toggle`、`has` 操作を持つ `study:favourites` を公開します。表示用の関数はローダーごとのキャッシュを作らず、このctx機能を参照します。認証確認後にお気に入りを準備し、保留中の変更を反映して、Explore、フラッシュカード、繰り返し読み込んだモジュール間でアカウントとセッションに紐付く状態を共有します。任意のお気に入りスナップショットがない場合は空の選択にキュー内の変更を適用し、キャッシュ済みコンテンツを隠したり更新失敗のトーストを出したりしません。アカウント変更時は表示上の選択を消し、権限拒否をキャッシュ欠落とは扱いません。

## 公開リソースのキャッシュ

トーストや機密情報の表示切り替えを含む共通スタイルを、論理 URL とビルド済み URL の両方でワーカーの起動マニフェストに含めます。Calendar は遅延読み込みするステータス用スタイルをプロバイダーで準備します。SPA ルートカタログは ctx を通じてバンドルと直接配信の読み込み間で共有され、別のローダーがオフラインで初めてカタログを読む場合も、認可された Study ルートを保持します。非公開ページのスナップショットはアカウントとセッションに紐付き、権限と同意の確認は引き続き適用されます。

キャッシュ済みの公開アセットは即座に返します。要求時のバックグラウンド確認はまとめて頻度を制限します。置き換え前に完全な応答本文を比較し、変更のないデータを保持します。Last-Modified が古い応答で新しいファイルを置き換えることはありません。ファイルが見つからない場合、接続失敗、途中で切れた本文、キャッシュ書き込み失敗では、以前の完全なファイルを保持します。変更された応答はアトミックな書き込みの成功後にのみ置き換えます。明示的なアクセス拒否、private/no-store 応答、同意の変更、モジュールアクセスの取り消しには引き続きポリシーを適用します。API 応答と認証済みドキュメントはワーカーではネットワークのみで扱います。

## アセットキャッシュの保持

ワーカーはページを実行せず、非公開データも取得せずに、ビルド済みの公開ページバンドル、動的チャンク、スタイル、生成メディアをすべて準備します。その後に取得した公開応答も自動的にキャッシュします。有効化時は古い保存領域を削除する前に完全な公開ファイルを新しい世代へ引き継ぎます。モジュールのリビジョンは現在のカタログで許可されているものだけを引き継ぎます。公開バンドルのダウンロードにページへの事前訪問は不要です。非公開コンテンツには引き続き、所有プロバイダーが準備した認可済みスナップショットが必要です。

## オフライン作業環境

認証済みログイン後、Study は登録済みの学習言語と指導言語について、スキーマ、読み取り可能な保存先、フォーム、閲覧済みマーカー、明示的に許可された軽量コレクションを準備します。Flashcards は既存のキャッシュ上限内で一覧と最大 80 件の該当デッキおよびカード詳細を準備します。登録言語の変更時も再準備します。同時読み取りは 2 ワーカーで制限し、プロバイダーの停止、アカウント変更、アクセス拒否、保存済みの法的同意を引き続き適用します。ページへの事前訪問は不要です。非公開スナップショットは認証済みタブとセッションに紐付きます。

オフラインのプロフィール表示には、自分のテキスト、投稿、つながり、設定、上限内のアバターとバナー画像を含む完全な準備済みスナップショットが必要です。他のユーザーのプロフィールは以前にキャッシュしていても表示できません。Administration、Modules、Users、Shares はオフラインでは利用できません。Settings のローカルな基本設定は開けます。保存したフォント、テーマ、言語、タイムゾーン、表示設定はローカルに適用し、サーバー送信用にキューへ保存します。メール確認、アカウント操作、サーバーが必要な追加設定はオフラインでは利用できません。

ブラウザーの終了・再読み込み警告は、現在のページとセッションで新たに作成された保護対象レコードだけを対象にします。実際に再読み込みすると警告は解除されますが、キューは再送用に保持します。新たな実際の編集で再度有効になります。Study の閲覧済みマーカーと分析はバックグラウンド活動であり、警告を有効にしません。他のタブのレコード、以前から保存されたレコード、ページの表示だけでは警告しません。プロバイダー停止後も、現在のページの変更は送信または削除されるまで保護します。

ホストは ctx を通じて `ui:languageCatalog.load` を公開し、認証済みログイン後に共通の言語カタログを準備します。基本の翻訳カタログは公開起動リソースに含めます。Settings とナビゲーションバーは同じライフサイクル内の読み取りを使用します。オフラインで言語設定を保存しても利用中のページは閉じず、その後のクライアント内移動に設定を適用します。

## オフラインの Study 練習

Library の管理画面と編集・検索・申請ページには接続が必要です。Study のホームとサブメニューは、切断直後も含めオフラインではこれらのリンクを非表示にします。Explore ではキャッシュ済みコンテンツの閲覧と描画を引き続き利用できます。Library プロバイダーは Explore だけをオフラインセッションのルートとして登録します。

登録言語の準備では、言語別カタログに加えて共通のスキーマカタログもキャッシュします。描画と Flashcards はオンラインで事前にページを開かなくても通常のスキーマ読み取りを利用できます。Flashcards は Study と Share の翻訳およびギャラリーテンプレートを準備し、登録時の準備と同じスキーマ指定の要求で選択言語のコレクションを読み取ります。準備済みデッキはギャラリーと練習画面をオフラインで開けます。音声、辞書取得、コンテンツ編集、アクセス・同意確認の制限は引き続き適用します。

保存完了後も、予約された再描画は新たな未保存の変更を確認します。2秒間の待機中に行った編集には破棄の確認が必要です。連続した保存はまとめられ、設定画面を離れると保留中の再描画は取り消されます。
