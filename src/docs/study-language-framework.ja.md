# スタディ言語フレームワーク

## 概要

スタディ言語フレームワークは、Cognisにおける言語学習コンテンツの構造化・登録・提供方法を定義します。Studyゲートウェイのインフラストラクチャと個々の言語モジュール（コンテンツ）を分離し、各言語のコアライブラリ（文字・単語・定義のリファレンスレジストリ）と子コンポーネント（インタラクティブな学習アクティビティ）を分離します。

**言語モジュール**は、ブートストラップ時にStudyゲートウェイに登録される独立したTypeScriptパッケージです。データベースや通知システムのようなアダプターパターンには従わず、コンテンツモジュールです。新しい言語を追加するには、新しいモジュールディレクトリを追加するだけです。Studyゲートウェイが自動的に検出します。

## 責任範囲

- 各言語モジュールが実装すべきコントラクトを定義する。
- ライブラリのデータモデルを定義する：文字・代替文字・定義・単語・文の階層レジスタ。
- 子コンポーネントがサブナビゲーションページを登録する方法を定義する。
- 貢献者がシステム全体を理解せずに文字、単語、学習アクティビティを追加できる標準を提供する。

責任外：Studyゲートウェイによるアダプター検出、クラスや授業の管理。

## アーキテクチャ

### ライブラリ・データモデル

ライブラリは言語のすべての要素を含む多層レジスタです。

**レイヤー1 — 文字 (`characters`)**: 言語の原子的な書き単位。日本語ではひらがなとカタカナ（漢字はalt_charactersへ）。各文字は `id`, `symbol`, `romanization`, `category` を持ちます。

**レイヤー2 — 代替文字 (`alt_characters`)** _(省略可)_: 複合または表語記号。漢字が典型例。各代替文字は `id`, `symbol`, `components`（基本文字のID）, `readings` を持ちます。

**レイヤー3 — 定義 (`definitions`)**: 特定の言語での意味のフラットストア。単語と文から参照されます。

**レイヤー4 — 単語 (`words`)**: 文字または代替文字の組み合わせ。頻度順にソートされた一つ以上の定義にマッピングされます。

**レイヤー5 — 文 (`sentences`)**: 単語の順序付き列。明示的な定義参照を持つか、各単語の主要定義から意味を導出します。

### 子コンポーネント

子コンポーネントは特定の言語の独立した学習機能です。言語モジュールを通じてUIにサブナビゲーションメニューを提供します。子コンポーネントは主にライブラリへのインターフェースであるべきです。

### ディレクトリ構造

言語モジュールは `src/modules/study/languages/<code>/` 以下に配置されます。子コンポーネントは `components/<id>/` 以下に配置されます。

## APIルート

| メソッド | パス                                    | 説明                           | 認証     |
| -------- | --------------------------------------- | ------------------------------ | -------- |
| GET      | `/api/v1/study/languages`               | 利用可能な学習言語の一覧取得   | Required |
| GET      | `/api/v1/study/languages/:code/modules` | 言語の子コンポーネント一覧取得 | Required |

## ライブラリと教室UIの規約

- Study サブナビゲーションでは、現在選択中の学習言語が Library 子コンポーネントを直接登録していない場合でも、admin/owner には **ライブラリ** を表示する必要があります。
- Study サブナビゲーションからライブラリへ遷移する際は、現在選択中の言語をフィルターとして渡し、初期表示をその言語コンテキストに合わせる必要があります。
- ライブラリデータは言語対応の全体モデルとし、言語はルート分割ではなくレコードのフィールド（例: `language`）として扱います。
- すべての言語モジュールは、教師と学習者が言語別クラス画面へ入れるように **教室** 子コンポーネントのルートを登録するべきです。
- 教室ページには、クラス選択、座席上限の可視化、役割別の挙動（教師の管理操作／学習者の閲覧中心＋退室）を含める必要があります。
