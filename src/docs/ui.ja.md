# UI

## 概要

`src/ui/` はCognisのブラウザフロントエンドをホストします。学習ワークフロー、ソーシャルインタラクション面、管理パネル、組み込みドキュメントブラウザを提供します。UIはサーバーレンダリングのマルチページアプリケーションです。

UIレイヤーは、どのゲートウェイやアダプターがインストールされているかを知りません。代わりに、ゲートウェイは `UIRegistry` とページエクステンションAPIを通じてランタイムでUI要素を提供します。

すべてのユーザー向けテキストは `src/ui/reuse/i18n.js` のi18nシステムを通じて処理されます。JavaScriptやHTMLテンプレートにテキストは直接ハードコードされていません。

## 責務

- すべてのページエントリポイントと関連するHTMLテンプレートをホストする。
- すべての非ログインページがレンダリングするレイアウトシェルを提供する。
- i18n、ページコンポーザー、未保存変更ガードのreaseユーティリティを維持する。
- テーマの一貫性を保つ: すべての要素がCSS変数から色を解決する。
- 4つの必須言語（en、de、ja、id）のi18n文字列パックを提供する。

## 共通の画像プレビュー

グローバルな `ui:imagePreview` はサムネイル描画、イベント設定、および登録済みの `ui:imagePreview:open` フローを通じた `open` 操作を提供します。`ui:reuse` から `image-preview.js` としても利用でき、操作の公開前に共通スタイルシートを読み込みます。画像ボタンを押すと、元画像を画面内に収まる自然なサイズで表示し、通常の X ボタンだけが表示されます。キーボード操作、Escape、フォーカスの復元、親画面やプロバイダー終了時の閉鎖は共通ポップアップのライフサイクルに従います。画像 URL と任意の削除操作は呼び出し側が管理します。Library の編集画面と詳細ギャラリーは、アップロード画像と同梱画像にこの共通コントロールを使用します。

共通の画像プレビュープロバイダーは、操作を公開する前にスタイルシートを読み込みます。画像専用ポップアップは見出しのマークアップを削除し、横長・縦長・パノラマ画像を横方向にも縦方向にもスクロールせず画面内に収めます。Library の詳細プレビューは最大 20rem × 18rem、編集画面のサムネイルは 8rem × 6rem を維持します。

## 応答性の高い画面移動

ログアウトは公開ルートのサービスワーカー保守を待たずに非公開セッションデータを消去します。同一のポリシー要求は通信を共有しますが、変更されたアクセス判断は統合しません。言語切り替えはカタログ提供元の準備を待ち、ログアウト時はアカウント専用操作を非表示にします。バンドル版と直接読み込み版のルーターはドキュメント状態、リスナー、表示の中断を共有し、設定からダッシュボードへの移動にも対応します。

## 静かなマーケットプレイス更新

マーケットプレイスは管理者専用の `/api/v1/modules/marketplace-state` スナップショットを15秒ごとに再検証します。ETag にはソース、インストール状態、キャッシュ済みの検出結果、おすすめ、再起動の要否が反映されます。変更がない場合は本文なしの `304` を返し、翻訳の再取得や再描画をせず、準備済みのカタログを保持します。ソースの検出は画面のマウント後に一度、その後は毎時およびソース変更時に行います。手動の更新は引き続きスキャンを強制します。非表示、オフライン、処理中のページではポーリングを一時停止し、アンマウント時に要求を中止してタイマーを解除します。

カタログの表示情報にはコンテンツから算出した `ui.stringsRevision` を含めます。`extendI18n(base, stringsBaseUrl, { revision })` は、同じアカウントとセッション内でバージョン付きの認証済み言語パッケージを再利用できます。リビジョンが変わると新しい文字列を取得します。識別情報が変わると非公開パッケージを消去し、遅延した応答が別のセッションを再投入することを防ぎます。失敗した読み込みは再試行できます。公開パッケージは従来のキャッシュとライフサイクルに伴う無効化を維持します。

おすすめフィードはマーケットプレイスサービスで共有し、同時の読み取りをまとめて5分間保持します。更新に失敗した場合は最後に取得できた一覧を維持し、次の試行まで1分待ちます。設定 URL が変わると別の結果に切り替え、手動の更新は有効期間を無視します。

## ガイド付きチュートリアル

チュートリアルはページや URL に紐付きます。利用条件を満たす初回訪問では、そのページの未完了ガイドを自動的に開始します。`page-context` のタイトル横にある疑問符 SVG から、そのページで利用できるガイドを再生できます。ホストは表示と寿命を管理し、各機能が文章、対象、スクリプトを所有します。権限は変更しません。

`showToast(message, { minRole: "admin" })` は運用上の通知を管理者と所有者だけに表示します。その他や不明な役割では DOM、タイマー、終了コールバックを作成しません。`minRole` を省略した通常の通知は全員に表示します。この表示制限はサーバーの認可を代替しません。

フローティングメニューはバージョン 1 の `ui:floatingMenus` と、段階付きフロー `ui:floatingMenu:request`、`present`、`dismiss`、`release` を使います。同じ優先度は要求順に処理し、高い優先度は低いメニューを一時停止します。予約は初回の許可または取消を示す `ready`、`present(element, { visible })`、`dismiss(element)`、`dispose()` を提供します。チュートリアルは完了、取消、所有者の解除まで、ステップ間も含め優先度 100 を保ちます。コンポーザーのスロットと再実行の選択も同じ待ち行列を使います。取り消した要求や古い表示処理は新しいメニューを置き換えません。空のスロットは表示を譲り、ページ解除時は監視と予約を破棄します。

トーストは、通知の作成や終了を遅らせずに共通スタイルシートを読み込みます。同時の通知は、各5秒までの試行を最大2回共有します。サイクルが失敗しても後続の通知で再試行できます。外部のリンクは保持し、トーストの読み込み処理が作成した失敗リンクだけを削除します。読み込み中に閉じた通知は再表示されません。ページのチュートリアルの対象と進行は変わりません。

## ダイアログのキーボード操作

各ダイアログには固有のアクセシブルな見出しがあり、未保存の変更に関する確認や複数ページのダイアログも区別できます。Tab と Shift+Tab による移動は、操作中のダイアログ内に留まります。下書きを保持すると編集画面にフォーカスが戻ります。最後のダイアログを閉じると、開くときに使った操作要素に戻り、その要素がなくなっていればページに戻ります。空のダイアログは操作要素が利用可能になるまでフォーカスを保持します。ページ移動による中断では、古いページにフォーカスを戻さずに解放します。閉じるアニメーション中のダイアログはキーボード操作を保持しません。ガイド付きチュートリアルから開いたダイアログにも同じ操作が適用されます。

### チュートリアルのフォーカス委譲

追加の機能 `ui:popupFocus` は、`register(overlay, handlers)`、`delegate(overlay, { signal, surfaces, contains, focus, onRevoke })`、`restore(overlay, preferred)` によりダイアログの所有者を調整します。登録はダイアログの描画処理が担当します。チュートリアルは、現在の手順で明示的に受け入れた操作中のダイアログだけに対して委譲を行います。許可する対象と操作要素、同じ文書に接続された表示領域、フォーカス用のコールバックを指定します。必須の中断シグナル、表示領域の削除、またはダイアログの終了で委譲は解除されます。新しいダイアログは、開くアニメーションの前からフォーカスを排他的に保持します。チュートリアルの終了や再実行では、閉じたページを再び開くことなく通常のキーボード操作に戻ります。`openPopup` のオプションは変更されません。

必須の `onRevoke` コールバックは、フォーカスを戻す前に委譲先のイベントハンドラーを同期的に解除します。

委譲先のコールバックは同期的に実行し、`contains` は真偽値を返す必要があります。例外、不正な判定値、非同期の戻り値、または再帰的なフォーカス操作が発生すると、委譲を解除して安全な診断情報を記録し、通常のフォーカス制御に戻ります。コールバックやログ記録の失敗によって、ダイアログの終了が中断されたり、結果が未確定のまま残ったりすることはありません。

## 言語リストの操作

言語の行、またはタッチ画面ではハンドルを、優先言語リストの希望する位置へドラッグします。移動先の行の中央より上なら前、下なら後に挿入し、表の空き領域では末尾に追加します。英語は代替の優先言語として残ります。変更は保存するまで下書きであり、破棄すると保存済みの順序に戻ります。オフラインでは優先言語の並べ替えのみが可能で、追加や削除はできません。

設定画面の通常のドラッグとタッチ・ペンのハンドルは `src/ui/app/settings/dropzones.js` の `bindListDropzones` を共有します。設定コントローラーはセレクター、操作の可否、ドロップ時の処理を定義し、ヘルパーは移動先の判定、表示、ポインターキャプチャ、キャンセルを管理します。再描画前に `cancel()` で操作を解除し、`dispose()` または渡したシグナルでリスナーを削除します。キャンセル、キャプチャ喪失、Escape、ページ移動、無効な場所へのドロップでは変更しません。操作可否の判定に失敗した場合は、エラーを伝える前に操作を解除します。キャプチャ解除中にキャンセル、コントローラーの破棄、行の置換が発生すると変更を適用しません。設定の言語チュートリアルは利用可能・優先言語の対象を維持し、同じドラッグと保存の手順を説明します。

## メッセージスタイルのプレビュー

外観のメッセージスタイルの下に、架空の会話であることを明示したサンプルが表示されます。受信と送信の例は Messages の表示を使用し、名前と地域に合わせた日付・時刻を示します。スタイルを切り替えると未保存の選択を確認でき、保存すると適用され、破棄すると保存済みの表示に戻ります。外観のガイドには、利用可能な場合だけプレビューの手順が含まれます。サンプルにリンク、プロフィール操作、既読通知、実際の会話データはありません。Messages が利用できなくても、選択と通常の設定保存は使用できます。セクションを再表示しても未保存の選択は維持され、設定を離れると未完了の描画は取り消されます。

メッセージスタイルのプレビューには、準備が整ったバージョン2の表示プロバイダーが必要です。Profile または Messages が利用できないときはサンプルだけを隠し、選択操作と未保存の選択は維持します。プロバイダーが回復すると現在の選択を自動表示します。任意のプレビュー用チュートリアルも同じ表示領域に従います。対応する Settings、Messages 2.8.1、Profile 3.0.19 のアセットを同時に配布してください。

## モジュール操作の結果

有効化と無効化は、変更要求とその後の状態確認が続く間、処理中になります。状態の読み取りで分かるのは現在の観測状態であり、この要求が確定したことの証明ではありません。モジュール画面を離れても送信済みの変更は取り消されず、古い画面が遅れて通知したり新しい画面を書き換えたりすることはありません。アカウントが変わると、待機中の操作と遅れて届いた結果の権限が無効になります。応答が失われた場合は、5秒の期限で状態を1回だけ読み取り、変更を自動で繰り返しません。結果が不明な間は「状態を確認」が操作ボタンの代わりに表示されます。後の読み取りやSPA内の再訪でも、反対の状態が続く間は操作をロックしたままにし、要求した状態を観測してから操作を戻します。任意の設定ガイドや中止されたカタログ更新によって、確認済みの有効化が拒否扱いになることはありません。必須設定を取り消した場合の無効化は1回だけ行います。応答が失われた場合は、正式な読み取りで無効状態が確認できたときだけ無効として照合し、それ以外は結果を不明のままにします。

マーケットプレイスのチュートリアルでは、利用可能な場合だけ「状態を確認」を説明し、結果が不明な間は通常の操作を省略します。既存の所有者と完了の識別子、設定ポップアップとチュートリアルの有効期間は維持されます。ホストのモジュール画面には独立してバージョン管理されるパッケージやマニフェストがないため、API、Core、任意のプロバイダーのバージョンやハッシュは変更しません。

照合によるライフサイクルイベントは observed-state として、応答確認済みの acknowledged-response と区別されます。観測した状態だけでは、この要求が確定した証明にはなりません。APIには永続的な操作結果の記録がなく、不明な状態の管理はSPA内では維持されますが、ブラウザーの完全な再読み込みでは失われます。その後はサーバーの現在の状態だけが取得でき、以前の要求の最終結果や実際のStudyの起動は確認できません。

無効化や設定の取り消しを含め、モジュール操作が処理中、または結果が不明な間は、そのモジュールを依存関係の条件として利用できません。繰り返しの操作やSPA内の再訪でも制限を維持し、待機中の有効化は実行開始時に準備状態を再確認し、任意の依存モジュールの選択は繰り返しません。有効状態の観測と設定の完了は別であり、取り消しが拒否された場合も設定は未完了です。設定の保存で設定完了を確認できても、不明な変更結果は解消しません。期待された無効状態を正式な読み取りで確認した場合は、通常の明示的な有効化を行えます。

設定、更新、チャネル変更にも、アカウントに結び付いた同じ処理中・結果確認を適用し、一時的な有効化、無効化、取り消しを含めて管理します。有効化と復元の直前には、選択された依存関係を再確認します。インストール後の復元は、送信の明確な拒否または処理の最終結果を確認した場合に限ります。送信や状態確認の応答が失われたり、処理結果の記録が見つからなかったりした場合は不明のままとし、復元や再試行を行いません。結果を失ったインストールはページのセッション中はロックされます。「状態を確認」でカタログを更新しても処理の完了は証明できません。完全な再読み込みはこのローカルな不確実性の記録を破棄しますが、完了の証明にはなりません。永続的な処理結果の記録や完全な再読み込み後の復旧は追加しません。
