# API

## 概要

`src/api/` は Cognis の HTTP 層です。Express 互換の Node.js サーバー、ルートレジストリ、認証ミドルウェア、および受信 HTTP リクエストをゲートウェイ操作にマッピングするすべての薄いルートハンドラーモジュールをホストしています。API 層は意図的に薄く保たれています。ルートハンドラーは入力を解析・検証し、ゲートウェイに委譲して、安定したレスポンスエンベロープを返します。ルートハンドラーはデータベースドライバーや外部サービス SDK への直接参照を保持しません。

サーバーはハードコードされたコンポーネントリストからではなく、起動時に存在するものから組み立てられます。ゲートウェイはブートストラップ時に `ctx.routeRegistry.register(...)` を介して自身のルートを登録します。サーバーはレジストリを反復してルートテーブルを構築します。ゲートウェイを削除するとそのルートが自動的に削除されます。

認証はログイン時に発行される不透明なベアラートークンを使用します。同じトークンは、サーバーレンダリングされたページガード用の HttpOnly Cookie (`cognis_access_token`) としても設定されます。有効期限のない CLI ブートストラップトークンが、信頼されたローカルツール用に起動時にディスクに書き込まれます。

## 責務

- HTTP サーバーをホストし、ルートレジストリをリクエスト処理に組み込む。
- すべての保護されたルートハンドラーが使用する `requireAuth` および `getAuthClaims` ミドルウェアを提供する。
- `{ data }` / `{ error }` レスポンスエンベロープ規約を適用する。
- `src/api/bootstrap/gateway.ts` を介してすべてのゲートウェイを依存順にブートストラップする。
- `src/api/bootstrap/db-init.ts` を介して起動時にデータベーススキーマを初期化する。
- ルートハンドラー用の再利用ユーティリティを提供する: `src/api/reuse/`。

責務外: ドメインロジックの実装、データの直接保存、またはどのゲートウェイがインストールされているかの把握。

## アーキテクチャ

### レスポンスエンベロープ

すべての API レスポンスは以下の 2 つの形式のいずれかを使用します:

```json
{ "data": { ... } }
```

```json
{ "error": { "code": "forbidden", "message": "Requires admin scope" } }
```

内部エラーの詳細はクライアントに送信されません。サーバー側のログが完全なエラーコンテキストをキャプチャします。

### 認証モデル

`POST /api/v1/auth/login` でトークンを取得します。レスポンスには `data.token` が含まれます。以降のリクエストでは `Authorization: Bearer <token>` としてトークンを送信します。ログインエンドポイントは、サーバーレンダリングされたルートガード用の HttpOnly Cookie として `cognis_access_token` も設定します。

トークンの有効期限は `COGNIS_ACCESS_TOKEN_TTL_SECONDS` で制御されます (デフォルト: `43200`、12 時間)。起動時、サーバーは信頼されたローカル CLI 使用のために有効期限のない CLI ブートストラップトークンを `COGNIS_CLI_TOKEN_PATH` (デフォルト `/app/config/cli-access.token`、モード `0600`) に書き込みます。

### デフォルトの永続化設定

| `DB_TYPE`                 | バックエンド | 接続                  |

| `postgresql` (デフォルト) | PostgreSQL   | `DATABASE_URL` が必要 |
| `mariadb`                 | MariaDB      | `DATABASE_URL` が必要 |

## 接続確認

`GET /api/v1/system/healthcheck` はコンポーネントの診断を実行せず、即座に `{ "data": { "status": "ok" } }` を返します。接続の有無の確認にはこのエンドポイントを使用します。`GET /api/v1/system/health` は詳細診断、時刻、稼働時間を引き続き提供します。任意コンポーネントの遅延だけで、稼働中のサーバーをオフラインと見なすことを防ぎます。

## オフラインルートの準備

`offline:registerSessionRoutes(ids, signal, { available })` は、オフライン時にルートとパスを受け取る任意の所有者判定関数を指定できます。シグナルの中断で宣言を解除します。ホストは `offline:prepareRouteAssets` を通じて公開ページコードとスタイルを別途準備し、`offline:areRouteAssetsReady` が完了を示します。`createOfflineReadCache` の `read.has(key)` とスコープ付き HTTP クライアントの `request.hasCachedRead(path)` は非公開データを返さずに存在を確認します。判定にはアカウント・セッション、有効期限、キャッシュ世代、プロバイダーのライフサイクルを含みます。権限を付与したり、保存済みの法的同意を不要にしたりするものではありません。

## ログインと保留中の送信

保留中の送信は、セッション認可と必要な同意が成功した後にバックグラウンドで開始します。タブ間の送信は専用のブラウザーロックで直列化し、スナップショットと確認処理にはネットワークを待たない短いストレージロックを使います。送信が遅くても読み込みと新しい保留書き込みを継続でき、確認時にストレージを再取得するため同時書き込みも維持されます。認証時に空のキューを書き直さず、未認証ページでは別アカウントの保留変更について警告しません。

## オフライン確認と警告

オフラインバナーの「接続を再確認」は直ちに `/api/v1/system/healthcheck` を呼び出し、同時確認をまとめ、接続できればセッションを再認可して保留中の送信を試みます。必要な同意は引き続き必須です。失敗時はエラーポップアップを出さずオフラインを維持します。共通ボタンスタイルと処理中表示を使用し、復旧後には更新ボタンが表示されます。自動確認は15分に1回のままで、明示操作ではそれ以前でも確認できます。

バックグラウンド分析はキューに維持しますが、終了警告は発生させません。所有者は `offline:outbox.register(owner, send, signal, { protectOnClose: false })` で指定し、ユーザー変更の既定値は引き続き保護です。新規レコードは分類を保存するため、プロバイダーの解放や再読み込み後も分析データを編集扱いにしません。旧レコードには有効な所有者の宣言を使い、不明な所有者は保護します。自動タイムゾーン同期は `saveUiPreferences(patch, { bufferOffline: false })` を使い、スコープ付き HTTP クライアントはオフライン時に保存せず拒否します。明示的な設定変更、メッセージ、カレンダー編集は引き続き保存して警告します。

## 再読み込み時の解錠とモジュール

同じ認証済みタブとセッションでは、再読み込み後も解錠を維持します。保管庫は引き続きパスワードで暗号化し、パスワードや平文の復号鍵は保存しません。セッションストレージには、現在のセッション秘密値から HKDF で導出した鍵で AES-GCM 暗号化した解錠情報だけを保存し、オリジン、アカウント、サーバーのアカウントインスタンス、セッションに結び付けます。復元前にサーバーによる確認が必要です。有効な自動ロック期限は認証され、再読み込みで延長しません。明示的なロック、ログアウト、アカウント・インスタンス・セッションの変更、期限切れで復元を無効にします。タブを閉じるか新しいセッションを始めると再解錠が必要です。旧式の平文 IndexedDB キャッシュは引き続き無効です。

ホストのルートアセット準備は、共通の ctx ごとにフローとキャッシュ機能を一度だけ登録します。バンドルされたスクリプトと外部モジュールのソースインポートは登録と準備済みルートの状態を共有し、Meetings を開く際の `offline:prepareRouteAssets` 重複エラーを防ぎます。

## 共通の最上部バナー

ホストはページやプロバイダーのマウント前から `ctx.capabilities.get("ui:broadcast").publish(id, descriptor, { signal, priority })` を提供します。記述子には平文の `title`、無害化済みの `bodyHtml`、信頼できる `actionsHtml`、`info`・`success`・`warning`・`danger` の表示種別を指定できます。戻り値は `element` と `remove()` を持ちます。同じ ID はその通知だけを置き換え、古い解放処理は新しい通知を削除しません。`signal` で寿命を管理し、小さい優先度から表示します。タイトルはエスケープされ、リッチテキストは呼び出し元が無害化します。

オフラインモードと Broadcast は、アプリのヘッダーより上の文書最上部に共通の固定バナースタックを表示します。オフラインモードを優先し、閉じる操作は設けず、接続再確認と復旧後の更新操作を維持します。お知らせを削除してもオフライン表示は消えません。Broadcast は切断中の通信を省略し、プロバイダーの終了時にバナーとタイマーを解放します。

## オフライン学習の空画面

準備済みの Study ページは、検証済みで必要な同意を満たすオフラインセッションなら非公開コンテンツの保存がなくても開けます。未保存の言語や設定は空のナビゲーションになります。Explore は通常の空の一覧を表示し、ルート利用不可やエラー通知の代わりに「オフライン用に保存されたコンテンツはありません」と案内します。Flashcards もデッキや必要な表示リソースがなければ空画面を維持します。通知は現在のページに限定し、重複表示しません。キャッシュ不足を理由にアクセス拒否や同意拒否を隠しません。Library と Flashcards は公開の翻訳や軽量テンプレートをオンラインで準備し、非公開データは容量制限付きのタブ内キャッシュに留めます。
