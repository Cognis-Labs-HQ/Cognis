# パフォーマンスのベースラインと予算

本番トラフィックは `docker/edge` のエッジプロキシで終端します。TLS 証明書を `docker/tls/fullchain.pem`、鍵を `docker/tls/privkey.pem` として用意してください。マネージド CDN でも同じキャッシュおよび転送ポリシーを実装できます。公開されるのはエッジのみであり、転送ヘッダーの置換が信頼境界を確立します。

## ホスト環境ベースラインの手順

ホストされたリリースに対して Lighthouse を3回実行し、中央値の成果物を CI に保存します。空のプロファイルによるコールドロード、1回の準備アクセス後のウォームロード、ダッシュボードから設定への SPA ナビゲーションを測定します。往復遅延150 ms、下り1.6 Mbps、上り750 Kbps、CPU 4倍低速をエミュレートします。リリース SHA、リージョン、ブラウザバージョン、コールド／ウォーム状態、リクエスト数、圧縮バイト数、LCP、ルートマウント時間、API p95 を記録します。

## 予算

| 操作               | リクエスト | 圧縮転送量 |      LCP | API p95 |
| ------------------ | ---------: | ---------: | -------: | ------: |
| コールドロード     |         45 |    500 KiB | 2,500 ms |  400 ms |
| ウォームロード     |         15 |    150 KiB | 1,800 ms |  300 ms |
| SPA ナビゲーション |         10 |    100 KiB | 1,500 ms |  250 ms |

最適化は、同一のホスト環境手順で保存済みベースラインに対する予算の悪化がない場合にのみ採用します。まずデータベースクエリ、ペイロード、キャッシュポリシー、アプリケーション処理を調査します。プロセス内キャッシュとエッジキャッシュで解消できない持続的かつキャッシュ可能なボトルネックが測定で実証された場合に限り、Redis を導入します。
