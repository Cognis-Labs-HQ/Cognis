# ライブラリ再設計計画

## 方針

固定レイヤーカタログを、利用側が所有するスキーマレジストリへ置き換えます。言語モジュールはバージョン付きライブラリスキーマを `ctx` 経由で登録し、アダプターはアルファベット、ハングル音節ブロック、単語、練習といった概念を知りません。アダプターは永続化、関係制約、解決処理、アクセス制御、汎用 UI メタデータだけを提供します。

スキーマは安定したレイヤー ID、翻訳済み表示名、フィールド、方向付き関係を定義します。関係には多重度、順序、必須性、削除規則、利用可能なリゾルバーを含めます。データが使用するスキーマバージョンは不変とし、構造変更は利用側が公開するマイグレーションで行います。

## 契約とデータモデル

1. Study ゲートウェイに `study:library` スキーマ登録 capability を追加し、ID 重複、参照先欠落、禁止された循環、不可能な多重度、バージョン後退を拒否します。
2. 作成、更新、削除、解決、検索、インポート、エクスポート、移行を、取り外し可能なステージを持つ名前付き `ctx` flow にします。アダプターは認可、検証、永続化、監査を、利用側は正規化と解決処理を提供します。
3. 中立な lookup 契約により、プロバイダーは対応言語、スキーマ、レイヤー、フィールドを宣言します。候補には出典と信頼度を付け、利用者が承認するまで保存しません。アダプターは Jisho などの具体的な実装を import しません。
4. スキーマバージョン、汎用エントリー、型付きフィールド、順序付きエッジ、別定義、出典を保存します。テーブルやサービス分岐にレイヤー名を埋め込みません。
5. 対象レイヤー、多重度、一意性、順序、言語方針、スコープ可視性、削除規則を一つのトランザクションで検証します。別定義は特別な列ではなく、宣言された関係で結ぶ通常のエントリーです。

## 解決と UI

Unicode 書記素分割は汎用の基礎にとどめます。利用側は最長一致や再帰的合成を実装でき、英字、韓国語の字母と音節ブロック、日本語の仮名と漢字に対応できます。曖昧な構成要素を暗黙に作成せず、順位付き候補と未解決範囲を返します。文は明示的に選択した単語エントリーの順序付きブロックから作り、エッジ順序を正とします。

アダプター所有 UI は `createPageComposer` で構築し、スキーマからナビゲーションと編集フォームを生成します。検索と絞り込み、全エントリーの詳細、入出力関係、別定義、出典、多重度フィードバック、解決プレビュー、lookup 候補確認、文ブロック編集を提供します。`/study/library/:schemaId/:layerId/:entryId` のような正規 URL は直接読み込みと app router の両方で動作し、ブラウザーは Study ゲートウェイの UI クライアントだけを使用します。

## 実装順序と完了条件

英語、韓国語、日本語の契約 fixture と、不正スキーマ、権限、曖昧性のテストを先に作成します。次にレジストリと汎用型、ロールバック可能な永続化と移行、flow、リゾルバー、ゲートウェイ API とクライアント、アクセシブルな完全 UI、dual-read 比較、固定レイヤー削除の順で進めます。

未知の構造をアダプター変更なしで登録でき、すべての書き込み経路が不正なエッジを拒否し、英語と韓国語 fixture を正しく解決し、文の同一性が順序付きブロックに基づき、lookup プロバイダーを `ctx` だけで交換でき、全エントリーに再読み込み可能な詳細 URL があり、ID、関係、出典、スコープを失わず移行を戻せることを完了条件とします。
