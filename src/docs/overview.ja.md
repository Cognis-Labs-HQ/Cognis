# Cognis 概要

## 概要

Cognisは、独立した学習者、教師、およびコミュニティ向けに設計されたモジュール式言語学習プラットフォームです。構造化された学習コンテンツとソーシャル機能、リアルタイムコラボレーション対応、そして深く拡張可能なバックエンドアーキテクチャを組み合わせています。目標は、コアコードベースを変更することなく、単一のユーザーからフルコミュニティまで成長できる自己ホスト型言語学習環境を簡単に展開できるようにすることです。

プラットフォームはゲートウェイファーストアーキテクチャを中心に構築されています：すべての主要なサブシステム（認証、通知、プロファイル、ファイルストレージ、ログ）は、独自のルート、アダプター、UIへの貢献、テスト、ドキュメントを所有するゲートウェイです。アプリケーションのコアはコントラクトとポリシーを定義し、具体的なゲートウェイやアダプターコードをインポートすることは決してありません。この分離により、共有コードを編集することなく、設定を変更するだけで新しいデータベースバックエンドの追加、認証プロバイダーの交換、またはサブシステムの完全な削除が可能です。

アダプターはゲートウェイインターフェースのプロバイダー固有の実装です。各ゲートウェイは、静的なインポートリストを管理するのではなく、起動時に既知のディレクトリをスキャンしてアダプターを検出します。その結果、新しいアダプター（例えばS3バックのファイルストレージアダプター）の追加には、正しい場所にアダプターディレクトリを配置するだけでよく、サーバーは存在するものから完全な機能セットを組み立てます。

モジュールは、コンテンツタイプ、カリキュラム、分析、またはインテグレーションなどのオプション機能でプラットフォームを拡張します。ゲートウェイと同様に、モジュールは自己完結型で自動検出されます。定義されたフロントエンドコントラクトを通じてUIにCSS、HTMLテンプレート、JavaScriptの動作を提供し、コアネームスペースとの衝突を防ぐ保護されたメカニズムを通じて独自のAPIルートを登録します。

## 責任範囲

- プラットフォーム基盤を提供する：HTTPサーバー、認証、永続化、ファイルストレージ、ログ、通知ディスパッチ。
- ゲートウェイを接続するゲートウェイ/アダプターパターンとケイパビリティストアを定義する。
- UIシェル、ページコンポーザー、i18nインフラストラクチャをホストする。
- モジュールのライフサイクルを管理する：検出、有効化、ルート安全性。
- 自動検出された `docs/` ディレクトリからアプリ内ドキュメントブラウザを提供する。

担当外: 特定のAuth プロバイダーロジック（アダプター）、特定のデータベースSQL（アダプター）、特定の通知トランスポート（アダプター）、またはモジュールが提供するコンテンツ。

## アーキテクチャ

### レイヤーモデル

```
core/            — コントラクト、インターフェース、ポリシーサービス
gateways/        — ドメインオーケストレーター (auth, db, notify, profile, files, logging)
adapters/        — 具体的なプロバイダー実装 (postgres, ldap, smtp など)
modules/         — オプションの機能拡張
api/             — HTTPサーバー、ルートレジストリ、リクエスト/レスポンス層
ui/              — ブラウザフロントエンド（ページ、レイアウト、再利用ユーティリティ、スタイル）
```

コアは `DatabaseGateway`、`FileStorageGateway`、`AuthAccountStore`、その他のインターフェースを `src/core/contracts/` で定義します。ゲートウェイはコアからインポートし、コアはゲートウェイが存在することを知りません。この一方向の依存関係が主要なアーキテクチャ上の不変条件です。

各ゲートウェイには、`GatewayBootstrapContext` を受け取る `bootstrap(ctx)` 関数があります。コンテキストはケイパビリティストア (`ctx.capabilities`)、ルートレジストリ (`ctx.routeRegistry`)、ゲートウェイレジストリ (`ctx.gatewayRegistry`)、現在のデータベース実行者とタイプへのアクセスを提供します。ゲートウェイはストアにケイパビリティを提供し (`ctx.capabilities.contribute('key', value)`)、他のゲートウェイはそれを取得します (`ctx.capabilities.get('key')`)。

### ケイパビリティストア

ケイパビリティストアは、直接インポートなしにゲートウェイを接続するインジェクションメカニズムです。例えば、ログゲートウェイはケイパビリティストアから `file:append`（ファイルゲートウェイが提供）を読み込み、ログの書き込みがファイルゲートウェイの抽象化を通じて行われるようにLoggerに渡します。プロファイルゲートウェイはアバターのアップロードを処理するために `file:gateway`（同じくファイルから）を読み込みます。

### 自動検出

ゲートウェイは起動時に `src/gateways/` をスキャンして検出されます。各ゲートウェイディレクトリには `bootstrap.ts` と `manifest.json` が含まれています。サーバーは各マニフェストの `requires` フィールドで決定された依存関係の順序でゲートウェイを読み込みます。

アダプターは各ゲートウェイが独自のブートストラップ時に `src/adapters/<gateway-id>/` をスキャンして検出されます。コアもサーバーも、どのアダプターがインストールされているかを知りません。

モジュールは `src/modules/`（内部、信頼済み）と `COGNIS_MODULES_ROOT/external`（外部アーカイブ、明示的な有効化確認が必要）から検出されます。ポインターファイルメカニズム（nginx スタイルの `<id>.load` シンボリックリンク）がどのモジュールがアクティブかを制御します。

### 主要なソースの場所

| エリア                         | パス                              |
| ------------------------------ | --------------------------------- |
| コアコントラクト               | `src/core/contracts/`             |
| コアサービス                   | `src/core/services/`              |
| HTTPサーバーエントリー         | `src/api/main.ts`                 |
| ルートレジストリ               | `src/api/reuse/route-registry.ts` |
| ゲートウェイ共有ユーティリティ | `src/gateways/shared.ts`          |
| ゲートウェイブートストラッパー | `src/api/bootstrap/gateway.ts`    |
| UIエントリーポイント           | `src/ui/app/`                     |
| UI再利用ユーティリティ         | `src/ui/reuse/`                   |
| プラットフォームドキュメント   | `src/docs/`                       |

## 拡張ポイント

Cognisは3つのメカニズムで拡張されます：

- **ゲートウェイ**: `bootstrap.ts` と `manifest.json` を含むディレクトリを `src/gateways/` に追加します。サーバーは自動的に検出します。
- **アダプター**: `src/adapters/<gateway-id>/` にディレクトリを追加します。所有するゲートウェイがそれを検出して読み込みます。
- **モジュール**: モジュールディレクトリを `src/modules/`（内部）の下に、またはモジュールアーカイブを設定された外部パスの下に配置します。管理者UIまたは `cognisctl` を通じて有効化します。
