# コンポーネントの復旧

## 障害の隔離

ブラウザーの提供元カタログには、サーバーが解決したモジュール、ゲートウェイ、アダプターの所有情報が含まれます。任意の所有元が失敗すると、そのコンポーネントの機能、フロー、リスナーをすべて解除します。他の所有元は読み込みを続け、翻訳されたエラー通知を表示します。同じカタログは、明示的な再読み込みまたは所有元のリビジョン変更まで隔離します。必須、重要、所有元不明、オフライン方針の提供元は障害時にアクセスを閉じます。必須または重要なコンポーネントは、自動でも手動でも無効にできません。それらが利用する依存先の無効化も防ぎます。

サーバーの経路で発生した予期しない例外は、その経路を登録したゲートウェイ、アダプター、モジュールに帰属させます。想定されたクライアントのエラーや不正なJSONは障害回数に含めません。管理者が確認したサーバー障害には同じ繰り返し障害の保護を適用し、リクエストのデータで別の所有元を指定することはできません。他のコンポーネントは通常どおり応答します。

## 自動的な無効化

管理者が報告した異なる提供元障害が五分間に三回発生すると、既存の認証済み無効化操作を実行します。報告は現在のサーバー登録と照合し、発生識別子で重複を除き、メモリ内の件数を制限し、コンポーネントのバージョンごとに分けます。管理者以外の報告は全体の無効化回数に加えません。カウンターはサーバー再起動時または期間終了時にリセットします。無効化の成功は通常のライフサイクルで保存され、カタログを更新します。修復または更新してから再度有効にしてください。

## コマンドライン操作

稼働中の Cognis コンテナーで、通常の CLI 認証情報を使って次のコマンドを実行します。アダプターはゲートウェイID、アダプターIDの順に指定します。`--all` は種類またはアダプターのゲートウェイで絞り込めます。一括操作は依存関係の順序を守り、保護対象やホスト管理の対象を飛ばし、個別の失敗後も継続します。すべての結果を表示し、失敗があれば終了コードを非ゼロにします。単一対象の有効化と無効化も同じ結果一覧形式を返します。設定変更とリポジトリーの取り込みは個別の対象に限定します。

```sh
cognisctl component:info module study-language-en
cognisctl component:info --all
cognisctl component:release-channel list module study-language-en
cognisctl component:release-channel set module study-language-en feature-guided-tutorials
cognisctl component:release-channel get module study-language-en
cognisctl component:upgrade module study-language-en
cognisctl component:upgrade module --all
cognisctl component:disable module --all
cognisctl component:enable adapter study --all
```

## 公開先と更新

公開先の取得、設定、一覧は、設定済みマーケットプレースのブランチとリリースを使います。選択は `config/component-channels.json` に原子的に保存します。更新には、その選択または導入済みブランチと、既存のインストーラー、依存関係の検証、整合性方針、認証を使います。有効だったモジュールは更新中だけ無効にします。実行中のインストール処理を完了まで確認し、失敗時は通常の検証を経て再度有効にすることを試みます。成功時は必要なサーバー再起動を報告します。時間切れで状態が不明な処理は無効なまま保持します。同梱のゲートウェイ、アダプター、コアモジュールはホストの配備で更新します。個別の公開先一覧は空で、公開先の設定は拒否します。

## 公開契約

バージョン一の `component:management` 契約は API コンポーネントが所有し、`system:contracts` で公開します。情報取得、公開先の選択、変更、障害報告は名前付きの `component:*` フローを実行します。`/api/v1/components` と管理操作には管理者権限が必要です。認証済み利用者は登録済み提供元の障害を報告できますが、その報告でコンポーネントを全体的に無効にすることはできません。各機能の操作は既存の認証済み管理経路を通ります。提供元の情報には、内容のハッシュを使う資産も含め、正式な所有元、バージョン、必須または重要な保護情報を記載します。
