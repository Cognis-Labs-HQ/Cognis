# ドキュメントの契約

紹介、実践的な手順、技術リファレンスを分離し、必要な詳しさを選べるようにします。

## インターフェース

各コンポーネントは `documentation.readme`、`documentation.usage`、`documentation.technical` に `docs/README.en.md`、`docs/USAGE.en.md`、`docs/TECHNICAL.en.md` を指定します。英語も `.en` を維持し、各言語に `.en`、`.de`、`.id`、`.ja` を付けます。宣言のパスは表示言語を固定せず、翻訳を含む文書群の英語版を示します。コアのトピックは、`index.<locale>.md`、`usage.<locale>.md`、`technical.<locale>.md` があるディレクトリから検出します。

## 設定

`npm run check:docs` を実行してください。PR の CI は `--base` と `--branch` で新しい変更履歴を比較し、ブランチ名による四言語の一組のみを許可します。

## 動作

### ログ出力の境界

アプリケーションの JavaScript と TypeScript、インラインスクリプト、イベントハンドラーは、注入されたログ機能または公開ブラウザー診断ポートを使って診断を発行します。ネイティブコンソールへのアクセスは、ログ出力アダプターと Logging ゲートウェイの初期化に限ります。同じ初期化ファイルにある他のハンドラーは例外になりません。コマンドやビルドのレポートは端末ストリームへ明示的に出力します。ネイティブコンソールの検査は開発ツールのソースにも適用し、テスト用フィクスチャは製品コードの走査から除外します。

`node --import tsx --test src/tooling/tests/logging/*.test.js` で、リポジトリと検出ケースを検査できます。インストール済み外部モジュールと `COGNIS_EXTERNAL_MODULES_ROOT` にも対応し、違反箇所のファイルと行を表示します。別名、計算されたプロパティ、`node:console` のインポートを拒否し、既存の違反に対する適用除外は設けません。

新しいトピックは概要を開きます。概要、使用例、技術情報は一つのコンポーネントバージョンに属します。サーバーは全ファイルを読んでから一括で公開し、不足した表示や部分的な翻訳があれば公開を拒否します。表示の切り替えは選択したバージョンを保ち、コンポーネントを削除しても過去の版を参照できます。

本文、ナビゲーション、検索は現在の UI 言語を優先し、その後に設定した代替言語と英語を使います。情報・使い方・技術と保存版にも同じ選択を適用します。

### 翻訳カタログ

配布するすべての `strings.xml` カタログは `<resources>` をルート要素にします。英語の値を空にせず、他の言語も同じキーと順序を維持します。リテラルの翻訳呼び出しとHTMLの翻訳属性は英語の項目に解決できなければなりません。`node --import tsx --test src/ui/tests/strings-coverage.test.js src/tooling/tests/translations/*.test.js` でカタログとソース内の参照を検査します。動的に組み立てるキーは、引き続き各コンポーネントの動作テストで検証します。

## セキュリティ

ドキュメントは公開情報です。認証情報、個人のアカウント情報、運用上の秘密を含めないでください。マニフェストは自分のドキュメント領域を参照します。コアは任意の Markdown ファイル名ではなく、ディレクトリのエントリー一式を読み込みます。

## リファレンス

README は目的、作業、アクセス、使い始め方を説明し、エンドポイントの仕様や実装コードを含めません。USAGE は実際の手順や公開された例、前提条件、結果、問題の解決を示します。TECHNICAL はインターフェース、設定、動作、セキュリティ、リファレンスを扱います。

各言語の H2 の名前と順序は `src/tooling/reuse/documentation/structure.json` で定義します。H1 は一つ、30 文字以内とし、紹介文を付けます。空または追加の節、未記入のテンプレート、閉じていないコード、見出し階層の飛び越しは検証エラーになります。テンプレートは `.github/documentation/` にあります。

対応する動作は該当する節で説明します。リリース履歴や実装の経緯はブランチの変更履歴だけに記載します。共通の技術的な段落は一か所が管理し、他の文書はそこへリンクします。

コンポーネントのアセットは所有者の公開用静的パスを使います。独立したアセット領域を持つ一つのコンポーネントだけが使うファイルをコアに置くことはできません。コア自身と共有のアセットはコアに置きます。CSS の読み込みはアルファベット順の連続したブロックとし、スタイル規則の前に空行を一つ入れます。

各種類に定型文ではなく、ソースで確認した有用な情報を記載します。メソッド、パス、項目、権限、既定値、永続性、不完全な連携を担当実装と照合します。手順例は使い方、実装契約は技術に置きます。自動検証は定型の空欄代替文と不足した参照を検出しますが、任意の文章の真偽を証明するものではありません。

GitHub のソースリンクは保存済みの資料からも既定ブランチの別名 `blob/HEAD` または `raw/HEAD` を使います。変更履歴のコミットリンクは固定したコミットを指します。
