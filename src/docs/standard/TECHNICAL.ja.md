# ドキュメントの契約

文書群は、検証された構造と言語別ソースを用い、導入情報、実行手順、技術契約を分離します。

## インターフェース

各コンポーネントは `documentation.readme`、`documentation.usage`、`documentation.technical` に `docs/README.en.md`、`docs/USAGE.en.md`、`docs/TECHNICAL.en.md` を指定します。英語も `.en` を維持し、各言語に `.en`、`.de`、`.id`、`.ja` を付けます。宣言のパスは表示言語を固定せず、翻訳を含む文書群の英語版を示します。コアのトピックは、`INFO.<locale>.md`、`USAGE.<locale>.md`、`TECHNICAL.<locale>.md` があるディレクトリから検出します。

文書のベース名は大文字と小文字を区別し、大文字で記述します。INFO、README、USAGE、TECHNICAL の小文字や大小混在の名前は、正しい名前のファイルが併存していても拒否されます。

### 必須の構成

文書の言語に対応する次の H2 見出しを、表の順序どおりに使います。Info はコアの INFO ファイルも含めて README の構成を使います。識別子は翻訳せず、見出しを別の名前に置き換えないでください。

| 言語 | Info / README                                                                            | 使用例                                                                      | 技術情報                                                                     |
| ---- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| en   | `What You Can Do` → `Before You Start` → `Get Started` → `Learn More`                    | `Prerequisites` → `Examples` → `Expected Results` → `Troubleshooting`       | `Interfaces` → `Configuration` → `Behavior` → `Security` → `Reference`       |
| de   | `Möglichkeiten` → `Vor dem Start` → `Erste Schritte` → `Weitere Informationen`           | `Voraussetzungen` → `Beispiele` → `Erwartete Ergebnisse` → `Fehlerbehebung` | `Schnittstellen` → `Konfiguration` → `Verhalten` → `Sicherheit` → `Referenz` |
| id   | `Yang Dapat Anda Lakukan` → `Sebelum Memulai` → `Langkah Awal` → `Pelajari Lebih Lanjut` | `Prasyarat` → `Contoh` → `Hasil yang Diharapkan` → `Pemecahan Masalah`      | `Antarmuka` → `Konfigurasi` → `Perilaku` → `Keamanan` → `Referensi`          |
| ja   | `できること` → `始める前に` → `はじめに` → `詳しい情報`                                  | `前提条件` → `使用例` → `期待される結果` → `問題の解決`                     | `インターフェース` → `設定` → `動作` → `セキュリティ` → `リファレンス`       |

先頭は字下げのない `# タイトル` を一つだけ置き、30文字以内にします。空行の後に内容を説明する導入段落を置き、その後に必須の H2 節を並べます。各見出しの前後を空行で区切ります。字下げした見出し、HTML 見出し、Setext 見出しは使いません。必須節の中には H3〜H6 の小節を設けられますが、階層を飛ばしてはいけません。各節と小節には表示される内容が必要です。親節は内容のある小節を含む形でも構いません。コメントは内容に数えません。

Info に実装コードやエンドポイント仕様を記載しません。使用例と技術情報では、バッククォートまたはチルダで囲むコード例を使えます。閉じる記号は開始と同じ文字を使い、開始以上の長さで、後ろに文字列を付けません。例の中の見出しやコメントはそのままの内容として扱います。コードや箇条書きを導入段落の代わりにはできません。

各トピックには `en`、`de`、`id`、`ja` ごとに3ファイル、合計12ファイルが必要です。コンポーネントのマニフェストには英語の README、USAGE、TECHNICAL のパスだけを宣言します。コアの各ディレクトリでは INFO、USAGE、TECHNICAL を使い、トピックごとのコンポーネントマニフェストは置きません。基本名は大文字、言語の接尾辞は小文字にします。独立した変更履歴領域を除き、追加の Markdown マニュアルは認めません。

## 設定

`npm run check:docs` を実行してください。PR の CI は `--base` と `--branch` で新しい変更履歴を比較し、ブランチ名による四言語の一組のみを許可します。

## 動作

### ログ出力の境界

アプリケーションの JavaScript と TypeScript、インラインスクリプト、イベントハンドラーは、注入されたログ機能または公開ブラウザー診断ポートを使って診断を発行します。ネイティブコンソールへのアクセスは、ログ出力アダプターと Logging ゲートウェイの初期化に限ります。同じ初期化ファイルにある他のハンドラーは例外になりません。コマンドやビルドのレポートは端末ストリームへ明示的に出力します。ネイティブコンソールの検査は開発ツールのソースにも適用し、テスト用フィクスチャは製品コードの走査から除外します。

`node --import tsx --test src/tooling/tests/logging/*.test.js` で、リポジトリと検出ケースを検査できます。インストール済み外部モジュールと `COGNIS_EXTERNAL_MODULES_ROOT` にも対応し、違反箇所のファイルと行を表示します。別名、計算されたプロパティ、`node:console` のインポートを拒否し、既存の違反に対する適用除外は設けません。

新しいトピックは概要を開きます。概要、使用例、技術情報は一つのコンポーネントバージョンに属します。サーバーは全ファイルを読んでから一括で公開し、不足した表示や部分的な翻訳があれば公開を拒否します。表示の切り替えは選択したバージョンを保ち、コンポーネントを削除しても過去の版を参照できます。

本文、ナビゲーション、検索は現在の UI 言語を優先し、その後に設定した代替言語と英語を使います。情報・使い方・技術と保存版にも同じ選択を適用します。

### 翻訳カタログ

配布するすべての `strings.xml` カタログは `<resources>` をルート要素にします。英語の値を空にせず、他の言語も同じキーと順序を維持します。リテラルの翻訳呼び出しとHTMLの翻訳属性は英語の項目に解決できなければなりません。`node --import tsx --test src/ui/tests/strings-coverage.test.js src/tooling/tests/translations/*.test.js` でカタログとソース内の参照を検査します。動的に組み立てるキーは、引き続き各コンポーネントの動作テストで検証します。

### 検証と限界

`npm run check:docs` は実際のコンポーネントマニフェストとコアのディレクトリを検証します。文書テストでは、すべての役割と言語について見出し、順序、内容、コード記号、ファイル名、マニフェストのパスを変えて違反の検出を確認します。また、各言語の標準にある節の表と機械可読スキーマを照合します。CI は文書チェックと全テストを実行します。これらは構成と具体的な参照先を検証するものであり、記述の正確性は担当する実装と照らして確認する必要があります。

## セキュリティ

ドキュメントは公開情報です。認証情報、個人のアカウント情報、運用上の秘密を含めないでください。マニフェストは自分のドキュメント領域を参照します。コアは任意の Markdown ファイル名ではなく、ディレクトリのエントリー一式を読み込みます。

## リファレンス

README は目的、作業、アクセス、使い始め方を説明し、エンドポイントの仕様や実装コードを含めません。USAGE は実際の手順や公開された例、前提条件、結果、問題の解決を示します。TECHNICAL はインターフェース、設定、動作、セキュリティ、リファレンスを扱います。

各言語の H2 の名前と順序は `src/tooling/reuse/documentation/structure.json` で定義します。H1 は一つ、30 文字以内とし、紹介文を付けます。空または追加の節、未記入のテンプレート、閉じていないコード、見出し階層の飛び越しは検証エラーになります。テンプレートは `.github/documentation/` にあります。

対応する動作は該当する節で説明します。リリース履歴や実装の経緯はブランチの変更履歴だけに記載します。共通の技術的な段落は一か所が管理し、他の文書はそこへリンクします。

コンポーネントのアセットは所有者の公開用静的パスを使います。独立したアセット領域を持つ一つのコンポーネントだけが使うファイルをコアに置くことはできません。コア自身と共有のアセットはコアに置きます。CSS の読み込みはアルファベット順の連続したブロックとし、スタイル規則の前に空行を一つ入れます。

各種類に定型文ではなく、ソースで確認した有用な情報を記載します。メソッド、パス、項目、権限、既定値、永続性、不完全な連携を担当実装と照合します。手順例は使い方、実装契約は技術に置きます。自動検証は定型の空欄代替文と不足した参照を検出しますが、任意の文章の真偽を証明するものではありません。

GitHub のソースリンクは保存済みの資料からも既定ブランチの別名 `blob/HEAD` または `raw/HEAD` を使います。変更履歴のコミットリンクは固定したコミットを指します。

変更履歴のリンク表示には、先頭7文字などの短いコミット参照を使用します。リンク先 URL には不変の完全な SHA を保持します。Markdown または HTML のリンク表示に完全な SHA が含まれる場合、文書検証コマンドとリポジトリのテストは失敗します。

文書の検証は、トピックの移動先とリポジトリーのソースを確認します。コミットのリンク表示は HTML を生成せずに文字を数え、無害化済みマークアップではなく診断結果を返します。
