# 技術リファレンス

UI の公開インターフェースと運用規則を説明します。

## インターフェース

UIRegistry が素材、ナビゲーション、管理項目、画面拡張を公開します。ブラウザー側は uiCtx と自身の中止シグナルで登録し、画面は Page Composer を使います。

## 設定

アカウント設定でテーマ・言語・フォントを選びます。各カタログが翻訳とメタデータを提供し、配置は各機能の独自上書きではなく Page Composer で管理します。

## 動作

接続の復旧時にはページの再描画前にコアとコンポーネントの翻訳キャッシュを無効化します。明示的な更新では最新のサーバー内容を取得し、障害時は完全なオフラインコピーを維持します。不正なXML応答は保存せず、次の読み込みでは強制再読み込みなしで復旧できます。

### 概要

`src/ui/` はCognisのブラウザフロントエンドをホストします。学習ワークフロー、ソーシャルインタラクション面、管理パネル、組み込みドキュメントブラウザを提供します。UIはサーバーレンダリングのマルチページアプリケーションです。

UIレイヤーは、どのゲートウェイやアダプターがインストールされているかを知りません。代わりに、ゲートウェイは `UIRegistry` とページエクステンションAPIを通じてランタイムでUI要素を提供します。

すべてのユーザー向けテキストは `src/ui/reuse/i18n.js` のi18nシステムを通じて処理されます。JavaScriptやHTMLテンプレートにテキストは直接ハードコードされていません。

### 責務

- すべてのページエントリポイントと関連するHTMLテンプレートをホストする。
- すべての非ログインページがレンダリングするレイアウトシェルを提供する。
- i18n、ページコンポーザー、未保存変更ガードのreaseユーティリティを維持する。
- テーマの一貫性を保つ: すべての要素がCSS変数から色を解決する。
- 4つの必須言語（en、de、ja、id）のi18n文字列パックを提供する。

### 共通の画像プレビュー

グローバルな `ui:imagePreview` はサムネイル描画、イベント設定、および登録済みの `ui:imagePreview:open` フローを通じた `open` 操作を提供します。`ui:reuse` から `image-preview.js` としても利用でき、操作の公開前に共通スタイルシートを読み込みます。画像ボタンを押すと、元画像を画面内に収まる自然なサイズで表示し、通常の X ボタンだけが表示されます。キーボード操作、Escape、フォーカスの復元、親画面やプロバイダー終了時の閉鎖は共通ポップアップのライフサイクルに従います。画像 URL と任意の削除操作は呼び出し側が管理します。Library の編集画面と詳細ギャラリーは、アップロード画像と同梱画像にこの共通コントロールを使用します。

呼び出し側による中止やプロバイダーの削除は、翻訳やポップアップのスタイルシートの準備を待たずに、準備中の画像プレビューを終了します。遅れて準備が完了しても、中止したビューアーを再表示したり、その失敗通知を表示したりしません。他の呼び出し側は共通の準備を引き続き利用できます。

公開操作 open は中止時に AbortError で失敗し、明示的に閉じた場合は正常に完了します。同じ有効な呼び出し側シグナルのままサムネイルを置き換えても、元画像の表示を維持します。呼び出し側のシグナルがないビューアーはプロバイダーが管理し、無関係なルート変更では閉じません。画像 URL は引き続き呼び出し側が管理します。既存の Library チュートリアルの対象と操作は変更せず、中止のための操作手順も追加しません。

共通の画像プレビュープロバイダーは、操作を公開する前にスタイルシートを読み込みます。画像専用ポップアップは見出しのマークアップを削除し、横長・縦長・パノラマ画像を横方向にも縦方向にもスクロールせず画面内に収めます。Library の詳細プレビューは最大 20rem × 18rem、編集画面のサムネイルは 8rem × 6rem を維持します。

### 応答性の高い画面移動

ログアウトは公開ルートのサービスワーカー保守を待たずに非公開セッションデータを消去します。同一のポリシー要求は通信を共有しますが、変更されたアクセス判断は統合しません。言語切り替えはカタログ提供元の準備を待ち、ログアウト時はアカウント専用操作を非表示にします。バンドル版と直接読み込み版のルーターはドキュメント状態、リスナー、表示の中断を共有し、設定からダッシュボードへの移動にも対応します。

### 静かなマーケットプレイス更新

この動作については[共通の契約](/docs/api/technical)を参照してください。

おすすめフィードはマーケットプレイスサービスで共有し、同時の読み取りをまとめて5分間保持します。更新に失敗した場合は最後に取得できた一覧を維持し、次の試行まで1分待ちます。設定 URL が変わると別の結果に切り替え、手動の更新は有効期間を無視します。

### 送信前のキャンセル

共有UIのオフラインクライアントは、呼び出し元のAbortSignalを登録済みリクエスト段階、保留キューの読み取り、送信待機に渡します。ネットワークリクエストやキューへの永続書き込みが始まる前のキャンセルは、その新しい操作を防ぎます。送信キューは保存ロック内でもキャンセルを再確認します。

追加の契約は`deliverOrQueue(ctx, owner, id, payload, send, { signal } = {})`と`outbox.submit(owner, id, payload, { signal } = {})`です。シグナルを渡さない既存の呼び出しと保存済み操作の再送は従来どおりです。後からキャンセルしても、受け付け済みのキューレコードを削除したり、送信済みリクエストを取り消したりしません。応答の確認が失われると結果が不明になる場合があり、確認せずに再送してはいけません。

この契約はゲートウェイやアダプターのパッケージではなく、共有UIアセットが所有します。更新された共有アセットをProfile 4.0.1と一緒に配布してください。プロフィール、メッセージ、カレンダー、Notifyメールは共有HTTPクライアントを使用し、Studyの描画、ライブラリー、お気に入り、Flashcardsも任意の送信ヘルパーを使用します。シグナルを渡さない呼び出しは既存の契約を維持します。カレンダー固有の実行時動作は変更しません。

### 検索結果の選択契約

ポインターまたはEnterで結果を選び、処理が終わるまで待ちます。各ポップアップでは処理中の選択コールバックを一つに制限します。検索の所有元が有効な間に限り、例外やPromiseの拒否が発生しても検索語、カテゴリ、複数選択を維持し、翻訳されたトーストで知らせます。失敗の通知だけでは操作が未送信とは限らないため、再試行前に操作先を確認してください。利用できなくなった結果は、再検索を促します。

`openSearchPopup`と`createSearchBar`は任意の`signal`を受け取り、`context.signal`を含む選択コンテキストをコールバックの第2引数に渡します。同期コールバックと成功を示す`undefined`の戻り値は従来どおりです。Promiseは完了を待ってから成功時に閉じます。厳密な`false`は追加のキャンセル結果であり、所有元が有効な間はエラーを表示せず検索を開いたままにします。フッター操作は標準の`click`を使い、キーボードやブラウザーによる操作にも対応します。`mousedown`では選択コールバックを呼び出しません。

閉じる、Escape、ルート移動やページの破棄、プロバイダーの終了、アカウント変更は、保留中のUI結果反映を無効にします。結果プロバイダーの登録解除は、そのプロバイダーに属する選択を無効にします。古い処理の完了によって新しいポップアップが閉じたり、遅れて通知が表示されたりすることはありません。ただし、キャンセルで送信済みの操作は取り消せません。呼び出し側は自身の有効期間を表すシグナルを渡し、操作を送信する前にコールバックのシグナルを確認する必要があります。

ナビゲーションバーからの選択は、ルート破棄前に`navigateTo`が返した`false`を伝え、移動が拒否された場合はエラーなしで検索を維持します。`route-will-change`または`pagehide`が発生すると、移動先の表示に後で失敗しても、検索は有効期間の終了として閉じます。その後の結果通知は、閉じた検索ポップアップではなく移動先またはルーターが担当します。

ワークスペースのチュートリアルでは、選択、待機、安全な再試行を説明します。対象、完了ID、「次へ」「戻る」、再実行は維持します。検索は共通UIであり、独立してバージョン管理されるパッケージやマニフェストはありません。

### フォームの検証

検証で無効と判定された入力には `aria-invalid="true"` が設定されます。`aria-describedby` は、呼び出し元が指定した説明に加え、現在満たされていない条件の既存の翻訳文を参照します。入力を修正すると、フォームビルダーが追加した無効状態と説明への参照だけが削除されます。未操作の入力や判定保留の条件（`null`）には、検証前に無効な ARIA 状態を設定しません。必須項目、任意項目、検証の戻り値に関する既存の規則は引き続き適用されます。ブラウザー標準の制約検証とタブ選択は、独自の条件とは別に扱われます。

表示される条件にはそれぞれ固有の ID があり、複数のフォームで同じ項目名を使う場合も区別されます。コントローラーの `detach()` または接続時の中止シグナルは、自身のイベントリスナーと ARIA 状態を解除します。明示的な検証呼び出しは引き続き利用できます。ページやポップアップの所有元は、フォームの有効期間が終わったら接続を解除する必要があります。この表示処理は入力値を記録しません。

呼び出し元による `aria-invalid` の変更や削除は、その後に無効な入力を再検証しても、修正や解除まで保持されます。呼び出し元が同じ `true` を書き込んだ場合は、フォームビルダーが設定済みの値と区別できません。独自の条件の評価中に接続が解除された場合、実行中の項目検証やフォーム全体の検証は結果を返しますが、解除後に表示を更新しません。解除後に明示的に検証を呼び出すと新たな評価が始まり、その状態も再び解除できます。

### チュートリアルの対象

項目の要件を確認し、満たされていない条件を修正してから操作を再試行してください。登録管理とセキュリティのチュートリアルでは、既存の操作、対象、完了 ID、画面移動を維持します。セキュリティのガイドでは、パスワードの要件、確認入力、キャンセルをすでに説明しています。共通の検証処理によって新しいチュートリアル操作や手順は追加されません。共通 UI には独立したバージョン付きパッケージやマニフェストはありません。

### 設定のメール操作

「主に設定」は追加・保存系、「削除」は破壊的な操作の表示を使用します。どちらもメール一覧全体で処理中のロックを共有し、同じページを再描画しても維持します。拒否、確認済みの変更、送信待ち、未確認の結果はそれぞれ異なる翻訳済み通知で示します。一覧の更新に失敗しても、保存済みの変更を失敗とは表示しません。ページを離れた場合、アカウントが変わった場合、プロバイダーが削除された場合は古い完了通知を表示しません。

「更新」は変更を繰り返さずに一覧を確認します。確認済みまたは不明な結果の照合には、Notifyの公開クライアントでバッファーを使わないオンライン専用読み取りと `cache: "no-store"` を使用します。キャッシュ済みの応答、共有中の読み取り、送信待ち操作を反映した予測一覧は使いません。有効な一覧に要求した削除または主アドレスの選択が反映されている場合にだけロックを解除します。送信待ちの結果は引き続きNotifyの通常の予測一覧を使用し、サーバー確認済みとは表示しません。照合の失敗、不正な一覧、オフライン、未反映の場合はロックと案内を維持します。結果を確認できないままの場合は、設定を開き直して一覧を見直してから新しい変更を開始してください。ロックは現在のページだけに属します。開き直しても以前の結果が証明されるわけではなく、永続的な変更受領記録は追加しません。

既存の一般チュートリアルは、一覧が空でも項目があっても同じメール一覧の対象、所有者、完了IDを使用します。処理中、送信待ち、「更新」の案内を4言語で更新しました。確認、再送信、追加、パスワード、アカウント管理の操作処理は従来どおりです。共有UIアセットには独立したパッケージバージョンはありません。

### カルーセル選択の有効期間

水平カルーセルは選択順序、押下状態、選択数を一緒に更新します。同じ識別子を持つカルーセルは選択した値を集約し、追加操作は項目を選択せずに追加できます。フォーカスやポインターによるプレビューは、マウントされたカルーセルが管理します。

所有元の `AbortSignal` を `mountHorizontalCarousels` に渡します。`onActivate` は項目の値とラベルを同期的に返すか、Promise の解決結果として返せます。`false` は選択を拒否し、同期結果は引き続き同期的に処理されます。シグナルの中止後は、保留中の有効化結果によって項目の識別子、ラベル、選択、ARIA 状態、件数を変更したり、`onChange` を通じて終了した所有元に通知したりすることはありません。有効化、順序決定、変更通知のコールバック内で中止された場合も、その後のウィジェット処理を止め、同じルート要素に新しくマウントされた選択を保持します。マウント時点で中止済みのシグナルはルート要素を変更しません。所有元のコールバック内部で行われた処理を取り消したり、元に戻したりするものではありません。

既存の作成チュートリアルは、エディター内容、セクション、フッターの対象、完了識別子、および次へ、戻る、再実行の進行を維持します。カルーセル選択のための独立したガイドや操作は追加しません。共有カルーセル資産には独立したコンポーネントパッケージのバージョンはありません。

### ダイアログの準備

中止済みの `openPopup` はリソースを取得せずに `null` を返します。スタイルシートまたは言語の準備中に中止した場合も、他の呼び出しや共有の言語初期化を中断せず、速やかに `null` を返します。失敗または中止した呼び出しは、ダイアログ、フォーカス所有権、スクロールロックを取得しません。言語の失敗は明示的に通知され、後の初期化で再試行できます。

ダイアログのスタイルは、バンドルと直接配信の呼び出し間で `ui:popupPreparation` を共有します。明示的な呼び出しは最大5秒の試行を共有し、そのうち最大1秒をキャッシュ内の完全なスタイルシートまたは進行中のキャッシュ更新に使います。キャッシュの欠落、不正常な応答、空の内容、拒否、停止時は、その試行内でネットワークに切り替えます。読み込み済みのリンクは再利用し、読み込み中のリンクは監視します。失敗時は自身が作成したリンクだけを削除し、既存リンクは保持します。失敗したリンクは次の試行から除外します。時間切れや読み込み失敗は `openPopup` を拒否し、閉じたと見なしたり、スタイルのない操作を妨げるダイアログを開いたりしません。有効な呼び出しには、失敗した試行ごとにローカライズされたエラートーストを1回表示します。中止済みの呼び出しは遅れて通知しません。次の明示的な呼び出しで再試行し、自動再試行ループは行いません。

`primePopupStylesheet()` は引き続きオフライン復旧用の完全なスタイルシートを更新し、同時更新をまとめ、失敗を記録して拒否しません。更新の上限は5秒です。期限後の遅い処理はDOMスタイルを追加・置換しません。ただし、ブラウザーに送信済みの Cache Storage 書き込みは取り消せません。キャッシュ準備の失敗は、その後のダイアログ復旧を無効化しません。アンカー付きプレビューは同期コントローラーを維持し、準備失敗を処理して失敗したプレビューを非表示にし、次の `show` で再試行します。`hide` と `destroy` は遅れた通知を防ぎます。既存の実行時エラー処理は、所有するスタイルシートの失敗を再帰的に報告しません。

チュートリアルの対象、完了ID、操作、次へ、戻る、再開始、再実行は変更しません。表示中ダイアログのフォーカス、入れ子、破棄確認、操作、時間制限、ロールバックの契約は維持します。共有UIに独立したパッケージバージョンはありません。

5秒の上限はスタイルシートの試行だけに適用され、`openPopup` の準備全体には適用されません。厳密な言語初期化は新しい時間制限を設けず、既存の有効期間を維持します。ローカライズされた失敗通知と拒否が遅れる場合も、呼び出しのシグナルによる中止は速やかに完了します。正常なアンカー付きプレビューはダイアログの言語リソースを初期化しません。

### フローティングウィンドウの操作

`ui:makeFloatingWindow`

フローティングウィンドウは、移動またはサイズ変更のジェスチャーを一度に1つ受け付けます。追加のタッチは実行中の操作を置き換えません。操作中のポインターを離す、キャンセルする、またはキャプチャを失うと、そのジェスチャーだけが終了し、現在の位置とサイズは保持されます。その後は通常どおり新しい操作を開始できます。

返された `release()` 関数と呼び出し元が指定する任意の中断シグナルは、フローティング動作とポインターキャプチャを解除します。呼び出し元のコンテンツを削除したり、閉じるコールバックを呼び出したりはしません。コールバックを呼ぶのは明示的な閉じるコントロールだけです。シグナルはウィンドウに必要な有効期間に合わせて選びます。永続的な通話 PiP は意図的にページシグナルを省略し、ルート通知だけでは閉じません。

### 構造化コンテンツのボタン

設定と管理画面の宣言的な拡張コンテンツには、`src/ui/reuse/structured-content.js` の `renderStructuredContent(groups)` を使用します。テキストとアクセシビリティ用ラベルは、担当コンポーネントの翻訳から渡します。

```js
renderStructuredContent([
    {
        items: [
            {
                type: "button",
                id: "inspect",
                text: inspectLabel,
                variant: "neutral",
            },
        ],
    },
]);
```

ボタン記述子の `variant: 'confirm'` は `btn-confirm` に、`variant: 'danger'` は `btn-cancel` に対応します。省略、`neutral`、その他の値は `btn-neutral` になり、未知の値も拒否しません。各ボタンには `structured-content__button` と `btn-animated` に加えて、結果の種類を示すクラスが必ず一つ付きます。作成や破壊的な操作のバリアントは担当コンポーネントが明示的に選択し、ラベルや ID から推測しません。

ネイティブの `type="button"`、エスケープされたテキストと属性（`id`、`name`、`ariaLabel`、`disabled`、`checked`）、グループ、区切り線を保持します。レンダラーは操作の実行やフォーム送信を行わず、マークアップを返します。イベント処理と一時的な無効状態は呼び出し元の責任であり、記述子には読み込み状態や任意のクラスの API はありません。ホストは既存の共通ボタンと構造化コンテンツのスタイルを読み込む必要があります。標準クラスは、折り返し、フォント継承、精度の低いポインター向けサイズの共通ルールに適用されます。

設定と管理画面のガイドは既存の対象と進行を維持します。このレンダラーは操作やチュートリアルの手順を追加しません。拡張コンテンツの担当側が、それぞれの操作とガイドを引き続き管理します。

### 標準のレイアウト操作

メインおよび入れ子のレイアウトパネルでは、完了、破棄、リセットに標準の `button type="button"` コントロールを使用します。これらの操作は、外側のフォームを送信したり画面を移動したりしません。レイアウトの送信中は既存の編集ロックで無効になり、送信に失敗すると明示的に再試行できるよう復元されます。完了は引き続き保存の確認後に編集を終了し、破棄は書き込みを行わずローカルの基準状態に戻し、リセットは既定のレイアウトを保存して編集を続けます。既存の操作クラスとワークスペースチュートリアルの対象 `#composer-edit-toggle` は変わりません。

## セキュリティ

移動先の非表示は認可ではありません。担当の機能を使い、画面終了やアカウント変更で待機処理を中止し、個人データを分離します。

## リファレンス

### ガイド付きチュートリアル

チュートリアルはページや URL に紐付きます。利用条件を満たす初回訪問では、そのページの未完了ガイドを自動的に開始します。`page-context` のタイトル横にある疑問符 SVG から、そのページで利用できるガイドを再生できます。ホストは表示と寿命を管理し、各機能が文章、対象、スクリプトを所有します。権限は変更しません。

`showToast(message, { minRole: "admin" })` は運用上の通知を管理者と所有者だけに表示します。その他や不明な役割では DOM、タイマー、終了コールバックを作成しません。`minRole` を省略した通常の通知は全員に表示します。この表示制限はサーバーの認可を代替しません。

フローティングメニューはバージョン 1 の `ui:floatingMenus` と、段階付きフロー `ui:floatingMenu:request`、`present`、`dismiss`、`release` を使います。同じ優先度は要求順に処理し、高い優先度は低いメニューを一時停止します。予約は初回の許可または取消を示す `ready`、`present(element, { visible })`、`dismiss(element)`、`dispose()` を提供します。チュートリアルは完了、取消、所有者の解除まで、ステップ間も含め優先度 100 を保ちます。コンポーザーのスロットと再実行の選択も同じ待ち行列を使います。取り消した要求や古い表示処理は新しいメニューを置き換えません。空のスロットは表示を譲り、ページ解除時は監視と予約を破棄します。

トーストは、通知の作成や終了を遅らせずに共通スタイルシートを読み込みます。同時の通知は、各5秒までの試行を最大2回共有します。サイクルが失敗しても後続の通知で再試行できます。外部のリンクは保持し、トーストの読み込み処理が作成した失敗リンクだけを削除します。読み込み中に閉じた通知は再表示されません。ページのチュートリアルの対象と進行は変わりません。

### アクションメニューの有効期間と操作

`openHamburgerMenu(button, { items, signal })` は `Promise<string|null>` を返します。任意の `signal` は準備中と表示中のメニューを現在のページまたはコンポーネントに結び付けます。結果を待つ前に、そのマウントのシグナルを取得してください。有効な項目を選ぶと既存の操作 ID を返し、閉じる操作、中止、開いたボタンの削除、新しいメニューによる置き換えでは `null` を返します。空の一覧や有効な操作のない一覧も `null` を返します。スタイルシートやメニューの順番を待っている間も中止できます。開いたボタンやメニューからフォーカスが離れると、スタイルシートや表示順を待機中でもメニューの準備を中止します。 保持された古い操作要素から選択したり、新しいメニューを閉じたりすることはできません。

アクションメニューは優先度 50 で `ui:floatingMenus` を使い、優先度の高いチュートリアル予約が表示を譲るまで待機します。表示中のメニューより優先度の高い予約が入ると、フォーカスを戻さずにそのメニューを閉じます。準備中と表示中の領域は `ui:transientSurfaces` によって有効期間を共有し、バンドル経由と直接配信の呼び出しでも同じ管理を使います。ユーザーとモジュールの既存のチュートリアル対象および操作処理は維持されます。この共通 UI の契約に独立したパッケージバージョンはありません。

開くと最初の有効な項目にフォーカスします。下矢印と上矢印で有効な項目を移動し、Home と End で最初と最後へ移動します。Escape で閉じた場合は、開いたボタンが現在も有効で文書に接続されている場合にのみフォーカスを戻します。Tab は通常のフォーカス移動を保ちながら閉じます。メニュー外のポインター操作による終了では、開いたボタンへフォーカスを戻しません。無効な操作は選択できません。既存の翻訳済みラベル、エスケープ済み HTML 値、危険を示す表示、画面幅に応じた配置を引き続き使用できます。

ダイアログ内の操作要素から開くメニューは、既存の `ui:popupFocus` によるフォーカス管理の委譲を利用します。メニュー内の移動と Escape は親ダイアログを閉じずにメニューを操作します。同じダイアログ内の別の操作要素へフォーカスを移すと、メニューを閉じて移動先のフォーカスを維持します。新しい子ダイアログを開いた場合や親を閉じた場合は、メニューの所有権を解除します。ダイアログの契約は変更しません。

### ダイアログのキーボード操作

各ダイアログには固有のアクセシブルな見出しがあり、未保存の変更に関する確認や複数ページのダイアログも区別できます。Tab と Shift+Tab による移動は、操作中のダイアログ内に留まります。下書きを保持すると編集画面にフォーカスが戻ります。最後のダイアログを閉じると、開くときに使った操作要素に戻り、その要素がなくなっていればページに戻ります。空のダイアログは操作要素が利用可能になるまでフォーカスを保持します。ページ移動による中断では、古いページにフォーカスを戻さずに解放します。閉じるアニメーション中のダイアログはキーボード操作を保持しません。ガイド付きチュートリアルから開いたダイアログにも同じ操作が適用されます。

### ダイアログを開く際の有効期間

`onOpen` はダイアログの追加後、表示アニメーションの開始前に同期的に実行されます。初期構築で例外が発生すると、`openPopup` は失敗したダイアログを削除し、そのフォーカス、イベントリスナー、タイマー、変更追跡、スクロールロックの利用権を解除してから、同じエラーで拒否されます。構築失敗ではキャンセルの許可や変更破棄の確認を求めません。すでに結果が確定した閉じる操作や所有元による中止は、そのまま確定結果として扱います。初期化関数が返す Promise は待機しません。

有効な親ダイアログや新しいダイアログは、自身のフォーカスとスクロールの所有権を維持します。画像プレビューの同期的な準備に失敗した場合も同じ解除処理を使用し、翻訳エラーは明示的なエラーとして伝播されます。通常の開閉アニメーション、必須ダイアログ、操作コールバック、変更確認、繰り返し呼ばれるページコールバックの契約は変わりません。後から呼ばれるページコールバックの例外は初期表示の失敗として扱いません。

既存のチュートリアル対象、所有者 ID、完了 ID、「次へ」「戻る」「再開」、再実行は維持されます。子ダイアログが失敗すると、受け入れ済みの有効な親チュートリアルへ所有権が戻ります。解除処理が失敗したダイアログを新たなチュートリアル対象にすることはありません。共通 UI に独立したバージョン付きパッケージやマニフェストはありません。

### ダイアログ操作の規約

Enterとスペースはフォーカス中の標準コントロールを操作します。「キャンセル」から別のフッター操作が選択されることはありません。未保存の変更を確認するダイアログでは、最初に安全な「キャンセル」へフォーカスを置き、「破棄」は危険を示す表示を使用します。Enterを押し続けてもダイアログ操作は繰り返されません。処理中の操作は再送信できませんが、明示的な「閉じる」と「キャンセル」は使用できます。古いコントロールや閉じる途中のダイアログからコールバックは呼び出されません。

標準フォームに属さない単一行のテキスト、検索、メール、URL、電話番号、パスワード欄で通常のEnterを押すと、`variant: "confirm"` が宣言された最初の利用可能なフッター操作を実行します。作成や保存などの結果は現在の操作記述で決まり、CSSクラスや操作IDだけでは既定の操作になりません。呼び出し側は破壊的な結果に `cancel`、安全な終了に `neutral` を指定する必要があります。標準フォームの送信、ボタン、リンク、テキストエリア、編集可能な内容、選択欄、複合コントロール、修飾キー、IME入力はそれぞれの操作を維持します。無効、非表示、inert、削除済みのコントロールは対象外です。

初期表示とページ切り替え後のフッターには、結果を表す共通クラスを一つだけ持つ標準の `button type="button"` を使用します。「完了」を含む中立の操作はダイアログ固有の外観を維持し、共通の折り返しとタッチ領域のスタイルを利用します。ページはフッターを追加・削除でき、差し替えた本文の操作にも同じコールバックの有効期間が適用されます。チュートリアルの対象、ラベル、完了ID、再実行の動作は変わらず、「次へ」と「戻る」は独自のキーボード操作を維持します。共通ホストダイアログに独立したコンポーネントのバージョンやマニフェストはありません。

メール確認のように、本文に登録された完了コントロールを意図的に隠してプログラムから操作することもできます。キーボードの既定の操作にはならず、有効状態、inert、処理中の操作、ダイアログの有効期間の確認は適用されます。

フォームビルダーで `includeSubmitButton: false` を指定したダイアログは `data-form-submit="external"` を宣言します。その入力欄では作成・保存用のフッター操作を利用でき、検証は引き続き操作のコールバックが担当します。フォームに関連付けられた標準の送信ボタンや画像入力がある場合は、フォーム要素の外側にあってもそちらを優先します。

### チュートリアルのフォーカス委譲

追加の機能 `ui:popupFocus` は、`register(overlay, handlers)`、`delegate(overlay, { signal, surfaces, contains, focus, onRevoke })`、`restore(overlay, preferred)` によりダイアログの所有者を調整します。登録はダイアログの描画処理が担当します。チュートリアルは、現在の手順で明示的に受け入れた操作中のダイアログだけに対して委譲を行います。許可する対象と操作要素、同じ文書に接続された表示領域、フォーカス用のコールバックを指定します。必須の中断シグナル、表示領域の削除、またはダイアログの終了で委譲は解除されます。新しいダイアログは、開くアニメーションの前からフォーカスを排他的に保持します。チュートリアルの終了や再実行では、閉じたページを再び開くことなく通常のキーボード操作に戻ります。`openPopup` のオプションは変更されません。

必須の `onRevoke` コールバックは、フォーカスを戻す前に委譲先のイベントハンドラーを同期的に解除します。

委譲先のコールバックは同期的に実行し、`contains` は真偽値を返す必要があります。例外、不正な判定値、非同期の戻り値、または再帰的なフォーカス操作が発生すると、委譲を解除して安全な診断情報を記録し、通常のフォーカス制御に戻ります。コールバックやログ記録の失敗によって、ダイアログの終了が中断されたり、結果が未確定のまま残ったりすることはありません。

### 言語リストの操作

言語の行、またはタッチ画面ではハンドルを、優先言語リストの希望する位置へドラッグします。移動先の行の中央より上なら前、下なら後に挿入し、表の空き領域では末尾に追加します。英語は代替の優先言語として残ります。変更は保存するまで下書きであり、破棄すると保存済みの順序に戻ります。オフラインでは優先言語の並べ替えのみが可能で、追加や削除はできません。

設定画面の通常のドラッグとタッチ・ペンのハンドルは `src/ui/app/settings/dropzones.js` の `bindListDropzones` を共有します。設定コントローラーはセレクター、操作の可否、ドロップ時の処理を定義し、ヘルパーは移動先の判定、表示、ポインターキャプチャ、キャンセルを管理します。再描画前に `cancel()` で操作を解除し、`dispose()` または渡したシグナルでリスナーを削除します。キャンセル、キャプチャ喪失、Escape、ページ移動、無効な場所へのドロップでは変更しません。操作可否の判定に失敗した場合は、エラーを伝える前に操作を解除します。キャプチャ解除中にキャンセル、コントローラーの破棄、行の置換が発生すると変更を適用しません。設定の言語チュートリアルは利用可能・優先言語の対象を維持し、同じドラッグと保存の手順を説明します。

### メッセージスタイルのプレビュー

外観のメッセージスタイルの下に、架空の会話であることを明示したサンプルが表示されます。受信と送信の例は Messages の表示を使用し、名前と地域に合わせた日付・時刻を示します。スタイルを切り替えると未保存の選択を確認でき、保存すると適用され、破棄すると保存済みの表示に戻ります。外観のガイドには、利用可能な場合だけプレビューの手順が含まれます。サンプルにリンク、プロフィール操作、既読通知、実際の会話データはありません。Messages が利用できなくても、選択と通常の設定保存は使用できます。セクションを再表示しても未保存の選択は維持され、設定を離れると未完了の描画は取り消されます。

メッセージスタイルのプレビューには、準備が整ったバージョン2の表示プロバイダーが必要です。Profile または Messages が利用できないときはサンプルだけを隠し、選択操作と未保存の選択は維持します。プロバイダーが回復すると現在の選択を自動表示します。任意のプレビュー用チュートリアルも同じ表示領域に従います。対応する Settings、Messages 2.8.1、Profile 3.0.19 のアセットを同時に配布してください。

### モジュール操作の結果

有効化と無効化は、変更要求とその後の状態確認が続く間、処理中になります。状態の読み取りで分かるのは現在の観測状態であり、この要求が確定したことの証明ではありません。モジュール画面を離れても送信済みの変更は取り消されず、古い画面が遅れて通知したり新しい画面を書き換えたりすることはありません。アカウントが変わると、待機中の操作と遅れて届いた結果の権限が無効になります。応答が失われた場合は、5秒の期限で状態を1回だけ読み取り、変更を自動で繰り返しません。結果が不明な間は「状態を確認」が操作ボタンの代わりに表示されます。後の読み取りやSPA内の再訪でも、反対の状態が続く間は操作をロックしたままにし、要求した状態を観測してから操作を戻します。任意の設定ガイドや中止されたカタログ更新によって、確認済みの有効化が拒否扱いになることはありません。必須設定を取り消した場合の無効化は1回だけ行います。応答が失われた場合は、正式な読み取りで無効状態が確認できたときだけ無効として照合し、それ以外は結果を不明のままにします。

マーケットプレイスのチュートリアルでは、利用可能な場合だけ「状態を確認」を説明し、結果が不明な間は通常の操作を省略します。既存の所有者と完了の識別子、設定ポップアップとチュートリアルの有効期間は維持されます。モジュール画面はホストのUIに含まれます。

照合によるライフサイクルイベントは observed-state として、応答確認済みの acknowledged-response と区別されます。観測した状態だけでは、この要求が確定した証明にはなりません。APIには永続的な操作結果の記録がなく、不明な状態の管理はSPA内では維持されますが、ブラウザーの完全な再読み込みでは失われます。その後はサーバーの現在の状態だけが取得でき、以前の要求の最終結果は確認できません。

無効化や設定の取り消しを含め、モジュール操作が処理中、または結果が不明な間は、そのモジュールを依存関係の条件として利用できません。繰り返しの操作やSPA内の再訪でも制限を維持し、待機中の有効化は実行開始時に準備状態を再確認し、任意の依存モジュールの選択は繰り返しません。有効状態の観測と設定の完了は別であり、取り消しが拒否された場合も設定は未完了です。設定の保存で設定完了を確認できても、不明な変更結果は解消しません。期待された無効状態を正式な読み取りで確認した場合は、通常の明示的な有効化を行えます。

設定、更新、チャネル変更にも、アカウントに結び付いた同じ処理中・結果確認を適用し、一時的な有効化、無効化、取り消しを含めて管理します。有効化と復元の直前には、選択された依存関係を再確認します。インストール後の復元は、送信の明確な拒否または処理の最終結果を確認した場合に限ります。送信や状態確認の応答が失われたり、処理結果の記録が見つからなかったりした場合は不明のままとし、復元や再試行を行いません。結果を失ったインストールはページのセッション中はロックされます。「状態を確認」でカタログを更新しても処理の完了は証明できません。完全な再読み込みはこのローカルな不確実性の記録を破棄しますが、完了の証明にはなりません。永続的な処理結果の記録や完全な再読み込み後の復旧は利用できません。
