# Cognis UI

接続済みフォームの暗黙的な送信は画面内で処理し、ブラウザーのドキュメント要求を発生させません。コンポーネントの送信処理には引き続きイベントを渡します。内部リダイレクトは SPA ルーターを使います。サーバーで描画するページへの明示的な移動にも未保存の変更確認を適用し、再開時にオフラインでの利用可否を再確認します。

`openPopup({ signal })` はポップアップを所有元の有効期間に結び付けます。シグナルの中断で破棄確認も閉じ、イベント処理、タイマー、フォーム追跡、スクロールロックを解放します。期限切れの画面や識別子に属する内容を残すかどうかは確認しません。同時のキャンセル操作は一つの破棄確認を共有します。

## 構成

- `src/layouts/`: 再利用可能なページレイアウトのガードレール。
- `src/reuse/`: 共有ユーティリティ。
- `public/templates/`: JS からインポートされ、静的アセットとして配信される HTML テンプレート。
- `src/app/`: ページ動作（study アプリ画面、login、docs、admin/settings/modules）。

## UX モデル

ページ（login を除く）はレイアウトモジュール経由で描画し、行/列のガードレールを一貫させつつ、ウィジェットのカスタマイズ性を維持します。

## API 駆動機能

- login は `/api/v1/auth/login` を使用。
- 製品 docs UI は `/api/v1/docs` を読み込み。
- ユーザーページ設定は `/api/v1/social/users/:accountId/preferences/:pageId` を使用。

## 国際化（i18n）

ユーザーに表示されるすべてのテキストは i18n ヘルパー経由で解決し、JS や HTML テンプレートにハードコードしてはいけません。

### 新しい文字列の追加

1. `src/ui/languages/<locale>/strings.xml` の各言語パックにキー/値を追加します。まず `en` から始めます。

    ```xml
    <string name="ui.app.mypage.my_label">My label</string>
    ```

2. 複数ページで使うラベルには `ui.reuse.*` キーを、ページ固有の文言には `ui.app.<page>.*` を使用します。

3. JS では `i18n.t()` で値を取得します。

    ```js
    const i18n = await createI18n();
    element.textContent = i18n.t("ui.app.mypage.my_label");
    ```

4. 静的 HTML テンプレートでは `data-i18n` 属性を追加し、描画後に `applyStaticTranslations(i18n)` を一度呼び出します。

    ```html
    <span data-i18n="ui.app.mypage.my_label"></span>
    ```

    ```js
    applyStaticTranslations(i18n, root);
    ```

    `placeholder` 属性には `data-i18n-placeholder`、`aria-label` 属性には `data-i18n-aria-label` を使用します。

### 対応属性

| 属性                    | 設定先                |
| ----------------------- | --------------------- |
| `data-i18n`             | `element.textContent` |
| `data-i18n-placeholder` | `element.placeholder` |
| `data-i18n-aria-label`  | `element.ariaLabel`   |

### 言語ファイル

言語パックは `src/ui/languages/<iso>/strings.xml` にあります。ランタイムは必要時に読み込み、セッション中はキャッシュします。ユーザーの言語設定は `localStorage` と cookie に保存され、Settings ページで変更できます。

フォールバック順: 優先言語（優先順）→ `en`。

### 検証

`src/ui/tests/hardcoded-strings.test.js` では次の 2 つを検査します。

- **Quoted string literals** — ユーザー向けに見える複数語文字列のシングル/ダブルクオート文字列リテラル（キー参照を除く）を検出します。
- **HTML template text nodes** — テンプレートリテラル内の HTML タグ間テキスト（例: `<th>ID</th>`）を走査し、`i18n.t()` の埋め込みなしで英字を含むケースを検出します。

実行コマンド:

```
node --test src/ui/tests/hardcoded-strings.test.js
```

`src/ui/app` と `src/ui/layouts` にコミットされるコードは、両方の検査を通過する必要があります。

## 詳細設定の編集

詳細設定 → 設定では、サーバー上のユーザープロフィールに保存される一度だけの安全確認に同意すると、UI 設定の全文書を JSON として編集できます。有効な変更は通常の設定システムを通じて保存、適用されます。リリースノートの確認記録は、この文書の妨げにならないよう別に保存されます。

ページのオーバーレイはドキュメントの body に配置し、作業領域の背景フィルターや包含ブロックがビューポート座標に影響しないようにします。描画パッドは表示中のページ内に収まり、スクロール時もドラッグ後の位置を保ちます。

## 管理画面の操作

管理 → コンポーネントでは、状態ラベル、ヘルス表示、電源スイッチが内容に応じた幅を使います。幅の狭い行では名前を操作部の上に配置し、詳細を開く操作部をその横に保ちます。操作部は利用可能な幅に合わせて折り返されます。長い名前、状態ラベル、バージョン情報も読めます。

電源スイッチと詳細を開く操作部には高さ 44 ピクセルの操作領域があります。Tab キーで使用可能なスイッチにフォーカスし、スペースキーで切り替えます。表示中のスライダーにフォーカス枠が付きます。必須ゲートウェイ、ロックされたアダプター、利用できないアダプターのスイッチは無効のままです。コンポーネントのチュートリアルではキーボード操作を説明し、電源、詳細表示、メタデータ、設定の対象は維持します。

セキュリティでは、セッションの有効期間、検証方式、承認スイッチを、表示される翻訳済みの見出しと関連付けます。数値入力は既定のログインセッション有効期間という名前を保ち、「単位」の選択欄にはその文脈と独自の表示ラベルを含めます。情報ボタンは入力ラベルの外に置きます。セキュリティの値は、従来の保存と破棄の手順に従います。

共有スイッチのスタイルは `display: none` を使わず、標準のチェックボックスを操作対象として保ち、表示中のスライダーにフォーカス枠を付けます。これはお知らせにも適用され、既存のラベルとメモリ内の下書きは変わりません。チェック状態と無効状態は標準の入力要素が管理し、コンポーネント行の寸法とスイッチの保護規則は維持します。

セキュリティ、コンポーネント、お知らせのチュートリアルは、手順、対象、進行を保ちます。名前と表示の変更による新しい操作はありません。[W3C のフォームラベルの指針](https://www.w3.org/WAI/tutorials/forms/labels/)と [APG のチェックボックス型スイッチ例](https://www.w3.org/WAI/ARIA/apg/patterns/switch/examples/switch-checkbox/)を参考にしています。レンダラーと CSS のテストは、実ブラウザーのキーボード移動、描画されたフォーカス、スクリーンリーダーの出力、端末互換性を証明するものではありません。

## 共有フォームの見出し

共有フォームビルダーは各項目の見出しと必須マークを一つのテキスト領域にまとめます。狭いフォームではラベルを折り返せます。マークには改行しない空白を使い、独立したグリッド項目にせず本文内に表示します。標準のラベルと入力の関連付け、必須属性、ラベル内のリンク、補足説明ボタンの役割は維持します。`setFieldRequired` はテキスト入力、選択欄、複数行入力、チェックボックス、ラジオボタンで同じ見出しを更新します。
見出しでは内容とマークの間の改行を防ぎ、内側のラベルでは空白のない長い語も含めて折り返しを許可します。

見出しは従来の項目内に残ります。カレンダーと共有のチュートリアルの対象や進行は変わらず、新しい操作や説明手順は不要です。

## パスワードフォームの文言

複数コンポーネントのパスワードフォームは、ホスト XML カタログの `ui.reuse.password_requirements` と `ui.reuse.passwords_match` を使います。Auth と Registration は英語、ドイツ語、インドネシア語、日本語で同じキーを使用します。ホストカタログを Auth 2.2.13 と Registration 1.2.9 に合わせてリリースし、該当文言を使用する連携も共有キーへ移行してください。同じ英語キーへの厳密なフォールバックを維持し、英語の欠落や空の値は明示的なエラーにします。

## コンテキストヘルプ

既存のラベルや見出しの横に `renderInfoTooltip(localizedText, localizedLabel, optionalId)` を使用します。ヘルプ文とボタンのラベルは担当コンポーネントの XML カタログから取得し、説明にはプレーンテキストを使います。この共通ヘルプには独立したコンポーネントバージョンはありません。

情報ボタンにポインターを合わせるかフォーカスすると、ヘルプを読めます。ボタンにフォーカスがある間、またはポインターがボタンかパネル上にある間は表示が続きます。別のヘルプボタンに移るとその説明が選ばれ、離れると、まだフォーカスまたはホバー状態にある説明に戻ります。Escape はフォーカスを移動せず、他の Escape 処理を妨げずにヘルプを閉じます。同じボタンで再び開くには、閉じたときの操作状態をいったん終了します。スクロールとサイズ変更でも従来どおり閉じます。
ポインターが共通パネル上にあるままキーボードのフォーカスで説明を切り替えると、そのホバー操作は新しく表示された説明に引き継がれ、ポインターが離れるかヘルプを閉じるまで続きます。

フォーカスを受け取らないパネルは `role="tooltip"` を使用し、アクティブなボタンは既存の説明を置き換えずにパネル ID を `aria-describedby` に追加します。ボタンを削除するとヘルプも閉じます。文書が変わると古いリスナーと監視処理を解除し、ページを離れると表示中のヘルプを消します。テーマに従う固定配置パネルは従来の配置規則を維持し、透明なポインター領域で隙間をつなぎます。遅延コールバックは使いません。

既存のページチュートリアルのラベル、対象、進行は変わりません。同じ操作部の横でヘルプを利用でき、新しい操作やチュートリアル手順はありません。設計上の参考は [W3C のホバーまたはフォーカス時のコンテンツ](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)と [APG のツールチップパターン](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)です。APG のパターンは作成途中で、タスクフォースの合意には至っていません。DOM イベントのテストは、適合性、実際の表示形状、タッチ操作、支援技術の出力を認証するものではありません。
