# 技術リファレンス

登録の招待 の公開インターフェースと運用規則を説明します。

## インターフェース

createRegistrationAdapter が登録の招待承認を提供し、CLI に invite:token:generate と invite:email:send を追加します。

## 設定

招待は創設者・管理者の発行設定、宛先ドメイン、未処理件数に従います。メールは有効な通知機能を使います。

## 動作

### 登録トークン

アダプターは `registrationUi` で認可スクリプトと言語リソースを宣言します。ゲートウェイは自身とアダプターが有効な間だけこの機能を読み込みます。

必須の登録トークンアダプターは、招待トークンとアカウント作成認可トークンを管理します。有効なメール通知プロバイダーを通じて使い捨てリンクを送信し、ユーザーページで管理者と創設者が招待するときのトークン元になります。

### SSO 承認と招待ポリシー

公開登録が無効な場合、Cognis は認証済みプロバイダー状態を不透明で期限付きの試行 ID の背後に保持し、このアダプター所有のトークンフォームを標準登録シェル内に表示します。「招待メールを送信」は SMTP で招待を送り、単独の登録トークンを「登録トークンを生成」で作成できるのは管理者と所有者だけです。公開登録ではトークン段階を省略します。創設ユーザーが同時に保持できる保留中のメール招待は最大 10 件で、使用済み、取り消し済み、または期限切れの招待は直ちに枠を返します。所有者だけが「管理 → 登録」で創設ユーザーまたは管理者による招待を無効にできます。

### 招待コマンド

管理者と所有者は創設者でなくても `/invite` を開けます。招待の発行には引き続き招待ポリシーが適用されます。有効な登録トークンアダプターは、SMTP で送信しない単独トークン用の `cognisctl invite:token:generate` と、招待メール用の `cognisctl invite:email:send person@example.com` を提供します。メールアドレスの引数を省くと CLI 入力画面が開きます。どちらも認証済みの登録 API を使い、ロール、ドメイン、配信の制限に従います。

`cognisctl invite:token:generate` はメールアドレスの引数を取らず、手動配信を要求します。メールを送信せずに登録リンクを返します。メールアドレスに紐づく招待には `cognisctl invite:email:send person@example.com` を使用してください。返された招待リンクは秘密として扱い、招待する相手だけに共有してください。標準の要約でリンクが省略された場合は `-v` で全体を表示できます。

### 型契約

トークンアダプターには、アカウント登録、存在確認、削除と、構造化データベース実行機能が必要です。テストは、ジェネリックなトランザクションと引き換え失敗後のアカウント削除を含め、これらの契約を直接提供します。トークンの検証と認可ルールは変わりません。

## セキュリティ

招待はメールと現在の方針に結び付きます。外部アカウント保存後に使用済みにし、配信失敗で有効な招待を置き換えません。

## リファレンス

### 技術仕様

公開登録が無効な場合、外部認証が Cognis アカウントを作成するには、セッションに有効なトークンがあり、プロバイダーのメールアドレスが招待先と一致する必要があります。プロバイダーがメールアドレスを返さない場合、アカウントゲートはメール入力が必要であることを報告します。この要求をキャンセルするか認可を省略すると、アカウントを作成せずにログインを中止します。

トークンは外部アカウントの保存後にのみ使用され、一致した招待先アドレスをアカウントの検証済みプライマリメールとして記録します。アカウントまたはメールの保存に失敗した場合、招待は引き続き利用できます。再招待は、新しいメールの送信に成功した後でのみ以前の保留中リンクを置き換えます。
