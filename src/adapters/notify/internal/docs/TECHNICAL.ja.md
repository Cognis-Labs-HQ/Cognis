# 技術リファレンス

アプリ内通知 の公開インターフェースと運用規則を説明します。

## インターフェース

createNotificationSender は現在の保存先を遅延参照します。bootstrapNotifyAdapter が常時配信、認証付き受信箱、ベルを登録します。db:executor があれば DbInternalNotificationStore を初期化し、なければ一時保存の警告を出します。

| メソッド | パス                            | 説明                     | 認証     |
| -------- | ------------------------------- | ------------------------ | -------- |
| `GET`    | `/api/v1/notify/inbox`          | ユーザーの通知一覧を取得 | ユーザー |
| `GET`    | `/api/v1/notify/inbox/count`    | 未読件数を取得           | ユーザー |
| `PUT`    | `/api/v1/notify/inbox/read`     | すべて既読にする         | ユーザー |
| `PUT`    | `/api/v1/notify/inbox/:id/read` | 1件を既読にする          | ユーザー |
| `DELETE` | `/api/v1/notify/inbox/:id`      | 1件の通知を削除する      | ユーザー |
| `DELETE` | `/api/v1/notify/inbox`          | すべての通知を削除する   | ユーザー |

ナビゲーション、スタイル、翻訳、アイコンは起動時に登録する `/static/gateways/notify-internal/` を使います。ベルはこのアダプターの `ui/assets/` に置きます。

## 設定

このアダプターに設定項目はありません。通知ゲートウェイがロードしている限り常に有効です（アダプターは自動検出されるため常時有効）。無効化するにはアダプターディレクトリを削除またはリネームしてください。その場合、通知ベルはUIから消えます。

通知の生成元は、項目を継続表示として指定し、識別子、アクセシブルなラベル、任意の SVG アイコン、操作の結果を含むアクションボタン記述子を提供できます。アダプターはこの汎用契約を検証して描画し、選択された識別子と通知ペイロードを通知します。生成元のドメインを解釈したり、生成元のケイパビリティを呼び出したりしません。

生成元は継続通知を別の UI プロンプトと関連付けられます。汎用 `cognis:notification-resolved` イベントは、生成元をアダプターに認識させることなく、同じ相関識別子を持つ通知をすべて画面と保存先から削除します。

生成元は、ロケールをキーとし `subject` と `body` を持つ `metadata.localizedText` マップを添付できます。内部ブラウザーアダプターは対応する最初のブラウザーロケールを選び、該当しない場合は元のエンベロープ文言を使用します。生成元のドメインは解釈しません。

## 動作

両方の保存先は受信者ごとに五十件を保ち、古いものから削除します。データベースは暗号化し、一定の DATA_ENCRYPTION_KEY で再起動後も読めます。DB がなければ再起動で消え、本番では鍵不足を拒否します。開発用の一時鍵では再起動前の内容を復号できません。アカウント削除で受信箱も消去します。

### 型付き配信契約

内部配信はctxを通じて構造化データベース実行機能を取得します。ログ契約は起動処理で対応している重要度を使用します。暗号化、受信箱の認可、常時有効な配信は変更しません。

### アカウント削除の確認結果

`deprovision-user` → `cleanup-dependencies` では、`system:contracts` を介して `auth:deprovisionOutcome` バージョン 1 を取得し、その実行で使われた元のオブジェクトを `deletedAccount(input, stageResults)` に渡します。削除の確定を示す Auth 所有の確認結果がある場合に限り、対象アカウントの保存済み通知を削除します。コピーした結果、無効化・アーカイブの結果、欠落した確認結果、利用できない確認結果では、この後処理は許可されません。

同梱の Auth 2.2.12、またはこのバージョン付き契約を実装する代替プロバイダーと組み合わせて導入します。変更可能な公開フロー結果で代用することはできません。削除後に再認可するのではなく、確定済みの削除結果に基づいて後処理を行います。開始済みの外部変更は、後続処理が失敗する前に一部が完了する場合があり、コンポーネントをまたぐロールバックは保証されません。通常の画面操作とチュートリアルは変わりません。

この変更で保護されるのは同梱の後処理コンポーネントです。導入環境でアカウント削除を有効にする前に、変更可能な公開フロー結果を依然として信頼する外部の後処理フックを更新するか、無効にしてください。

- 未読通知の件数を示すバッジを表示し、ページ表示中は10秒ごと、非表示中は30秒ごとのポーリングで更新する。

### 受信トレイの状態と復旧

ベルを開くと通知を確認できます。「再試行」は既読化や削除の要求を繰り返さず、受信トレイを再読み込みします。初回の読み込み失敗は、受信トレイが空であることを意味しません。更新に失敗しても、最後に確認できた行、検索結果、未読数を保持します。拒否された変更と確認できない変更は別のメッセージで通知します。確認できない変更は既に完了している可能性があるため、やり直す前に更新してください。変更が確認済みであれば、その後の更新に失敗しても変更結果を表示します。

ナビゲーションバーは公開プロバイダーローダー向けに `mountProvider(scopedUiCtx)` を公開します。アダプターは `request` と `reconcile` の段階を持つ `notify:internal:readInbox` と `notify:internal:mutateInbox` を登録します。有効な受信トレイ応答と現在のルート契約に従う確認応答だけがメモリ内の状態を更新します。最新の有効な読み込みを優先し、処理中の変更は重複操作を防ぎ、古い読み込みを無効にします。通知IDが同じでも、更新ごとに内容、順序、既読状態を反映します。書き込み要求を自動で再送することはありません。

状態と未完了のUI処理は、現在のアカウント、トークン、ページ、プロバイダーの有効期間に限定されます。ログアウト、アカウント変更、ページのマウント、プロバイダーの破棄により古い処理を無効にします。削除された行や閉じられた確認画面から後続操作は実行できません。検索登録、イベントリスナー、タイマー、一時パネルの登録は所有者とともに解除します。ブラウザーに永続的な受信トレイキャッシュは作成しません。

ワークスペースのチュートリアルは引き続き `#notification-toggle` を開き、`.notification-panel` を説明します。共有の一時的な有効期間が終了すると、読み込み中でもパネルを閉じます。空であることを確認済みの受信トレイでは削除を無効にし、取得できない場合は空と表示せず「再試行」を提示します。継続通知の独立したポップアップ、操作、関連付け、有効期限の動作は維持します。

生成元による関連通知の解決は、現在の所有者の有効期間内で重複を除き、順番に実行します。処理中のユーザー操作と最新の読み込みを待ってから一致する通知を削除します。確認できない削除を自動で繰り返すことはありません。

### キーボードで移動

Tab で通知リンクに移動し、Enter でリンク先を開きます。リンク先のない未読通知には「通知を既読にする」ボタン、リンク先のない新着通知には「通知の受信トレイを開く」ボタンがあります。ボタンは Enter とスペースの標準動作に従います。コマンド、削除、閉じる操作は独立したコントロールで、キーボードフォーカスが表示されます。リンクのない新着通知を開いても、受信トレイは閉じません。

修飾キーを押しながらのクリックと中央クリックはブラウザーの標準リンク動作を維持し、現在の受信トレイや既読状態を変更しません。通常の操作は既存の既読確認と移動方針に従います。リンク先が開いても、既読への変更が成功したとは限りません。HTTP と HTTPS のリンク先のみをリンクとして表示します。外部のリンク先は別の閲覧コンテキストで開き、開いたウィンドウへのアクセスを遮断し、参照元情報を送信しません。

キャンセル可能な `cognis:notification-action` イベントは、通常のリンク操作と修飾キー付き操作に適用されます。所有コンポーネントは受信トレイの変更を待つ前に通常のクリックを同期的に処理するため、公開ルーターが二重に移動することはありません。処理中または利用できない行では、更新に成功するまでリンク先を取り除きます。無効になったコントロールは操作を受け付けません。ワークスペースのガイドはベルとパネルの対象を維持し、リンク、既読ボタン、キーボード操作、読み込みだけを行う再試行を説明します。継続通知のコマンド、有効期限、関連付けの有効期間は維持します。

### スタイルシートの復旧

プロバイダーは共有するスタイルシートの読み込みを最大5秒間待ちます。読み込みイベントを受け取るか、読み込み済みのシートがあれば、スタイルを適用して表示できます。エラーや時間切れはスタイルが利用できない結果であり、読み込み成功ではありません。この場合もベルと受信トレイを表示し、レイアウトが不完全な可能性を翻訳済みのエラートーストで知らせます。受信トレイの「再試行」は通知データのみを再取得します。アプリを開き直してプロバイダーが新たにマウントされると、スタイルシートを再試行できます。現在のマウントでは自動的に繰り返しません。

ブラウザーの各リンク要素は、待機中、読み込み済み、失敗、時間切れの状態を保持し、直接配信コードとバンドル済みコードで共有します。個々の待機側を中止してもリソースのイベント監視と期限は継続し、結果が確定すると解放されます。プロバイダーの中止は自身の待機だけを終了し、他の待機側に有用なリクエストを削除しません。中止されたプロバイダーが後からベルを作成したり、受信トレイを取得したり、失敗通知を表示したりすることはありません。終了時には自身のスタイルシートエラートーストを閉じます。

正常な外部リンクと属性は保持します。プロバイダーが作成したリンクは失敗や時間切れで削除します。既存リンクの所有権は元のローダーに残り、シートが読み込まれるまでは後続の試行で使用しません。次の有効なマウントで作成する代替リンクは最大1つで、同時マウントはその期限を共有します。終了済みの試行から遅れて届くイベントは代替リンクの結果を確定できません。ページのスタイルシート所有権を示す属性は追加しないため、ルートのスタイル切り替えがこのリソースの所有権を取得することはありません。ベル、受信トレイ、到着通知の寿命は、引き続きスコープ付きctxが管理します。

既存のワークスペースガイドは、表示が不完全なマウント後や復旧後も `#notification-toggle` と `.notification-panel` を対象にします。操作と進行は変わらず、別のチュートリアルは不要です。リソースの復旧は通知の生成元、カテゴリー、配信方針、到着通知の抑制を変更しません。

## セキュリティ

通知ルートは受信者を認証し、そのアカウントの記録を操作します。永続化には DATA_ENCRYPTION_KEY が必要で、一定の秘密鍵として管理します。
