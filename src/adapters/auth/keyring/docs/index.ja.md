# ユーザーキーリングアダプター

設定は登録済みの読み込み・表示フローで `keyring:readState` を実行してから保管庫の状態を表示します。最初は読み込み中を表示し、メタデータの取得不能と保管庫の未作成を区別します。再試行で保管庫を作成したりパスワードを求めたりしません。バンドル版と直接読み込み版は一つのプロバイダーを共有します。画面遷移、識別子の変更、ロック時には機密性のあるポップアップとイベント処理を破棄します。

保管庫のPUT要求はAPIの共通JSONストリーム読み取り処理を使い、有効な保管庫容量と追加の1 KiBを上限にします。ポリシー、413エラー、直列化済みデータの検査はアダプターが引き続き担当し、別のバッファ処理は維持しません。

保管庫の標準容量は2 MiBで、プロセス内処理の絶対上限は8 MiBです。有効なポリシーをクライアントに返します。PUTはバッファリングやJSON解析の前に受信バイト数を数え、過大なリクエストを拒否します。GETは解析前に保存サイズを確認します。暗号化済みのデータは基本行とサイズ制限付きの追加行に保存し、置換と削除をアトミックに行い、結合した単一のクエリで読み取ります。各行はUTF-8最大60,000バイトで、サーバーは引き続き秘密情報を復号しません。

## 概要

ユーザーキーリングアダプターは、ブラウザーで暗号化された不透明な保管庫を認証済みアカウント向けに永続化します。ログインプロバイダーにかかわらず、パスワード、暗号鍵、その他のユーザー固有の秘密情報を単一の安定したケイパビリティで扱うための必須認証アダプターです。

ブラウザー側の標準インターフェースは `src/adapters/auth/keyring/ui/keyring.js` のままです。暗号化と復号はブラウザー内で行われ、アダプターが平文の秘密情報を受け取ることはありません。

## 責務

- `db:executor` ケイパビリティを通じて保管庫ストアを初期化する。
- `ctx` を通じてルートファクトリーと保管庫ストアのケイパビリティを提供する。
- 検証済みの不透明な保管庫エンベロープを保存し返却する。

責務外: ユーザー認証、暗号鍵の導出、保存された秘密情報の解釈。

## アーキテクチャ

`src/adapters/auth/keyring/index.ts` は認証ゲートウェイによって自動検出され、`auth:keyringVaultStore` と `auth:keyringRouteFactory` を提供します。ゲートウェイがルートコンテキストをファクトリーへ渡すため、認証検査は注入されたままです。`src/adapters/auth/keyring/store.ts` はデータベース実行ケイパビリティのみを通じて永続化へアクセスします。

## 設定

この必須アダプターは有効な `db:executor` を使用します。管理者はアダプター設定で、暗号化保管庫の最大サイズを MiB 単位で指定し、パスワード導出の反復回数を設定します。既存の保管庫は記録済みの導出回数を保持し、設定値は保管庫の作成時に適用されます。暗号化保管庫の既定容量は 2 MiB です。

## API ルート

| メソッド | パス                   | 説明                             | 認証     |
| -------- | ---------------------- | -------------------------------- | -------- |
| GET      | `/api/v1/auth/keyring` | アカウントの暗号化保管庫を読む。 | ユーザー |
| PUT      | `/api/v1/auth/keyring` | 暗号化保管庫を置き換える。       | ユーザー |
| DELETE   | `/api/v1/auth/keyring` | 暗号化保管庫を削除する。         | ユーザー |

## ブラウザー Capability API

コンポーネントはアダプター内部を直接インポートせず、`uiCtx.capabilities` からキーリング操作を取得します。`keyring:forComponent` で帰属先付きスコープを作成し、Capability が所有する安定した識別子で秘密情報を解決します。解決処理は既存値を検証し、欠落または無効な場合は利用者への入力要求や信頼できる情報源への照会を行えます。ロック状態、項目管理、パスワード変更、操作履歴のページング、一時ゲストキーリングのライフサイクルも Capability として公開されます。

```js
const keyring = uiCtx.capabilities.require("keyring:forComponent")("Meetings");
const password = await keyring.resolve("meeting:123:password", {
    action: "join",
    process: "meeting 123",
    validate: (value) => value.length > 0,
    prompt: ({ invalid }) => askForPassword(invalid),
});
```

## ログイン時のロック解除動作

ログイン時、アダプターは既存の保管庫をアカウントパスワードで復号できるかだけを試します。失敗した場合は保管庫をロックしたままにし、ロック解除ダイアログを開かず、ダッシュボードへの移動も妨げません。コンテキスト付きのロック解除ダイアログは、コンポーネントがキーリング保護されたコンテンツを解決するときにのみ要求されます。

## アカウントのプライバシーとキーリングの分離

同じ認証済みタブとセッションでは、再読み込み後も解錠を維持します。保管庫は引き続きパスワードで暗号化し、パスワードや平文の復号鍵は保存しません。セッションストレージには、現在のセッション秘密値から HKDF で導出した鍵で AES-GCM 暗号化した解錠情報だけを保存し、オリジン、アカウント、サーバーのアカウントインスタンス、セッションに結び付けます。復元前にサーバーによる確認が必要です。有効な自動ロック期限は認証され、再読み込みで延長しません。明示的なロック、ログアウト、アカウント・インスタンス・セッションの変更、期限切れで復元を無効にします。タブを閉じるか新しいセッションを始めると再解錠が必要です。旧式の平文 IndexedDB キャッシュは引き続き無効です。

## アクセスのキャンセルと手動復旧

帰属情報付きの解除要求をキャンセルすると、同時に待機している要求をすべて拒否し、ページを再読み込みするまで後続の自動要求を抑止します。アダプターは `{ suppressed: true }` を含む `cognis:keyring-access-state` を送信し、暗号化コンテンツの Poller はこの状態で停止します。Page Composer のトグル列上部に表示されるフローティングロック操作だけが手動解除を試行でき、認証成功後に抑止を解除して `{ suppressed: false }` を送信します。

## 破壊的リセット

`DELETE /api/v1/auth/keyring` は破壊的リセットの契約です。不透明な保管庫を削除する前に、Authentication は `auth:registerKeyringDataOwner` で登録された各所有者を呼び出し、暗号化ルームなどキーリング項目に依存するオブジェクトだけからアカウントを削除します。アカウントインスタンス、プロフィール、フォロワー関係、依存しないアカウント所有データは変更しません。ロック中の Settings 操作はこのルートを使用した後、すべてのキーリング操作を「キーリングが見つかりません」バナーと作成操作だけに置き換えます。作成時にはパスワード確認と自動ロック時間を指定します。解除中の操作は現在の保管庫内の項目だけを削除します。

## 履歴の増加からの復旧

暗号化された保管庫は、64 KiB以内で最大1,000件の最新の操作履歴を保持します。この制限のために秘密情報を削除することはありません。繰り返しの読み取りは進行中の保存処理を共有します。認証済みのGETは、書き込み上限が低い場合でも既存の保管庫を絶対上限の8 MiBまで取得でき、クライアントが履歴を縮小できます。PUTには設定された上限が引き続き適用されます。バックグラウンド同期の失敗時にはエラートーストを表示し、暗号化されたローカルコピーを保持します。
