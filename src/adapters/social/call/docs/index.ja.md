# 通話シグナリング

Call アダプターは、ルーム単位の通話招待、呼び出し、応答、終了、タイムアウト、ブラウザープロバイダーへの引き渡しを所有します。Messages は `social:callUi` ケイパビリティだけを利用します。

通話はスレッドヘッダーを残し、チャット履歴とメッセージ入力欄を置き換える呼び出し画面から始まります。受信者には、応答操作で通話トークン付きのルームを開く継続的な Calls 通知が届きます。未応答の通話は 45 秒後に期限切れになります。応答後、アダプターは `phase: connect` で `voip:startCall` を呼び出し、プロバイダーはコンポーネントまたはナビゲーションアクションを返します。埋め込みミーティングの操作は Call ツールバーと分離され、その矢印でミーティングをピクチャーインピクチャーへ移動して Messages を復元します。

## 使用例

Call アダプターは、Messages と `voip:startCall` ブラウザプロバイダーが利用可能な場合に自動的に有効になります。

## 技術仕様

`social:callUi` ケイパビリティは、招待状態、45 秒のタイムアウト、通知の応答リンク、コンポーネントのマウント、通話終了、プロバイダーへの引き渡しを管理します。

着信は通知ベルの一覧には追加されません。応答、拒否、または期限切れになるまで短時間通知の領域に表示され続け、緑の応答操作と赤の拒否操作を提供します。Messages を開いている間、対象ルームは一時的にルーム一覧の先頭へ移動します。発信者には、キャンセル、受信者の拒否、未応答、Meeting プロバイダーによる引き渡し拒否を区別したフィードバックが表示されます。

各通話の状態変化は Messages のルーム履歴にルームイベントとして保存されるため、すべての参加者が発信、応答、キャンセル、拒否したユーザーと未応答になった通話を確認できます。ブラウザーは、招待が応答、拒否、キャンセル、または期限切れになるまで、着信と発信で異なる合成呼び出し音を繰り返し再生します。

最新の招待が呼び出し中の間、そのルームイベントは操作可能な通話カードになります。受信者は会話内で応答または拒否でき、発信者には呼び出し状態が表示されます。通話状態が変化するか新しい通話が始まると、履歴項目は操作のない通常イベントになります。着信プロンプトはシェル起動時に保存済み通知から復元され、呼び出し音にはより強い反復パルスが使われます。

応答済みコンポーネントのピクチャーインピクチャー移動は冪等です。矢印を再度操作してもフローティングウィンドウは再作成またはリサイズされません。最初の操作で矢印とインライン領域を隠し、会話を復元して再描画し、コンポーネントが閉じるまでカメラ操作を無効化します。アクティブな通話カードには塗りつぶし背景とアニメーション枠を使い、終了済みイベントには応答・拒否操作を残しません。

通話コンポーネントをピクチャーインピクチャーへ移動すると、永続的なドキュメントシェルへ移され、呼び出し元ページの中断や SPA ルートのクリーンアップ後も維持されます。明示的にコンポーネントを閉じた場合は完全なクリーンアップを行い、元のホストが接続中なら復元します。

保持された PiP ポータルは、安定した要素 ID を含むブローカー所有のコンポーネントステージをウィンドウの親として維持します。Jitsi などのプロバイダーは、参加者の退出、キック、または会議終了時に親ステージを解決し、ホストの `component-pages:discard` ケイパビリティを呼び出せます。破棄後は一時的な通話ステージも削除されます。

ルームの通話操作を表示する前に、Call UI は認証済みルーム状態エンドポイントを照会します。アクティブな通話ではカメラ操作がアクティブになり、クリックすると既存のプロバイダー Meeting へ直ちに再接続します。呼び出し中の通話は新しい招待を作成せず再利用し、発信者は待機を再開し、他の参加者は既存通話へ応答します。サーバーも作成直前に同じ確認を行い、競合時の招待の交差を防ぎます。
