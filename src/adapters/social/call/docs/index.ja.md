# 通話シグナリング

Call アダプターは、ルーム単位の通話招待、呼び出し、応答、終了、タイムアウト、ブラウザープロバイダーへの引き渡しを所有します。Messages は `social:callUi` ケイパビリティだけを利用します。

通話はスレッドヘッダーを残し、チャット履歴とメッセージ入力欄を置き換える呼び出し画面から始まります。受信者には、応答操作で通話トークン付きのルームを開く継続的な Calls 通知が届きます。未応答の通話は 45 秒後に期限切れになります。応答後、アダプターは `phase: connect` で `voip:startCall` を呼び出し、プロバイダーはコンポーネントまたはナビゲーションアクションを返します。埋め込みミーティングの操作は Call ツールバーと分離され、その矢印でミーティングをピクチャーインピクチャーへ移動して Messages を復元します。

## 使用例

Call アダプターは、Messages と `voip:startCall` ブラウザプロバイダーが利用可能な場合に自動的に有効になります。

## 技術仕様

`social:callUi` ケイパビリティは、招待状態、45 秒のタイムアウト、通知の応答リンク、コンポーネントのマウント、通話終了、プロバイダーへの引き渡しを管理します。

着信は通知ベルの一覧には追加されません。応答、拒否、または期限切れになるまで短時間通知の領域に表示され続け、緑の応答操作と赤の拒否操作を提供します。Messages を開いている間、対象ルームは一時的にルーム一覧の先頭へ移動します。発信者には、キャンセル、受信者の拒否、未応答、Meeting プロバイダーによる引き渡し拒否を区別したフィードバックが表示されます。

各通話の状態変化は Messages のルーム履歴にルームイベントとして保存されるため、すべての参加者が発信、応答、キャンセル、拒否したユーザーと未応答になった通話を確認できます。ブラウザーは、招待が応答、拒否、キャンセル、または期限切れになるまで、着信と発信で異なる合成呼び出し音を繰り返し再生します。
