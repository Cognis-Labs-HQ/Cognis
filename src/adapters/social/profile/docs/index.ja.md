# プロフィールゲートウェイ

## 概要

プロフィールゲートウェイは、ユーザープロフィール、ソーシャルグラフ、投稿、アバター・バナーアップロード用のファイル管理を所有します。各Cognisアカウントに公開されたアイデンティティとコミュニティグラフ内での位置を提供します。このゲートウェイを削除すると、コア、認証、他のゲートウェイに影響を与えることなく、すべてのプロフィール、ソーシャル、投稿、ファイル機能がプラットフォームから削除されます。

## 責務

- `account_profiles`、`account_follows`、`account_blocks`、`posts` データベーステーブルを所有・初期化する。
- すべてのプロフィールとソーシャルエンドポイントでアカウントレベルと投稿レベルの公開設定を強制する。
- ソーシャルグラフを管理する: フォロー、アンフォロー、ブロック、ブロック解除、フォロワー/フォロー中リスト。
- `file:gateway` ケイパビリティを通じてアバターとバナーのアップロードを管理する。
- `profile:createProfile`、`profile:setRoleByHandle`、`preferences:store` をケイパビリティストアに提供する。

## アーキテクチャ

### 公開設定モデル

| 段階                   | プロフィール閲覧可能な対象 | 投稿・カウントの閲覧可能な対象 |
| ---------------------- | -------------------------- | ------------------------------ |
| `hidden`（デフォルト） | 自分と管理者のみ           | — （投稿は403を返す）          |
| `private`              | 既存のフォロワーのみ       | フォロワーのみ                 |
| `friends`              | 認証済みユーザー全員       | フォロワーのみ                 |
| `community`            | 認証済みユーザー全員       | 認証済みユーザー全員           |

### 主要なソース

| パス                                     | 目的                                           |
| ---------------------------------------- | ---------------------------------------------- |
| `src/gateways/profile/bootstrap.ts`      | ブートストラップエントリポイント               |
| `src/gateways/profile/routes/social.ts`  | フォロー、ブロック、フォロワーのルート         |
| `src/gateways/profile/routes/posts.ts`   | 投稿の作成、一覧表示、削除                     |
| `src/adapters/db/reuse/profile-store.ts` | `DbProfileStore` — すべてのプロフィールSQL操作 |

## プロフィールの即時更新

保存したプロフィール情報はすぐに表示されます。フォロワー数、フォロー数、および各ユーザーカードは自動的に更新されます。プロフィール画像では、一度に1件の選択またはアップロードだけを受け付けます。

フォローの変更とバナー高さの選択は、バックグラウンド同期の完了を待たずに即時反映されます。

メッセージ操作のフィードバックはプロフィール所有の言語資源から読み込まれるため、プロフィール表示はメッセージアダプターの有効状態に依存しません。

## 空き状況

プロフィールメニューには現在の空き状況が表示され、ログイン中のユーザーは「空き」「取り込み中」「仮予定」から選択できます。アバターのステータス表示にポインターを合わせると、判定された状態がツールチップに表示されます。他のコンポーネントは、ctx の `social:getUserAvailability` ケイパビリティを通じて、アカウント ID からカレンダーを考慮したユーザー状態を照会できます。

## 提供する UI ケイパビリティ

独立したプロフィールプロバイダーは `ui:profileAvatarRenderer` を提供します。プロフィール画像を描画するモジュールは、この ID を `requiresCapabilities` で宣言する必要があり、Cognis は SPA ルートのマウント前にプロバイダーを読み込みます。

### ブラウザークライアント機能

`social:profileUiClient` は依存ページのマウント前に独立したプロフィールプロバイダーが提供し、ブラウザーモジュールが所有アダプターのクライアント経由でプロフィールデータを取得できる `getCurrentProfile()` を公開します。

## 外部プロフィールの公開範囲

`profile:applyExternalProfile` は `profileVisibility` として `hidden`、`private`、`friends`、`community` を受け付けます。有効な値はプロフィール作成または同期後の公開範囲として保存され、不明な値は無視されます。

## 検索エラーを出さずに不明な在席状態を返す

在席状態の GET は、存在しないプロフィールとプライバシーで制限されたプロフィールのどちらにも成功応答で unknown を返します。応答の形を揃え、手動設定やカレンダーの状態は読みません。所有者、ブロック、コミュニティ、友達、非公開の既存ルールを維持し、変更は引き続き所有者だけが行えます。アバターの表示は不明となり、見つからないエラーを繰り返しません。

## オフラインのソーシャル変更

Profile と Messages のプロバイダーは ctx 経由で有効期間に対応した HTTP 操作を登録します。検証済みのタブでは、読み込み済みのプロフィール・投稿・ルーム一覧・暗号化された履歴を利用できます。プロフィール文、在席状態、フォロー・ブロック状態、バナー配置、投稿の作成・削除、既存ルームの暗号化メッセージ、リアクションの最終状態、既読通知をアカウント別に送信待ちとして保存します。後のオンライン編集も同じ所有者の保留項目を待ちます。準備中やキューの待機中にアカウントやセッションが変わると操作を中止します。メッセージと投稿は安定した `operationId` UUID を使い、内容の相違や他のアカウントからの再送を拒否します。メッセージの再送で通知は重複しません。既読通知は元の閲覧時刻を維持します。

チャットは保存前に暗号化し、平文・ルームキー・認証情報をキューに追加しません。プロフィール文と投稿内容は現在のアカウントのブラウザーストレージに保存します。最大 350,000 バイトのアバター・バナーは既存の 1 MB・1,000 件・7 日間のキューを共有します。大きな画像には接続が必要です。容量不足では翻訳済みのエラーを表示し、メッセージと投稿の下書きは永続保存に成功した後にのみ消去します。制限は各コンポーネント単位ではなくキュー全体に適用します。

変更はサーバー確認まで保留します。メッセージには送信待ち状態を表示し、プロフィール・投稿・メディアには標準の送信待ちトーストを使います。現在のアカウントに保留項目があれば、無効なプロバイダーの項目を含め、閉じる操作や再読み込みでブラウザー標準の未保存変更の確認を表示します。確認済みまたはアカウントの消去後に警告は解除されます。文言や事前のユーザー操作の要否はブラウザーが決めます。保留項目は再読み込み後も残り、警告によって破棄されることはありません。

ソーシャルのキャッシュはタブ内のみで、同意が必要です。初回訪問、非公開ページのオフライン再読み込み、ルーム作成、メンバー・キーの管理、通話、大容量アップロードには接続が必要です。入力中状態や一時的な在席通知は再送しません。送信時には現在のサーバー認可を確認し、切断中のキャッシュでは遠隔の権限取り消しを知ることはできません。アクセスと再送の前に ToS への同意が引き続き必要です。

## プロフィールの初期化

プロフィールの在席処理は、送信待ち対応クライアントの登録とアバターのスタイル読み込みが完了してからプロバイダーのマウントで開始します。インポートだけでは在席コールバックやポーリングを開始しません。無効化やマウント失敗では購読・ページリスナー・タイマー・在席キャッシュを解除し、古い非同期処理が後のプロバイダーを更新しないようにします。これによりオンラインの管理ページ初期化中の `profile_client_unavailable` を防ぎます。

## 公開プロフィール名

公開 SSO プロフィール名には認証元の名前空間を含めません。既存の認証元付き名称はプロフィール初期化時に置き換え、重複時はランダムな接尾辞を付けます。すでに認証元を含まない名称は維持します。アカウント ID、ID の対応付け、投稿、関係は変更しません。名称変更に伴い公開プロフィールの URL は変わります。認証元の情報、メール、ログイン履歴は管理者専用のユーザー一覧に表示します。アカウントごとの開閉式詳細は共通スタイルを使い、開く際に認可済み情報を取得します。

## アカウントのプライバシーとキーリングの分離

SSO アカウントにはプロバイダーを示さないランダムな ID を使用します。プロバイダー ID は別に保存し、管理者だけに表示します。公開ユーザー名には含めません。Auth はプロフィールやメールの変更前にユーザー名を確保します。同じプロバイダー内の重複名は拒否し、別プロバイダーとの重複には短いランダムな接尾辞を付けます。ユーザー一覧と操作 API は公開用の `username` と内部用の `accountId` を区別します。

従来の SSO レコードが存在していても、既存のローカルアカウントは引き続き使用できます。起動時にデータベースのリセットは必要ありません。従来の SSO アカウントのログインと作成処理だけを個別に拒否し、不透明な ID での再作成を必要とします。アカウント ID、関係、会議の自動移行や自動削除は行いません。

## 突然の接続断

オフラインモードに入ると一時的なプレゼンスと在席情報の定期取得を停止し、復旧後に再開します。手動の在席状態変更は引き続き既存のオフラインバッファーを使用します。

## 保存済みキューの結果

キュー内のプロフィール文章、投稿、サイズ制限内の画像アップロードは、表示更新の失敗でも完了結果を維持します。文章の更新にはオンラインではサーバー応答を、オフラインでは明示的な保留表示を使います。送信失敗時は下書きを保持し、後続の表示更新失敗で重複送信を促しません。

## オフライン作業環境

オフラインのプロフィール表示には、自分のテキスト、投稿、つながり、設定、上限内のアバターとバナー画像を含む完全な準備済みスナップショットが必要です。他のユーザーのプロフィールは以前にキャッシュしていても表示できません。

## 確認済み設定のスナップショット

Profileの設定保存が成功すると、再送時やオンライン専用の保存時も、次の読み込み前にプロバイダー所有の容量制限付きスナップショットを更新します。オフラインでの設定統合は確認済みの項目を保持し、残りの保留変更を反映します。遅延した読み込みは新しい確認済みデータを上書きせず、アカウント変更、プロバイダー終了、保存失敗によって古いデータが公開されることもありません。

## プロフィール編集とロール

プロフィール編集は、表示名、自己紹介、所在地、ウェブサイトについて、そのコンポーネントが定める上限を使用します。ロール同期は不変のアカウントIDから公開プロフィール名を解決し、ロールと公開範囲を更新します。

`profile:setRole(accountId, role)` → `Promise<void>`.

## ストレージとルートの型

プロフィールのロールと公開範囲の型を保存済みレコードに合わせ、モデレーターと非公開・友達・コミュニティの公開範囲を含めます。設定の読み取りは保存済み JSON テキストを返します。永続化テストはロールバックに対応するプロフィール所有の構造化データベース代替実装を使います。

## 認証情報の適用範囲

アカウント操作には検証済みのアカウントセッションが必要です。共有リソースの操作ではゲスト認証情報を明示的に検証し、リソースの権限を適用する前に現在の共有許可を再確認します。アカウント名から認証情報の種類を判断しません。取り消されたアクセスや有効期限切れのアクセスは拒否されます。

## アカウント削除の確認結果

`deprovision-user` → `cleanup-dependencies` では、`system:contracts` を介して `auth:deprovisionOutcome` バージョン 1 を取得し、その実行で使われた元のオブジェクトを `deletedAccount(input, stageResults)` に渡します。削除の確定を示す Auth 所有の確認結果がある場合に限り、対象アカウントのプロフィール、ソーシャル関連データ、設定を削除します。コピーした結果、無効化・アーカイブの結果、欠落した確認結果、利用できない確認結果では、この後処理は許可されません。

同梱の Auth 2.2.12、またはこのバージョン付き契約を実装する代替プロバイダーと組み合わせて導入します。変更可能な公開フロー結果で代用することはできません。削除後に再認可するのではなく、確定済みの削除結果に基づいて後処理を行います。開始済みの外部変更は、後続処理が失敗する前に一部が完了する場合があり、コンポーネントをまたぐロールバックは保証されません。通常の画面操作とチュートリアルは変わりません。

この変更で保護されるのは同梱の後処理コンポーネントです。導入環境でアカウント削除を有効にする前に、変更可能な公開フロー結果を依然として信頼する外部の後処理フックを更新するか、無効にしてください。

## プロフィール編集の再試行

プロフィール編集は、サーバーが保存を確認するか、アカウントに紐づくオフラインバッファーが永続的に受け付けるまで、入力内容をそのまま保持して開いたままになります。要求の拒否、応答の読み取り失敗、バッファーへの書き込み失敗ではエラーを表示し、下書きを破棄せずに保存を再び有効にします。保存の連続クリックや Enter でも処理中の要求は一件だけです。処理中は入力欄を一時的に無効にします。カード、ナビゲーション、ローカル表示名の更新に失敗しても、受け付け済みの保存を失敗とは扱いません。

破棄、閉じる、Escape、背景のクリックでは、共通の未保存変更確認を使用します。確認画面でキャンセルするとフォームを保持します。破棄を確認すると閉じ、遅れて返る結果を無視します。送信済みの要求は閉じても取り消せないことを通知で伝えます。保存結果は、開いている破棄確認の決定を待ってから画面に反映します。ページ移動、再マウント、アカウントやセッションの切り替え、ダイアログの破棄により、以前の編集結果は画面に反映されなくなります。再度開くと最後に受け付けられたプロフィールを使い、以前のダイアログの終了アニメーション中でも入力欄とラベルの識別子は重複しません。未送信の下書きはページ移動や再読み込みを越えて保存されません。

プロフィール所有のエディターは既存の `social:profile:request` ctx フローを使用し、フィールド検証、共通ポップアップのフォーカス管理、オフライン配信ポリシーを維持します。合成 DOM テストでは実際のページマウント、ポップアップ、フォームビルダー、登録済み要求フローを、制御された通信とストレージで実行します。実ブラウザーのレイアウトやサーバー・データベースの動作を確認するものではありません。

## 画像読み込みの回復

ナビゲーションバーとプロフィールのプレビューでは、無関係な更新時も変更のない画像を維持します。一時的なネットワーク障害や HTTP 408、425、429、5xx は画像キーを恒久的に無効化しません。次の明示的な更新または表示時に再試行でき、自動再試行タイマーはありません。削除の確認（404/410）、アクセス拒否（401/403）、明示的な無効化、アカウントやトークンの変更、プロバイダーの削除により対応する画像を除去します。プロフィールページのメイン画像は別の利用箇所で、この回復契約の変更対象ではありません。

独立したプロバイダーは有効期間中 `ui:profileAvatarRenderer` を所有します。`fetch(key)` は引き続き URL または null を返します。`hydrate(container, { signal })` は任意のキャンセルを受け付け、`invalidate(key)` は指定キーを消去します（省略時はすべて）。キャッシュはアカウント、アクセストークン、プロバイダーの有効期間に限定され、同時読み込みを統合し、最大128キーを保持します。成功した結果と確認済みの否定結果は、60秒後から必要時に再検証します。内容のダイジェストにより同じバイト列では URL を維持し、内容が変わった場合は新しい URL にします。追い出し、無効化、終了時に所有するオブジェクト URL を解放します。切り離された要素は保持しません。

ナビゲーション用プロバイダーは `avatarState`（`available`、`missing`、`denied`、`retryable`、`invalid`、`stale`）、任意の `avatarKey`、成功時のみ `avatarBlobUrl` を返します。`onAvatarError` はその URL を破棄し、`signal` はプロバイダーの終了を通知します。明示的に再試行可能な結果に限り、同じアカウント、トークン、プロバイダーの画像を、キーが不変または未確定の場合に維持できます。不明または欠落した状態では画像を許可せず、不確かな認可を成功と扱いません。このホスト側の変更と Profile 3.0.19 は同時に配布してください。新しいホストと古いプロバイダーの組み合わせでは、対応するプロバイダーが利用可能になるまでイニシャルを表示します。

プロフィール情報のチュートリアルはプロフィールへのリンクとプレビューを引き続き説明します。操作対象、進行、完了識別子は変更しません。

レンダラーは依存する表示プロバイダー向けに正確な準備状態 `available` も公開し、マウント時と失効時に自身の `cognis:profile-avatar-renderer-changed` を通知します。スコープの中止時には、機能の登録を削除する前にこの値が偽になります。初期化の失敗と再有効化でも同じ通知経路を使います。登録されていることだけで準備完了と判断してはいけません。
