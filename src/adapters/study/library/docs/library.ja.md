# ライブラリアダプター

## 利用側定義のスキーマ

ライブラリアダプターは関係付けられた汎用学習データを保存します。利用側は ctx capability `study:library` を通じて、不変かつバージョン付きのスキーマを登録します。スキーマが言語、レイヤー、型付きフィールド、方向付き関係を定義し、アルファベット、単語、文などの名称をアダプターに固定しません。

関係は対象レイヤー、多重度、順序、任意のリゾルバーを宣言します。すべての書き込みでフィールド、スキーマバージョン、対象、可視性、多重度を検証します。別定義も利用側が宣言する通常のレイヤーと関係で表現します。

## 解決、API、UI

`grapheme` リゾルバーは Unicode 書記素を、`longest-match` は明示的に区切られたブロックを使用します。どちらも項目を暗黙に作成せず、候補と未解決単位を返します。lookup プロバイダーは `registerLookupProvider` で追加し、出典付きの順位候補を返し、登録時の callback で解除できます。作成、解決、lookup は名前付き ctx flow に参加します。

Study ゲートウェイはスキーマ検出、一覧、作成、詳細、双方向追跡、解決プレビュー、lookup 候補を提供します。スキーマ駆動 UI は、内部用の定義レイヤーと助詞レイヤーを直接閲覧の対象から除外します。閲覧可能なレイヤーでは、タブ、メタデータ絞り込み、項目カード、メタデータのピル、範囲アイコンを使用します。再利用可能なポップアップ詳細は、大きくした項目見出しの下に定義と意味を表示します。文の助詞を含む認識済みの構成要素は、独立したコンポーネント区画ではなく、その見出し内の移動可能なサブボックスとして表示し、助詞の詳細は読み取り専用のままです。絞り込み選択欄は共通テーマのスタイルを使用し、選択を即時適用します。グローバル、利用者、クラスの権限はサービス境界で引き続き強制します。

## 宣言的コンテンツパック

導入済み言語パックは、検証に `inspectContentPack(root)`、データ専用ライブラリの導入に `ingestContentPack(root)` を呼びます。ルートには `manifest.json`、参照スキーマ、レイヤー ID のサブディレクトリを持つコンテンツディレクトリを置きます。ファイルは安定 ID と明示的関係を持つレコード配列です。Cognis はグラフ全体を検証し、名前空間 ID、digest、receipt を記録して、スキーマ、項目、edge を原子的に保存します。完全な作成契約は `study-language-framework.ja.md` にあります。

## ローカライズされた定義

意味役割が `definition` の各レイヤーは、モジュール所有の文字列キープレフィックスと、文字列キーおよびローカライズ済みテキストのフィールドを宣言します。定義は、それを必要とする項目の編集時にのみ管理し、独立したライブラリ区画として直接閲覧または編集できません。英語は引き続き必須の原文であり、生成キーは定義レコードに保持され、未入力言語は任意の `localization:translateString` ケイパビリティで補完できます。
