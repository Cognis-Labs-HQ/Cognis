# ライブラリアダプター

## 拡張可能なブラウザー操作

Libraryプロバイダーはライフサイクルに紐づくctxから`study:library:client`を公開します。すべてのゲートウェイクライアント操作は`study:library:<clientFunction>`の`before`、`execute`、`after`を通ります。例えば`study:library:createLibraryEntry`の`before`を拡張すると、`input.args`（クライアント関数の位置引数）を確認・変更でき、エラーを送出するとリクエスト前に拒否できます。`after`は`data.result`を受け取り、戻り値を調整できます。サーバー側の認可と検証は引き続き適用されます。読み取り、辞書解決、インポート、公開リクエスト、メディア変更に同じ境界を使用します。プロバイダーの解除時は実行中のリクエストを中止し、機能、フロー、フックを削除します。古いハンドルは拒否され、再有効化時には新しい操作が登録されます。

constructorを含むグループ化した関係名はデータとして扱い、オブジェクトの継承プロパティを参照しません。

ライブラリのJSON変更要求は最大5 MiBとし、それを超えるストリームは変更処理の前にHTTP 413で拒否します。カード項目のJSONと検索用の正規化済み表現には、それぞれUTF-8で50,000バイトの上限を設け、検索用データに見出しとタグの余地を残します。音声添付は正確なアップロードパスを必要とし、ディレクトリ移動や入れ子のパスは保存先へのアクセス前に拒否します。作成と編集は同じ正規参照の書き込み処理を共有し、グループ、位置、選択した活用を維持します。保存場所の読み込み失敗は翻訳されたトーストで通知し、中止された画面の応答は現在の操作部を更新しません。

パッケージ資産はstudy_library_asset_chunksに保存し、発行者、パック、版、完全な資産パスから生成するSHA-256識別子と整数の位置をキーにします。公開URLと元のバイト列は維持します。パックの索引で削除範囲を限定します。スキーマはスキーマと版の識別子を維持し、基本断片とstudy_library_schema_partsを使います。両方の内容をUnicodeの境界でUTF-8最大60,000バイトの断片に分割します。読み取りでは順序どおりに復元し、インポートでは既存のトランザクション内で置換します。版の競合、単独の発行者による更新、ロールバック、短い内容への置換の意味は維持します。

通常の参照は既存のキーを維持します。グループ化した配置は、グループと位置を含む決定的なreference_idを持つstudy_library_reference_groupsに保存します。スキーマの初期化時に既存のグループ行をトランザクションで移し、失敗した場合は再試行のため元のグラフを維持します。読み取り、逆参照、削除、編集、不要項目の整理は両方の現行の関係ストアを使用します。インポート時の参照削除は提供者の編集を保護しつつ、元の項目IDを500件ずつ処理します。新規カードの通知は、作成の最外側トランザクションがコミットされた後に送信します。

外部モジュールの初期化には、検証済みコンテンツパックの取り込みを完了してから機能を公開できるよう、標準で2分間の制限時間が設けられます。ホストが明示した制限時間は引き続き適用されます。失敗や時間切れの場合は登録済みの提供機能が削除され、モジュールは利用できない状態を維持します。再有効化時には保存済みのバージョン別録音を再利用し、不足するファイルはFilesゲートウェイ経由で復元します。変更のないパックも含め、ライブラリの項目と関係の整合処理は引き続き実行されます。

カード作成の候補は別の行に表示され、入力欄と発音の保存ボタンの配置が安定します。辞書の結果を選択すると、未確定の表記が小さい「っ」などの非表示の文字単位も含めて正規の文字参照として確定されます。確定済みの構成は維持され、非表示の単位は一覧には表示されません。

カード編集では、変更を破棄する前にキャンセルの確認を求めます。カルーセルから同じカードを複数回配置でき、各配置をドラッグで並べ替えられます。文の発音プレビューでは各構成カードを枠で囲み、重複する入力表示を省きます。カルーセルのホバープレビューは主要な発音と定義だけを表示し、画面内に収まります。

表のグリッドはカード間隔分の内側余白を確保し、カード枠とフォーカス枠が完全に見えるようにします。空間的な子の配置では、各方向の残り容量を測定し、有効な祖先経路が使用している座標だけを予約し、子孫がカーソルによって非表示になった代替分岐のスロットを再利用できるようにして、子孫の枝全体を収容できる方向を優先します。該当方向がない場合は、表示可能容量が最大の方向を選びます。

## 利用側定義のスキーマ

ライブラリアダプターは関係付けられた汎用学習データを保存します。利用側は ctx capability `study:library` を通じて、不変かつバージョン付きのスキーマを登録します。スキーマが言語、レイヤー、型付きフィールド、方向付き関係を定義し、アルファベット、単語、文などの名称をアダプターに固定しません。

関係は対象レイヤー、多重度、順序、任意のリゾルバーを宣言します。すべての書き込みでフィールド、スキーマバージョン、対象、可視性、多重度を検証します。別定義も利用側が宣言する通常のレイヤーと関係で表現します。

レイヤーは関係の対象として同じレイヤーを指定でき、ある項目から同一レイヤー内の別の項目を明示的に展開できます。同一レイヤーの関係は既定で構成として表示され、バリアントとして指定された関係、または `alternateSpelling` を明示した関係だけが別表記として表示されます。

## 解決、API、UI

入れ子の子は完全なサブツリーとして維持します。展開した子をホバーまたはフォーカスすると、兄弟の経路を閉じずに、その直接の子をすべて表示します。長押しのヒントはホバー時にカード下部の予約領域へ一行で表示し、長い場合は切り詰めるため、折り返した説明がプレビュー内容を隠しません。 子カードはホバー時も完全に不透明な浮き上がった表面を維持し、下にあるカードが透けないようにします。

`grapheme` リゾルバーは Unicode 書記素を、`longest-match` は明示的に区切られたブロックを使用します。どちらも項目を暗黙に作成せず、候補と未解決単位を返します。lookup プロバイダーは `registerLookupProvider` で追加し、出典付きの順位候補を返し、登録時の callback で解除できます。作成、解決、lookup は名前付き ctx flow に参加します。

Study ゲートウェイはスキーマ検出、一覧、作成、詳細、双方向追跡、解決プレビュー、lookup 候補を提供します。スキーマ駆動 UI は、内部用の定義レイヤーと助詞レイヤーを直接閲覧の対象から除外します。閲覧可能なレイヤーでは、タブ、メタデータ絞り込み、項目カード、メタデータのピル、範囲アイコンを使用します。再利用可能なポップアップ詳細は、大きくした項目見出しの下に定義と意味を表示します。文の助詞を含む認識済みの構成要素は、独立したコンポーネント区画ではなく、その見出し内の移動可能なサブボックスとして表示し、助詞の詳細は読み取り専用のままです。リゾルバーに基づく参照は、移動可能な強調ボックスだけで表示し、重複する関係見出しや構成演算子は表示しません。 構成要素のラベルと発音は、ポップアップのタイトル項目および副タイトル項目の契約で表現し、詳細本文では発音用または構成要素用の別コンテナとして重複表示しません。使用例は、順序付きレコードから直接参照される項目にだけ表示し、別の関連項目を介して推移的に表示することはありません。メタデータ絞り込みは即時反映するピルとして表示し、モジュールが提供する場合はスキーマの詳細グループを使用します。グローバル、利用者、クラスの権限はサービス境界で引き続き強制します。 メタデータ絞り込みは、シリアル化された絞り込み値を持つ基本カードだけを評価するようになり、浮動バリエーションカードが未定義値を JSON 解析へ渡すことを防ぎます。 バリエーションを持つ文字カードでは、ホバー時にローカライズ済みの長押し案内を表示し、長押ししきい値に達した後にだけ子カードを展開します。親または子にフォーカスがある間は開いた状態を保ち、フォーカスが外れると閉じます。バリアント関係を専用の詳細節へ重複表示しません。 展開した子カードには緑色の方向矢印と枠線を付け、親との間隔を通常カード同士の間隔と同じにします。

コンテンツ所有者、管理者、所有者は、表示中の複数項目を選択し、関係とともに完全に削除できます。削除したモジュール内容は、存在しない場合にモジュールの有効化ライフサイクルで復元されます。削除確認で選択したコンテンツハッシュをブロックリストに登録すると、同一レコードの再インポートを防止できます。 右クリック後の複数選択操作にはページコンポーザーの浮動アクションバーを使用し、通常のカードクリックまたは閉じる操作で選択モードを終了します。関係リンクは参照先項目の閲覧可能なレイヤーへ切り替え、共通の対象強調表示を使用します。定義参照は表示中の定義テキスト自体に適用し、スキーマで宣言したリゾルバー関係だけが構成要素ボックスを生成するため、重複または無関係な書記体系リンクを防ぎます。ダークテーマの音声操作部ではネイティブパネルの彩度を明示的に除去します。

最小グリッドは `grid.rowSize` から制限付きのチャート幅と比例カード尺度を導出します。明示的な空白項目は寸法付きグリッドセルとして保持され、列が詰まることを防ぎます。

## 宣言的コンテンツパック

導入済み言語パックは、検証に `inspectContentPack(root)`、データ専用ライブラリの導入に `ingestContentPack(root)` を呼びます。ルートには `manifest.json`、参照スキーマ、レイヤー ID のサブディレクトリを持つコンテンツディレクトリを置きます。ファイルは安定 ID と明示的関係を持つレコード配列です。Cognis はグラフ全体を検証し、名前空間 ID、digest、receipt を記録して、スキーマ、項目、edge を原子的に保存します。項目 ID はパック版が変わっても安定し、導入時に以前のインポートにある同一コンテンツハッシュを関係を保持したまま 1 つの正規項目へ統合します。 空間的な階層には `child: true` が必要です。`variant: true` は代替形を追加で識別できますが、展開の有効・無効には影響しません。`hidden: true` のレコードは、関係が子であっても空間配置の対象になりません。ブラウザーは明示された各子に境界内のグリッドスロットを割り当て、子チェーンを最大 4 階層まで再帰的に展開します。構成要素の参照先としてのみ必要なレコードには `hidden: true` を設定します。このレコードは詳細で解決および深層リンクできますが、表のカードとしては表示されません。子レコードは実際の概念上の親を参照し、独立したライブラリ項目のまま保持されます。ポインターを浮遊バリエーションへ移動して詳細を開けます。レイヤーは `rowSize` と、コンテンツレコード ID、数値の `displayId`、または明示的な空欄 `{ "blank": true }`（`null` も引き続き対応）を並べた `items` を持つ `grid` を定義できます。ブラウザーは表内の位置を保持し、指定された行幅に合わせて各カードを拡縮します。権限を持つコンテンツ所有者と管理者の選択チェックボックスは、カードを右クリックするまで非表示で、右クリック後はダークテーマに対応した状態でライブラリ全体に表示されます。完全な作成契約は `study-language-framework.ja.md` にあります。 メタデータフィルターグループでは、常に 1 つのタグを選択状態に保つ `required: true` と、モジュール指定の初期タグを選ぶ `defaultTag` を宣言できます。表示タグが 1 つだけのグループでは、そのタグが自動選択されます。 レイヤーに `minimal: true` を設定すると、通常のクリック、長押しによるバリアント表示、選択操作を維持したまま、各エントリの主要ラベルだけをコンパクトなカードに表示できます。 コンテンツパックの文レコードは、順序付きの語彙単位および助詞への参照によって全文を表す必要があり、リンクされていないテキストを含むラベルはインポート時に拒否されます。 レコードに `hidden: true` を設定すると、参照や詳細ポップアップでは利用可能なまま、そのレコードとすべての子孫を直接の一覧表示から除外できます。

## ローカライズされた定義

意味役割が `definition` の各レイヤーは、モジュール所有の文字列キープレフィックスと、文字列キーおよびローカライズ済みテキストのフィールドを宣言します。定義は、それを必要とする項目の編集時にのみ管理し、独立したライブラリ区画として直接閲覧または編集できません。英語は引き続き必須の原文であり、生成キーは定義レコードに保持され、未入力言語は任意の `localization:translateString` ケイパビリティで補完できます。

## 書記単位の発音と音声

書字単位のスキーマは標準の `pronunciation`（`stringList`）と `audio`（`audio`）フィールドを宣言します。発音の値を必須にするかどうかはプロバイダーが指定します。読みが不明な出典文字では、読みを作り出すことなく任意の発音フィールドを省略できます。必須の発音フィールドでは、値の欠落は引き続き拒否されます。 コンテンツパックは MP3、Ogg、WAV、WebM、M4A ファイルを認証済みパックアセットとして提供します。ライブラリは、ファイルゲートウェイを通じてコンポーネント管理の `study-library-audio` 名前空間にこれらのファイルを保存します。永続化、容量制限、物理ファイル管理はファイルゲートウェイが担い、各再生リクエストでは引き続き項目の範囲を検証します。 文字と代替文字の発音はカードと詳細タイトルで書記単位の横に表示し、単語と文の発音はテキストの下に表示します。モジュールは `lexicalUnit` レコードに 1 つの文字参照を設定することで、単独で意味を持つ 1 文字の単語をモデル化できます。文字の詳細には、その入力側の単語関係が表示されますが、ライブラリが内容を自動生成することはありません。 ポップアップタイトル横の書記単位の発音には、エスケープ済みの副タイトル契約を使用し、より小さい標準ウェイトの文字で表示します。音声領域は強制的な色置換を無効化し、ダークモードでネイティブ操作部の彩度を除去します。

## メタデータフィルターグループ

バッジフィールドは既定でフィルター対象です。プロバイダーは、その他のプリミティブまたはローカライズ済みメタデータフィールドに `detail.filterable: true` を設定し、その値を学習者向けフィルターとして公開できます。フィルター対象フィールドは `detail.group` で関連フィルターをまとめ、`detail.exclusive` で選択方法を指定できます。グループ内の全フィールドが `exclusive: true` を宣言すると、ピルを選ぶ際に以前のグループ選択が解除されます。既定値の `false` では複数のピルを選択できます。同じ名前のグループに属する全フィールドは同一の排他設定を使用する必要があります。

## 認証済み音声再生

Study ゲートウェイクライアントは認証済み API クライアントを通じて項目の音声を取得し、一時オブジェクト URL をプレイヤーへ渡します。詳細ポップアップを閉じると URL は破棄されます。ネイティブのプレイヤー操作部はライトとダークの配色に対応し、現在のアプリケーションテーマに従います。

## 構造化表示

各レイヤーのローカライズ済みメタデータが表示名になります。文字以外のレイヤーは `displayDefinition: true` を指定でき、その場合は必須の定義リレーションと、各インポート項目からその定義への参照が必要です。言語モジュールは `study:library:composeEntryDetail` を通じて、言語固有の助詞効果を含む文の統合定義を提供できます。Cognis 自体は言語コンテンツを生成しません。宣言済みで空ではなく、非表示でないフィールドだけを汎用表示します。グリッドではレコード ID、数値の `displayId`、空白を表す `{ "blank": true }` を利用できます。

定義項目は直接開いたりリンクしたりせず、他の項目へローカライズ済みテキストを提供するためだけに使用します。表示する翻訳は、現在の UI 言語のものに限定します。リゾルバー関係は `presentationRole` の `composition`、`alternateSpelling`、`pronunciation` を区別し、単語全体の読みを曖昧な文字列として表示しません。

構成が現在の項目と同じラベルを持つ 1 項目だけの場合は、重複する構成ブロックを表示せず、そのディープリンクをポップアップ見出しとして表示します。

ページコンポーザーのウィジェットはライブラリスキーマに合わせて縮み、利用可能な幅を上限とするため、余分なウィジェット幅による横方向のはみ出しを防ぎます。

削除では、最終的な関係カスケードの解決と影響を受ける全エントリの認可を同一トランザクション内で行います。そのため、同時に追加された関係によって、実行者に許可されたコンテンツを越えて削除範囲が広がることはありません。

語彙単位と順序付き語彙列では、`alternateSpelling` として提示される関係を、主要な詳細見出しの直下に移動可能な副表記として表示します。構造上の子やバリアントの子を、詳細本文の別表記セクションとして重複表示することはありません。

主要表記または副表記と同一の発音は1回だけ表示します。発音テキストは通常のタイトルメタデータとして扱い、同じようなラベルを持つ表記単位へのリンクへ推測変換しません。関係リンクは、宣言されたライブラリ参照だけを基にします。

## コンテンツパックの更新

導入済みプロバイダーは自身の名前空間の正式な情報源であるため、パック更新時には発行者が省いたレコードを削除します。意図的に部分的なレコード集合を公開する場合に限り、マニフェストで `pruneOmittedRecords` を明示的に `false` にできます。

## 管理画面と学習ページ

`/study/library` は管理者専用のデータエディターです。サイドメニューは、定義と関係のレコードを含む選択言語の全レコードをスキーマとレイヤー別にまとめます。レイヤーを選ぶとアクティブ状態が直ちに移動し、簡潔な行一覧を表示します。行をクリックするとスキーマ駆動編集ポップアップの読み取り専用版が開き、右クリックでは複数選択モードに入り、小さなテーマ対応の鉛筆から編集可能版を開きます。

学習用の層は「探索」のサイドメニューに移動し、URL は `/study/explore/<ISO 言語>/<navigationSlug>` です。モジュールは各層に一意の `navigationSlug` を指定でき、省略時は層 ID を使います。ライブラリと申請の URL は変わりません。長い表題や定義の省略表示は文のプレビューだけに適用します。

## 集中できるカードと編集

学習カードのプレビューは簡潔に保ち、主ラベルと発音を同じ行に置き、その横には範囲アイコンだけを表示します。定義、メタデータ、関係、その他の補助情報は詳細ポップアップに残し、重複区画を作らずにディープリンクを利用できます。

管理者用編集ポップアップは生の JSON を表示せず、各レイヤーのフィールドおよび関係スキーマから操作項目を生成します。ローカライズ文、リスト、真偽値、数値、文字列、関係先に適した入力を使用し、閉じる際の保護機能が変更済みフィールドを追跡します。

## プロバイダー所有の編集契約

編集可能な各フィールドは、入力方式とローカライズ済みラベルをプロバイダーのスキーマで宣言します。変更不可の分類は作成後に固定され、音声の選択とアップロードは Files ゲートウェイ名前空間の言語プレフィックス内に限定されます。複合要素は利用可能な最も近い層を参照し、たとえば 日本語 は 日本 と 語 を参照し、日本 は 日 と 本 を参照します。

関連項目ボタンでは、ラベルをホバー表示で重複させません。語彙リンクにはプロバイダー提供の発音を含めるため、`人 ひと` のような正しい 1 文字の語彙単位を、書記単位レコードの `人` と区別しつつ、意味のある 1 文字語を非表示にしません。バリアント案内はカード下部の小さな専用領域に置き、主要内容を覆いません。ダークテーマのカード面は白ではなくアプリ背景側へ合成します。

展開中のバリアント分岐も基本グリッド内にクリップします。Cognis はまずプロバイダー指定の方向を尊重し、描画後のグリッド境界に対して代替方向を評価して収まる最初の配置を選び、分岐を閉じるとプロバイダー設定へ戻します。長押し案内は文字を鮮明に保つため静止表示とし、ラベルを 25% 大きくしました。

表示中のカードは割り当てられた位置を維持し、子孫だけが個別に収まるよう調整されます。経路の枝刈りによって兄弟カード数より配置方向が少なくなる場合、追加の子カードは親を移動したり重ねたりせず、同じ行または列の外側へ積み重ねられます。

語彙単位の詳細ポップアップでは、語彙ラベルをポップアップタイトルだけに表示します。タイトル詳細には現在の Cognis 言語向けにローカライズされた定義だけを表示し、見出し横で綴りや発音が重複しないようにしました。

関連エントリのリンクから独自の定義を持たない語彙単位を開いた場合、ポップアップは移動元カードに表示されていたローカライズ済み定義を引き継ぎます。語彙レコード自身の定義は常に優先されるため、同じ表記単位に結び付く複数の語彙でも、それぞれ固有の意味を保持できます。前後移動とタイトル構成リンクでは、このフォールバック文脈を引き継ぎません。

カードはプロバイダーが定めた順序で複数の定義レコードを参照できます。最初のローカライズ済み定義はカードタイトルと同一でない限りタイトル詳細に表示され、以降の定義は「追加の定義」セクションに表示されます。このセクションは空の場合には表示されません。移動元から継承した文脈は、移動先の語彙に定義が一つもない場合だけフォールバックとして使用されます。

実行時の配置調整では、ルートカードと表示中の枝ですでに配置された各子カードの領域を予約します。境界内の希望位置が空いていればプロバイダー指定の方向を維持し、埋まっている場合はカードの重なりが最小となる境界内候補を選びます。これにより兄弟カードが同じ枠へ重なることを防ぎ、近接位置が足りない場合の行・列方向への外向き配置は維持されます。

## 新着コンテンツの追跡

ライブラリは、閲覧済み項目の UUID をアカウントごとに保存します。プロバイダー更新ではこの状態を維持し、更新されたパック全体ではなく、新しく追加された安定項目 ID のみを有効なアカウントへ通知します。プロバイダーパック、または承認されたユーザー・管理者の投稿によってグローバル項目が追加されると、有効なアカウントへライブラリ通知を送ります。閲覧済みキャッシュにない項目には、プレビューで **新着** ピルを表示します。ホバー、詳細表示、編集画面の表示は、直接リンクや関連項目経由の場合も、そのアカウントの閲覧済み状態を保存します。保存に成功すると対応するプレビューのマーカーを即座に消し、再読み込み後も状態を維持します。

## 投稿、公開範囲リクエスト、検索

ユーザーは個人名前空間、教師はさらに自身のクラス、管理者はさらにグローバル領域へカードを作成できます。言語プロバイダーは `study:library:registerConstructor` でレイヤー固有のフォーム項目を構成し、公開範囲、クラス選択、定義プレビュー制御はアダプターが所有します。個人またはクラスへの作成前に、同一の閲覧可能なグローバル項目があれば明示的な確認を求めます。

個人カードは、在籍クラスでは担当教師の審査へ、グローバルでは管理者の審査へ公開できます。保留中の申請は申請者または権限のある管理者が取り下げられます。承認時にはコピーせず元のカードが移動します。申請者の帰属は保持され、グローバルコンテンツの変更を申請できます。下書きを変更した管理者は共同所有者になります。公開範囲の変更と削除には引き続き移動先の権限が必要です。プロバイダーの manifest は `protected: true` を設定でき、保護項目は移動も削除もできません。インポート項目とユーザー作成項目には正規化した検索テキストを保存し、サイドメニュー検索は全レイヤーを対象として結果のないレイヤーを隠します。

## 言語所有のカードコンストラクター

言語パックは、作成可能な各レイヤーのスキーマに `cardConstructor` を指定できます。この仕様には、ローカライズ済みの主ラベル、順序付きフィールド ID と関連 ID、プロバイダー既定値、非表示カードおよび定義プレビュー切り替えの公開可否を含めます。Cognis はロールに応じた公開範囲とクラスの制御を追加し、コンストラクターのないレイヤーでは作成を意図的に読み取り専用にします。 作成先は個人スコープが既定で、権限のある管理者は全体公開を選択でき、教師は有効なスキーマの言語と一致する書き込み可能なクラスだけを選択できます。

作成画面では、スクロールバーや方向ボタンを使わずにすべての関連候補を表示します。ホバー時のプレビューには現在の UI 言語の定義を使用します。選択または提案された項目はドラッグ可能な構成ブロックとなり、安定 ID から関連参照を生成し、参照された表記単位を再帰的にたどって発音を導出します。定義の作成時には、対応するすべての UI 言語の翻訳を要求します。

実行時の言語モジュールは、公開 ctx ケイパビリティ `study:library:provider` を取得し、`ingestContentPack(moduleRoot)` と `registerConstructor(...)` を呼び出す方法も利用できます。フォーム公開前にコンストラクターの ID を登録済みスキーマと照合します。戻り値の解除関数により、モジュール無効化時に実行時コンストラクターを安全に解除できます。

順序付き字句シーケンスでは、`presentationRole` が `composition` の関係（従来の合成関係では省略も可）だけをラベルの再構築に使用します。発音や代替表記のリンクは字句レイヤーを対象にして位置を再利用しても、文の構成要素とは見なしません。

詳細ビューでは `composite` クラスを表示しません。それ以外のコンテンツクラスは人が読める末尾部分に変換して Pill として表示します（例: `lexical:noun` は **Noun**）。複合見出しでは代替読みと発音を主要な読みの直下に置き、定義は右側の列に維持します。逆引き語彙ナビゲーションでは同じラベルの字句項目を抑止し、正しい単語から表記単位への関係が自己再帰のように見えないようにします。タイトル詳細のリンク付き表記についても、正規化した文字列とリンク先の両方が主要タイトルを構成する既存リンクと一致する場合は省略します。resolverRole と presentationRole のどちらも持たない関係は依存専用エッジとして扱い、タイトル構成とは推論せず、逆方向ナビゲーションと削除ポリシーには利用できます。詳細ビューでは語彙での使用とその他の受信依存関係を 1 つの **使用元** セクションにまとめ、正規化ラベルが同じ複数レコードでは語彙ターゲットを優先します。複合ポップアップ見出しでは主要タイトルと読み詳細の行間を狭め、カードプレビューでは重複排除後に残るタイトルと定義テキストを中央揃えに保ちます。

子カードの分岐を開いている間、無関係な親カードはホバーに反応せず通常の表面を維持し、スコープ／表示範囲アイコンも背景とともにぼかされます。アクティブな親カードと表示中の子孫パスは鮮明で操作可能なままです。

## 外部パッケージ契約

`study:library` は、実行可能なプロバイダーとデータ専用コンテンツパックの正式な境界です。パックは、マニフェストとスキーマの両方に記載された名前空間だけを所有します。スキーマ、レイヤー、フィールド、関係、コンストラクター、選択肢のラベルはローカライズ済みマップです。プロバイダーのメタデータには JSON 互換値を追加でき、Cognis は各値を検証し、完全なスキーマを保存して、`listSchemas()` と `GET /api/v1/study/library/schemas` から変更せず返します。未知のフィールド型は宣言的な `validation` 規則がある場合に限り受理されます。組み込み型には文字列、有限数、安全な整数、真偽値、リスト、ローカライズ済みテキスト、単一またはリストのアセット・音声参照があります。パック保護、意味役割、グリッド、詳細ヒント、アクティビティ互換性、定義のローカライズ、関心情報、ライセンス、アセットは、このバージョン付き契約の一部です。`tests/fixtures/` の合成フィクスチャはプロバイダー CI の互換性基準です。

実行可能プロバイダーによる直接のスキーマ登録は、スキーマバージョンごとに不変です。ただし、権威あるコンテンツパックの新しいリリースでは、そのスキーマバージョンを所有するインストール済み項目の発行者とパック ID がすべて同一である場合、同じ互換バージョンの保存済みスキーマ文書を改訂できます。Cognis は独立登録または別所有者のスキーマとの衝突を拒否し、スキーマと項目を一つのトランザクションで更新して、成功後にメモリ上のスキーマを更新します。

コンテンツレコードは `lexical:noun` や `lexical:verb` のような名前空間付き `class` 値を宣言できます。Library は、将来のクラス別表示やアクティビティのために、このプロバイダー中立な分類を検証して保持します。リスト形式のローカル音声参照は個別にキャッシュされ、アセット一覧は認証済み URL に書き換えられ、インストール受領情報にはマニフェストのメタデータが保持されます。

## 公開リクエスト

公開リクエストは Study の **リクエスト** ページに表示されます。有効な管理者には新規リクエストと他の管理者の判断について Study 通知が届きます。

## 管理と作成

管理 Library は、選択済みの Study 言語に属するレイヤーだけを折りたたまないメニューで表示します。エディターはラベルとコンテンツクラスを先頭に置き、表示モードと編集モードを区別し、未保存変更を保護し、編集時だけ保存を表示します。定義レコードは常に非表示で `definition` クラスを持ち、プレビューや表示設定の切替を表示しません。順序付きシーケンスは `composite` クラスを持ちます。コンテンツレコードは `editable: false` を指定でき、助詞レイヤーは常に編集不可です。作成はユーザー向けレイヤーページの `+` ページアクションからのみ行い、公開範囲、内容、関係を順に設定します。送信者はリクエストページで自分の公開申請の状態確認と取り下げができます。

カード作成時、解決済みのカードは Input コントロール内に保持され、選択されたレコードと未解決の基本文字の両方から発音がリアルタイムで導出されます。カルーセル内の重複ラベルは、最適なローカライズ済み定義プレビューにまとめられます。関係は読み取り専用の親・カード・子マップとして表示され、定義タブでは入れ子のダイアログから複数の完全な翻訳セットを作成してリンクできます。個人およびクラス領域の作成者には管理用の「非表示」コントロールを表示しません。グローバル公開は「公開」と表示し、情報ツールチップで審査リクエストについて説明します。

定義レイヤーは直接作成の対象外で、別のカード作成画面から作成・リンクされた場合にのみ存在します。種類の選択後、作成ダイアログには共通の未保存変更保護が適用されます。詳細の音声は簡潔なスピーカー操作になり、カード自身の音声、または複合カードでは順序付き構成要素の音声を連続再生します。構成要素に音声がない場合は無効になります。`strokePattern` フィールドは、決定的な書き取り練習のため、順序付き正規化座標、単調な時刻、任意の筆圧、合格許容値を保存します。

カード作成の各関係カルーセルは縦スクロール可能な2行に制限され、共有アンカーポップアップ制御により表示領域内で安定したプレビューを表示します。定義関係にはカルーセルを表示せず、専用の多言語セットダイアログで非公開レコードを作成・リンクします。Input 解決は正規化された入力全体との完全一致を比較し、関係図には明示的に選択した構成レコードのみ表示します。公開操作は1行に保ち、作成操作は枠線のない中央配置のプラスを使い、描画・編集操作にはホバーラベルを付け、スピーカー素材にはライト・ダークの専用版を用意します。

関係カルーセルは2行を維持したまま横方向にスクロールします。筆順パターンは予約済み実装データとしてカード詳細には表示されません。描画・音声操作はライト・ダークのペア素材を使い、描画練習を開始すると詳細ダイアログを閉じます。

Study Library ページはドキュメント全体を自然にスクロールし、内部コンテンツのスクロール領域との競合を防ぎます。カードプレビューの高さは統一されています。関連項目の追加操作では、カード種別が固定され、見出しにも種別が示された入れ子の作成画面が開きます。入れ子のダイアログは親ダイアログより前面に表示されます。カルーセルのプレビューは内容に合う大きさの body ポータルだけに描画され、項目からホバーまたはフォーカスが外れると直ちに消えます。

フィールドは `input.linkRelationships` を宣言し、複数のプロバイダー定義関係を通じて読みや発音をリンクできます。ホストは一致する参照を作成時の位置順に統合し、表示する各部分を対象カードのラベルまたは発音別名と照合しながら、リンク先には元のカードを維持します。

フローティング作成操作では、現在のテーマに応じて黒または白の 2rem のプラス記号を使用します。作成画面のカルーセル見出しにはプロバイダーの対象レイヤーメタデータを使用し、項目もその対象レイヤーだけに限定します。音声スピーカーアイコンは OS の配色設定ではなく、アプリのテーマに従って明示的なライト・ダーク用アセットを切り替えます。

Library カードには、習熟度などの検索可能なタグを設定できます。ランタイムプロバイダーは `study:library:provider` を通じて既存の検索プロバイダー契約を登録でき、検索結果は出典と信頼度を伴う `strokePattern` などの検証済みフィールドを提供できます。

## 作成画面の検索プロバイダー

ランタイムコンテンツプロバイダーは `study:library:provider.registerLookupProvider` を通じて検索実装を登録します。安定した ID、ローカライズ済みのサービス名、スキーマとレイヤーの対応判定、および作成画面の未加工入力を受け取る非同期検索を提供します。Cognis は対応する各プロバイダーを入力欄の下に **検索サービス: サービス名** として表示します。選択されたプロバイダーは正規ラベル、検証済みフィールド値、順序付き関係参照、出典、信頼度を返すことができ、作成画面は最も信頼度の高い結果を適用します。エンドポイントの管理は Study ゲートウェイクライアントに維持されます。

モジュール有効化時には、必要なサーバー機能を注入済みルートコンテキストと system ctx に提供された公開機能の両方で検証します。そのため、モジュールは `requiresCapabilities` に `study:library:provider` を安全に宣言でき、非公開 ctx 機能は引き続き利用できません。

作成と編集では、順序のない関係に位置情報を付けずに参照を維持します。関係構造は表示モードだけに表示され、編集・作成フォームでは非表示コントロールを通じて参照を保持します。複合文字フォームには自由入力できる **入力** フィールドを表示し、基本文字参照カルーセルにはプロバイダーの発音フィールド名を使い、入力後にだけ検索操作を同じ行へ表示します。ストロークパターンは非表示のプロバイダーデータとして扱います。定義追加には大きなニュートラル操作を使い、カルーセルのプレビュー背景は内容全体を包む大きさになります。

既存の複合書記単位カードでは、タグ入力コントロールの横やコンテンツタブの上ではなく、発音フィールド内に発音セレクターを配置します。カルーセルの見出しには、コンテンツプロバイダーが定義したローカライズ済み対象レイヤー名を使用します。選択された基本書記単位をカードの発音またはラベル内の出現順に並べ、その順序から保存する発音を導出します。既存の音声フィールドには保存済みファイル名を表示し、新規アップロードでは識別可能なファイル名を保持し、スピーカーアセットはアプリの現在のテーマに従います。

## プロバイダー連携の発音編集

プロバイダーは発音フィールドに `input.linkRelationships` を設定できます。エディターは自由入力のタグ欄を、指定された関係だけの順序付きカルーセルに置き換え、各対象レイヤーについてプロバイダーが定義したローカライズ済み名称を表示します。プロバイダーが導入したカードを保存するとユーザー変更済みとして記録されるため、その後のコンテンツパック同期でもユーザーのフィールドと関係が保持されます。

発音編集は繰り返し可能な2段階の操作です。プロバイダー互換の構成カードを選択し、生成された読み方を確定します。カルーセル項目には主表示値ではなく発音が表示されます。複合文字単位は基本文字単位から、順序付き語彙列は語彙や助詞などの語彙単位から構成されます。音声アップロードにはカードとフィールドに固有の安定したオブジェクトキーを使うため、再アップロード時には以前のオブジェクトが上書きされます。

描画練習を開いている間は、画パターンを持つ別のカードを選ぶと、詳細ダイアログを開かず既存のパッドへそのカードを読み込みます。

語彙、文、複合カードは順序付き文字単位の参照から描画ガイドを再帰的に生成し、独自の画パターンを宣言できません。プロバイダー所有の代替文字は可能な場合に関連文字の音声を再利用し、ユーザー所有カードへ明示的にアップロードした音声は引き続き優先されます。

作成フォームは、必須ラベルとローカライズされた定義欄に共通フォームビルダーを使用します。代替文字の入力は自由文ですが、辞書プロバイダーが一致を確認した後にのみ有効になり、プロバイダーの結果は筆順パターンなどの非表示必須項目にも保持されます。発音セレクターは発音欄内に配置され、単語は文字カードから発音を構成でき、助詞は作成者が選べるコンテンツ分類から除外されました。複合描画の解決では、発音リンクより主表記を優先します。

編集時は既存レコードをプロバイダーの最新スキーマで検証し、保存済みのスキーマバージョンを移行するため、プロバイダー更新後も音声取得と更新が有効に保たれます。詳細取得では、エディターを閉じた後も編集権限が維持されます。描画は筆記単位と語彙に限定され、語彙の筆順解決では発音リンクではなく主表記を使用します。

作成対象から助詞レイヤーを除外しました。語彙の Input はプロバイダーが宣言した文字、代替文字、語彙カルーセルを使用し、文と複合の Input は助詞、代替文字、語彙カルーセルを使用します。これらのレイヤーは順序付き Input から発音を再帰的に導出し、独立した発音エディターを表示しません。代替文字の Input は自由入力のまま、プロバイダーが宣言した文字カルーセルを Pronunciation 内に表示します。
代替文字の発音構成では、プロバイダーが宣言した発音カルーセルから基本文字カードを選択します。語彙、文、複合のコンストラクターは発音フィールドを省略し、保存時に順序付き関係グラフ全体から発音を再計算します。

すべての `cardConstructor` ペイロードは `input_carousels` と `pronunciation_carousels` を公開します。各配列にはそのコンストラクターの対象レイヤー ID を指定します。入力カルーセルは主値を構成し、発音カルーセルはそのレイヤーを対象とする宣言済みの読み関係をすべて満たします。代替文字では発音カルーセルの最小数だけが必須で、未解決の主参照は作成を妨げません。lookup プロバイダーはプロバイダー所有の出典・順位メタデータを省略でき、Library が登録済みプロバイダーから値を正規化します。

カードコンストラクターのカルーセル配列は必須であり、欠落時は推測せず拒否します。実行時フォームのコントリビューションは、スキーマ表示だけでなくサーバー側の関係検証にも適用されます。編集フォームは作成フォームと同じ宣言済み発音カルーセルを使用します。音声アップロードは正規化したカード名とフィールド ID を保存ファイル名に使うため、再アップロード時に同じオブジェクトを上書きします。

カードコンストラクターは、作成と編集の両方で使用する唯一のフォーム契約です。`fields` リストが表示するスカラーフィールドを決め、`relationships`、`input_carousels`、`pronunciation_carousels` が利用可能な関係カルーセルを決めます。代替文字のコンストラクターは Input を自由入力のままにし、文字関係を Pronunciation に配置できます。語彙のコンストラクターは文字、代替文字、語彙の関係を Input に配置でき、文と複合のコンストラクターは助詞、代替文字、語彙の関係を配置できます。語彙、文、複合の発音は順序付き構成要素から再帰的に導出されるため、それらのコンストラクターでは発音フィールドを省略します。

作成フォームまたは編集フォームに発音フィールドが表示される場合、Library は汎用のリスト用テキストエリアではなく発音コンポーザーを表示します。内部に表示するレイヤー固有の関係カルーセルは、引き続きコンストラクターの `pronunciation_carousels` が決定します。

語彙、文、複合のフォームは、プロバイダーのペイロードに派生フィールドが含まれていても、発音用の汎用リスト値エディターを表示しません。その他のリスト型プロバイダーフィールドには、削除可能なタグチップではなく改行区切りの通常のテキスト領域を使用し、エントリ分類タグには専用のメタデータコントロールを維持します。

語彙カードと文カードは、独自の音声がアップロードされていない場合、順序付き依存項目の音声を一つの連続音声として再生します。カードへの任意の音声アップロードは、この派生シーケンスより優先されます。依存項目のいずれかに音声がない場合、無効化されたスピーカーにカーソルを合わせると理由が表示されます。

発音カルーセルは、実行時フォームのコントリビューションがスカラー関係一覧から関係を省略していても、コンストラクターのカルーセルレイヤー宣言が示すすべての関係を読み込むようになりました。カルーセル項目の選択は発音値へ即座に反映され、重複していた自由入力欄と発音確定ボタンは作成・編集フォームの両方から削除されました。

複合表記単位は基本表記単位から発音を構成します。語彙単位は基本表記単位を発音に、表記単位や語彙単位を入力に使用します。順序付き語彙列は選択された語彙単位と助詞から発音を導出します。これらの意味役割が現在のコンポーザー契約を定義します。

組み込みのセマンティックコンポーサープロファイルは、指定されたカルーセル契約を直接適用するようになりました。代替文字は自由入力と原子的文字の発音カルーセル、語彙は原子的文字・代替文字・語彙の入力カルーセルと原子的文字の発音カルーセル、文は助詞・代替文字・語彙の入力カルーセルを使用し、編集可能な発音は表示しません。語彙の発音は文字レイヤーの値から再帰的に事前入力され、文の発音は常に完全に派生されます。

原子的文字レイヤーと助詞レイヤーは不変のカタログデータです。Library API は、管理者や所有者を含むすべてのロールに対して、これらのレイヤーの作成・更新・更新申請・削除を拒否するようになりました。UI の権限応答では編集・削除操作を非表示にし、読み取り専用の閲覧は維持します。

順序付き選択は、すべての入力カルーセルで一つの構成位置列を共有するようになりました。位置バッジはリレーションカルーセルごとに1から再開せず、保存されるカード全体の順序を示します。

作成フォームでは Cognis 内部のコンテンツクラス選択を表示しなくなりました。詳細表示ではプロバイダーが定義したローカライズ済みレイヤー名でカードを識別し、順序付きシーケンスのレコードには `sentence` や `composite` といった意味上のラベルではなくプロバイダーのレイヤー ID を使用します。派生した発音は、リスト値の発音フィールドを含め、プロバイダーが宣言したフィールド契約に従ってシリアライズされます。

派生フィールドのシリアライズでは、コンストラクターで絞り込まれた編集レイヤーではなく、プロバイダースキーマから契約を解決します。そのため、コンポーザーが直接入力欄を意図的に省略しても、必須の発音フィールドを検出できます。

コンストラクターが入力または発音のカルーセルレイヤーを宣言すると、対応する見出しの下とカルーセルの上に、選択済みカードを常時表示するフィールドが配置されます。既存項目の選択状態で初期化され、カルーセル選択に即時追従し、構成順序を保ち、選択済みカードを直接削除できます。

カルーセル連携フィールドは、フィールド直下にあるプロバイダー定義の真偽値 `multi_value` を受け付けます。複数値フィールドには明示的な **{フィールド}を保存** 操作が追加され、確定した値は編集中の構成欄の上に削除可能なピルとして表示され、置換のために再編集できます。すべてのカルーセル構成欄では、設定済みカルーセルが提供するカードに解決されたテキストだけを受け付け、未解決テキストがあるフォームは無効になります。選択済みカードまたは確定値の削除には専用の × 操作と確認が必要です。既存カードの編集画面にも作成フォームと同じ関係カルーセルを表示します。

フィールド直下の真偽値 `multi_value` が複数値を宣言する唯一の契約です。確定済みピルをクリックしてもステージング構成へ読み込まれません。複数値のステージングは空で開始し、小型の × 操作は確認なしでステージ中のカードだけを削除します。参照は表示中のフィールド別保存操作を押したときだけ確定され、ステージ中カードを削除しても保存済み値は変わりません。カードのラベルは独立した編集値として表示せず、順序付きの主要 Input 構成から生成します。保存に成功すると、表示中のカードプレビューも直ちに更新されます。

カルーセルのすべてのカードで、定義がない項目を含め、ホバー時とキーボードフォーカス時のプレビューを再表示します。カルーセルプレビューと音声不足ツールチップは body 直下のアンカーポータルに描画するため、カード、カルーセル、ポップアップのオーバーフローで切り取られません。

グループ化した関係では、複数値フィールドごとの入れ子参照配列を保持します。各発音が独立した順序付き文字列を所有でき、コンテンツパック検査、検証、永続化、API 編集、リンク付きタイトル表示の全工程で、曖昧な単一リストへ平坦化せずグループを維持します。

非表示カードは、すべてのカルーセルと入力候補一覧から除外します。既存カードを編集する際、すでに設定されている非表示依存関係は基礎となる関係コントロールに保持しますが、作者が選択できるカルーセル候補としては表示しません。

保存領域から読み込んだグループ化リレーションは、各項目を位置順に並べる前に欠番を詰めます。そのため、グループ番号に欠番があってもライブラリエントリ API は失敗せず、保存された各発音グループの順序は常に一定に保たれます。

ライブラリのカードプレビューには、異なる発音を先頭から最大2件だけ表示します。閲覧カードが過度に高く密集しないようにしつつ、エントリの詳細画面では引き続きすべての発音を確認できます。

発音表示では、入れ子になった文字列を完全な読みへ連結してからカードのラベルと比較します。そのため、`["さ", "き"]` のようなグループ化された発音は `さき` として扱われ、カードが同じ値を使用している場合は重複表示されません。

リンク付き発音タイトルは、UIに実際に表示される内容でも重複判定します。リンクされた文字ラベルを連結し、空白とUnicode表現を正規化してからカードの値と比較します。これにより、保存された発音表現が異なる場合でも、リンクされた `さ` + `き` が `さき` のタイトルを繰り返しません。

複数値フィールドの1つのグループは、宣言された複数のリンク関係にまたがることができます。グループ番号はそれらの関係間で対応するため、検証では各関係のグループ数を合計せず、最大のグループ数をフィールド値の数と比較します。これにより、意味のある読み区間と直接の文字接尾辞を組み合わせた発音を扱えます。

リンクされた発音がカードの主値と完全に一致する場合、タイトル詳細は表示を1段深く解決し、リンク先カード自身の発音値を示します。これにより、`さ` + `き` のような仮名表記は `さき` を重複表示せず、文字レイヤーの読みを表示できます。

タイトル参照の重複除去では、一致する文字を個別に削除せず、順序付き表記を1つの単位として扱うようになりました。完全な表記が主値と一致する場合、リンク先の文字カードは自身の発音値を表示します。部分的な断片によって主値と見かけの発音が食い違うタイトルは生成されません。漢字の詳細画面では、隣接カードから推測した読みではなく、プロバイダーが記録した完全な読み一覧を引き続き表示します。

ステージ中のComposerカードを削除するには、コンパクトな×ボタンを正確にクリックする必要があります。周囲の選択済みカード表示や空の構成領域では削除されません。また、作成ポップアップを閉じる前に、プロバイダーが要求する各関係の最小数を検証します。定義が不足している場合は標準の検証トーストを表示し、ポップアップ、選択カード、入力テキスト、入れ子の定義を保持したまま修正できます。

項目見出し内の長い発音と定義は開始位置を維持しつつ、見出し幅の最大 40% に収まり、続きは下の行へ折り返されます。定義の前には発音との違いが分かりやすいダッシュを表示します。カード作成コンポーザーではタグを 8 件、定義を 10 件、発音を 16 件までに制限し、上限に達した場合はローカライズされたトーストで通知します。

発音がある密な見出しだけに 4 列配置を適用し、スピーカーをスコープアイコンの下へ移動しました。発音ブロックは見出しの最大 40% を使い、定義はその右側で独立して折り返されます。タグ 8 件、定義 10 件、発音 16 件の上限は、作成と編集の両方のコンポーザーに適用されます。

展開した文字の子ブランチが表示中のライブラリグリッドからはみ出す場合、実行時の配置調整は反対の上下左右方向へ切り替える前に、すべての斜めスロットを評価します。表示中のルートカードも占有領域として扱い、境界内で衝突しない最初の斜め位置を選ぶことで、子カードと接続線の両方をキャンバス内に保ちます。

## 文の構成と変形

各 `tag_carousels` 項目には `excludeFromBrowse` の宣言が必須です。`false` は表示対象の語彙を通常の閲覧にも残し、`true` はコンポーザー専用にします。非表示の発音補助カードとは独立した、プロバイダーによる明示的な設定です。既存のメタデータフィルターの選択動作は維持します。

`literal_carousels` は繰り返し利用できる句読点を 1 行の読み取り専用カルーセルとして提供します。英語なら `, . ? !`、日本語なら `？！。、` のように、その言語で使う記号をプロバイダーが列挙します。

プロバイダーは動詞・副詞の基本形に `verb` または `adverb` を付け、レイヤーの `views` に `layout: transformTree` を宣言します。名前付きビューは明示的に選択された場合だけ項目を絞り込み、そのタグによって語彙を通常の閲覧から除外しません。コンテンツパックは `歩く` のような基本形の語彙項目だけを提供し、活用形ごとのカードを収録してはいけません。スキーマ単位の `transformSets` が決定的な状態遷移を定義します。各規則は開始状態と終了状態を指定し、`removeSuffix` と `append` で 1 回の接尾辞置換を行います。同じ状態から複数の規則へ分岐でき、生成状態からさらに規則を続けられます。`matchTags` で適用対象の基本形クラスを選び、`godan-ku` のようなタグで活用群を区別できます。

```json
{
    "transformSets": [
        {
            "id": "godan-ku",
            "matchTags": ["verb", "godan-ku"],
            "baseState": "base",
            "rules": [
                {
                    "id": "potential",
                    "fromState": "base",
                    "toState": "potential",
                    "removeSuffix": "く",
                    "append": "ける"
                },
                {
                    "id": "negative",
                    "fromState": "base",
                    "toState": "negative",
                    "removeSuffix": "く",
                    "append": "かない"
                },
                {
                    "id": "desiderative",
                    "fromState": "base",
                    "toState": "desiderative",
                    "removeSuffix": "く",
                    "append": "きたい"
                }
            ]
        }
    ]
}
```

文の接続表現タグは専用のコンポーザーカルーセルを選び、通常の入力カルーセルからは除外されます。通常の閲覧での表示は、プロバイダーが明示した `excludeFromBrowse` 設定に従います。編集コンポーザーは、保存済みの文ラベルと順序付き参照から繰り返し可能な句読点トークンを復元します。変形ツリーのノードは操作可能になり、生成形を選ぶと経路プレビューが更新されますが、保存される正規項目は基本形カードのままです。契約検証では、重複した句読点リテラル、空の変形セット、重複する状態遷移、変化のない規則を拒否します。

子カードの分岐は、より深い子孫を開いても、配置済みの各カード位置を維持するようになりました。新たに表示された子孫だけを深さ順に測定し、表示領域内の衝突しない空きスロットへ振り分けるため、自然なツリー移動中の祖先カードの跳躍、カードの重なり、接続矢印の密集を防ぎます。

斜め方向の子カード経路に、より広く連続したポインター通路を設けました。分岐の切り替えには短いホバー待機を加え、選択中のカードは脈動アニメーションではなく安定したフォーカスリングで示します。代替方向は遠いスロットより先に優先軸の近傍を試すため、初期配置がより密で一貫したものになります。

入力と発音の合成は、再利用可能な同一のトークン入力レンダラーと関係カルーセル実装を共有するようになりました。入力カルーセルはトークン欄の直下に表示され、同じ小型の削除ボタンと選択状態を使用します。依存カードの作成ボタンは、対象レイヤーでユーザー作成が許可される場合にだけ表示されます。新しい依存カードは、作成・編集の両コンポーザーで共通のカルーセル項目レンダラーを通して追加されます。

関係カルーセルから新しく作成した依存カードは、そのカルーセルの通常の選択処理を通して挿入されるため、返されたカードが直ちに選択され、作業中の構成ステージへ追加されます。また、代替文字の発音コンポーザーでは、プロバイダーがより一般的な関係表示ロールを使用していても、原子文字を対象とするすべての関係を発音ソースとして扱います。

画データに対応するカードコンポーザーには、専用の **画パターン** セクションが表示されます。検索プロバイダーは入力可能なフィールド ID を宣言し、画フィールドを宣言したプロバイダーは簡潔な **検索** 操作としてこのセクションに配置されます。読み込まれた正規化済みの画データは、4 rem 四方の小さなプレビューに描画されます。複数タブのエディター検証では、無効な必須データを含む各タブを強調し、最初の無効フィールドを含むタブを開いて、そのフィールドへフォーカスを移します。必須の定義がない場合は、定義作成操作へ移動します。

ポップアップのタイトル定義から先頭のダッシュを削除しました。発音グループと定義グループはタイトル行に配置され、カードの主タイトルと垂直方向の中央を揃えます。

レイヤースキーマで `dictionary_lookup: false` を指定すると、`dictionary` 機能を宣言する検索プロバイダーを抑止できます。検索プロバイダーは中立的な機能と入力対象フィールド ID を宣言し、画検索操作は画パターンセクションだけに配置されます。代替文字コンポーザーは定義以外の関係を発音ソースとして扱い、定義を必須にしません。タグはすべてのコンテンツフォームの末尾に表示されます。必須項目を含むタブは通常の外観を保ち、赤いアスタリスクだけを表示します。必須定義がない場合は追加操作も強調されます。

Library エディターのタブ切り替え、無効タブ表示、最初の無効フィールドへのフォーカスは、再利用フォームコンポーザーの `bindTabbedFormValidation` コントローラーへ委譲されます。Library 側はドメイン固有の定義フォーカス先と必須マーカークラスだけを指定します。

代替文字のフォームペイロードは、同じスキーマの語彙フォームペイロードから `pronunciation_carousels` を直接コピーします。コンポーザーは、代替文字専用のカルーセル推論や関係フィルタリングを行わず、整合済みのペイロードを使用します。筆順検索では、プロバイダーの **検索** アクションを引き続き筆順内に配置します。ライブラリのレイヤールートは、プロバイダー定義の動詞・副詞ビューが使う任意のビュー区間を受け付けます。

代替文字フォームのペイロード整合では、`pronunciation_carousels` と、そのカルーセルを描画する関係 ID の両方を更新します。置き換え対象だった語彙の発音カルーセル関係を削除し、語彙カードの発音カルーセルが使う文字関係を追加します。これにより、代替文字フォームの発音には文字カルーセルが表示され、語彙は表示されません。

発音の導出は最初の明示的な発音で停止し、基本文字カードの場合だけラベルへフォールバックします。これにより、新しい単語や文が文字単位の読みへ分解されません。作成時は正規化した入力だけで表示可能な重複を拒否し、続行すると新しい行を作らず既存カードを選択することを確認画面で示します。プッシュ要求の保存と審査は `update` と `merge` の両方を認識します。

ポップアップの定義は右端の専用列ではなく、カードタイトル直下から始まるグリッドの2行目に配置されます。読みはタイトル行の中央に維持され、長い定義はタイトルの下で自然に折り返されます。

助詞の発音解決は基本文字と同様に終端として扱われます。明示的な助詞の発音を優先し、ない場合は助詞のラベルを使います。助詞から文字参照へ再帰しないため、は や が など文脈依存の助詞は作成された発音を維持します。

空の発音ステージを保存するとエラートーストが表示されます。保存済み発音カードの削除操作はカード内に収まり、保存済みカードを選択するとグループ化された構成参照がステージへ戻り、対応するカルーセルカードが編集用に再選択されます。

「カードプレビューに定義を常に表示」操作を、定義概要と同じ「定義」タブへ移動しました。既存カードの編集画面でも定義を追加でき、新しく作成した定義は直ちに選択され、表示中の定義概要へ追加されます。

カードポップアップのタイトルにある親カードの表示は、読みと同じ配置で定義より前に挿入されるようになりました。親カードの定義を継承するカードでは、親カードの表示がタイトル行にまとまり、定義はタイトルの下に保持されます。

コンテンツパックのエントリタグは検証され、コンテンツ識別子に含められ、ライブラリエントリのタグ列と検索テキストに保存さるようになりました。これにより、プロバイダーがタグ付けした語彙は、取り込み後も動詞や副詞などの定義済みビューに表示されます。

変形セットは、任意の長さの連鎖ルールと分岐ルールに対応し、任意の発音接尾辞操作とローカライズされた定義の上書きも指定できます。動詞ビューと副詞ビューは、これらのパスを接続されたテックツリーとして表示します。カルーセルで変形可能なカードを選択すると同じツリーが開き、正規の基底カードへの参照を保ったまま、選択した形を文に挿入します。変形された参照を再度開くと、作成時の形が検出され、その形で基底カードが開き、変形固有の発音と定義を含む完全なパスが表示されます。

子カードの配置調整では、すべての先祖カードが絶対的な除外領域として扱われます。斜め方向と上下左右を段階的に大きな距離で評価するため、塞がれた子カードは必要に応じて2スロット以上外側に移動し、親系列のカードを横切ったり背後に消えたりしません。

変換ツリー表示は、ページ幅を使う密なカードグリッドから始まるようになりました。利用可能な変換がないカードをクリックしても何も起こりません。展開可能なカードを開くとそのカードが上部へ移動し、ほかのカードはアニメーションしながら消え、中央に配置したルートの直下からコンテンツ幅全体へツリーが広がります。閉じる操作でグリッドへ戻れます。変換を選ぶとルートまでの経路全体が強調され、流れるように連続アニメーションします。また、狭いカードでのはみ出しを防ぐため、変換ラベルは値の上に配置されます。

変換ツリーでは、元の動詞または副詞カードを変更しない視覚的なルートとして維持し、その下にあった選択形の重複表示を削除しました。接続線は途切れずにつながり、ツリー全体で常にアニメーションしながら、選択した経路は明確に強調されます。展開済みの元カードをクリックすると、標準の詳細表示が開くようになりました。

動詞・副詞の項目は語彙ページに残り、プロバイダーの変換タグはフィルターとして表示されます。各規則は、任意の `matchPrefix` と `matchSuffix` 境界、および必須の `template` を持つローカライズ済み `definitionTransform` を宣言できます。テンプレートは選択した経路に沿って合成され、`{{ definition }}`、`{{ stem }}`、`{{ prefix }}`、`{{ suffix }}` を利用できます。固定マーカーではなく、文法的な変化をプロバイダーが表現できます。「Variants」で選択すると、変換後のタイトル・発音・定義・描画入力で詳細を再表示し、編集を無効にします。

変換グラフは各深度を一つの横列に配置し、定義をカードの下へ移し、14rem 幅の定義列を確保します。横方向と縦方向のオーバーフローはグラフ表示領域だけに制限されるため、ポップアップ操作を表示したまま、深い、または分岐の多い活用も読みやすく保ちます。

定義変換では、順序付きでローカライズされた `replacements` も宣言できます。最初に一致した置換がフォールバックテンプレートより先に以前の変換を書き換えるため、`to (want to) exist` → `to (have wanted to) exist` のような文脈依存の連鎖を表現できます。一方、`{{ definition }}` を使うテンプレートでは `to (want to) exist (and then)` のように意味を末尾へ追加できます。未変換の項目は、最初の変換行の上に中央配置されたルートカードとして表示されます。

文の参照では `transformation: { "setId": "...", "path": ["rule-id", "..."] }` を宣言できます。Cognis はその経路が参照先の基本項目に適用可能か検証し、関係とともに保存して、ラベルの推測に頼らず正確な生成形を解決します。変換後の詳細では標準の子マーカーによる **元: {親}** 注釈を表示し、その親注釈を選ぶと標準形の動詞または副詞を開きます。
代替のタイトル構成はライブラリ階層に従います。文は単語へ、単語は複合・原子的な文字単位へ、複合文字単位は原子的な文字単位へリンクできます。そのため、同綴異義の語彙項目が別の語彙項目の綴り要素として扱われることはありません。たとえば「花」と「鼻」の読み `はな` は、それぞれ独立して `は` と `な` にリンクします。

インラインでのカード作成では、保存前に仮選択中の発音用文字を確定します。検索ですでに取得した読みを保存すると、発音を重複させずに選択した文字へのリンクを付けます。検索結果は発音一覧の改行形式ですぐ再表示され、主入力を変更しても自動生成した語彙と文の読みが表示されます。詳細見出しは一覧内の位置ではなく読み全体で文字グループを照合し、未リンクの読みも正規の文字カードに結び付けられます。

変形した語彙の見出しと読みは、表示中の形を構成する正規の文字単位にリンクします。「使用元」には完全に解決できる正規の表記と読みの構成も含まれるため、保存済みの参照がより小さな単位を指す場合でも、複合かなから語彙へ戻れます。直接の関係は引き続き表示され、不完全な構成から部分的なリンクは生成されません。

詳細の関係一覧には直接隣接する項目を表示します。「使用元」、使用例、関係ツリーでは、別の表記や読みの親項目を経由する場合にのみ到達する項目を除外します。グループ化された参照も対象です。直接のリンクは引き続き利用でき、循環参照による繰り返し探索は発生しません。類似項目には引き続き同じ階層の項目を表示します。

同じカードに中間項目を経由して到達できる場合でも、直接の関係は表示されます。保存された参照、グループ化された参照、見出しを構成する正規の文字単位は直接リンクを保持し、あ → ある + あるく と あ → ある → あるく の両方に対応します。別の親項目を経由する場合にのみ到達できる関係だけを除外します。

新しい語彙カードは入力確定時と保存前に辞書で品詞と対応する活用タグを自動検出します。手動のタグを維持し、曖昧な品詞は利用者が選択します。遅れて届いた結果で別の下書きを変更しません。選択中の動詞・形容詞の副詞形・複数形はその変形に対応する音声を要求します。見出しの出典表示から基本カードへ移動できます。アップロード欄と再生用音声要素のセレクターを分離し、文字エディター初期化時のエラーを修正しました。

依存関係の保存では、グループ化された参照を含む各リンクの公開範囲を検証します。個人用カードは閲覧可能な共有カードと自分の個人用構成要素を使用できます。クラス用カードの構成要素は全体公開または同じクラス用、全体公開カードの構成要素は全体公開である必要があります。変更申請は送信前に参照スキーマを検証し、公開の承認時には最新の依存関係を再確認します。変更によって審査中の公開申請を無効にすることはできません。共有カードや審査中の申請が広い公開範囲を必要とする場合、個人用への変更を禁止します。作成と編集の応答には、クラスの書き込み権限に対応した操作権限を含めます。

削除時には、グループ化された参照を含め、連鎖削除と削除制限の対象となる削除可能な依存カードをすべて確認します。参照を切り離すだけのカードは保持します。トランザクションは、削除前に対象カードすべての所有者、クラス権限、保護状態、審査状態を検証します。別の連鎖削除で対象になる制限付きカードは、探索順序によって失敗しなくなります。共有カードの作成時に依存項目の公開範囲が狭い場合、個人用としての保存を選択できます。公開支援では、非表示の定義を含む公開可能な末端の構成要素を先に申請し、承認後に親カードを申請できます。

削除の確認はサーバーが保存済みのスキーマバージョンを使って計画し、現在のページに表示されていない依存カードも含めます。Study ゲートウェイクライアントはデータを変更しない削除事前確認を提供します。

## 辞書のインポートと下書き

辞書の検索結果を確認してから、発音、分類、タグ、参照、語義ごとの定義を適用できます。インポートした発音は、手動で保存した発音と同じ操作部品ですぐに表示されます。自動生成した発音は主入力の変更に追従し、ユーザーの別の発音を保持します。必須タブの印は一つになり、定義の追加ボタンも小さくなります。

共通の検索契約は `class`、`tags`、`definitions`（言語別の翻訳と出典）、`sourceUrl` を受け取ります。プロバイダー固有のデータは宣言済みフィールドに保存します。日本語モジュールは非表示の `dictionary_data` に Jisho のレコード全体を保持します。インポートした定義にも、公開範囲、競合検出、依存関係の検証、キャンセル時の削除が適用されます。

不足している翻訳を取得する操作は `{ translations, languages }` を `POST /api/v1/study/library/definitions/localize` に送信します。`localization:translateString` で不足する UI 言語を取得し、既存の翻訳を保持します。プロバイダーがない場合や失敗した場合は `missingLanguages` を返します。不足する訳文は編集でき、英語を別の言語の欄にコピーしません。定義を手動で追加する場合にも利用できます。

## 管理者のカード作成と筆順検索

管理者は公開チェックボックスなしでグローバル名前空間にカードを直接作成します。インライン作成や辞書インポートの定義も同じ公開先を使い、非公開の依存カードは保存前に公開する必要があります。筆順欄の検索は辞書プレビューを開かず、提供された筆順をすぐに適用します。

## 検索結果を開いている編集画面に反映

辞書検索は結果ポップアップや適用操作を挟まず、開いているカード編集画面に値を直接反映し、返された定義と発音をすべて確定します。既存の値がある場合は検索前に置き換えを確認します。キャンセルや結果なし、検索失敗の場合は現在のカードを保持します。筆順検索に成功すると検索ボタンを非表示にします。辞書の出典URLはリンクとして表示せず、非表示の出典データに保存します。

## 参照を解決するインポートと定義の編集

辞書インポートは、通常のリンクやグループ化したリンクを追加する前に、提供元のレコードIDをアクセス可能なインストール済みカードに対応付けます。参照先が見つからない、または曖昧な場合は警告し、保存を妨げずに値をリンクなしで保持します。確定した定義は既存の権限確認付きカード編集画面で編集でき、保存すると編集画面の要約も更新されます。辞書出典データなどの非表示スキーマフィールドはフォームに表示せず、保存された値を保持します。

## カード編集の検索修正

取得した筆順がある場合、辞書の検索結果や保存済みカードから読み込んだ場合も筆順検索ボタンを非表示にします。筆順を消去すると検索が再表示されます。定義編集では翻訳を「内容」に表示し、不要な「定義」タブを省きます。セミコロンで区切られた辞書の意味を個別の確定済み定義として取り込み、対応する翻訳と元の出典メタデータを保持します。構造化された意味がある場合、まとめられた出典定義へのリンクを置き換えます。

## 辞書の発音リンク

辞書から取り込む発音は、全体を構成できる最長の一致を使ってインストール済みの仮名に解決します。きょやっくなどの複合文字と同じ文字の繰り返し位置を保持します。読みグループには正規の項目IDを順序付きで保存し、不足する文字がある読みを部分的にリンクしません。定義は一致するカードを再利用し、必要な場合は通常の編集処理で作成します。下位カードの作成は引き続きカルーセルを中心に行います。文字と助詞は提供元のみが作成する読み取り専用のレイヤーを維持します。文の編集画面では辞書検索を提供しません。

## 辞書の候補を選択

語彙作成では、不要な「入力」見出しを省き、組み合わせたカードの入力欄を一つ使用します。辞書検索をその直下に表示し、選択した構成カードを含む全体の文字列を検索します。語彙の発音は漢字の読みから自動生成せず、手動入力または辞書からの取り込みで設定します。一件の結果は直接編集画面に反映し、複数の結果は「複数の候補が見つかりました」という見出しの下にカードのプレビューを横並びで表示します。候補をクリックして確認すると、項目、発音、定義、タグ、関係を取り込みます。候補を選択するまで確認ボタンは無効です。キャンセル時は現在の編集内容を保持し、定義を作成しません。辞書で確認したカードの文字列は送信でき、その後文字列を変更すると再度解決が必要です。文の発音は引き続き構成要素から導出し、文の辞書検索は無効のままです。

## 語彙の入力を保持

語彙の辞書検索は、入力したテキスト、構成要素の順序、選択した入力カードを保持しながら、補足フィールド、発音、定義を取り込みます。フォームはAPIと同じ正規化比較で一致する定義を再利用します。新しく取り込んだ定義は直ちにキャッシュされ、同じ意味の繰り返しによる競合を防ぎます。再利用時は保存先の公開範囲を守り、既存の定義の翻訳を保持します。

## 変換した文と公開範囲の移動

文の作成、編集、詳細表示では、順序付き参照ごとに選択した変換から発音を導出します。同じ語根の繰り返しにも個別の位置と変換経路を保持します。定義済みの句読点は隣接するタイトルリンクを妨げずに表示されます。タイトルと発音のリンクは選択した形を開き、語根に戻る操作を保持します。公開範囲の移動は登録済みのStudy Libraryフローを実行し、更新した権限を返します。自分のカードは移動後も表示されます。共有カードは元の作成者のユーザー範囲に戻るため、操作名は「移動先: ユーザー」です。プロバイダー所有コンテンツ、共有の依存カード、審査待ちの申請、アクセス制限は引き続き不正な移動を防ぎます。開発者向け指示では、実行可能な実装のない機能、操作、ルート、フローの公開を明示的に禁止しています。

## 簡潔なコンポーネント実装

入力検証、識別子のパターン、定義言語、派生方向は共通の役割別ヘルパーを使用します。コンテンツ音声処理は専用モジュールに分離し、コンテンツパックは安定したレコード識別子を直接使用します。

## 辞書検索とキャッシュ

Cognis core は `core:cache` で辞書キャッシュを管理します。保存した検索は一時間後にコールド状態となり、次の利用時に提供元の変更を確認します。変更結果は十二時間の反映時刻まで保留し、変更のない内容は維持します。同時検索は一つの確認を共有し、確認失敗時は最後に成功した結果を保持します。状態は再起動後も残ります。モジュールは提供元のデータを取得するだけで、検索のスケジュールや独自の応答キャッシュを管理しません。Jisho に軽量な変更通知 API はないため、確認には通常の検索応答が必要です。手動の更新ボタンはありません。発音とカードのリンクは常に現在アクセスできる内容から解決します。

## レビューと範囲変更

管理者とオーナーは個人カードを権限のある共有範囲へ直接移動し、学習者はレビューを申請します。移動先の文字とアイコン全体がボタンになります。申請には提出したカード、変更案、範囲、作成者、日時、状態、権限に応じた操作を表示します。取り下げを含む判断履歴を保持します。カードの変更と判断を同一のデータベーストランザクションで確定し、保留状態からの条件付き更新で重複操作を防ぎます。検証に失敗した判断は取り消され、古い申請や重複操作にはエラーを表示します。提出時の内容を保持し、元カードが変更された後の承認を防ぎます。

## 効率的な辞書参照解決

辞書結果は参照カードの読み込みが成功してから表示されます。プレビューでは参照先のエントリーIDまたは提供元IDと、発音に必要な基本文字だけを取得します。カルーセル用の全ライブラリは編集画面やリンク先カードを開く際に読み込みます。カード一覧の参照はカードごとではなく一括取得します。申請一覧は取得済みの行を利用し、権限のない申請や完了済み申請の元カードを再取得しません。検索と審査プレビューでは非表示フィールドに同じ表示条件を適用します。期限切れの辞書キャッシュは期限インデックスを使用し、書き込み時に削除します。承認による移動も、判定トランザクション内で直接移動と同じ登録済みフローを実行します。

キャッシュに一致した場合も登録済み検索フローを実行するため、拡張フックが一貫して適用されます。

学習ナビゲーションは保留中の審査項目だけを取得し、申請ページではすべての状態の履歴を保持します。

自分の申請は提出した全状態を読み取り専用で表示します。保留中が唯一のレビュー一覧です。ヘッダーには申請者と確認者のプロフィール画像とリンクを表示し、決定時刻は状態バッジで確認できます。カード名、主要な発音、定義を展開可能な一行の概要にまとめ、関連カードを関係ごとに整理します。公開範囲を狭める操作にはキャンセルボタンのスタイルを使用します。移動方向が相反する選択や変更のない移動先では、該当する選択を解除するまで操作を無効にします。

## 辞書の読みのグラフ

辞書の元データは作成画面と詳細画面で非表示のメタデータとして保持します。取得した発音には親カードと同じ公開範囲の非表示語彙カードを使用します。複数の読みを持つ漢字では各読みに非表示カードを作り、名前を元の漢字へ、発音を順序付きのかなへリンクします。読みが一つの漢字は直接かなへリンクします。単語全体の読みは利用可能な最も近い漢字の読みの構成要素と残りのかなで構成します。定義は非表示の読みへ直接リンクします。Cognis は提供元の識別子を解決し、通常のフィールド、レイヤー、依存関係、ACL の検証を通してグラフを一括保存します。文字と助詞の作成は提供元に限定します。同じひらがなの読みを繰り返すだけのカタカナ候補は、辞書がそのカタカナ表記を示す場合を除いて除外します。漢字の正式な音読みと実際の外来語の読みは保持します。

## 検証済みの操作ステージ

辞書の再取り込みは一致する非表示の読みカードを再利用し、重複競合を起こしません。所有者の検証と保存は対応する ctx ステージで実行し、編集には更新フローを用意します。フックの拒否時は書き込みをロールバックします。不正な検索入力には安全な検証コードを返し、予期しない内部障害には一般的なサーバーエラーを返します。共通の定義検証はコンポーネント内の reuse に配置します。

## 構成と移動

カルーセルのカードにポインターを重ねると、位置番号の代わりに一致する配置すべてが強調されます。ポインターでドラッグすると、文字を選択せずに各配置を並べ替えられます。入力した動詞の候補も、幅を広げた２列の活用選択を開きます。登録済み定義はごみ箱から関連付けを外せ、辞書の意味順を維持します。画面の再登録では以前のイベントリスナーを解除し、一括削除の確認は１回だけ開きます。

共有カードを個人領域へ移動するには、管理者自身も確認と管理者審査への申請が必要です。承認時にアクセスを失う依存カードを再計算し、その連鎖削除と移動を同一トランザクションで行います。利用可能な個人カードは残ります。保護カード、プロバイダーのコンテンツ、依存する審査中申請がある場合は承認できません。通常の削除権限は変わりません。申請成功はトーストで通知し、削除されたカードの所有者にはStudyカテゴリの通知を送ります。move-to-personalエンドポイントは、移動済みカードではなく、審査中申請をHTTP 201で返します。

## 辞書と活用

活用カード内では見出し、読み、定義を同じ列に揃えます。原形を使う操作は中立スタイルのボタンです。ドラッグ中は移動先の前後に縦の挿入マーカーを表示します。Jishoから読み込む語彙には対応する活用グループのタグを保存し、新しく作った動詞は親の構成に配置する前に活用選択を開きます。副詞の品詞も保持しますが、現在の日本語スキーマには副詞の活用セットはありません。

辞書プロバイダーはprerequisitesとして{ key, layer, label }の配列を返せます。作成画面で候補を選択した後、Cognisは指定の公開範囲で既存の複合文字カードを解決し、なければ辞書から取得して定義と読みのグラフを含むカードを作成します。この経路では原子的な文字と助詞を作成できません。主カードと非表示の読みの参照では、別名キーを正式なIDに置き換えます。語彙の入力は変更せず、読み込んだ表記リンクは入力が検索語と一致する間だけ使用します。検索結果を見るだけでは依存カードを作成しません。

不足する必須フィールドは、保存前に登録済みの補助検索プロバイダーから取得します。漢字の筆順パターンにはKanjiVGを使います。各漢字、定義、非表示の読みは、公開範囲を検証した１つのグラフとして保存します。

## カード識別とインポート

重複カードの統合は登録済みフローで実行します。管理者は追加内容を即時反映し、学習者は共有カードのレビューを申請します。元の入力構成と単一値を保持し、別の読み・意味・タグと許可された非表示読みカードを追加します。個人用の依存カードを共有グラフに追加することはできず、失敗時は下書きを保持します。同じ構成の辞書結果は読みと意味をまとめます。異なる長い表記を選ぶと即時適用し、続行または閉じる操作では完全一致の構成を使います。取り込んだ読みは非表示カードをたどって個別の仮名に解決し、編集時は古いグループ参照を置き換えます。作成成功時は通知を表示します。同じ関係のカルーセルは、文構造カードを含む互いの選択を保持します。

フィルターは選択中のレイヤーの表示内容に合わせます。移動ではカード識別子を保持して `relocatedAt` を記録し、個人用と共有の範囲を繰り返し移動しても新規カードとして表示・通知しません。新しい公開カードと新しいプロバイダーのレコードは通常どおり通知します。申請には元の下流カードの詳細と意味を保存します。権限のある履歴では移動後もその文脈を保持し、元のカードを削除した場合は利用不可と表示します。

## 入れ子の子カード配置

展開した子カードはアクティブな枝の近くの空き位置に配置します。暗く表示された背景カードが子カードをグリッドの端へ押し出すことはありません。さらに深い子カードを開いても、配置済みの祖先は移動しません。縦方向の空間が不足する場合は、グリッドにスクロール可能な余白を確保し、閉じると解除します。ウィンドウやカードのサイズが変わると配置を再計算します。ポインターとキーボードのフォーカスで枝の表示を一貫して制御し、子カードの長押しは現在の枝を継続します。保留中の配置処理はまとめて実行し、枝を閉じるとキャンセルします。

## Study の閲覧とお気に入り

Flashcards は所有するデッキ、アカウントに共有されたデッキ、有効な言語プロバイダーの完全なスターターデッキを一覧表示します。共有リンクのアクセス規則は維持され、公開ディレクトリーにはなりません。ウィジェット右上の + メニューでデッキの作成とインポートを選択します。Explore、Library、Flashcards はアカウントに保存される Study のお気に入りと並べ替え（提供順、A–Z、Z–A、新しい順、古い順）を再利用します。星はお気に入りだけを表示すると金色になります。Library 項目、デッキ、個々の学習カードのお気に入りは独立しています。お気に入りはアクセス権を追加しません。描画パッドは画面遷移時にセッションを終了し、composer や shell のクラスを上書きしません。

## 辞書検索結果

辞書検索はURLパラメーターなしで `/study/library/search` を開きます。ゲートウェイクライアントは検索語・言語・辞書をアカウントごとのサーバー設定に保存し、認証済みセッションを通して取得します。他のアカウントはこの状態を読めません。複数の候補は横スクロールのプレビュー列に表示され、選択するとスクロール位置を保ったまま単一の詳細表示を更新します。候補が1件なら詳細を直接表示します。バッジの重複と辞書の生データ表示を避け、カード作成には既存のコンポーザーと依存関係解決を使います。キャッシュの期限と更新方針はCognis coreが管理します。

## 任意の語形と到達可能なプレビュー

各活用セットは文法上の `matchTags` と必須の `flag`（例：`transform:verb`、`transform:plural`）を宣言します。対応するフラグを持つ基本カードだけが活用を有効にします。不明または生成不能なフラグは検証に失敗します。活用形は基本カードの正規UUIDと `{setId, path}` で識別する読み取り専用ビューです。独立したカードとして作成、インポート、同梱することはできません。文法クラスの異なる独立した同形語は保持できます。

基本カードへのリンクは見出しの出典表示に統合し、前へ・次への操作を維持します。

明示的な文のタイトル構成では、複数語のカードや選択した変形を含め、リンクされた構成要素間の空白を保持します。空白は通常のテキストとして扱い、正規の単語と句読点はリンクとして操作できます。構成要素の欠落や未宣言の句読点がある不完全な構成は引き続き拒否します。

## 発音音声

Bootstrap は `study:audio:provider` を必須とし、辞書と筆順のプロバイダーとともに解除可能な音声プロバイダーを登録します。発話ラベルと優先する読みに基づいて同梱録音を解決し、容量制限付きでファイルを読み、不足する音声は明示的なエラーにします。解除時には処理中の取得を中断します。Cognis はカードへのアクセスを認可し、スキーマから選択した変形の発話形を導出し、作成済みフィールドを変更せず Files に非公開キャッシュを保存します。`study:library:audio` フローは認可、検証、解決を実行し、`study:audio:fetch` はプロバイダーのバイト列を検証して取得します。文の音声は構成要素を順番に再生します。

初期録音は多言語ニューラルモデル Kokoro をオフラインで使用し、英語に `bf_emma`、日本語に `jf_alpha` を使用します。クリップは 128 kbps、開始前の無音 200 ms、終了後の無音 180 ms、上限付きピーク正規化、遅めの発話速度で生成します。モデルの帰属表示と Apache ライセンスは `data/audio/VOICE-LICENSE.txt`、声と処理設定は録音一覧に記録します。

音声の取得は学習者が再生を要求したときに始まり、カードを開くだけでは音声を要求しません。再生エラーはホストのローカライズ済みトーストと構造化ログで示します。文の構成要素は選択した変形記述を保持し、認証済み音声エンドポイントは任意の表示テキストを受け取らず、スキーマから発話形を導出します。英語の文字組み合わせの初期音声は記載された IPA 音素から合成し、アルファベットの音声は文字名を発音します。

## 辞書音声とホストのキャッシュ

要求された発音が同梱されていない場合、English Study は English Dictionary API で単語を検索し、その発音メディアエンドポイントから一致する MP3 を取得します。優先 IPA の読みが指定されている場合は一致が必須で、異なる発音で代用しません。`api.dictionaryapi.dev` の HTTPS メディアだけを許可し、リダイレクトを拒否します。検索とダウンロードは一つの制限時間を共有し、両方の応答をストリーミング時のバイト数で制限します。録音がない場合は明示的なエラーを返します。Google の音声サービスは使用しません。

録音キャッシュはモジュールではなく Cognis が管理します。認可後、非公開の Files キャッシュで取得済み録音をカード間および再起動後も再利用します。同時再生要求は取得と保存を共有します。キーには提供元の識別子、リビジョン、言語、役割、ラベル、読みを含め、読みや提供元リビジョンが変われば別途解決します。要求や保存の失敗は再試行できます。モジュールが辞書に接続するのは、再生要求時にキャッシュがない場合だけです。

## 間を付けた合成と手動置換

文カードには任意の音声フィールドがあります。初回再生時に Cognis は全構成要素へのアクセスを認可し、最初の発音グループだけを選び、指定の変形を適用して、開始前の無音と単語・読点・文末の間を持つ一つの連続 WAV を生成します。録音は非公開でキャッシュし、構成音声のバイト列、読み、変形、間の変更で識別子が変わります。新規カードと既存カードの両方で必要時に生成します。通常の作成画面で音声をアップロードすると生成音声を即座に置き換え、明示ファイルを削除すると自動合成に戻ります。提供元は語の録音を提供し、Cognis が合成とキャッシュ方針を管理します。

## 参照データの収録範囲

日本語の参照カタログは同梱する公式 KANJIDIC2 データの全 13,108 字、英語のカタログは Open English WordNet の全 135,969 語彙項目（正規化キー 127,311 件）を収録します。別の遅延読込辞書プロバイダーであり、149,077 件のカードを起動時に一括取り込みするものではありません。Study 検索で参照辞書を選び、対応項目を通常のグラフ検証経由で取り込みます。意味や使用可能な読みがない項目は不明のままとし、発音・翻訳・筆順を捏造しません。全 Unicode 漢字や存在し得る全英単語の網羅を意味しません。

漢字の読みは JMdict の一般的な用例と利用可能な頻度情報に基づき、送り仮名形も含めて並べます。グループ参照と初期音声は同じ順序に従い、漢字再生は常に最初の読みを使います。既存英単語カードには一つの IPA を収録し、参照項目は優先する英国発音内の原資料の順序を他の方言より先に維持します。発音頻度は文脈に依存し、原資料は全ての読みの普遍的順位を提供しません。

`python3 scripts/import-reference.py --source <source-file>` で参照シャードを再生成します。日本語は `--priorities <reading-priorities.json>` に対応します。`data/reference/manifest.json` に原資料のチェックサム、帰属、件数、シャードのハッシュを記録します。要求されたキーのシャードだけを読み込み、実行時の検索結果は Cognis がキャッシュします。

## 参照項目の完全な読みの録音

日本語はさらに `data/audio/reference/` の容量制限付きバンクに、完全な読みのニューラル音声 2,913 件を同梱します。初期録音と合わせて、原資料で読みが分かる全 12,356 字の優先読みに対応します。残る 752 字には読みが記録されておらず、音声を捏造しません。索引は最初の読みを選び、ファイル範囲と中断を確認します。`python3 scripts/reference-audio.py plan --work <directory>` で計画を作り、合成スクリプトで一覧を処理し、`pack` で容量制限付きバンクを生成します。

日本語の並べ替えツールは `--dictionary <JMdict.gz> --kanji-dictionary <KANJIDIC2.xml.gz> --output <priorities.json>` と任意の `--content-root data/library/content` に対応します。一般的な独立語の読みを優先し、他の読みは実在語の対応付けを頻度で重み付けして並べ、`data/audio/primary-readings.json` の確認済み単字カード用の指定を維持します。連濁と促音化は原資料の標準読みに戻して集計します。訓・音・名乗りの読みを保持し、選択された最初の読みだけが再生とキャッシュ識別を決めます。頻度情報は順序付けの手掛かりであり、全発音に通用する普遍的な頻度測定ではありません。

自動合成には発話対象の構成要素の録音が必要です。不足する録音は明示的なエラーとし、通常の音声アップロード欄から補えます。同梱アルファベットに結び付けられない参照項目の綴りは、原文と定義を保持し、架空の綴りリンクを作りません。

## 書き取りの答えを隠す

パッドの見出しは最初に文字を隠し、共通ボタンをクリックすると表示します。別の文字を読み込むと再び隠します。フローティングセッションは解除可能な `study:drawing:observe` 機能で現在のカードを通知します。一致するLibraryプレビューは開いたままぼかして操作不能にし、パッドの文字変更または終了時に解除します。読みと意味はパッドに残します。埋め込みの書き取りにも同じ処理を適用し、文字の表示を補助付き試行として通知します。

## 読み方の結果とリンク

Explore のカードリンクは `/study/explore/<language>/<layer>/<card-id>` に正規カード ID を含みます。Ctrl、Command、Shift を押しながらクリックするとブラウザー標準の操作を利用でき、直接開いても該当カードのプレビューを表示します。未回答のカードを調べた場合は補助ありの試行として扱います。通常の移動では、ブラウザーの「戻る」でデッキの順序を復元します。

## 保存される学習設定

新しい語彙カードは入力確定時と保存前に辞書で品詞と対応する活用タグを自動検出します。手動のタグを維持し、曖昧な品詞は利用者が選択します。遅れて届いた結果で別の下書きを変更しません。選択中の動詞・形容詞の副詞形・複数形はその変形に対応する音声を要求します。見出しの出典表示から基本カードへ移動できます。アップロード欄と再生用音声要素のセレクターを分離し、文字エディター初期化時のエラーを修正しました。

## 参考画像とリクエスト審査

カードには `input.control: "imageFiles"` を持つ任意の `imageList` フィールドを宣言できます。カード編集画面から PNG・JPEG・WebP・GIF を1ファイルにつき最大5 MiBまでアップロードでき、詳細画面に画像が表示されます。同梱画像はコンテンツパックの assets ディレクトリからの相対パスを使い、ライセンス表記を保持します。アップロードしたファイルは非公開で、閲覧権限のあるカードまたはリクエスト経由でのみ取得できます。`PUT /api/v1/study/library/images` で画像データを送信し、`GET /api/v1/study/library/entries/:id/images/:field/:index` でカード画像を取得します。権限のあるリクエストのプレビューには対応する `push-requests` パスを使用します。

リクエストには通常のカードプレビューが表示されます。保留中の提案カードを開くと下書きを編集でき、`PATCH /api/v1/study/library/push-requests/:id` は管理者に限定されます。下書きの保存では公開中のカードは変更されません。承認時に下書きが反映され、申請者と変更を行った管理者が共同所有者になります。変更のない保存では所有者は追加されません。申請者と承認者のプロフィールプレビューには明確なラベルが付きます。承認・却下・取り下げにはそれぞれ確認が必要です。有効な管理者には新規リクエストと他のユーザーの判断について Study 通知が届きます。リクエストのナビゲーションリンクは点滅しません。

閲覧操作には、ページに読み込まれたカードを即座に絞り込むテキスト検索があります。選択したフィルターやお気に入り条件と併用できます。

## メディアと通知の修正

モジュール同梱画像を含む参考画像が、Library 編集画面と読み取り専用の詳細画面でサムネイル表示されます。マウスを重ねるかキーボードでフォーカスすると赤い削除ボタンが現れ、タッチ画面では常時表示されます。削除に確認は不要で、下書きとファイル選択を消去し、未使用の一時アップロードも破棄します。未保存の編集画面を閉じた際にもプレビューと一時ファイルを解放します。保存済みカードやリクエスト履歴が参照する画像は保持されます。 削除ボタンには不透明な背景が付き、写真の上でも見やすくなります。独自の画像ファイルと保存済みの参照は、サーバーの再起動やプロバイダーの再読み込み後も維持され、編集したカードへのプロバイダー更新でも保持されます。

マイク録音はブラウザーの許可への回答を待ち、回答待ち中は重複要求と保存を防ぎます。編集画面を閉じた後に許可されたストリームは停止します。許可の拒否と録音非対応には個別のメッセージを表示します。マイク・再生・再読み込みは同じ幅で1行に並びます。集合複数形は該当する名詞群をまとめた1つのチェックボックスとなり、無関係な選択肢は非表示になります。 音声ファイル名は非表示です。再生ボタンは最新の一時アップロードまたはマイク録音を再生し、遅れて届いた保存済み音声に置き換わりません。録音中はマイクのアイコン自体が赤くなり、ホバー中も維持されます。ボタンの通常のテーマ表示は変わりません。

Study 通知は送信時に現在のケイパビリティを解決するため、起動順やコンポーネントの再有効化によって配信が恒久的に無効になることがありません。配信結果を確認し、成功した送信先がない場合は失敗として扱います。一部の失敗を記録し、成功した受信者と送信方式も監査できます。

グローバルな `ui:imagePreview` はサムネイル描画、イベント設定、および登録済みの `ui:imagePreview:open` フローを通じた `open` 操作を提供します。`ui:reuse` から `image-preview.js` としても利用でき、操作の公開前に共通スタイルシートを読み込みます。画像ボタンを押すと、元画像を画面内に収まる自然なサイズで表示し、通常の X ボタンだけが表示されます。キーボード操作、Escape、フォーカスの復元、親画面やプロバイダー終了時の閉鎖は共通ポップアップのライフサイクルに従います。画像 URL と任意の削除操作は呼び出し側が管理します。Library の編集画面と詳細ギャラリーは、アップロード画像と同梱画像にこの共通コントロールを使用します。

共通の画像プレビュープロバイダーは、操作を公開する前にスタイルシートを読み込みます。画像専用ポップアップは見出しのマークアップを削除し、横長・縦長・パノラマ画像を横方向にも縦方向にもスクロールせず画面内に収めます。Library の詳細プレビューは最大 20rem × 18rem、編集画面のサムネイルは 8rem × 6rem を維持します。

## 学習メディア

カード詳細の参考画像はスクロールバーを隠した横スクロールの列に表示されます。音声再生はカード名、階層、アーティスト名 Cognis、アプリアイコンをシステムのメディアセンターに送り、再生・一時停止・停止と終了時の後処理に対応します。同梱の文音声を自動結合より優先します。言語モジュールには日本語34文、英語45文の直接録音を同梱し、日本語の仮名124クリップを日本語表記と明示された音声 ID で再生成しました。

## 音声の再生成

グローバルカードの音声を再生成すると、音声フィールドと検索インデックスのみを更新します。必須の識別情報、スキーマ、分類、所有者、独自メディア、グループ化された参照は保持します。更新時刻の楽観的チェックにより、同時編集を上書きせず拒否します。以後の再生には、再生成してキャッシュした録音を使用します。

## 発音の削除操作

確定済みの発音チップでは、読みの構成要素の隣に間隔を空けて削除ボタンを配置します。右から左のレイアウトにも対応し、短い読みでも長い読みでも X が内容に重なりません。

## 無効な学習言語の分離

Study Library は保存済みのスキーマ、カード、音声、画像、同梱ファイル、審査依頼を公開する前に、言語の稼働中ケイパビリティを確認します。無効な言語は一覧から消え、直接取得も拒否します。再有効化すると保存内容を削除せずにアクセスを復元します。実行中の登録状態とコンテンツの永続化を分離します。

## 稼働中の言語レジストリを参照

ライブラリの利用可否はアダプター内のケイパビリティ保存先ではなく、システムの稼働中レジストリから言語の登録を確認します。一方の言語を無効にしても、ほかの言語のスキーマ、カード、初期デッキの依存先は利用でき、再有効化で保存内容を復元します。公開レジストリを古いローカル情報より優先します。

正式なパッケージ更新でも、ユーザー作成カードや編集済み提供カードから到達できる省略項目を保持します。再帰的な依存関係と循環参照も保護し、それらから参照されない古い提供内容は削除できます。

描画パッドで文字を開いている間、Explore のグリッド内の該当カードのプレビューをぼかし、操作を無効にします。重複表示や再描画後も同じ状態を維持し、文字の変更、パッドの終了、ページからの移動時にカードの大きさを変えずに元に戻します。

## 通知テキストを一度だけ復号

リクエスト通知はXMLエンティティを単一の走査で復号し、アカウントとリクエストの値をリテラルデータとして一度だけ挿入します。符号化されたエンティティ文字列をさらに復号しません。優先言語の文字列が空または存在しない場合は英語を使用し、英語もない場合は明示的なエラーにします。4つのリソースカタログは通知処理のインスタンスの有効期間中キャッシュされ、読み取り失敗時は再試行できます。

## 動的に生成される活用形

各活用セットは文法上の `matchTags` と必須の `flag`（例：`transform:verb`、`transform:plural`）を宣言します。対応するフラグを持つ基本カードだけが活用を有効にします。不明または生成不能なフラグは検証に失敗します。活用形は基本カードの正規UUIDと `{setId, path}` で識別する読み取り専用ビューです。独立したカードとして作成、インポート、同梱することはできません。文法クラスの異なる独立した同形語は保持できます。

規則は接尾辞の削除・追加、任意の接頭辞操作、順序付き `suffixes`、不規則変化を表す見出し語別の `forms` により表記と発音を変換します。例外指定は汎用の文字列操作を置き換えます。複数語の表現を含めて状態を連結でき、増大する循環は拒否します。定義テンプレートの補間は一度だけ行い、挿入した文字列を再解釈しません。

詳細表示、文の検証、音声は同じ解決処理を使います。生成ビューは参考画像を保持し、基本形の音声・筆順フィールドを除去します。生成した表記と第一発音で音声を検索し、再生成しても基本カードを変更しません。書字練習は生成した表記の文字パターンを合成し、筆画グループを保持して空白を無視します。録音テストでは有効な各規則に経路付きのクリップを必須とします。活用形カードの保存表現や互換用の別名はサポートしません。

公開プロバイダー契約は `transformationModel: "generated"` を宣言し、両言語モジュールは登録前にこれを必須とします。有効なセットの各規則が基本カードに適用できなければ検証に失敗します。形容詞から副詞への変換など、品詞が変わる規則は `resultClass` を指定できます。明示的な参照が無効な場合は基本形に置き換えず、処理を拒否します。

Library の UI プロバイダーは、正規の項目を順番どおりに見出しへ表示する利用側向けに `study:library:presentation.titleComposition(detail, schemas)` を公開します。Library の詳細タイトルと同じロジックで、保存された参照グループ、リテラル文字列、選択された変形を解決します。プロバイダーを無効にすると、この機能も削除されます。Flashcards はこのプロバイダーを必須とし、リンクされた見出し項目をテーマ対応ボタンで表示します。Explore への移動時も選択した変形を保持します。

## 学習者向け分類の整理

レイヤーの `detail.tags` は、学習用ピルとして表示するローカライズ済みタグを明示します。内部タグは変形や編集のために保持します。`filterable` を指定したタグだけがフィルターになります。選択肢の表示名を翻訳し、プロバイダーの定義順で表示します。任意のフィールドは `detail.autoSelectSingle: false` で初期選択をなくせます。

文字列フィールドは `derivation: { kind: "rankedReferences", relationships, values, requireAll, transformationValues }` を宣言できます。値は易しい順から難しい順に並べます。正規の参照 ID と選択された変形規則の級を使って判定し、保存されたフィールド値を文法の最低要件として扱います。文は最も難しい要件の級だけに一致します。N5 と N4 の混在は N4 となり、N5 だけの文や N3 を含む文は N4 に一致しません。`requireAll` が有効な場合、分類が不明・曖昧・アクセス不可なら未分類にします。表示単位で結果をキャッシュし、保存カードを書き換えず、参照内容の更新に追従します。

## 汎用の難易度プロファイル

両方の Study モジュールは共通の `difficulty_level` フィールドを使います。同一の正規化処理と契約テストが `data/library/difficulty.json` を読み、表示名、選択肢の順序、出典タグの対応、基本レイヤーの既定値、変形の難易度をデータとして扱います。日本語は JLPT N5～N1、英語は既存の初級・中級・上級を表示します。不明な値は未分類のままです。ホストは言語固有の規則や別名フィールドを使わず、宣言されたフィールドを順位付けします。

## 開いたカードを閲覧済みにする

直接リンク、関連項目、前後への移動で詳細を開くと、認証済みユーザーの正規カード ID を閲覧済みとして保存します。編集画面でも同じ処理を使います。保存成功時に対応するプレビューの「新規」表示とローカル状態を更新し、ホバーと詳細表示の同時リクエストをまとめます。保存失敗は詳細表示を妨げず再試行できます。読み込み失敗やキャンセルでは未閲覧カードを変更せず、開いた詳細に古い「新規」ピルを表示しません。

任意の単一選択欄にはローカライズした **未設定** を用意します。未分類のカードを編集しても先頭の難易度を自動選択せず、不明な状態を維持します。

辞書検索コンテキストの読み取りは、認可と解決のステージを持つ `study:library:readSearchContext` を使用します。書き込みは `study:library:searchContext` を維持し、保存前の検証ステージで拡張機能が入力を調整できます。その後サービス側でも検証します。両操作は共有リンクの主体を拒否します。書き込みは 16 KiB を超えると HTTP 413 で停止し、不正な JSON は HTTP 400 を返して保存済みの状態を変更しません。予期しない失敗では固定のエラーコードだけを公開します。

## 通知と永続化の修正

Libraryの追加・削除通知はXMLカタログの英語、ドイツ語、インドネシア語、日本語の文面を含み、英語へのフォールバックと `study:library:notifyContent` フローを使用します。置換したカード名を再解釈しません。特権ユーザーの書き込みでも実在するクラスが必要です。ランキングの保存失敗時は観測を取り消し、シーズン切り替えでは再起動後も最終順位を再計算して、保存失敗時に状態を復元します。確認済みの管理者はルームに所属していなくても一致する連携元の紐付けを解除できます。

## オフライン学習の空画面

準備済みの Study ページは、検証済みで必要な同意を満たすオフラインセッションなら非公開コンテンツの保存がなくても開けます。未保存の言語や設定は空のナビゲーションになります。Explore は通常の空の一覧を表示し、ルート利用不可やエラー通知の代わりに「オフライン用に保存されたコンテンツはありません」と案内します。Flashcards もデッキや必要な表示リソースがなければ空画面を維持します。通知は現在のページに限定し、重複表示しません。キャッシュ不足を理由にアクセス拒否や同意拒否を隠しません。Library と Flashcards は公開の翻訳や軽量テンプレートをオンラインで準備し、非公開データは容量制限付きのタブ内キャッシュに留めます。

## オフライン学習アセット

ポップアップ用アイコンの両テーマ版を、提供元のライフサイクルに従うホストのオフラインアセット機能で準備します。キャッシュ済みの閲覧と描画は利用できます。オフラインではコンテンツ編集を無効化し、開いているポップアップの編集操作も接続喪失時に無効化します。装飾アイコンが取得できない場合は翻訳済みの操作ラベルを表示します。

## オフライン利用の維持

オフラインのルート登録は、バンドル版と直接配信版の繰り返し読み込みでも保持されます。スクリプト、スタイル、機能提供元が同じルート記述を再構築しても準備状態を維持し、アセットが変わった場合は再準備が必要です。メッセージは認証済みログイン後にチャット一覧、翻訳、絵文字カタログを準備します。初めてオンラインで訪問する前でもオフラインでページを開けます。自動で開くのはチャット情報と履歴がキャッシュ済みの場合だけで、未保存の履歴を選ぶと専用の情報トーストを表示します。Exploreは別のコレクションや閲覧済み情報が欠けていても、利用可能なキャッシュ済み項目を維持します。権限や同意の拒否は引き続き伝播します。バナーのボタンは共通の操作行に直接配置し、継承した上下のずれを解消します。

## 学習お気に入りの共有

Library の管理画面と編集・検索・申請ページには接続が必要です。権限のあるナビゲーションリンクは、切断直後も含めオフラインでは表示を維持したまま無効になります。Explore ではキャッシュ済みの閲覧と描画を利用できます。Library プロバイダーがオフラインのセッションルートとして登録するのは Explore のみです。

登録済み言語の準備では、Study の契約を通じて共通のスキーマカタログ、各言語のカタログ、許可された軽量コレクションをキャッシュします。利用側は事前にページを訪問せずに準備済みのスキーマとコレクションを読み込めます。描画リソースも初回使用前に準備します。音声、辞書取得、コンテンツ編集、アクセス確認には既存の制限を適用します。

## アカウントIDによる通知配信

Library の申請・コンテンツ通知は不変の `accountId` を宛先に使用し、公開ユーザー名が異なる SSO ユーザーにも配信します。申請の判断では同じ ID で操作したアカウントを除外します。

Studyの申請、コンテンツ、削除の通知は、Libraryのブートストラップ時に登録したカテゴリを使用します。実行時には現在の通知機能を取得するだけで登録処理は行わず、SMTPのブートストラップ制限によって配送や公開範囲変更の通知が止まることを防ぎます。
