# Study リーダーボード

未認証の定義・順位要求は注入された認証検査を呼び出し、データを読む前にHTTP 401で終了します。ルートの引数は既存の型付きHTTP契約と権限検査を使います。

スナップショットはUnicodeの境界でUTF-8最大60,000バイトの行に分割し、トランザクションで置き換えます。既存の単一行の状態も同じ読み取り処理で取得します。メタデータのregisterDefinition、assignCohort、setParticipationはPromise<void>を返すため、完了を待つ必要があります。名前付きctxフローを実行し、保存失敗を呼び出し元へ伝え、失敗したメタデータ変更を元に戻します。シーズンの切り替えも待機可能なPromiseを返します。同時に行われるクラスのランキング登録は、処理中の登録を共有します。

ランキングアダプターは、許可されたグループ内の検証済み学習記録を順位付けし、アクセシブルな順位表を提供します。

## 使用方法

```ts
const leaderboard = ctx.capabilities.require("study:leaderboard");
const table = await leaderboard.requestTableModel(query, "ja");
```

## 技術仕様

### プロバイダー連携

アダプターは `study:leaderboard` を `ctx` で公開します。言語パックなどの Study プロバイダーは Bootstrap 時にこの Capability を取得し、クラスルームまたは参加選択式イベントの定義を登録できます。定義では辞書順または加重順位、最低証拠数、ローリングまたはシーズン期間、同順位規則、コホート方針、任意の昇格・降格を指定します。

プロバイダーは完了した集合を公開 Capability `engagement:recordActivity` に送ります。得た XP をリーダーボードへ反映するには、認可済みアクター、定義 ID、基準 ID、同じ証拠付きアクティビティ集合を指定して `study:leaderboard` の `scoreActivity` を呼び出します。リーダーボードは記録前にすべてのイベントを `study:progress` で検証します。

### プライバシーとクラス

プロフィール可視性判定が閲覧者への本人表示を許可しない限り、順位表には別名を表示します。ブロックと非公開アカウントの規則はクラスルームでも有効です。コホート割り当てと参加設定は定義単位なので、クラス、個人、イベントの競争を対象者を混在させず併存できます。

### ライフサイクル

`rollover` で終了シーズンを保存し、次のシーズンを開始します。訂正時は置換前に以前の証拠を無効化します。アクセシブルでローカライズ済みの表には `requestTableModel`、中立な順位モデルには `queryStandings` を使用します。

起動にはDBゲートウェイが必要です。保存失敗を記録し、後続の保存を妨げません。同一観測の再送では、重複を追加せずに状態を保存します。クラス権限は、取り消し後も含め呼び出しごとに確認します。

## 練習報酬の永続化

確定した練習XPは`study:leaderboard:recordPractice`を通じてランキングへ渡されます。保存済みの点数を使うため、倍率を再度消費しません。正規のクラス練習では、既存の最小参加人数によるプライバシー規則を持つクラスXPランキングを作成します。参加に同意済みでアクセス可能なイベントの明示的なXP基準にも結果を送れます。観測の識別子にはランキングと基準を含めます。訂正時は対応する観測を無効化し、表示時には現在のクラス所属を確認します。
