# SMTP TFAアダプター

メールコード方式は、通知ゲートウェイのSMTP送信アダプターを使い、設定とログイン用のワンタイムコードを送ります。コード長は送信アダプターの配送ポリシーが管理し、TFAはctxを通じて参照します。

## 使用例

1. 管理画面の通知ゲートウェイでSMTPを設定して有効にします。
2. そこで**コード長**を例えば8桁に設定して保存します。新しいメール確認コードと、メールコードTFAの設定・ログイン用コードにこの値が使われます。
3. 設定画面でメールコードTFAを有効にし、確認済みの主メールアドレスに届いたコードを入力します。ログインでは最新のチャレンジのコードを入力してください。再送すると、現在のポリシーに基づく置き換えコードが発行されます。

## 技術仕様

### 前提条件

- 通知ゲートウェイのSMTP送信アダプターが設定済みで、有効になっている必要があります。
- SMTPの提供元は、`notify:emailDeliveryPolicy` バージョン1、メールの可用性、配送機能をctx経由で提供する必要があります。提供元が存在しない場合、無効な場合、または未設定の場合、新しいチャレンジは明示的に失敗します。
- ユーザーアカウントに確認済みの主メールアドレスが必要です。

### 設定と保存

通知SMTPの**コード長**は、メール確認とメールコードTFAのコード長を編集・保存する唯一の設定です。既定値は6桁で、整数に正規化したうえで4～10桁に制限します。TFAには別途編集・保存するコード長設定はなく、提供元を利用できない場合に独自のポリシーで代用することもありません。

### 配送ポリシーとチャレンジ

コード長と再送間隔は、発行時の `notify:emailDeliveryPolicy` から取得します。共通の確認ヘルパーが暗号学的に安全な乱数で数字を生成します。保存したコード長の変更は、再送時の置き換えコードを含む、その後のチャレンジに適用されます。発行済みの設定・ログイン用コードは使用・置き換え・有効期限切れまで元の長さを保持し、設定変更で解釈が変わることはありません。入力長のメタデータは、後から変更されたポリシーではなく、発行済みのチャレンジを表します。

チャレンジコードはプロセスメモリに保存します。アプリの再起動や方式の無効化で、保留中の設定・ログイン用コードは無効になります。複数インスタンス構成では、チャレンジの有効期間を通してリクエストを同じインスタンスに固定する必要があります。

### 登録とライフサイクル

アダプターはブートストラップ中に `notify:registerEmailPurpose` でコード通知アクションを登録し、`notify:sendEmail` で送信します。登録、通知内容、チャレンジの状態を管理し、TFAゲートウェイは共通のアダプターライフサイクル用フックを提供します。ゲートウェイの無効化でSMTPキューと保留中のチャレンジを取り消します。再有効化では新しい登録を作成し、古いチャレンジは復元しません。ログイン表示と言語リソースはこの方式が所有します。
